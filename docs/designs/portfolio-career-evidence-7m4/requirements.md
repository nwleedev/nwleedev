# 채용 판단에 쓸 경력 증거를 만드는 포트폴리오 애플리케이션 요구사항

이 문서는 포트폴리오 애플리케이션의 후속 범위를 결정할 요구사항 기준선이다. 첫 구현 범위를 정할 때 조사 근거와 함께 사용한다.

## 의도한 결과

- 동료 개발자와 채용담당자가 단순한 프로젝트 목록이 아니라 문제를 대하는 방식, 전문 분야, 기술적 판단과 품질 기준을 통해 어떤 개발자인지 이해할 수 있는 포트폴리오 웹 애플리케이션의 요구사항을 정한다.
- 여러 페이지에서 서로 다른 미니 애플리케이션을 사용할 수 있게 하며, 각 미니 애플리케이션이 구체적인 사용자 과업과 확인 가능한 경력 증거를 제공하게 한다.
- 2026년에 등록되었거나 모집 시작이 확인되는 3년차 이상 프론트엔드 개발자와 프론트엔드에 가까운 프로덕트 엔지니어 채용공고를 조사하고, 자격요건과 우대사항에 연결되는 사례를 정리한다.
- 실제 채용 판단과 연결할 수 있는 사용자 과업 성과와 지표의 조건, 수집 방법과 한계를 조사한다.
- 3D, 데이터 시각화, 캔버스와 이커머스를 포함한 후보를 검토하고 정적 배포만으로 구현할 수 있는 후보도 찾는다.

## 반드시 지킬 조건

- 채용공고 조사는 대기업, 대기업 계열사, 유니콘과 중견기업을 대상으로 하고 중소기업 공고는 제외한다.
- 채용공고는 2026년 게시, 재게시 또는 모집 시작을 확인할 수 있어야 한다. 2026년 수정일만 확인되는 공고는 그것만으로 포함하지 않는다.
- 프론트엔드 또는 프론트엔드 중심 역할에서 경력 3년 이상을 숫자로 확인할 수 있어야 하며, 현재 공고와 종료 공고를 모두 조사할 수 있다.
- 동일 공고의 반복 게시를 여러 건으로 계산하지 않는다. 출처별 게시일, 모집 상태나 경력 기준이 다르면 차이를 기록한다.
- 공고마다 회사, 역할, 게시 또는 모집 시작일, 검토 시점의 상태, 경력 기준, 자격요건, 우대사항, 출처와 검토일을 확인할 수 있게 한다.
- 공통으로 반복되는 조건과 특정 도메인이나 역할에만 필요한 조건을 구분한다.
- 포트폴리오 애플리케이션과 그 안에서 제공하는 미니 애플리케이션의 역할을 구분한다.
- 지금 당장 사용자를 모집하기 어려운 조건을 전제로, 초기 포트폴리오의 성패를 외부 유입량이나 대규모 사용성 표본에 의존시키지 않는다.
- 포트폴리오 PDF의 내용을 웹 페이지로 옮기는 방식으로 만들지 않는다.
- 이미 존재하는 애플리케이션을 복제하지 않는다.
- 개인 메모 후보는 LLM 호출 없이도 정확한 반복, 포함 관계와 어휘상 근접 반복을 구분할 수 있어야 한다.
- 3D 생성 세계 후보는 키보드로 게임 캐릭터처럼 이동할 수 있어야 하며, 충돌 판정, 중력과 지면 판정으로 벽 관통과 허공 보행을 막아야 한다.
- 3D 생성 세계 후보는 다음 배경을 추가로 생성하더라도 충돌체와 이동 가능한 지면의 검증이 끝나지 않은 구역에 진입할 수 없게 해야 한다.
- 미니 애플리케이션의 수보다 각 사례가 보여주는 문제 해결, 기술적 판단, 사용자 결과와 검증 방법을 우선한다.
- 사용자 수, 방문 수와 성능 점수만으로 성과를 주장하지 않는다. 수치를 제시할 때에는 대상, 측정 조건, 기준값, 결과값, 표본과 지원자의 기여 범위를 확인할 수 있어야 한다.
- 표본이나 비교 조건이 뒷받침하지 않는 인과관계와 일반화된 사용자 성과를 주장하지 않는다.
- 정적 배포 후보와 백엔드를 사용하는 후보를 모두 조사할 수 있다.
- 후속 구현 범위는 한 명의 개발자가 지속해서 운영할 수 있어야 한다.
- 현재 또는 이전 직장의 비공개 정보와 확인할 수 없는 성과를 경력 증거로 사용하지 않는다.

## 완료를 확인할 증거

- 조사 문서가 현재 접근 가능한 공식 채용공고와 1차 자료를 출처와 검토일과 함께 비교하고, 2026년 등록 또는 모집 시작 여부를 구분한다.
- 채용공고 조사 문서가 동일 회사의 비슷한 공고 수를 늘리기보다 서로 다른 대기업, 유니콘과 중견기업의 사례를 비교한다.
- 채용공고 조사 문서가 자격요건과 우대사항을 별도로 종합하고, 반복 횟수의 집계 기준과 제외한 공고의 사유를 설명한다.
- 포트폴리오 사이트 사례 조사 문서가 실제 사이트마다 첫 화면의 자기소개, 증거 유형, 탐색 방식, 사이트 자체가 보여주는 역량과 한계를 구분한다.
- 조사 문서가 채용 판단에 도움이 될 가능성이 있는 증거와 의미가 약하거나 과장될 수 있는 수치를 구분한다.
- 조사 문서가 포트폴리오 애플리케이션과 미니 애플리케이션의 책임을 구분한다.
- 조사 문서가 후보마다 대상 사용자, 사용자 과업, 보여줄 역량, 배포 형태, 검증 방법, 운영 부담과 한계를 설명한다.
- 조사 문서가 정적 배포 후보를 포함하고, 후보에 백엔드가 필요하면 그 이유와 운영 부담을 설명한다.
- 개인 메모 후보 조사 문서가 LLM 없는 어휘상 근접 반복 탐지 절차, 점수와 임계값, 오탐 위험과 검증 방법을 설명한다.
- 3D 생성 세계 후보 조사 문서가 화면에 보이는 자산, 충돌체와 이동 가능 구역의 책임을 구분하고 키보드 이동, 벽 충돌, 지면 판정, 청크 준비 상태와 실패 시 동작을 설명한다.
- 후속 범위 결정자가 조사 근거를 사용해 첫 미니 애플리케이션 후보를 비교할 수 있다.
