# use-better-terms 쇼케이스 구현 플랜

기존 개발자 소개 화면의 정보 순서와 배치를 유지하면서 별도 쇼케이스 페이지를 추가한다. 준비된 보고서의 원문과 수정본을 데스크톱 아티클에서 표현별로 전환하고, 수정 이유는 아티클 아래 목록에서 확인할 수 있게 한다. 모바일에서는 예시 목록을 제공한다.

## 기준과 적용 지침

- 기준 요구사항은 [쇼케이스 요구사항](requirements.md)의 `방문자가 확인할 내용`, `완료를 확인할 방법`, `추후 결정할 사항`이다. 원문 표시의 조사 근거는 [VS Code 편집기의 마크다운 원문 표시](references/vscode-markdown-editor.md)를 따른다.
- 기존 화면에서 유지할 내용과 시각 규칙은 [개발자 소개 사이트 요구사항](../developer-portfolio-f4b7/requirements.md)의 `한 페이지의 정보 순서`, `글과 언어 관리`, `편집형 시각 규칙`, `글꼴과 글자 체계`, `색상`, `여백과 반응형 배치`, `조작과 움직임`, `접근성` 및 [디자인 체계](../../../DESIGN.md)를 기준으로 확인한다. 쇼케이스에 허용된 차이는 쇼케이스 요구사항에 적힌 본문 너비, 아티클 글꼴과 구문 강조, 수정 표현의 배경색이다.
- 이후 코드 작업에는 [Astro, FSD와 Tailwind CSS 구현 규칙](../../dev/frontend/astro-fsd-tailwind.md)을 적용한다. 새 외부 의존성은 이 플랜의 전제가 아니다.
- 현재 예시는 한국어 원문과 수정본 한 쌍이다. 이 플랜에서는 한국어와 영어 소개 화면 모두 같은 한국어 쇼케이스로 연결한다. 영어 소개 화면의 링크 이름은 영어로 제공한다. 이는 별도 번역 요구가 없는 현재 자료에 따른 작업 선택이며, 쇼케이스의 영어판을 승인된 요구사항으로 취급하지 않는다.

## 작업 순서

1. **보고서와 수정 지점 정리**
   - 진행 상태: 완료. 두 게시 문서가 준비된 원문과 수정본에 각각 일치하며, 확인된 18개 변경 구간을 빠짐없이 연결했다.
   - 생성 대상: `apps/entry/src/_pages/better-terms/content/report.before.md`, `report.after.md` 및 수정 지점 자료를 담을 `apps/entry/src/_pages/better-terms/model/changes.ts`. 준비된 두 보고서의 게재 가능 문구를 확인하고, 수정 전후 표현과 목록의 이유를 같은 지점에 연결한다. 제목, 문단 나눔, 목록 및 표 안의 수정도 빠뜨리지 않는다.
   - 확인: 아티클의 전환 전 텍스트와 전부 전환한 텍스트를 각각 게시할 보고서 원문 및 수정본과 대조한다. 목록의 각 항목이 실제 수정 지점 하나 이상을 설명하고, 강조하지 않은 내용이 바뀌지 않는지 확인한다.
   - 중단: 두 문서의 차이를 누락 없이 연결할 수 없거나 게재할 수 없는 정보가 발견되면 보고서 게시를 멈추고 무엇을 수정하거나 제외할지 결정한다.

2. **쇼케이스 진입과 화면 구성**
   - 진행 상태: 완료. 한국어와 영어 소개 화면에서 새 쇼케이스 주소로 이동하는 링크를 제공하고, 별도 페이지에 보고서와 수정 목록을 세로로 배치했다. 정적 빌드에서 세 주소가 생성됨을 확인했다.
   - 선행 조건: 1번의 게시 콘텐츠.
   - 생성 대상: `apps/entry/src/pages/better-terms.astro`와 `apps/entry/src/_pages/better-terms/ui/ShowcasePage.astro`. 수정 대상: `apps/entry/src/_pages/home/ui/IndependentWorkSection.astro`, `apps/entry/src/shared/terms/ko.json`, `en.json`, `types.ts`. 기존 독립 작업 항목에서 별도 페이지로 이동하게 하고, 쇼케이스의 아티클과 예시 목록을 한 페이지에 세로로 배치한다.
   - 확인: 두 언어의 소개 화면에서 링크를 따라 사례에 도달한다. 소개 화면의 영역 순서, 기존 항목의 내용과 배치, 언어 전환 및 본문 바로가기는 그대로 작동한다. 쇼케이스는 별도 주소에서 직접 열 수 있다.
   - 중단: 쇼케이스의 언어 구성이 바뀌면 연결 대상과 안내 문구를 다시 확인한 뒤 이 단계를 진행한다.

3. **아티클의 전환 동작**
   - 진행 상태: 완료. 두 보고서를 그대로 재구성하는 표현별 전환 자료와 전체 전환을 연결했다. 브라우저에서 한 표현의 전환과 복원, 전체 전환과 복원, 전체 전환 상태의 변화를 확인했다. `pnpm entry:check`를 통과했다.
   - 선행 조건: 1번의 수정 지점 자료와 2번의 화면.
   - 수정 대상: `apps/entry/src/_pages/better-terms/`의 아티클과 전환 상태 파일. 제목 기호, 목록, 링크, 코드 울타리와 표의 원문 문자를 유지하고, 수정 지점만 클릭 또는 키보드로 개별 전환한다. 전체 전환의 표시 상태는 모든 지점의 실제 상태와 일치시킨다. 상태 전환은 입력과 바뀐 문구가 분명해 독립적으로 확인하기 좋은 작업 단위다. 테스트 코드 작성은 현재 계획에 포함하지 않는다.
   - 확인: 한 지점을 두 번 누르면 선택한 문구와 강조만 전후로 바뀌고 다른 지점은 유지된다. 하나라도 수정 전이면 전체 전환이 비활성 상태로 보이며, 누르면 모든 지점이 수정 후가 된다. 모두 수정 후일 때 누르면 전부 수정 전이 된다. 표는 격자 없이 원문의 `|`와 구분 문자를 보여주며 줄 번호가 없다.

4. **페이지 스크롤과 시각 규칙**
   - 선행 조건: 2번과 3번의 화면 및 동작.
   - 수정 대상: `apps/entry/src/_pages/better-terms/`의 아티클, 전환 영역과 목록 스타일, 필요할 때만 `apps/entry/src/shared/styles/global.css` 및 `DESIGN.md`. 전체 전환 영역은 아티클을 읽는 구간에서만 화면 상단에 남게 하고, 아티클 뒤에는 수정 전, 수정 후, 이유 목록을 둔다. 모바일에서는 목록을 읽을 수 있게 하며 아티클과 전체 전환은 추가하지 않는다.
   - 확인: 페이지 전체가 함께 스크롤되고 아티클 내부의 별도 세로 스크롤이 없다. 목록으로 내려가면 전환 영역도 사라진다. 실제 변경 표현에만 붉은색과 초록색 인라인 배경이 적용되고 글자 굵기는 500이다. 320px, 390px, 데스크톱 폭과 200% 글자 확대에서 내용 순서, 읽기와 조작이 유지된다. 키보드 포커스, 명암비, 움직임 감소 설정, 고정 영역에 가려지는 조작 요소를 확인한다. 아티클에 별도 테두리나 안팎 여백을 더하지 않고, 허용된 차이 외의 글꼴, 색, 여백과 단일 칼럼 규칙을 기존 화면과 대조한다.

5. **통합 확인과 기록**
   - 선행 조건: 1~4번 완료.
   - 확인: `pnpm entry:check`와 `pnpm entry:build`를 실행하고 생성된 페이지를 브라우저에서 확인한다. 게시된 두 문서, 수정 지점 목록, 링크와 키보드 전환을 실제 화면에서 대조한다. 마지막에 요구사항의 `완료를 확인할 방법`을 한 번 검토하고 확인한 사실을 기록한다. 문서 작성만으로 화면 구현을 완료했다고 표시하지 않는다.

작업을 실행할 때에는 각 단계가 끝난 뒤 이 플랜의 진행 상태와 확인 내용을 갱신한다. 모바일 아티클과 전체 전환은 추후 결정을 기다린다.
