# use-better-terms 쇼케이스 구현 플랜

기존 소개 화면과 쇼케이스의 시각 규칙을 유지하면서, 쇼케이스의 전체 보고서를 프론트엔드 보고서 다섯 편에서 선정한 두 문단씩으로 바꾼다. 데스크톱 아티클에서는 표현별 전환을, 그 아래와 모바일에서는 수정 이유 목록을 제공한다. 문서 사이는 마크다운 원문 문자 `---` 한 줄로 구분한다.

## 기준과 적용 지침

- 기준 요구사항은 [쇼케이스 요구사항](requirements.md)의 `방문자가 확인할 내용`, `완료를 확인할 방법`, `추후 결정할 사항`이다. 문단 원문은 [선정한 프론트엔드 보고서 발췌문](references/frontend-report-excerpts.md), 원문 표시의 조사 근거는 [VS Code 편집기의 마크다운 원문 표시](references/vscode-markdown-editor.md)를 따른다.
- 기존 화면에서 유지할 내용과 시각 규칙은 [개발자 소개 사이트 요구사항](../developer-portfolio-f4b7/requirements.md)의 `한 페이지의 정보 순서`, `글과 언어 관리`, `편집형 시각 규칙`, `글꼴과 글자 체계`, `색상`, `여백과 반응형 배치`, `조작과 움직임`, `접근성` 및 [디자인 체계](../../../DESIGN.md)를 기준으로 확인한다. 쇼케이스에 허용된 차이는 쇼케이스 요구사항에 적힌 본문 너비, 아티클 글꼴과 구문 강조, 수정 표현의 배경색이다.
- 이후 코드 작업에는 [Astro, FSD와 Tailwind CSS 구현 규칙](../../dev/frontend/astro-fsd-tailwind.md)을 적용한다. 새 외부 의존성은 이 플랜의 전제가 아니다.
- 기존에는 한국어 보고서 한 편의 원문과 수정본을 게시했고, 소개 화면의 한국어 및 영어 링크가 같은 쇼케이스로 연결된다. 발췌문 교체에는 이 연결 방식을 유지한다. 영어판 아티클은 현재 요구사항에 없다.

## 작업 순서

1. **발췌문과 수정 지점 준비**
   - 진행 상태: 원문 두 문단씩 선정하여 [발췌문 자료](references/frontend-report-excerpts.md)에 보존함. 게시용 수정본과 수정 지점 자료의 교체는 미진행.
   - 수정 대상: `apps/entry/src/_pages/better-terms/content/report.before.md`, `report.after.md`, `apps/entry/src/_pages/better-terms/model/changes.ts`. 다섯 문서의 선정된 문단만 게시용 원문과 수정본에 담고, 스크립트 감지와 문맥 검토를 모두 거친 표현을 전환 지점으로 연결한다. 문서별 제목과 `---` 한 줄은 양쪽 문서에서 동일하게 유지한다. 목록의 수정 이유는 그 지점에서 실제로 바뀐 뜻과 문장을 설명한다.
   - 확인: 문서마다 정확히 두 문단이 들어가고 세 문단을 넘기지 않는지 대조한다. 전환 전 문단은 발췌문 자료와 문자 단위로 일치하며, 전부 전환한 문단은 수정본과 일치한다. 선정되지 않은 문단과 스크립트가 감지하지 않은 표현은 나타나지 않는다. 강조하지 않은 문장과 인용 링크는 바뀌지 않는다.
   - 중단: 문단 안의 표현을 맥락상 고쳐야 하는지 판단할 수 없거나 원문의 게재에 문제가 발견되면 그 문단의 게시를 멈추고 교체 또는 제외를 결정한다.

2. **쇼케이스 진입과 화면 구성**
   - 진행 상태: 기존 링크와 별도 페이지 구현 완료. 발췌문 교체의 영향을 받지 않는 구성으로 유지한다.
   - 유지 대상: `apps/entry/src/pages/better-terms.astro`, `apps/entry/src/_pages/home/ui/IndependentWorkSection.astro`, `apps/entry/src/shared/terms/ko.json`, `en.json`, `types.ts`.
   - 확인: 두 언어의 소개 화면에서 쇼케이스에 도달하고, 소개 화면의 영역 순서와 기존 항목 배치가 유지되는지 최종 단계에서 다시 확인한다.

3. **아티클의 전환 동작**
   - 진행 상태: 기존 한 편의 전체 보고서 전환은 구현됨. 다섯 문서의 발췌문으로 전환 대상을 바꾸는 작업은 미진행.
   - 선행 조건: 1번의 수정 지점 자료와 2번의 화면.
   - 수정 대상: `apps/entry/src/_pages/better-terms/`의 아티클과 전환 상태 파일. 다섯 문서의 표현을 독립적으로 전환하고, 전체 전환은 모든 문서의 수정 지점에 적용한다. 문서 제목과 `---`는 전환하지 않는다. 테스트 코드 작성은 현재 계획에 포함하지 않는다.
   - 확인: 한 지점을 두 번 누르면 선택한 문구와 강조만 전후로 바뀌고 다른 지점은 유지된다. 하나라도 수정 전이면 전체 전환이 비활성 상태로 보이고, 전체 전환을 누르면 모든 문서의 지점이 함께 바뀐다. 문서 제목과 `---`는 그대로 남는다.

4. **페이지 스크롤과 시각 규칙**
   - 진행 상태: 기존 보고서의 본문 폭, 원문 표시, 고정 토글과 모바일 목록은 구현됨. 문서 다섯 편의 연속 표시와 문서별 목록 배치는 미진행.
   - 선행 조건: 2번과 3번의 화면 및 동작.
   - 수정 대상: `apps/entry/src/_pages/better-terms/ui/ShowcasePage.astro`와 발췌문 표시 및 목록에 영향을 주는 같은 페이지의 파일. 문서별 제목과 두 문단을 이어 읽게 하고, 문서 사이는 원문 `---` 한 줄로 나눈다. 목록은 문서별로 수정 지점을 묶는다. 기존 아티클 구간의 고정 토글과 모바일 목록을 유지한다.
   - 확인: 문서 사이에 별도 여백, 간격, 테두리나 카드 형태가 없고 `---` 한 줄만 표시된다. 페이지 전체가 함께 스크롤되고 목록에 닿으면 토글이 화면 밖으로 이동한다. 320px, 390px, 데스크톱 폭과 200% 확대에서 읽기와 키보드 조작이 유지된다. 실제 변경 표현에만 붉은색과 초록색 인라인 배경을 적용한다. 쇼케이스에서 허용된 차이 외의 글꼴, 색, 여백과 단일 칼럼 규칙을 기존 화면과 대조한다.

5. **통합 확인과 기록**
   - 진행 상태: 새 발췌문 구성에 대한 확인은 미진행. 기존 전체 보고서를 확인한 사실은 새 구성의 완료 근거로 사용하지 않는다.
   - 선행 조건: 1~4번 완료.
   - 확인: `pnpm entry:check`와 `pnpm entry:build`를 실행하고 생성된 페이지를 브라우저에서 확인한다. 선정한 열 문단, 문서별 구분, 수정 지점 목록, 링크와 키보드 전환을 실제 화면에서 대조한다. 마지막에 요구사항의 `완료를 확인할 방법`을 한 번 검토하고 확인한 사실을 기록한다. 문서 작성만으로 화면 구현을 완료했다고 표시하지 않는다.

작업을 실행할 때에는 각 단계가 끝난 뒤 이 플랜의 진행 상태와 확인 내용을 갱신한다. 모바일 아티클과 전체 전환은 추후 결정을 기다린다.
