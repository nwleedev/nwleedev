# Use Better Terms 화면 정리와 하이라이트 표시 수정 플랜

쇼케이스를 `/projects/use-better-terms`로 연결하고 상단 아이콘, 제목과 소개 문구를 정리한다. 하이라이트 때문에 틀어진 줄 배치는 보고서 내용 변경 없이 수정한다. 원문과 수정본, 개별 전환, 전체 전환, 아티클 구간의 고정 토글과 모바일 목록은 유지한다.

## 기준과 적용 지침

- 기준은 [쇼케이스 요구사항](requirements.md)의 `주소와 상단 UI`, `방문자가 확인할 내용`, `완료를 확인할 방법`, `추후 결정할 사항`이다. 마크다운 원문 표시의 근거는 [VS Code 편집기의 마크다운 원문 표시](references/vscode-markdown-editor.md), 줄 배치 문제의 근거는 [하이라이트 배치 조사](references/highlight-layout.md)다.
- 개발자 소개 화면의 순서와 쇼케이스에 허용된 시각적 차이는 [개발자 소개 사이트 요구사항](../developer-portfolio-f4b7/requirements.md)의 `한 페이지의 정보 순서`, `편집형 시각 규칙`, `글꼴과 글자 체계`, `색상`, `여백과 반응형 배치`, `조작과 움직임`, `접근성` 및 [디자인 체계](../../../DESIGN.md)를 기준으로 확인한다.
- 코드 변경에는 [Astro, FSD와 Tailwind CSS 구현 규칙](../../dev/frontend/astro-fsd-tailwind.md)을 적용한다. 현재 `apps/entry`는 Astro 7.3.3, Tailwind CSS 4.3.3, TypeScript 6.0.3과 `phosphor-astro` 2.1.0을 사용한다. 새 외부 의존성을 추가하지 않는다.
- 게시용 두 보고서는 `apps/entry/src/_pages/better-terms/content/report.before.md`와 `report.after.md`다. 이 수정에서는 두 파일의 문자, 줄바꿈과 공백을 보존한다. 개인 위치, 비공개 도메인과 자격 정보는 코드, 문서와 커밋에 기록하지 않는다.
- 각 절차의 완료 조건을 확인한 뒤 그 절차의 상태와 근거를 이 플랜에 갱신한다. 자동 검사와 화면 확인이 다른 사실을 증명하면 각각 구분한다.

## 현재 적용 상태와 미완료 항목

보고서 두 버전은 이미 게시용 파일에 반영되어 있다. 원문은 413줄, 수정본은 408줄이며, 기존 적용에서 각 입력 파일과의 문자 일치가 확인되었다. 13개 절에 변경 구간 35개를 연결했고 아티클은 현재 123곳의 전환 요소를 제공한다. 표시 방식이 달라져도 이 개수를 고정하기 위해 보고서 내용을 바꾸지 않는다.

기존 적용에서는 `pnpm entry:check`, `pnpm entry:build`, 전후 텍스트 재구성, 개별 클릭과 Enter, 전체 토글과 Space 및 아티클 구간에서의 토글 고정이 확인되었다. 모바일 320px과 390px에는 목록만 표시되며 가로 넘침이 없는 상태도 확인되었다. 확인된 조작과 표시는 유지한다.

줄 배치 수정은 미완료다. 여러 줄 버튼이 inline-block으로 표시되는 현상 때문에 문자 일치만으로 화면의 읽는 순서를 검증할 수 없었다. 실제 200% 확대도 미확인이다. 기존의 640px 너비 확인은 확대 확인을 대신하지 않는다. 새 주소, 홈 아이콘, 제목, 소개 문구와 수정 이유의 변경은 아래 절차에서 적용할 대상이다.

## 적용 순서

### 1. 주소와 홈 이동

상태는 구현 대기다. 한국어와 영어 소개 화면에서 새 주소로 이동하고, 쇼케이스의 홈 아이콘에서 `/`로 돌아갈 수 있어야 한다.

- 생성: `apps/entry/src/pages/projects/use-better-terms.astro`.
- 수정: `apps/entry/src/_pages/better-terms/ui/ShowcasePage.astro`, `apps/entry/src/shared/terms/ko.json`, `en.json`, `apps/entry/astro.config.mjs`.
- 제거: 기존 화면을 제공하는 `apps/entry/src/pages/better-terms.astro`. 이전 주소의 직접 접속은 새 주소로 이동시키는 호환 처리로 유지한다.
- 선택한 아이콘은 설치된 `phosphor-astro`의 기본 `House.astro`다. [Phosphor의 집 모양 후보](https://phosphoricons.com/?q=house)에서 기본 House, HouseLine과 HouseSimple의 선과 형태를 비교했다. 기존 프로필 아이콘과 같은 계열이며 문이 있는 기본 House가 홈 이동을 구별하기에 적합하다. 보이는 크기는 24px, 조작 영역은 44px로 두고 기존 링크 색상과 포커스 토큰을 적용한다. 채운 바탕, 카드 테두리나 새로운 테마는 추가하지 않는다.
- [설치된 패키지의 제공 방식](https://github.com/SeanMcP/phosphor-astro/blob/174cb17a18f61c61caac62ab1aba1307acd9b317/README.md)은 SVG를 Astro 컴포넌트로 제공한다. 홈 이동은 기본 HTML 링크로 구현할 대상이며, 접근 가능한 이름은 `홈으로 이동`이다. SVG 자체는 보조 기술에서 제외한다.
- [Astro의 주소 생성과 이동 안내](https://docs.astro.build/en/guides/routing/)에 따라 새 주소의 진입 파일과 이전 주소의 이동 처리를 함께 확인한다. 현재 정적 빌드의 기본 redirect는 meta refresh HTML을 생성한다. 이 방식만으로 서버가 HTTP 301을 반환한다고 기록하지 않는다.
- 확인: 새 주소 직접 접속, 두 언어의 진입 링크, 이전 주소의 이동, 홈 링크의 목적지와 Enter 조작이 정상이다. 아이콘은 현재 밝은 테마에 맞고 포커스가 보인다.
- TDD는 적용하지 않는다. 주소 연결과 정적 아이콘은 기존 빌드 및 브라우저 탐색으로 확인한다.

### 2. 제목, 소개와 수정 이유

상태는 구현 대기다. 1번의 파일 이동을 반영한 화면에 요구사항의 제목과 문구를 적용한다.

- 수정: `apps/entry/src/shared/terms/ko.json`, `en.json`, `apps/entry/src/_pages/better-terms/model/changes.ts`. `ShowcasePage.astro`는 문구를 표시하는 부분에 필요한 변경만 포함한다.
- 제목은 `Use Better Terms`, 한국어 소개 문구는 요구사항의 `주소와 상단 UI`에 적힌 `개선할 수 있습니다`로 끝나는 문장을 사용한다. 아티클 제목은 `문서 비교`이며 영어 문구도 같은 의미로 정리한다. 스킬 식별자와 URL은 문구 변경에 맞춰 다시 이름 짓지 않는다.
- 수정 이유의 `고쳤습니다`는 `수정했습니다`로 정리한다. `기재했습니다`는 출처나 정보를 문서에 기록한 사실을 설명할 때 적합하며, 현재의 `적었습니다`를 모두 이 동사로 바꾸지는 않는다.
- 2.2절 이유의 `직접 적었습니다`는 `명시했습니다`, 3.2절 이유의 `그 인터페이스를 쓰는 코드를 적었습니다`는 `이를 사용하는 코드를 주석에 명시했습니다`, 5.3절 QueryClient 이유의 `공식 예시에 맞춰 적었습니다`는 `공식 예시에 맞게 수정했습니다`, 8절 이유의 `검토할 순서를 적었습니다`는 `검토할 순서를 제시했습니다`로 정리한다. 각 문장은 기존 변경 이유를 유지하도록 함께 다듬는다.
- 확인: UI에 이전 제목, 이전 소개와 `보고서 전체`가 남아 있지 않다. 수정 이유에 `적었습니다`, `고쳤습니다`가 없고 각 동사는 실제 변경을 설명한다. 보고서 파일과 목록의 수정 전후 인용 내용은 바뀌지 않는다.
- TDD는 적용하지 않는다. 변경 문구와 실제 수정 내용의 대조로 확인한다.

### 3. 하이라이트의 줄 배치와 개별 전환

상태는 구현 대기다. 2번까지의 상단 UI를 유지하면서 원문, 수정본과 일부 전환 상태의 줄 배치를 바로잡는다.

- 수정: `apps/entry/src/_pages/better-terms/ui/ShowcasePage.astro`, `SourceTokens.astro`. 표시와 조작 구간의 연결에 필요한 경우에만 `model/article.ts`와 `source.ts`를 수정한다.
- 기존 전후 내용과 수정 이유의 연결은 유지하고, 강조된 텍스트도 주변 텍스트와 이어서 배치한다. 구체적인 요소와 표시 방식은 구현 시 표준 동작과 브라우저에서 확인한 배치에 따라 정한다.
- 여러 줄, 줄 처음과 끝의 변경, 빈 줄, 표 구분자와 코드의 들여쓰기를 모두 처리할 대상에 포함한다. 숨겨진 버전이 공간을 차지하거나 복사된 텍스트에 섞여서는 안 된다. 화면 너비에 따른 자동 줄바꿈은 보고서 파일에 새 줄을 추가하는 방식과 구별한다.
- 개별 전환의 클릭, Tab, Enter와 Space, 선택한 지점의 포커스 및 전후 상태 전달을 유지한다. 하나라도 수정 전이면 전체 토글이 꺼진 상태를 표시하는 기존 규칙도 유지한다.
- 확인: 표시된 원문과 수정본이 각각 게시용 문서와 문자 단위로 일치한다. 제목 기호와 제목 문구, 목록 번호와 첫 문장, 3.4절 코드의 import, 변수 선언, 문자열과 닫는 괄호가 원래 줄 순서로 읽힌다. 표의 행과 빈 줄도 유지된다. 일부 지점만 전환해도 인접 텍스트의 순서가 틀어지지 않는다.
- TDD는 적용하지 않는다. 새 테스트 코드 없이 기존 재구성 확인과 실제 줄 배치 확인을 사용한다. 타입 검사나 텍스트 일치만으로 화면 배치의 완료를 판단하지 않는다.
- 중단: 두 보고서 파일을 바꾸어야만 표시가 맞거나 개별 전환의 의미가 달라지는 해결안은 적용하지 않는다. 전후 문서의 문자열과 표시 구간의 연결을 다시 확인한다.

### 4. 통합 확인과 완료 기록

상태는 1~3번 완료 후 진행이다. 각 단계에서 확인한 증거와 통합 검사로 요구사항의 완료 조건을 한 번 확인한다.

- 수정: 앞 단계에서 확인된 결함이 있는 파일과 이 플랜에서 그 결함을 처리하는 절차의 상태를 갱신한다. 재사용되지 않는 표시 코드를 교체한 경우 이전 구현을 함께 제거하며 임시 복제 컴포넌트나 검사 스크립트를 남기지 않는다.
- 기존 `pnpm entry:check`와 `pnpm entry:build`가 통과해야 한다. 수정 전후 두 보고서 파일의 diff는 없어야 하며, 아티클에서 현재 표시 중인 버전의 텍스트도 원문 또는 수정본 파일과 일치해야 한다.
- 브라우저에서 768px과 1440px의 원문, 수정본 및 일부 전환 상태를 확인한다. 문제가 있던 0절 제목, 요약의 6번 항목, 2.1절 제목과 3.4절 코드를 포함하고 표도 확인한다. 320px과 390px에서는 기존 모바일 목록과 홈 이동을 확인한다.
- 실제 200% 글자 확대에서 정보와 조작 수단이 유지되는지 확인한다. 확대가 적용되었는지 알 수 없다면 이 조건은 미완료로 남기며, 화면 너비만 줄인 화면을 확대 증거로 기록하지 않는다.
- 개별 전환과 전체 전환, 일부 수정 전 상태의 토글 표시, 키보드 포커스, 아티클 안에서만 토글이 상단에 남는지, 새 주소와 홈 이동 및 소개 화면의 기존 배치를 확인한다.
- 중단: 검사 실패, 문자 불일치, 줄 순서의 틀어짐이나 조작 수단의 손실이 남으면 구현 완료로 기록하지 않는다.
