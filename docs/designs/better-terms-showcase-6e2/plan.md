# use-better-terms 보고서 비교 적용 플랜

「React + TypeScript 프론트엔드 아키텍처 보고서」의 원문과 수정본 전체를 기존 쇼케이스에 게시한다. 개발자 소개 화면의 배치와 쇼케이스의 개별 전환, 전체 전환, 아티클 구간의 고정 토글을 유지한다. 모바일에는 수정 이유 목록을 제공한다.

## 기준과 적용 지침

- 기준은 [쇼케이스 요구사항](requirements.md)의 `방문자가 확인할 내용`, `완료를 확인할 방법`, `추후 결정할 사항`이다. 마크다운 원문 표시의 근거는 [VS Code 편집기의 마크다운 원문 표시](references/vscode-markdown-editor.md)를 따른다.
- 개발자 소개 화면의 순서와 쇼케이스에 허용된 시각적 차이는 [개발자 소개 사이트 요구사항](../developer-portfolio-f4b7/requirements.md)의 `한 페이지의 정보 순서`, `편집형 시각 규칙`, `글꼴과 글자 체계`, `색상`, `여백과 반응형 배치`, `조작과 움직임`, `접근성` 및 [디자인 체계](../../../DESIGN.md)를 기준으로 확인한다.
- 코드 변경에는 [Astro, FSD와 Tailwind CSS 구현 규칙](../../dev/frontend/astro-fsd-tailwind.md)을 적용한다. 현재 `apps/entry`는 Astro 7.3.3, Tailwind CSS 4.3.3과 TypeScript 6.0.3을 사용한다. 새 외부 의존성을 추가하지 않는다.
- 게시용 문서의 두 버전은 `apps/entry/src/_pages/better-terms/content/report.before.md`와 `report.after.md`에 둔다. 개인 PC의 임시 파일 위치는 저장소 문서, 코드, 커밋에 기록하지 않는다.
- 기존 소개 화면의 한국어와 영어 링크는 같은 쇼케이스로 연결된다. 모바일 아티클과 토글은 보류된 상태를 유지한다.

## 작업 순서

1. **보고서 원문과 수정본 게시**
   - 상태: 대기.
   - 수정: `apps/entry/src/_pages/better-terms/content/report.before.md`, `report.after.md`. 두 임시 보고서의 전체 내용을 각각 게시용 문서로 옮긴다. 기존 다섯 보고서 발췌문은 두 게시용 파일에서 제거한다.
   - 확인: 두 게시용 파일이 제공된 각 버전과 문자 단위로 일치한다. 제목, 날짜, 모든 절, 표, 코드 블록, 링크와 출처가 남아 있다. 개인 위치와 비공개 정보가 게시용 파일에 없는지 확인한다.
   - 중단: 원문에 게시하면 안 되는 정보가 발견되면 그 정보의 처리 결정을 받기 전에는 게시하지 않는다.

2. **변경 지점과 설명 연결**
   - 상태: 대기.
   - 선행 조건: 1번 완료.
   - 수정: `apps/entry/src/_pages/better-terms/model/changes.ts`, `article.ts`, 필요하면 `source.ts`. 전체 보고서의 변경 지점이 전후 문서를 정확히 재구성하도록 연결하고, 목록을 보고서 절 순서로 묶는다. 표현 수정, 기술 설명 보정과 예시 교정을 실제 변경에 맞게 설명한다. 이전 발췌문의 제목과 설명은 제거한다.
   - 확인: 모든 지점을 수정 전으로 두면 원문 전체가, 모두 수정 후로 두면 수정본 전체가 재구성된다. 변경되지 않은 문자와 마크다운 문법은 유지되며 수정 이유가 없는 변경 지점은 남기지 않는다. 긴 표와 코드 블록에서 변경 지점이 주변 문구를 가리지 않는다.
   - 중단: 전후를 일대일로 연결할 수 없는 구간이 있으면 임의로 내용을 보태지 않고 게시용 문서와 변경 지점 정의를 다시 확인한다.

3. **쇼케이스 화면과 진입 문구 갱신**
   - 상태: 대기.
   - 선행 조건: 2번 완료.
   - 수정: `apps/entry/src/_pages/better-terms/ui/ShowcasePage.astro`, 필요하면 화면에 쓰는 `SourceTokens.astro`, `apps/entry/src/shared/terms/ko.json`, `en.json`. 한 편의 전체 보고서와 절별 변경 목록에 맞춰 제목과 설명을 바꾼다. 개별 전환, 전체 전환, 데스크톱 고정 토글 및 모바일 목록의 기존 동작은 유지한다.
   - 유지: `apps/entry/src/pages/better-terms.astro`, 소개 화면의 영역 배치와 한국어 및 영어 진입 링크의 목적지.
   - 확인: 데스크톱에서 원문과 수정본 전체를 각각 읽을 수 있다. 개별 전환은 선택한 지점만 바꾸고 전체 전환은 모든 지점을 바꾼다. 모바일 목록에서도 변경 이유가 읽힌다. 마크다운 표와 코드 블록이 텍스트로 표시된다.

4. **통합 확인**
   - 상태: 대기.
   - 선행 조건: 1~3번 완료.
   - 수정: 앞 단계에서 확인된 결함이 있는 파일만 수정한다. 플랜에는 각 단계의 완료 사실과 확인한 증거를 기록한다.
   - 확인: 저장소가 정한 `pnpm entry:check`와 `pnpm entry:build`가 통과한다. 브라우저에서 데스크톱의 개별 전환, 전체 전환, 키보드 조작과 스크롤을 확인한다. 320px과 390px에서는 목록만 보이고 가로 오버플로우가 없으며, 200% 확대에서도 읽을 수 있다. 소개 화면 두 언어의 링크와 영역 배치를 확인한다. 마지막에 요구사항의 완료 조건을 한 번 검토한다.
   - 중단: 검사 실패나 원문과 수정본의 재구성 불일치가 남으면 완료로 기록하지 않는다.
