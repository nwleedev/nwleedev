# use-better-terms 쇼케이스 요구사항

기존 개발자 소개 사이트의 `use-better-terms` 쇼케이스에는 프론트엔드 보고서 다섯 편에서 선정한 문단을 보여준다. 방문자는 아티클에서 표현의 수정 전후를 전환하고, 아래 목록에서 수정 이유를 살펴볼 수 있어야 한다.

## 방문자가 확인할 내용

- 개발자 소개 화면에서 쇼케이스 페이지로 이동할 수 있어야 한다. 소개 화면의 기존 영역 순서와 배치는 유지한다.
- 쇼케이스 예시에는 [선정한 프론트엔드 보고서 발췌문](references/frontend-report-excerpts.md)의 다섯 문서에서 각 두 문단을 사용한다. 문서별 발췌문은 세 문단을 넘기지 않는다. 스크립트가 감지했고 문맥을 확인해 실제 수정이 필요한 표현만 전환 대상으로 삼는다. 선정하지 않은 문단과 스크립트가 감지하지 않은 표현은 쇼케이스에 추가하지 않는다.
- 아티클에서 한 문서의 두 문단을 연속으로 보여주고, 다음 문서 앞에는 마크다운 원문 문자 `---`만 한 줄로 표시한다. 문서마다 별도 여백, 간격, 테두리나 카드 형태를 더하지 않는다. 문서 제목은 두 문단의 출처를 알아볼 수 있게 원문 표기 방식으로 표시한다.
- 데스크톱에서는 선정한 문단을 VS Code 편집기의 텍스트처럼 읽기 전용 아티클로 보여준다. 문서 제목의 `#`, 문단에 포함된 링크 문법과 문서 구분용 `---`를 원문 그대로 표시한다. 마크다운 문법은 고정폭 글꼴과 구문 강조로 구별한다. 줄 번호는 표시하지 않는다. 아티클 전체를 감싸는 별도의 테두리나 안팎 여백은 두지 않는다.
- 아티클은 수정 전 표현을 붉은 인라인 배경색으로 보여준다. 방문자가 강조 표현을 누르면 그 표현만 수정 후 표현으로 바뀌고 초록 인라인 배경색으로 표시된다. 개선된 표현을 다시 누르면 그 표현만 수정 전 상태로 돌아간다. 다른 강조 표현의 상태는 바뀌지 않는다.
- 아티클 바로 위에서 전체 전환 토글을 오른쪽에 둔다. 모든 강조 표현이 수정 후 상태일 때만 토글이 활성화되어 보이고, 하나라도 수정 전 상태이면 비활성화되어 보인다. 비활성 토글을 누르면 모든 강조 표현이 수정 후 상태로 바뀐다. 활성 토글을 누르면 모두 수정 전 상태로 돌아간다.
- 페이지를 스크롤할 때 전체 전환 토글을 담은 영역은 아티클을 읽는 동안에만 화면 상단에 붙어 있어야 한다. 아티클을 지나 아래 목록으로 내려가면 토글 영역도 화면 밖으로 이동한다. 아티클과 그 밖의 페이지는 함께 스크롤되며, 아티클만 따로 세로 스크롤하는 영역을 만들지 않는다.
- 아티클 아래에는 문서별로 수정 지점을 묶은 예시 목록을 둔다. 각 항목에서 `수정 전` 문장, `수정 후` 문장과 수정 이유를 차례로 읽을 수 있어야 한다. 파일 업로드를 주요 사용 방식으로 삼지 않는다.
- 데스크톱 아티클과 데스크톱 및 모바일의 예시 목록에서는 수정 전 표현에 붉은 인라인 배경색을, 수정 후 표현에 초록 인라인 배경색을 적용한다. 문장 전체가 아니라 실제로 바뀐 표현만 강조하고, 강조한 글자는 본문보다 한 단계 높은 500 굵기로 표시한다.
- 쇼케이스 페이지의 본문 너비는 개발자 소개 화면과 다를 수 있다. 아티클의 고정폭 글꼴과 마크다운 구문 강조, 수정 표현에 쓰는 두 배경색, 본문 너비를 제외한 시각 규칙은 [개발자 소개 사이트의 편집형 시각 규칙](../developer-portfolio-f4b7/requirements.md#편집형-시각-규칙)을 따른다.

## 완료를 확인할 방법

- 데스크톱 아티클에서 제목의 `#`, 문단의 링크 문법, 문서 사이의 `---`와 줄 구분을 확인할 수 있다. 줄 번호나 아티클을 감싸는 별도 테두리와 안팎 여백은 나타나지 않는다.
- 아티클에는 다섯 문서의 선정된 두 문단씩만 나타난다. 문서 구분은 원문 문자 `---` 한 줄로 표시되며, 문서마다 별도 여백, 간격이나 테두리가 생기지 않는다. 아티클과 예시 목록의 수정 전 문구는 [선정한 발췌문](references/frontend-report-excerpts.md)과 일치하고, 수정 후 문구는 문맥을 확인해 작성한 수정본과 일치한다.
- 붉게 강조된 표현 하나를 선택하면 그 표현만 개선된 문구와 초록색 강조로 바뀐다. 같은 표현을 다시 선택하면 수정 전 문구와 붉은색 강조로 돌아가며, 다른 표현은 기존 상태를 유지한다.
- 모든 표현이 초록색일 때만 전체 전환 토글이 활성화되어 보인다. 붉은 표현이 하나라도 있으면 비활성화되어 보이며, 비활성 토글을 누르면 모두 초록색으로, 활성 토글을 누르면 모두 붉은색으로 바뀐다.
- 아티클을 읽으면서 페이지를 스크롤하면 토글 영역만 화면 상단에 남고 아티클과 그 밖의 페이지는 함께 움직인다. 목록을 읽을 때는 토글 영역이 화면 상단에 남지 않으며, 아티클 내부에는 별도의 세로 스크롤이 없다.
- 아티클을 조작하지 않아도 아래 목록에서 각 수정 지점의 수정 전후와 이유를 모두 읽을 수 있다. 강조 배경 위의 글자는 기존 본문 명암비 기준을 충족한다.
- 개발자 소개 화면의 기존 영역 순서와 배치가 유지된다. 쇼케이스 페이지에서는 본문 너비, 아티클의 고정폭 글꼴과 구문 강조, 수정 표현의 배경색을 제외한 시각 규칙이 유지된다.

## 추후 결정할 사항

- 모바일 아티클과 전체 전환 토글은 현재 요구사항에 포함하지 않는다. 모바일 예시 목록은 유지하며, 아티클과 토글을 제공할지는 추후 결정한다.
