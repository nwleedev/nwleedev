# use-better-terms 쇼케이스 요구사항

기존 개발자 소개 사이트에 `use-better-terms` 쇼케이스 페이지를 추가한다. 방문자는 준비된 문서 예시를 통해 스킬 적용 전후의 표현과 수정 이유를 이해할 수 있어야 한다.

## 방문자가 확인할 내용

- 개발자 소개 화면에서 쇼케이스 페이지로 이동할 수 있어야 한다. 소개 화면의 기존 영역 순서와 배치는 유지한다.
- 데스크톱과 모바일의 별도 예시 목록에서 준비된 문서의 수정 지점마다 `수정 전` 문장, `수정 후` 문장과 수정 이유를 차례로 읽을 수 있어야 한다. 파일 업로드를 주요 사용 방식으로 삼지 않는다.
- 데스크톱에서는 예시 한 건의 수정 전후 문장을 같은 폭에 겹쳐 놓는다. 구분선 왼쪽에는 수정 전 문장, 오른쪽에는 수정 후 문장이 보이고, 구분선을 움직이면 각각 보이는 부분이 달라져야 한다. 드래그 외에도 구분선 조절 영역을 한 번 누르거나 키보드로 위치를 바꿀 수 있어야 한다. `수정 전`, `수정 후` 표시와 수정 이유는 구분선 비교가 아닌 별도 예시 목록에 둔다.
- 데스크톱의 구분선 비교와 데스크톱 및 모바일의 예시 목록에서는 수정 대상 표현에 붉은 인라인 배경색을, 대체한 표현에 초록 인라인 배경색을 적용한다. 문장 전체가 아니라 실제로 바뀐 표현만 강조하고, 강조한 글자는 본문보다 한 단계 높은 500 굵기로 표시한다.
- 구분선 비교에서 수정 전후의 같은 수정 지점에는 강조 표현 앞에 같은 번호를 표시한다. 번호는 주변 글자를 가리지 않아야 한다. 강조 표현을 마우스로 누르거나 키보드로 선택하면 그 번호가 적힌 예시 목록 항목으로 이동할 수 있어야 한다. 예시 목록의 각 수정 항목에도 번호를 표시한다.
- 이번 쇼케이스의 모바일 화면에는 구분선 기반 비교를 넣지 않는다.
- 쇼케이스 페이지의 본문 너비는 개발자 소개 화면과 다를 수 있다. 수정 표현에 쓰는 두 배경색과 본문 너비를 제외한 시각 규칙은 [개발자 소개 사이트의 편집형 시각 규칙](../developer-portfolio-f4b7/requirements.md#편집형-시각-규칙)을 따른다.

## 완료를 확인할 방법

- 방문자가 구분선을 움직이지 않아도 별도 예시 목록에서 준비된 예시의 수정 전후와 이유를 모두 읽을 수 있다. 구분선 비교에는 `수정 전`, `수정 후` 표시와 수정 이유가 나타나지 않는다.
- 데스크톱에서는 드래그, 키보드 또는 구분선 조절 영역을 한 번 누르는 방식으로 위치를 바꿀 수 있다. 모바일에서는 구분선이 나타나지 않고 같은 예시를 목록에서 읽을 수 있다.
- 데스크톱의 구분선 비교와 데스크톱 및 모바일 목록에서 바뀐 표현만 붉은색 또는 초록색 배경으로 구분된다. 강조 글자는 500 굵기를 사용하며, 색을 구별하지 못해도 별도 목록의 수정 전후 표시와 수정 이유로 차이를 알 수 있다. 강조 배경 위의 글자도 기존 본문 명암비 기준을 충족한다.
- 구분선 비교의 수정 전후 강조 표현 앞에 같은 번호가 표시되고, 번호가 인접한 글자를 가리지 않는다. 어느 쪽 강조 표현을 마우스나 키보드로 선택해도 같은 번호의 목록 항목이 화면에 나타난다.
- 개발자 소개 화면의 기존 영역 순서와 배치가 유지되며, 쇼케이스 페이지에서는 본문 너비와 수정 표현의 배경색 외의 시각 규칙이 유지된다.
