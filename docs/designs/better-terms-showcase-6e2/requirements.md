# use-better-terms 쇼케이스 요구사항

기존 개발자 소개 사이트에 `use-better-terms` 쇼케이스 페이지를 추가한다. 방문자는 준비된 문서 예시를 통해 스킬 적용 전후의 표현과 수정 이유를 이해할 수 있어야 한다.

## 방문자가 확인할 내용

- 개발자 소개 화면에서 쇼케이스 페이지로 이동할 수 있어야 한다. 소개 화면의 기존 영역 순서와 배치는 유지한다.
- 준비된 예시마다 수정 전 문장, 수정 후 문장과 수정 이유를 차례로 읽을 수 있어야 한다. 파일 업로드를 주요 사용 방식으로 삼지 않는다.
- 데스크톱에서는 예시 한 건의 수정 전후 문장을 같은 폭에 겹쳐 놓는다. 구분선 왼쪽에는 수정 전 문장, 오른쪽에는 수정 후 문장이 보이고, 구분선을 움직이면 각각 보이는 부분이 달라져야 한다. 드래그 외에도 구분선 조절 영역을 한 번 누르거나 키보드로 위치를 바꿀 수 있어야 한다.
- 이번 쇼케이스의 모바일 화면에는 구분선 기반 비교를 넣지 않는다. 수정 전 문장, 수정 후 문장과 수정 이유를 목록에서 읽을 수 있어야 한다.
- 쇼케이스 페이지의 본문 너비는 개발자 소개 화면과 다를 수 있다. 너비를 제외한 시각 규칙은 [개발자 소개 사이트의 편집형 시각 규칙](../developer-portfolio-f4b7/requirements.md#편집형-시각-규칙)을 따른다.

## 완료를 확인할 방법

- 방문자가 구분선을 움직이지 않아도 준비된 예시의 수정 전후와 이유를 모두 읽을 수 있다.
- 데스크톱에서는 드래그, 키보드 또는 구분선 조절 영역을 한 번 누르는 방식으로 위치를 바꿀 수 있다. 모바일에서는 구분선이 나타나지 않고 같은 예시를 목록에서 읽을 수 있다.
- 개발자 소개 화면의 기존 영역 순서와 배치가 유지되며, 쇼케이스 페이지에서는 본문 너비 외의 시각 규칙이 유지된다.
