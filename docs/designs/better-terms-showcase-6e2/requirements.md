# use-better-terms 쇼케이스 요구사항

기존 개발자 소개 사이트에 `use-better-terms` 쇼케이스 페이지를 추가한다. 방문자는 준비된 문서 예시를 아티클로 읽으면서 스킬 적용 전후의 표현을 확인하고, 아래 목록에서 수정 이유를 살펴볼 수 있어야 한다.

## 방문자가 확인할 내용

- 개발자 소개 화면에서 쇼케이스 페이지로 이동할 수 있어야 한다. 소개 화면의 기존 영역 순서와 배치는 유지한다.
- 데스크톱에서는 준비된 마크다운 문서를 아티클로 보여준다. VS Code의 마크다운 미리보기처럼 제목, 문단, 목록, 인용문, 표와 코드 블록을 문서 형태로 읽을 수 있어야 한다. 아티클 전체를 감싸는 별도의 테두리나 안팎 여백은 두지 않는다.
- 아티클은 수정 전 표현을 붉은 인라인 배경색으로 보여준다. 방문자가 강조 표현을 누르면 그 표현만 수정 후 표현으로 바뀌고 초록 인라인 배경색으로 표시된다. 다른 강조 표현의 상태는 바뀌지 않는다.
- 아티클 바로 위에서 전체 전환 토글을 오른쪽에 둔다. 모든 강조 표현이 수정 후 상태일 때만 토글이 활성화되어 보이고, 하나라도 수정 전 상태이면 비활성화되어 보인다. 비활성 토글을 누르면 모든 강조 표현이 수정 후 상태로 바뀐다. 활성 토글을 누르면 모두 수정 전 상태로 돌아간다.
- 페이지를 스크롤할 때 전체 전환 토글을 담은 영역만 화면 상단에 붙어 있어야 한다. 아티클과 그 밖의 페이지는 함께 스크롤되며, 아티클만 따로 세로 스크롤하는 영역을 만들지 않는다.
- 아티클 아래에는 수정 지점별 예시 목록을 둔다. 각 항목에서 `수정 전` 문장, `수정 후` 문장과 수정 이유를 차례로 읽을 수 있어야 한다. 파일 업로드를 주요 사용 방식으로 삼지 않는다.
- 데스크톱 아티클과 데스크톱 및 모바일의 예시 목록에서는 수정 전 표현에 붉은 인라인 배경색을, 수정 후 표현에 초록 인라인 배경색을 적용한다. 문장 전체가 아니라 실제로 바뀐 표현만 강조하고, 강조한 글자는 본문보다 한 단계 높은 500 굵기로 표시한다.
- 쇼케이스 페이지의 본문 너비는 개발자 소개 화면과 다를 수 있다. 수정 표현에 쓰는 두 배경색과 본문 너비를 제외한 시각 규칙은 [개발자 소개 사이트의 편집형 시각 규칙](../developer-portfolio-f4b7/requirements.md#편집형-시각-규칙)을 따른다.

## 완료를 확인할 방법

- 데스크톱에서 마크다운 문서의 제목, 본문과 서식 요소를 아티클로 읽을 수 있으며, 아티클을 감싸는 별도 테두리나 안팎 여백이 나타나지 않는다.
- 붉게 강조된 표현 하나를 선택하면 그 표현만 개선된 문구와 초록색 강조로 바뀌고, 나머지 표현은 기존 상태를 유지한다.
- 모든 표현이 초록색일 때만 전체 전환 토글이 활성화되어 보인다. 붉은 표현이 하나라도 있으면 비활성화되어 보이며, 비활성 토글을 누르면 모두 초록색으로, 활성 토글을 누르면 모두 붉은색으로 바뀐다.
- 페이지를 스크롤하면 토글 영역만 화면 상단에 남고 아티클, 목록과 그 밖의 페이지는 함께 움직인다. 아티클 내부에는 별도의 세로 스크롤이 없다.
- 아티클을 조작하지 않아도 아래 목록에서 각 수정 지점의 수정 전후와 이유를 모두 읽을 수 있다. 강조 배경 위의 글자는 기존 본문 명암비 기준을 충족한다.
- 개발자 소개 화면의 기존 영역 순서와 배치가 유지되며, 쇼케이스 페이지에서는 본문 너비와 수정 표현의 배경색 외의 시각 규칙이 유지된다.

## 결정이 필요한 사항

- 모바일에서 아티클과 전체 전환 토글을 제공할지는 아직 정하지 않았다. 모바일의 예시 목록은 유지한다.
- 개선된 표현을 다시 누를 때 그 표현만 수정 전으로 되돌릴지 정한다.
- 아티클 아래의 예시 목록을 읽는 동안에도 전체 전환 토글을 화면 상단에 유지할지 정한다.
