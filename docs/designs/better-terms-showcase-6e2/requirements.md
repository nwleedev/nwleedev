# use-better-terms 쇼케이스 요구사항

쇼케이스는 「React + TypeScript 프론트엔드 아키텍처 보고서」 한 편의 원문과 수정본 전체를 비교한다. 방문자는 아티클에서 바뀐 지점을 하나씩 전환하고, 아래 목록에서 수정 전후와 이유를 읽을 수 있어야 한다.

## 방문자가 확인할 내용

- 개발자 소개 화면의 한국어와 영어 링크에서 같은 쇼케이스 페이지로 이동할 수 있어야 한다. 소개 화면의 기존 영역 순서와 배치는 유지한다.
- 아티클은 보고서의 제목부터 출처와 마지막 확인 항목까지 원문 전체를 빠짐없이 보여준다. 제목, 문단, 목록, 표, 코드 예시, 링크와 마크다운 표기 순서를 유지한다. 전체 전환을 마치면 수정본 전체를 같은 순서로 읽을 수 있어야 한다.
- 수정본은 단어와 문장 표현뿐 아니라 일부 기술 설명, 예시 코드와 확인되지 않은 항목도 바로잡았다. 쇼케이스에서 이런 변경을 모두 단순한 단어 치환이나 검사 스크립트가 감지한 항목이라고 설명하지 않는다. 아래 목록에서는 각 변경의 이유를 표현 수정, 기술 설명 보정, 예시 교정 가운데 실제 내용에 맞게 밝힌다.
- 데스크톱에서는 보고서를 VS Code 편집기의 원문처럼 읽기 전용 아티클로 보여준다. 마크다운 문법은 고정폭 글꼴과 구문 강조로 구별한다. 줄 번호는 표시하지 않는다. 아티클 전체를 감싸는 별도 테두리나 안팎 여백은 두지 않는다.
- 아티클의 수정 전 부분은 붉은 인라인 배경색으로 표시한다. 방문자가 강조된 부분을 누르면 그 부분만 수정 후 내용으로 바뀌고 초록 인라인 배경색으로 표시된다. 다시 누르면 수정 전 내용으로 돌아간다. 다른 변경 지점의 상태는 유지한다.
- 아티클 바로 위에 전체 전환 토글을 오른쪽 정렬로 둔다. 모든 변경 지점이 수정 후 상태일 때만 활성화되어 보인다. 수정 전 지점이 하나라도 있으면 비활성화되어 보이며, 누르면 모든 지점을 수정 후로 바꾼다. 활성 토글을 누르면 모두 수정 전으로 돌아간다.
- 페이지를 스크롤할 때 토글을 담은 영역은 아티클을 읽는 동안에만 화면 상단에 붙어 있어야 한다. 아티클을 지나 아래 목록으로 내려가면 토글도 화면 밖으로 이동한다. 아티클만 따로 세로 스크롤하는 영역은 만들지 않는다.
- 아티클 아래에는 보고서의 절 순서에 따라 변경 지점을 묶은 목록을 둔다. 각 항목에서 수정 전 내용, 수정 후 내용과 수정 이유를 읽을 수 있어야 한다. 파일 업로드를 주요 사용 방식으로 삼지 않는다.
- 데스크톱 아티클과 데스크톱 및 모바일 목록에서는 실제로 바뀐 부분만 강조한다. 수정 전에는 붉은 배경색, 수정 후에는 초록 배경색을 사용하고, 강조한 글자는 본문보다 한 단계 높은 500 굵기로 표시한다. 색만으로 전후 상태를 구별하도록 만들지 않는다.
- 쇼케이스의 본문 너비는 개발자 소개 화면과 다를 수 있다. 아티클의 고정폭 글꼴과 마크다운 구문 강조, 수정 부분의 두 배경색, 본문 너비를 제외한 시각 규칙은 [개발자 소개 사이트의 편집형 시각 규칙](../developer-portfolio-f4b7/requirements.md#편집형-시각-규칙)을 따른다.

## 완료를 확인할 방법

- 아티클의 모든 변경 지점을 수정 전으로 맞춘 뒤 표시된 텍스트를 게시용 원문과 대조하면 내용과 순서가 일치한다. 모든 지점을 수정 후로 맞추면 게시용 수정본과 일치한다. 제목, 표, 코드 블록, 링크, 출처와 마지막 절이 빠지지 않는다.
- 붉게 강조된 부분 하나를 선택하면 그 부분만 수정 후 내용과 초록 강조로 바뀐다. 같은 부분을 다시 선택하면 원래 내용으로 돌아간다. 전체 전환은 보고서의 모든 변경 지점에 적용된다.
- 목록은 변경 지점을 보고서 절에 맞춰 보여준다. 기술 설명과 예시 코드의 교정을 단순한 단어 교체로 소개하지 않으며, 아티클을 조작하지 않아도 수정 이유를 읽을 수 있다.
- 데스크톱 아티클에는 마크다운 원문 문법이 보이고 줄 번호, 별도 테두리와 안팎 여백이 없다. 페이지 전체가 스크롤되며, 토글은 아티클이 보이는 동안에만 상단에 남는다.
- 모바일에서는 기존의 수정 전후 목록을 읽을 수 있다. 강조 배경 위의 글자는 기존 본문 명암비 기준을 충족한다. 개발자 소개 화면의 배치와 쇼케이스에서 허용하지 않은 시각 규칙은 유지된다.

## 추후 결정할 사항

- 모바일 아티클과 전체 전환 토글은 현재 요구사항에 포함하지 않는다. 모바일 목록은 유지하며, 모바일에 아티클과 토글을 제공할지는 추후 결정한다.
