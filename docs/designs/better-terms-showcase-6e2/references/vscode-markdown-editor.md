# VS Code 편집기의 마크다운 원문 표시

쇼케이스 아티클은 렌더링된 마크다운 미리보기가 아니라 문법 문자가 보이는 편집기 텍스트를 참고한다. 표도 격자 대신 `|`와 구분선이 보이는 원문으로 읽힌다. 이 자료는 [쇼케이스 요구사항의 아티클 표시 방식](../requirements.md#방문자가-확인할-내용)을 구현하거나 검토할 때 편집기와 미리보기를 구별하기 위한 근거다.

## 확인한 사실

2026년 9월 28일에 확인한 [VS Code의 마크다운 문서](https://code.visualstudio.com/docs/languages/markdown)는 파일을 편집기에서 여는 방식과 렌더링된 미리보기를 별도 보기로 설명한다. 미리보기는 원문을 해석해 보여주므로 이번 아티클이 참고할 화면과 다르다.

[VS Code의 마크다운 구문 정의](https://github.com/microsoft/vscode/blob/main/extensions/markdown-basics/syntaxes/markdown.tmLanguage.json)는 제목, 목록, 링크, 인용문, 코드 울타리와 표에 서로 다른 구문 범주를 지정한다. 표의 `|`도 마크다운 표 문법으로 분류한다. [VS Code 테마 설명](https://code.visualstudio.com/api/references/theme-color)에 따르면 구문 색은 문법 범주와 사용 중인 색상 테마에 따라 달라지므로, 편집기에 고정된 단일 색 조합은 없다.

[VS Code의 기본 편집 안내](https://code.visualstudio.com/docs/editing/codebasics)에 따르면 자동 줄바꿈은 기본적으로 꺼져 있으며, 켜면 편집 영역의 너비에 맞춰 줄이 접힌다. 따라서 긴 문장과 표가 있는 원문은 화면 너비가 줄어들 때 어떻게 줄을 접을지 정해야 한다. [WCAG 화면 재배치 지침](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)은 일반 텍스트를 읽을 때 가로 스크롤이 필요하지 않아야 한다고 설명하며, 행과 열을 함께 읽어야 하는 표에는 예외를 둔다.

## 쇼케이스에 반영한 점과 남은 판단

편집기에서 직접 확인한 예시 문서는 제목의 `#`, 목록 기호, 링크의 대괄호와 괄호, 표의 `|`와 구분선을 원문 그대로 보여줬다. 고정폭 글꼴과 구문별 글자색도 확인했다. 파일 탭, 탐색기, 줄 번호와 미니맵은 텍스트 주위에 있는 편집기 UI이며, 마크다운 원문의 표시 방식과 구별된다.

요구사항은 원문 문법을 보존하는 방식으로 갱신했다. 색상과 글꼴의 정확한 값은 기존 개발자 소개 사이트의 시각 규칙에 맞춰 정해야 한다. 모바일 아티클 제공 여부와 화면 너비가 줄어들 때 긴 표의 줄바꿈 방식은 아직 확정되지 않았다.
