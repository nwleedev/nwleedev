# 개발자 소개를 뒷받침할 프로젝트와 글

프로젝트와 글은 **사용자의 목적을 이해하고, 실제로 사용할 수 있는 서비스로 구체화하는 개발자**라는 소개를 뒷받침할 때 선별한다. 방문자가 개발자의 관심과 함께 개발할 때 기대할 가치를 이해하는 것이 목적이다. 기술 분야별로 경험을 하나씩 채우거나 구현 방법을 많이 설명하는 것을 선정 기준으로 삼지 않는다.

개인 메모 앱, Issnuta와 아래 두 글은 이 목적에서 살펴볼 후보다. 이 후보들을 자기소개와 연결한 구성은 [홈페이지 한국어 초안](homepage-copy.md)에서 읽을 수 있다. 이 문서의 개별 설명은 후보 자료이며, 현재 홈페이지 문구는 전체 초안에서 수정한다. 게재 목록과 순서는 아직 확정하지 않았다.

현재 방문자가 사용할 수 있는 서비스는 없으며, [제작 내용을 먼저 소개하는 결정](../decisions/project-availability.md)에 따라 서비스 준비 후 이용 링크를 추가한다.

이 문서는 [홈페이지 구성](../requirements.md#홈페이지)을 정하기 위한 자료다. 2026년 9월 15일 개인 메모 앱의 Git 기록과 구현, GitHub CLI로 [Issnuta 저장소](https://github.com/nwleedev/issnuta)의 설명과 README를 확인했다. Codex 앱 브라우저에서는 [기존 블로그](https://blog.nwlee.com/)의 목록과 아래 두 글의 본문을 읽었다. 전체 프로젝트와 글의 우선순위를 평가한 것은 아니며, 현재 소개 방향을 보충할 후보를 선정했다.

## 프로젝트 후보: 개인 메모 앱

개인 메모 앱에서는 **사람들이 기록한 정보를 어떻게 다시 사용하는지에 관심을 두는 개발자**라는 면을 설명할 수 있다. 여러 메모의 문장을 골라 다시 사용하려는 목적은 이 관심을 구체적으로 보여준다. 화면 배치와 저장 처리의 변경 내역은 [개발 목적과 Git 근거](personal-notes-project.md)에서 확인할 자료다. 이 해석은 [사용자 이해와 화면 설계를 앞세우는 소개](developer-introduction.md)를 뒷받침하는 후보이며, 실제 사용자 조사를 수행했다는 뜻은 아니다.

홈페이지의 현재 설명은 [개인 메모 앱 소개](homepage-copy.md#개인-메모-앱)에서, 프로젝트 상세는 [목적과 개발 기준을 설명하는 초안](personal-notes-project.md#웹사이트에-사용할-문구-초안)에서 관리한다. 문장을 다시 사용하려는 목적을 정보 구성과 내용 보존의 기준으로 구체화할 수 있다는 의미를 전달한다.

프로젝트 설명에서는 어떤 필요에 관심을 두고 어떤 서비스를 만들고 있는지 먼저 전달한다. [테스트 경험](personal-notes-testing.md)은 입력값과 실제 저장을 구분해야 한다는 개발 기준의 근거로 활용한다. 검사 도구나 실행 순서는 소개 본문에 넣지 않는다. 현재 제공하지 않는 계정 동기화나 의미 유사성 자동 판별은 소개에 넣지 않는다. 게재 여부와 외부에서 열람할 소스 주소는 아래 질문에서 확인한다.

## 프로젝트 후보: Issnuta

Issnuta에서는 **사용자가 서비스를 필요로 하는 상황과 실제로 사용할 수 있는 조건을 함께 고려하는 개발자**라는 면을 설명할 수 있다. 인터넷 연결이 없는 상황에서도 번역하려는 목적이 그 근거다. 브라우저에서 모델을 실행했다는 사실은 이 목적을 뒷받침하는 기술 설명이며, 프로젝트를 소개하는 주된 이유는 사용자의 필요에 대한 관심이다.

2026년 9월 15일 확인한 [한국어 README](https://github.com/nwleedev/issnuta/blob/f9b75720ee22fb142d821438227ac4dac8e1e95b/README.ko.md)는 프로젝트를 “모바일 우선 오프라인 번역 PWA”로 소개한다. 먼저 선택한 언어의 모델을 내려받아 저장한 뒤, 인터넷 연결 없이 번역할 수 있다고 설명한다. 한국어와 영어, 한국어와 일본어 사이의 번역을 제공한다.

홈페이지의 현재 설명은 [Issnuta 소개](homepage-copy.md#issnuta)에서 관리한다.

프로젝트 상세 소개 초안:

> 인터넷 연결이 없는 환경에서도 필요한 문장을 번역할 수 있도록 만든 웹 애플리케이션입니다. 사용할 언어의 모델을 미리 저장하면 한국어와 영어, 한국어와 일본어 사이를 번역할 수 있습니다.
>
> 번역이 필요한 순간에 인터넷에 연결할 수 있는지도 설계의 기준으로 삼았습니다. 모델을 준비하는 과정과 오프라인에서 번역하는 과정을 구분해, 사용 조건에 맞는 서비스 제공 방식을 구체화했습니다.

프로젝트 설명은 사용 환경의 제약을 기능의 제공 방식에 반영할 수 있다는 의미를 전달한다. 오프라인 번역이라는 목적과 모델의 사전 저장을 연결한 설명은 위 README의 동작 방식을 해석한 것이다. 여행 경험, 실제 사용자의 요청이나 번역 정확도에 대한 성과는 추가하지 않는다. 이력서의 오프라인 번역 경험과 연결해 소개할 수 있는 후보지만, 첫 버전 게재 여부는 아직 정하지 않았다.

소스 코드는 외부에서 열람할 수 있다. 2026년 9월 15일 GitHub CLI로 저장소 정보와 위 README를 다시 확인했다. 저장소의 홈페이지 주소 항목은 비어 있고 README에는 로컬 실행 방법이 있어, 이 자료만으로 배포된 서비스의 접속 주소나 현재 동작을 확인할 수는 없다. 저장소 자료만으로 현재도 개발을 진행하는지 판단하지 않는다. 게재가 정해지면 아래 질문의 답변에 따라 실제 개발 상태를 표시한다. 서비스 링크를 추정하거나 소스 코드 링크를 서비스 이용 링크로 대신하지 않는다.

AI 작업 문서 도구와 일기 관리 및 분석 서비스도 [이력서에서 확인한 후보](content-and-site-direction.md#첫-소개와-프로젝트)다. 개인 메모 앱과 일기 관리 팀 프로젝트는 서로 다른 프로젝트로 구분한다.

## 개인 프로젝트 소개를 위해 확인할 질문

아래 세 질문은 게재 구성과 상태 표시를 정하기 위한 미결정 사항이다. 홈페이지와 상세 문구는 후보로 작성하되, 답변에 따라 달라지는 목록과 표시 및 소스 연결은 확정하지 않는다. 질문과 선택지는 콘텐츠 작성용이며 방문자에게 보여줄 본문에 포함하지 않는다.

### 첫 버전에 어떤 개인 프로젝트를 소개할까?

- 개인 메모 앱과 Issnuta를 함께 소개한다. 기록을 다시 활용하는 목적과 인터넷 연결이 없는 사용 환경을 각각 고려한 경험을 보여줄 수 있어 추천한다.
- 개인 메모 앱만 소개한다. 현재 개발 중인 메모 앱의 목적과 개발 기준에 집중하고, Issnuta는 첫 버전 목록에서 제외한다.

두 프로젝트를 선택하면 기록의 재사용을 먼저 설명하고 사용 환경에 대한 관심으로 이어지는 순서를 제안한다. 개수를 늘리는 것이 목적은 아니며, 각 프로젝트가 설명하는 관심과 기대할 기여가 서로 다르기 때문에 함께 소개할 수 있다.

### Issnuta의 현재 개발 상태는 무엇인가?

Issnuta를 게재하는 경우에만 필요한 질문이다. 저장소의 마지막 변경 시점만으로 현재 개발 상태를 판단할 수 없으므로 사실에 맞는 항목을 선택한다.

- 현재 개발 중이다. 프로젝트에 `개발 중`으로 표시한다.
- 개발을 잠시 중단했다. 프로젝트에 `개발 일시 중단`으로 표시한다.
- 기능 개발을 마치고 서비스 제공을 준비 중이다. 프로젝트에 `서비스 준비 중`으로 표시한다.

어느 상태에서도 실제 서비스가 준비되기 전에는 이용 링크를 추가하지 않는다. 상태 선택은 다른 상태보다 유리하게 보이기 위한 표현 선택이 아니며, 사실 확인이므로 추천 항목을 정하지 않는다.

### 개인 메모 앱의 소스 코드는 어떻게 안내할까?

- 첫 버전에는 프로젝트 소개와 제작 내용만 제공하고 소스 링크는 추후 추가한다. 현재 확인된 외부 열람 주소가 없어 이 방식을 추천한다.
- 외부에서 열람할 수 있는 저장소 링크도 제공한다. 실제 저장소 주소와 열람 가능 여부를 확인한 뒤 프로젝트 설명에 연결한다.

소스 연결을 선택해도 저장소의 접근 권한을 변경한다는 뜻은 아니다. 소개할 수 있는 소스 주소가 확인될 때까지 연결만 미결정으로 남기고 문구 작성은 계속할 수 있다.

## Key를 활용하여 컴포넌트 상태를 초기화하기

이 글에서는 **익숙한 방식도 목적에 맞는지 원리를 살펴 다시 판단하는 개발 태도**를 읽을 수 있다. 특정 API를 안다는 사실보다, 이전에 사용하던 방법을 돌아보고 대안을 비교한 이유가 소개에 보탤 의미다.

2025년 9월 21일 발행한 [글 원문](https://blog.nwlee.com/use-react-keys-to-reset-components)은 URL 검색 조건이 바뀌어도 자식 컴포넌트의 상태가 유지되는 상황을 설명한다. “동일한 위치에 있는 컴포넌트는 상태가 보존된다”는 원리에서 출발해, Effect에서 상태를 변경하는 방법과 `key`로 상태를 초기화하는 방법을 비교한다. 본문은 2026년 9월 15일 확인했다.

홈페이지 설명 초안:

> 검색 조건이 바뀌어도 이전 상태가 남는 이유를 React의 상태 보존 방식으로 살펴보고, 초기화 목적에 맞는 구현 방법을 비교합니다.

이 글을 소개하면 대표 사례의 SharedWorker나 SSE 경험 외에도 프레임워크의 기본 원리를 이해하고 적용하는 관심을 보여줄 수 있다. 실제 제목과 링크를 사용하며, 사례에 없는 성능 수치나 라이브러리 전문성을 추가하지 않는다.

## AI 에이전트에서 작업 맥락을 관리하기 위해 사용한 방법

이 글에서는 **개발 과정에서 반복되는 불편을 발견하고 자신에게 필요한 방법을 찾아 개선하는 태도**를 읽을 수 있다. 목표와 결정 사항을 잃는 문제를 겪으며 기록 방식을 바꾼 경험이 그 근거다. AI 도구를 사용했다는 사실만으로 전문성을 주장하지 않는다.

2026년 3월 8일 수정한 [글 원문](https://blog.nwlee.com/codex-work-context-maintainance)은 긴 작업에서 목표와 결정 사항을 놓치는 문제를 설명한다. “이미 결정된 방식에 대해서 고민하거나 번복한다”는 문제를 제시하고, 데이터베이스와 파일을 사용한 방법을 비교한다. 계획, 결정, 진행 상황과 조사 기록을 나누어 작업별로 관리한 경험이 담겨 있다. 본문은 2026년 9월 15일 확인했다.

홈페이지 설명 초안:

> AI와 개발을 이어갈 때 목표와 결정 사항을 다시 확인할 수 있도록, 필요한 기록을 구분해 관리하는 방법을 소개합니다.

도구를 사용한다는 사실에 더해 반복되는 문제를 발견하고 기록 방식을 개선한 판단을 보여주는 후보다. 본문에 실린 당시의 스크립트를 현재 사이트의 구현 방식으로 채택한다는 뜻은 아니다.

## 게재 결정과 문구 관리

개수와 순서보다 먼저, 자기소개와 후보를 함께 읽었을 때 개발자의 관심과 협업에서 기대할 가치가 이어지는지 확인한다. 프로젝트 설명은 어떤 서비스를 만드는지 알려주고, 글의 요약은 무엇을 읽을 수 있는지 알려주는 역할이다. 이 설명들을 모은 것만으로 개발자 소개가 완성되지는 않는다.

같은 관심을 반복해서 보여주는 항목은 줄일 수 있고, 개발자에 대한 이해를 넓혀 주는 항목은 함께 소개할 수 있다. 기술 종류를 더 많이 보여준다는 이유로 개수를 늘리지 않는다. 전체 소개 문구를 기준으로 추천 목록을 만든 뒤, 게재 의향이나 제공 가능 여부가 모호한 항목을 확인한다.

글의 제목과 Issnuta는 원문 및 저장소를 식별하는 이름으로 유지하고, 홈페이지 설명은 수정 가능한 한국어 초안으로 관리한다. 프로젝트의 게재 방식과 최종 목록, 글의 선정 및 배치는 한국어 콘텐츠 구성에서 정한 뒤 플랜에 반영한다.

서비스 준비 전에도 개발 상태와 상세 설명을 제공한다. 이용 링크가 없다는 이유로 프로젝트 영역을 생략하거나 실제 접속할 수 없는 주소를 넣지 않는다. 서비스 준비 후 이용 링크를 추가하는 절차는 [프로젝트 제공 결정](../decisions/project-availability.md#제작과-완료-확인에-미치는-영향)을 따른다.
