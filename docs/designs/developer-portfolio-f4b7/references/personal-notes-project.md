# 개인 메모 앱의 개발 목적과 소개 근거

개인 메모 앱은 **문장을 다시 사용하려는 목적에서 화면 구성과 저장 기준을 정한 프로젝트**로 소개할 수 있다. 개발자에게 기대할 강점은 그 목적을 실제 화면과 완료 기준으로 구체화하는 판단이다. 문장 선택, 편집과 저장의 구현 내역은 이 판단을 설명하는 데 필요한 근거로 선별한다.

이 문서는 [개발자 소개와 문구 작성](../requirements.md#개발자-소개와-문구-작성)에 사용할 프로젝트 근거와 한국어 초안이다. 2026년 9월 15일 `feature/personal-notes-app`의 초기 요구사항부터 `94283e3`까지 Git 기록을 확인했다. 전체 변경 내역을 평가한 문서는 아니며, 개발 목적과 소개에 필요한 결정 및 구현을 선별했다. 현재 방문자가 사용할 수 있는 서비스는 없다.

## 여러 메모의 문장을 다시 사용하는 과정

초기 요구사항 `52f3131`은 여러 메모에서 선택한 텍스트를 하나로 모으고, 사용 빈도와 텍스트의 겹침을 확인하며, 반복 부분으로 템플릿을 만들 수 있어야 한다고 명시한다. 짧은 원문은 “서로 다른 여러 메모에서 선택한 텍스트를 하나의 누적 텍스트에 추가”다. 출처는 해당 커밋의 `docs/designs/personal-notes-app-8fd/requirements.md`다.

현재 구현에는 선택한 텍스트를 결합해 복사하는 `copyBatchText`, 두 문장의 같은 부분과 달라지는 부분으로 템플릿을 제안하는 `suggestTemplate`, 입력값을 템플릿에 반영하는 `renderTemplate`이 있다. `94283e3`의 다음 파일에서 확인했다.

- `apps/notes/src/features/edit-batch-copy/model/copy-batch-text.ts`
- `apps/notes/src/features/suggest-template/model/suggest-template.ts`
- `apps/notes/src/entities/template/model/render-template.ts`

이 기록을 함께 보면 메모 보관에 더해 **필요한 문장을 골라 조합하고 반복해서 사용하는 과정**이 개발 목적이라고 해석할 수 있다. 특정 직업의 사용자를 조사했다거나 작성 시간을 줄였다는 성과는 이 기록만으로 확인할 수 없다.

## 메모를 고르면서 선택한 문장도 확인하는 화면

독립된 복사 목록 화면은 원본 메모와 선택한 문장 목록 사이를 오가게 한다는 이유로, 충분한 공간에서는 메모와 일괄 복사 패널을 나란히 배치하는 방향을 정했다. `8ab8917`의 화면 통합 결정과 `94283e3`의 `docs/designs/personal-notes-app-8fd/decisions/accumulator-workspace-panel.md`에 선택지와 이유가 기록되어 있다.

메모 영역의 폭이 줄면 같은 캔버스를 축소하는 대신 메모 목록과 상세 편집을 사용한다. 목록에서의 짧은 누르기, 길게 누르기, 텍스트 편집과 스크롤이 경쟁하는 문제를 고려해 편집을 상세 화면으로 나눴다. 근거는 `94283e3`의 `docs/designs/personal-notes-app-8fd/decisions/responsive-note-presentation.md`다. 같은 시점의 `apps/notes/src/_pages/notes/ui/notes-collection.tsx`에는 `MobileNotesWorkspace`와 `NotesBoard`를 연결하는 구현이 있다.

소개에서는 반응형 화면을 만들었다는 사실보다 **화면에서 함께 확인할 정보와 서로 충돌할 수 있는 조작을 구분한 판단**을 강조할 수 있다. 실제 사용성 개선 수치나 모든 기기에서의 정상 동작을 입증한 것으로 확대하지 않는다.

## 저장 성공과 복구 초안 제거 실패를 구분

메모 원문 저장은 성공했지만 복구 초안 제거만 실패하는 경우를 별도로 처리했다. `f811f3b`는 저장 성공을 유지하면서 초안 제거가 남았음을 보관하고, 다음 저장 기회에 제거를 다시 시도하도록 변경한다. 이미 저장한 원문을 실패한 것으로 되돌리지 않는 것이 변경 이유다.

`94283e3`의 `apps/notes/src/_pages/notes/model/save-note-content.ts`는 복구 초안을 먼저 저장한 뒤 원문을 저장한다. 초안 제거만 실패하면 저장된 메모와 `draftCleanupRequired`를 반환한다. `note-content-save-state.ts`는 본문이 달라지지 않았어도 초안 제거가 남아 있으면 다시 저장 처리를 시작한다. 같은 디렉터리의 `save-note-content.test.ts`에는 재시도 뒤 원문과 수정 번호를 유지하고 초안만 제거하는 기대 결과가 있다.

이 사례는 **오류가 발생한 단계와 이미 완료한 처리를 구분하는 판단**을 보여준다. 모든 자료 손실을 방지했다는 주장이나 오류 발생률 수치로 쓰지 않는다.

## 중단된 조작이 다음 선택을 방해하지 않도록 처리

`1be9223`은 모바일의 길게 누르기를 중단한 뒤 남은 클릭 억제 상태와, 변경사항을 버리는 중 발생한 추가 이동 요청의 처리를 변경했다. `apps/notes/src/_pages/notes/ui/mobile-note-card.tsx`에서는 새 조작과 키보드 실행 때 이전 클릭 억제 상태를 정리한다. `note-detail-page.tsx`에서는 편집, 이동 확인, 변경사항 폐기를 구분하고 폐기 중의 추가 이동 요청이 진행 중인 처리를 바꾸지 않게 했다.

두 변경은 사용자가 입력을 취소하거나 다음 조작을 이어갈 때 이전 상태가 영향을 주지 않도록 한 사례다. 성공하는 순서만 구현하는 데서 나아가, **사용자가 선택을 바꾸거나 조작을 중단한 뒤의 동작까지 구체화한 경험**으로 설명할 수 있다.

## 웹사이트에 사용할 문구 초안

홈페이지용 이름은 `개인 메모 앱`을 사용한다. 별도 서비스 이름과 게재 여부는 아직 정하지 않았다.

> 반복해서 사용하는 문장을 모으고, 필요한 내용만 조합해 다시 쓰는 개인 메모 앱을 개발하고 있습니다.

프로젝트 상세 소개 초안:

> 여러 메모에 흩어진 문장을 골라 조합하고, 반복되는 부분을 다시 쓸 수 있는 개인 메모 앱을 개발하고 있습니다.
>
> 이 프로젝트에서는 문장을 다시 사용하는 과정에 주목했습니다. 원문과 선택한 문장을 함께 확인하도록 화면을 구성하고, 휴대전화에서는 문장을 고르는 조작과 편집이 서로 방해하지 않도록 나눴습니다.
>
> 다시 사용할 문장은 필요할 때 그대로 남아 있어야 합니다. 작성한 내용의 보존을 중요한 개발 기준으로 삼고, 저장 중단이나 실패가 생기면 이미 저장한 내용과 다시 처리할 부분을 구분하도록 설계했습니다.

이 문구는 개발 중인 프로젝트의 목적에서 설계 기준이 어떻게 이어지는지 설명하는 초안이다. [채용 수요와 소개 방향](developer-introduction.md#채용-수요와-실제-경험을-대조한-판단)에 맞춰 사용자의 목적을 구현 기준으로 바꾸는 판단을 보여준다.

테스트 경험은 사용자가 작성한 내용을 중요하게 여기는 기준을 뒷받침하는 조사 자료다. [테스트 조사](personal-notes-testing.md#프로젝트-상세에-사용할-문구-초안)의 검사 방법은 프로젝트 소개에 자동으로 포함하지 않는다. 개발자에 대해 전달할 의미를 먼저 정하고, 그 의미를 이해하는 데 추가 근거가 필요한 경우 상세 기술 설명에서 사용한다.

## 확인한 기록과 남은 사항

현재 구현의 텍스트 비교는 줄 단위의 일치, 포함 관계와 문자열 조각의 겹침을 구분한다. `94283e3`의 `apps/notes/src/_pages/analysis/model/analyze-text.ts`가 근거다. 초기 요구사항에 있던 의미 유사성 자동 판별을 현재 제공하는 것으로 소개하지 않는다. 계정과 기기 간 동기화도 같은 시점의 요구사항에서 후속 개발 항목으로 남아 있다.

커밋과 코드, 테스트에 적힌 기대 결과를 확인했으며 이 조사에서 앱을 실행하거나 테스트를 재실행하지 않았다. 따라서 배포 여부, 현재 브라우저 동작과 검사 통과 여부를 증명한 자료로 사용하지 않는다. 각 파일은 함께 적은 커밋의 저장소 루트 기준으로 찾을 수 있으며 `git show <커밋>:<파일>`로 원문을 확인할 수 있다.

게재 후보와 서비스 준비 전의 소개 방식은 [홈페이지 연결 콘텐츠](homepage-content.md)에서 정한다. 외부에 제공할 소스 주소와 실제 서비스 주소는 확인된 뒤 추가한다.
