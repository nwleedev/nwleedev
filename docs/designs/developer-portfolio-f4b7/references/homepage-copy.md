# 홈페이지 한국어 문구 초안

사용자에게 필요한 화면과 기능을 구체화하는 역량을 먼저 소개한다. 동료와 대안을 조율한 경험과 실제 사용의 불편을 해결한 경험으로 그 가치를 뒷받침한다. 아래 본문은 [개발자 소개와 문구 작성 요구사항](../requirements.md#개발자-소개와-문구-작성)에 따라 홈페이지에서 이어 읽을 수 있도록 구성한 초안이다.

첫 소개 문장은 확정된 표현을 유지하고, 개인 메모 앱과 Issnuta를 함께 소개한다. 나머지 문구와 배치, 글의 선정은 제안이다. 문구의 근거와 남은 사항은 방문자용 본문 뒤에 구분한다. 현재 홈페이지 문구는 이 문서에서 다듬고, [소개 방향과 후보 비교](developer-introduction.md)는 편집 근거로 사용한다.

### 개인 프로젝트

기록한 내용을 다시 사용하는 과정과 인터넷 연결이 없는 환경처럼, 서비스가 실제로 쓰이는 조건을 고려합니다.

#### 개인 메모 앱

기록한 문장을 다음 작성에도 활용할 수 있도록, 여러 메모에서 필요한 내용을 골라 조합하는 앱을 개발하고 있습니다. 문장을 다시 사용하는 과정과 작성한 내용의 보존을 함께 고려합니다.

#### Issnuta

인터넷 연결이 없는 환경에서도 번역을 이용할 수 있도록 만든 웹 애플리케이션입니다. 필요한 모델을 미리 저장하면 한국어와 영어, 한국어와 일본어 사이의 번역을 이용할 수 있습니다.

서비스를 점검하며 문제가 생길 수 있는 조건을 살피고 있습니다. 원인과 영향을 검토해 개선할 내용과 우선순위를 정합니다.

### 경험으로 보여주는 역량

#### 사용자에게 필요한 정보 구성

여러 종류의 정보에서 함께 확인해야 할 관계를 판단하고, 화면의 구성 기준을 구체화합니다. 실행 이력에서는 시작 기록과 후속 진행을 함께 보여주도록 구성하고, PM과 목록 및 페이지 나누기 기준을 조율했습니다.

#### 사용자의 선택을 고려한 기능 설계

처리가 오래 걸리거나 사용자가 선택을 바꿀 때 필요한 안내와 동작을 설계합니다. 5~10분이 걸리는 문서 생성에서는 이동과 취소 여부를 확인하고, 취소하지 않기로 선택한 뒤에도 진행 안내를 유지했습니다.

#### 필요한 정보를 유지하는 성능 개선

화면의 조작을 방해하는 원인을 분석하고, 필요한 정보를 유지하면서 반응성을 개선합니다. API 응답의 크기와 형식을 유지한 채 3~4초 동안 발생하던 화면 정지를 해결했습니다.

#### 판단에 필요한 지표의 정확성

지표가 나타내는 의미와 계산을 이해하고, 사용자가 자원 상태를 판단할 수 있도록 표시 오류를 바로잡습니다. 대시보드의 지표 오류와 조회 방식을 개선했으며, 10분 동안의 데이터 전송량은 96.5 MB에서 41 KB로 줄였습니다.

### 오픈소스 기여

기존 코드를 이해하고 다른 동작에 미칠 영향을 고려해 문제를 해결합니다. React Router와 Outline에 기여한 수정은 공식 릴리스에 반영됐습니다.

- **React Router:** 선택적 URL 매개변수가 잘못 일치하는 문제를 수정했습니다. [기여 내용](https://github.com/remix-run/react-router/pull/14689)과 [v7.13.1 릴리스](https://github.com/remix-run/react-router/releases/tag/react-router%407.13.1)에서 확인할 수 있습니다.
- **Outline:** 인라인 이미지 앞의 글자를 지우지 못하는 문제를 수정했습니다. [기여 내용](https://github.com/outline/outline/pull/10759)과 [v1.2.0 릴리스](https://github.com/outline/outline/releases/tag/v1.2.0)에서 확인할 수 있습니다.

## 문구의 근거와 게재 판단

이 절부터는 콘텐츠 작성용 자료이며 방문자에게 보여줄 본문에 포함하지 않는다. 2026년 9월 15일 기준으로 기존 자료의 사실과 소개에서 전달할 의미를 대조했다. 경력 및 회사 사례는 [이력서와 포트폴리오 분석](content-and-site-direction.md), 프로젝트와 글은 [게재 후보 조사](homepage-content.md)를 근거로 한다.

### 첫 소개가 설명하는 능력과 기여

여러 종류의 정보는 실행을 시작한 기록과 후속 처리 기록처럼 역할이 다른 정보를 뜻한다. 별도로 제공된 기록을 사용자의 확인 목적에 맞게 구성한 경험에서, 함께 확인해야 할 정보의 관계를 판단하는 능력을 도출했다. 화면 수나 화면 사이의 이동을 전제하지 않는다. PM과 목록 및 페이지 나누기 기준을 조정한 경험은 이 정보 구성을 동료와 구체화한 근거다. [정보 구성과 협의 근거](content-and-site-direction.md#요구-조정과-ui의-정확성)

화면의 안내와 실제 처리 결과를 일치시킨다는 설명은 문서 생성 중 서버 상태를 확인한 경험과 대시보드의 표시값을 교정한 경험에서 도출했다. 정보 구성과 상태 판단을 함께 고려해 사용자가 화면을 믿고 판단할 수 있도록 설계하는 능력을 설명한다. 사용자 신뢰의 향상을 측정했다거나 사용자 조사, 디자인 전담이나 조직 전체의 기술 리더십을 맡았다는 주장으로 확대하지 않는다. [문서 생성 경험](content-and-site-direction.md#장시간-작업과-상태-동기화), [지표 교정 경험](content-and-site-direction.md#전송량-감소와-표시값-교정)

[카카오페이와 당근 채용공고 조사](frontend-hiring-and-positioning.md#기업별로-요구하는-역량)에서는 사용자 이해와 정보 구성, 동료와 함께 문제를 해결하는 능력을 기대 역량으로 확인했다. 이 수요와 실제 경험을 연결해 첫 소개에서 능력과 기여를 먼저 설명한다. [Brittany와 Emil의 소개 방식](developer-websites.md#실제-사이트-비교)처럼 개발자의 기준을 먼저 읽고 경험에서 그 근거를 확인하게 하되, 두 개발자의 전문 영역이나 표현을 가져오지는 않는다.

### 프로젝트와 사례가 보태는 의미

개인 프로젝트는 사용 목적과 실제 사용 조건을 기능 및 개발 기준으로 구체화하는 능력을 보여준다. 개인 메모 앱은 기록을 다시 사용하려는 목적을 문장 선택과 조합, 내용 보존의 기준으로 연결한 경험이다. Issnuta는 인터넷 연결이 없을 때도 번역하려는 목적에 맞춰 모델을 미리 저장하는 사용 조건을 정한 경험이다. 두 설명은 프로젝트에서 기대할 수 있는 판단을 해석한 것이며, 실제 사용자 조사나 생산성 향상을 측정했다는 주장이 아니다. [프로젝트별 근거와 해석](homepage-content.md)

개인 메모 앱과 Issnuta를 함께 소개하는 구성은 [프로젝트 게재 결정](../decisions/project-availability.md#첫-버전에-소개할-프로젝트)을 따른다. 기록의 재사용을 먼저 설명하고 인터넷 연결이라는 환경 조건으로 관심을 확장하는 순서는 제안이다. Issnuta의 현재 활동은 발생 가능한 문제를 살피고 개선할 내용을 구체화하는 관점으로 설명한다. 특정 문제를 해결했거나 개선 계획을 모두 수립했다는 성과를 추가한 것은 아니다.

메모 앱은 첫 버전에 소개만 제공하고 Issnuta는 소스 저장소를 연결한다. 메모 앱에도 이후 URL을 추가하면 소스 링크를 표시할 수 있도록 [소스 주소와 링크 표시 결정](../decisions/project-availability.md#소스-주소-추가와-링크-표시)을 적용한다.

대표 사례 네 개는 [선정한 구성](../decisions/featured-cases.md)을 유지한다. 홈페이지에서는 각 경험에서 기대할 수 있는 능력을 먼저 설명하고, 확인된 사례와 성과를 이어서 제시한다. 직무 전반에 대한 자기평가로 읽히지 않도록 문구마다 근거가 되는 경험을 붙였다. 처리 방식과 도식은 [사례 상세](featured-case-copy.md)에 둔다.

- 정보 구성: 종류가 다른 기록의 관계를 파악하고 PM과 목록 기준을 조율한 경험을 연결했다. 서비스가 제공하는 정보를 사용자에게 필요한 화면 구성으로 구체화하고, 동료와 구현 기준을 협의할 수 있다는 의미다. [정보 구성과 협의 근거](content-and-site-direction.md#요구-조정과-ui의-정확성)
- 기능 설계: 오래 기다리거나 선택을 바꾸는 상황에 필요한 안내를 판단한 경험을 연결했다. 실행 이후에 필요한 동작도 화면 설계에 포함할 수 있다는 의미다. 취소하지 않기로 한 선택과 취소가 완료된 상태를 구분하며, 문서 생성 시간이 단축됐다는 뜻으로 쓰지 않는다. [문서 생성 경험](content-and-site-direction.md#장시간-작업과-상태-동기화)
- 성능 개선: 응답의 크기와 형식을 유지하며 화면 정지를 해결한 경험을 연결했다. 필요한 정보를 제공하면서 사용자가 조작할 수 있는 화면을 만드는 기술적 역량을 설명한다. 3~4초는 개선 전 화면 정지 시간이다. [화면 반응성 근거](content-and-site-direction.md#화면-반응성과-실시간-데이터)
- 지표의 정확성: 지표의 의미, 계산과 누락 원인을 확인해 표시를 바로잡은 경험을 연결했다. 사용자에게 판단의 근거가 되는 정보를 제공할 수 있다는 의미다. 전송량 감소는 조회 효율을 개선한 별도 성과이며, 10분이라는 비교 조건을 유지한다. [표시값과 전송량 근거](content-and-site-direction.md#전송량-감소와-표시값-교정)

정보 구성과 기능 설계는 [카카오페이가 요구한 정보 전달과 예외 상황 예상](frontend-hiring-and-positioning.md#카카오페이-복잡한-정보를-이해하기-쉽게-만들고-예외를-예상)에, 성능과 지표 개선은 [당근이 요구한 문제 이해와 기술 판단](frontend-hiring-and-positioning.md#당근-사용자-문제를-질문하고-상황에-맞는-기술을-선택)에 연결된다. 앞의 두 사례로 화면 설계에서 기대할 기여를 설명하고, 뒤의 두 사례로 그 화면을 실제로 사용할 수 있게 만드는 기술적 이해를 보탠다. 이 연결은 2026년 9월 14~15일 조사한 공고와 경험을 대조한 편집 판단이다.

개인 메모 앱의 테스트 자료는 작성한 내용을 다시 사용할 수 있어야 한다는 개발 기준의 근거로 활용했다. [프로젝트 상세 초안](personal-notes-project.md#웹사이트에-사용할-문구-초안)은 화면에 입력값이 보이는 상태와 저장이 끝난 상태를 구분하는 판단을 설명한다. 검사 도구와 실행 순서는 소개에 넣지 않았으며, 조사 사실과 후속 활용 조건은 [테스트 경험 자료](personal-notes-testing.md)에 유지한다.

### 오픈소스와 글이 보태는 의미

오픈소스 기여는 자신이 만든 코드 밖에서도 기존 동작을 이해하고 수정에 참여할 수 있다는 근거다. 2026년 9월 15일 GitHub CLI로 [React Router PR](https://github.com/remix-run/react-router/pull/14689)과 [Outline PR](https://github.com/outline/outline/pull/10759)의 작성자가 `nwleedev`이며 두 PR이 병합됐음을 확인했다. 릴리스 반영은 [공식 기록을 대조한 자료](content-and-site-direction.md#외부에서-확인할-수-있는-오픈소스-기여)를 따른다.

React 글은 기존에 쓰던 방법을 원리에 비추어 다시 판단하는 태도를, AI 작업 맥락 글은 반복되는 개발 과정의 불편을 개선하는 태도를 보탠다. 글의 실제 내용과 확인 날짜는 [글 후보 조사](homepage-content.md)에 있다. 두 편을 함께 둔 구성은 이 차이를 읽을 수 있는지 확인할 제안이며, 별도 전문 분야를 추가한다는 뜻은 아니다.
