## 문구의 근거와 게재 판단

Identity는 [개발자 소개에서 앞세울 가치](../decisions/developer-positioning.md)를 반영한다. 운영 문제, 서버 응답 처리, 비동기 작업 상태와 배포 후 확인을 함께 말하되 모든 경험에 관여한 것처럼 확대하지 않는다.

네 기여의 사실과 수치 조건은 [이력서와 포트폴리오 분석](content-and-site-direction.md) 및 [대표 경험의 편집 근거](featured-case-copy.md)를 대조했다. 이 문구는 제공 자료에 기록된 사실을 설명하며 운영 코드나 측정 원본을 별도로 감사한 결과는 아니다.

- 운영 지표: 포트폴리오 13쪽의 지표 오류 원인, 조회 변경과 실제 응답 대조를 사용했다. 10분 전송량을 응답 한 건의 크기나 로딩 시간으로 바꾸지 않았다.
- 문서 생성: 포트폴리오 11~12쪽의 대기 안내, 취소, 이벤트와 재조회 및 배포 확인을 사용했다. 이력서 1쪽의 요청 횟수는 3초 폴링 가정과 비교한 값으로 명시했다.
- 응답 처리: 포트폴리오 5쪽의 처리 위치 변경, 재사용과 배포 확인, 6쪽의 REST 및 스트림 병합과 분할 JSON 처리를 구분했다. FPS, INP와 새 성능 수치는 만들지 않았다.
- E2E 및 인증: 기존에 확인한 시나리오 수와 포트폴리오 15쪽의 인증 불일치, 복구 적용과 QA 배포 기록을 사용했다. 운영 장애가 완전히 사라졌다거나 모든 시나리오가 항상 통과한다고 확대하지 않았다.

이전 회사의 세 설명은 기존 이력서 기반 문구 안에서 문제, 적용 기술과 행동을 풀어 썼다. WebSocket의 정확한 원인과 변경 코드는 확인되지 않아 더 구체화하지 않았으며, 두 회사의 경험을 추가 근거 없이 나누지 않았다. 수치나 새로운 책임 범위를 추가하려면 별도 근거가 필요하다.

영어 구현에서도 같은 뜻과 조건을 유지한다. 제목은 추상적인 분야명 대신 실제 변경을 드러내도록 바꾸었으며, 카드와 큰 숫자 없이 읽히는 본문을 사용한다. 코드, 상세 상태도와 시행착오의 전체 과정은 블로그에 남긴다.

오픈소스 기여는 실제 PR과 공식 릴리스 링크가 준비된 경우에만 게재한다. Independent Work의 이용 및 소스 링크도 외부에서 열 수 있는 주소를 확인한 뒤 추가한다.

Offline Translation Web App의 `30초 이내 배포`는 비교 조건을 추가로 확인해야 하므로 현재 방문자용 문구에서 제외했다. Email, GitHub, Blog와 LinkedIn은 이력서와 포트폴리오의 링크를 대조했다. Résumé 주소는 저장소가 추적하는 파일에 기록하지 않고 빌드 환경에서 주입한다.
