# 개발자 소개에서 앞세울 가치

첫 소개에서는 **서비스 문제의 원인 분석, 데이터 흐름과 비동기 상태 개선, 배포 후 실제 동작 확인**을 앞세운다. 사용자에게 필요한 화면을 구성하고 동료와 구현 기준을 협의한 경험은 이 기술적 판단이 실제 서비스에서 어떻게 적용되었는지 보여주는 근거로 연결한다.

이 결정은 [개발자 소개와 편집 기준](../requirements.md#개발자-소개와-편집-기준)에 따라 Identity, Experience와 콘텐츠 순서를 정하는 기준이다. 첫 화면의 최종 문장을 그대로 고정하는 결정은 아니다.

## 비교한 방향과 선택 이유

사용자 이해와 화면 설계를 먼저 설명하는 기존 방향과, 운영 환경에서 발생한 문제를 찾아 데이터 및 상태 흐름을 개선하는 방향을 비교했다.

이력서와 포트폴리오에서는 대시보드 조회량, 문서 생성 상태 확인, 화면 정지, 인증 및 E2E 검증처럼 원인 분석부터 실제 동작 확인까지 이어지는 경험이 반복된다. 이 조합을 먼저 보여주면 특정 화면 스타일이 아니라 프론트엔드 서비스의 문제를 원인 분석부터 배포 후 확인까지 해결하는 개발자로 설명할 수 있다.

사용자 이해와 화면 설계 경험은 제외하지 않는다. 작업 이력의 정보 단위를 정한 경험과 장시간 작업의 안내 및 취소 동작을 설계한 경험을 각 Engineering Contribution의 판단 근거로 사용한다. 다만 첫 소개의 중심을 이 두 사례에만 두지 않는다.

## 문구와 경험에 미치는 영향

- Identity는 서비스 문제, 데이터 흐름, 비동기 상태와 배포 후 검증을 한두 문장으로 설명한다.
- Experience는 회사별로 묶고 Data & Monitoring, Async State & Realtime, Browser Runtime & Realtime Data, Reliability & Delivery 기여를 보여준다.
- 기술 이름은 독립된 역량 목록이 아니라 각 기여의 보조 정보로 둔다.
- 수치와 외부 기여는 자기평가보다 먼저 확인할 수 있는 근거로 사용한다.

한국어와 영어의 실제 문장은 [홈페이지 문구](../references/homepage-copy.md)에서 다듬는다. 새로운 경험이 생겨 소개의 중심이 달라지면 이 결정을 다시 비교한다.
