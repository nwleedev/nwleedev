# 서비스 준비 전 프로젝트 소개 방식

첫 버전에는 개발 중인 프로젝트의 목적과 제작 내용을 먼저 소개한다. 실제 서비스가 준비되면 이용 링크를 추가한다.

이 결정은 [Project](../requirements.md#project), [홈페이지](../requirements.md#홈페이지)와 [완료를 확인할 결과](../requirements.md#완료를-확인할-결과)에 적용한다. 현재 방문자가 사용할 수 있는 사이드 프로젝트 서비스는 없다.

## 비교한 방식과 선택

제작 내용을 먼저 소개하는 방식과 실제 서비스를 사용할 수 있을 때 포트폴리오 첫 버전을 완성하는 방식을 비교했다. 제작 내용을 먼저 소개하면 서비스 준비 전에도 개발 목적과 구현 과정의 판단을 설명할 수 있다. 이 방식을 선택하고 프로젝트의 현재 개발 상태를 함께 표시한다.

상세 설명과 서비스 이용은 각각 별도의 링크로 제공한다. 실제 이용 주소가 없는 항목에는 서비스 링크를 만들지 않으며, 소스 저장소를 서비스 이용 링크로 대신하지 않는다.

## 제작과 완료 확인에 미치는 영향

프로젝트 선정과 한국어 상세 설명을 먼저 준비한다. 첫 버전의 완료 확인에서는 목적, 제작 내용과 개발 상태를 읽을 수 있는지 확인하며, 서비스 배포를 포트폴리오 제작의 선행 조건으로 두지 않는다.

서비스가 준비되면 접속 주소와 주요 사용 동작을 확인한 뒤 홈페이지, 프로젝트 목록과 상세에 이용 링크를 추가한다. 실제 서비스의 개발과 배포를 이 포트폴리오 작업에서 수행한다는 결정은 아니다. 첫 버전에 게재할 프로젝트 목록과 소스 제공 여부도 별도로 정한다.
