# 첫 버전의 프로젝트와 서비스 소개 방식

첫 버전에는 개인 메모 앱과 Issnuta를 함께 소개한다. 프로젝트의 목적과 제작 내용에서 개발자의 판단과 기대할 기여가 드러나도록 구성하고, 실제 서비스가 준비되면 이용 링크를 추가한다.

이 결정은 [Project](../requirements.md#project), [홈페이지](../requirements.md#홈페이지)와 [완료를 확인할 결과](../requirements.md#완료를-확인할-결과)에 적용한다. 현재 방문자가 사용할 수 있는 사이드 프로젝트 서비스는 없다.

## 비교한 방식과 선택

제작 내용을 먼저 소개하는 방식과 실제 서비스를 사용할 수 있을 때 포트폴리오 첫 버전을 완성하는 방식을 비교했다. 제작 내용을 먼저 소개하면 서비스 준비 전에도 개발 목적과 구현 과정의 판단을 설명할 수 있다. 이 방식을 선택하고 프로젝트의 현재 개발 상태를 함께 표시한다.

목적과 제작 내용은 같은 페이지에서 읽을 수 있게 제공한다. 상세 설명을 위한 내부 페이지는 만들지 않는다. 실제 이용 주소가 없는 항목에는 서비스 링크를 만들지 않으며, 소스 저장소를 서비스 이용 링크로 대신하지 않는다.

## 첫 버전에 소개할 프로젝트

개인 메모 앱만 소개하는 구성과 Issnuta를 함께 소개하는 구성을 비교해 두 프로젝트를 함께 소개하기로 했다. 개인 메모 앱은 기록의 재사용을 정보 구성과 내용 보존의 기준으로 구체화한 경험을, Issnuta는 인터넷 연결이 없는 사용 환경을 고려한 경험을 보여준다. 서로 다른 필요를 서비스 설계에 반영하는 능력을 설명할 수 있는 구성이다.

개인 메모 앱은 개발 중인 앱으로 소개한다. Issnuta는 발생할 수 있는 문제를 살피는 현재 활동을 개선 역량과 연결한다. 문제를 찾고 발생 조건과 원인을 검토해 개선할 내용을 정하는 관점을 문장으로 설명한다. 현재 활동을 단순한 상태 이름으로 대신하지 않으며, 확인하지 않은 개선 성과나 완료 여부를 추가하지 않는다. 실제 문구는 [홈페이지 초안](../references/homepage-copy.md#issnuta)에서 다듬는다.

## 소스 주소 추가와 링크 표시

개인 메모 앱은 첫 버전에 소개와 제작 내용만 제공한다. 소스 링크를 바로 제공하는 방식과 추후 추가하는 방식을 비교해, 저장소 URL을 나중에 추가할 수 있는 구성을 선택했다. Issnuta에는 [열람 가능한 저장소](https://github.com/nwleedev/issnuta)를 소스 링크로 연결한다.

소스 URL은 프로젝트 콘텐츠의 선택 항목으로 관리한다. 값이 없으면 소스 링크와 그 링크를 위한 빈 공간을 표시하지 않는다. 메모 앱의 URL은 첫 버전에 설정하지 않으며, 이후 열람 가능한 주소를 콘텐츠에 추가하면 소스 링크가 표시되도록 구성한다. 주소를 추가하기 위해 UI 코드를 수정하지 않아야 한다.

소스 URL은 단일 페이지의 해당 프로젝트에 연결한다. 링크 이름과 안내 문구는 [한 곳의 terms 폴더](terms-storage.md)에서 관리하며, URL을 저장할 구체적인 형식은 콘텐츠 저장 방식을 결정할 때 정한다. URL이 없는 상태와 추가된 상태를 모두 확인한다.

## 제작과 완료 확인에 미치는 영향

프로젝트의 목적, 제작 내용과 현재 활동을 한국어로 간결하게 준비한다. 첫 버전의 완료 확인에서는 이 설명으로 개발자의 관심과 판단 기준을 읽을 수 있는지 확인하며, 서비스 배포를 포트폴리오 제작의 선행 조건으로 두지 않는다.

서비스가 준비되면 접속 주소와 주요 사용 동작을 확인한 뒤 같은 페이지의 프로젝트 소개에 이용 링크를 추가한다. 실제 서비스의 개발과 배포를 이 포트폴리오 작업에서 수행한다는 결정은 아니다. 두 프로젝트의 게재와 소스 제공 방식은 위 결정을 따르고, 글의 선정과 세부 문구 및 배치는 한국어 콘텐츠 구성에서 이어서 정한다.
