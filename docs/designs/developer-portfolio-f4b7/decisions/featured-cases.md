# 홈페이지 대표 사례 선정

홈페이지의 Cases에는 **작업별 이력 구성, 장시간 문서 생성, 화면 정지 해결, 대시보드 개선** 네 사례를 소개한다. 사용자에게 필요한 화면을 설계한 경험과 이를 구현하며 해결한 기술적 문제를 함께 보여준다.

이 결정은 [홈페이지 요구사항](../requirements.md#홈페이지)의 대표 사례 3~4개를 선정하고, [사용자 이해와 화면 설계를 앞세우는 소개 방향](developer-positioning.md)을 실제 경험으로 뒷받침하기 위한 기준이다.

## 비교한 구성과 선택 이유

네 사례를 모두 소개하는 구성과 대시보드 개선을 전체 사례 목록에 두고 홈페이지에는 세 사례만 소개하는 구성을 비교했다. 세 사례는 소개를 짧게 만들 수 있지만, 홈페이지에서 표시값 교정과 수치로 확인되는 전송량 감소를 함께 보여주기 어렵다. 네 사례를 통해 서로 다른 판단과 성과를 제시하는 구성을 선택했다.

- 작업별 이력 구성은 사용자가 확인할 정보의 단위를 정하고 PM과 구현 기준을 협의한 경험을 보여준다.
- 장시간 문서 생성은 기다리는 동안의 안내와 취소에 따른 처리를 설계한 경험을 보여준다.
- 화면 정지 해결은 응답 크기와 형식을 유지하면서 브라우저의 처리 위치를 바꾼 경험을 보여준다.
- 대시보드 개선은 잘못된 표시값을 교정하고 반복 조회를 줄인 경험을 보여준다. 데이터 전송량은 10분이라는 비교 구간과 함께 제시한다.

각 사례의 사실과 수치 조건은 [개발 경험 분석](../references/content-and-site-direction.md#자료에서-확인한-경험과-근거의-한계)에 있다. 회사의 채용 요건과 사례의 연결은 [문구 구성과 편집 근거](../references/developer-introduction.md#대표-사례-문구의-구성)를 따른다.

## 문구와 화면 구성에 미치는 영향

작업별 이력 구성과 장시간 문서 생성을 먼저 배치하고, 화면 정지 해결과 대시보드 개선을 뒤에 연결하는 순서를 제안한다. 최종 배치와 각 사례의 제목 및 요약 표현은 [문구 초안](../references/developer-introduction.md#대표-사례-문구의-구성)에서 다듬는다. 네 사례를 선정한 것이 모든 문구와 배치를 확정했다는 뜻은 아니다.

React Router와 Outline 기여는 요구사항에 따라 홈페이지의 오픈소스 영역에서 소개한다. 실제 사이드 프로젝트와 블로그 글의 선정은 이 결정에 포함하지 않는다.

사용할 수 있는 회사의 UI 이미지는 아직 정하지 않았다. 사례 선정은 회사 화면의 사용 여부를 확정하는 결정이 아니다. 사례를 뒷받침할 자료의 제공 조건이 달라지거나 새로운 대표 경험이 생기면 선정을 다시 검토한다.
