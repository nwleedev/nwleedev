# 일괄 복사 순서와 제거 복구 결정

일괄 복사 항목은 추가 당시의 원문 스냅샷을 줄바꿈으로 이어 붙이고 같은 텍스트의 반복 추가를 허용한다. 실행 취소와 다시 실행은 저장 목록의 제거에만 적용하며 새로고침 전 애플리케이션 실행 동안 유지한다. 넓은 패널은 항목 하나를 클릭해 선택할 수 있고, pointer drag 또는 선택된 항목 본문의 `ArrowUp`과 `ArrowDown`으로 순서를 바꾼다. 항목 우측 상단에는 직접 삭제 버튼을 제공한다. 모바일 확인 페이지는 길게 누른 뒤 drag와 항목 동작 선택창의 `위치 변경`을 함께 제공한다. 순서 번호, 위로와 아래로 버튼은 항상 표시하지 않는다.

## 결정 질문과 요구 결과

[요구사항의 일괄 복사 순서와 복구 조건](../requirements.md#반드시-지킬-조건)은 항목 추가 순서, 항목 선택, drag 및 방향키 재정렬, 목록 밖 제거와 제거의 실행 취소 및 다시 실행을 요구한다. 저장 목록 관리 표현에서 재정렬을 시작할 위치, 선택과 포커스의 구분, 구분자, 반복 항목, drag 없이 실행할 방법과 이력 수명도 정해야 했다.

## 검토한 선택지

- 원본 메모의 최신 내용을 매번 읽으면 이미 만든 누적 결과가 나중 편집으로 바뀐다.
- 같은 텍스트를 자동 제거하면 사용자가 같은 문구를 반복하려는 의도를 잃는다.
- 누적 전체 snapshot을 이력으로 저장하면 제거를 되돌릴 때 그 뒤의 순서 변경까지 함께 되돌릴 수 있다.
- 제거 명령만 역연산으로 보관하면 제거된 항목과 위치를 복원하면서 다른 동작과 구분할 수 있다.

## 결정 이력

- 초기 권장안은 줄바꿈 구분자, 중복 허용과 새로고침 전 제거 이력이었다.
- 재검토에서는 목록 밖 제거가 실수인지 알 수 있는 예정 상태, 드래그 없는 대안과 제거 명령 전용 이력이 필요하다는 점을 보완했다.
- 현재 결정은 스냅샷 항목, 명시적인 드래그 상태, 버튼 대안과 애플리케이션 실행 동안 유지하는 제거 이력을 함께 제공하는 것이다.
- 일괄 복사 기능의 위치 재검토에서는 이 목록과 이력을 별도 페이지가 아니라 메모 화면의 보조 패널에서 사용하기로 했다.
- 첫 모바일 일괄 복사 요구에서 `48rem` 미만에는 같은 목록과 이력을 `/accumulator` 페이지에서 사용하고, 각 항목의 왼쪽 버튼에서 재정렬을 시작하기로 했다. 당시 길게 누른 메모의 선택 해제도 항목 제거 명령으로 처리했다.
- 화면 사용 검토 뒤 넓은 메모 화면의 일괄 복사 패널에서는 순서 번호, 위로, 아래로와 상시 제거 버튼을 없애고 재정렬을 pointer 드래그로만 수행하도록 변경했다. 제거는 항목에 pointer를 올렸을 때 우측 상단에 나타나는 아이콘 버튼으로 실행하며, 실행 취소와 다시 실행의 이력 및 키보드 단축키는 남기되 패널 버튼은 제거한다.
- 이 변경은 `48rem` 미만의 저장 목록 관리 표현에 승인된 왼쪽 재정렬 버튼, 위로, 아래로 및 제거 대안을 바꾸지 않는다. 당시에는 hover를 사용할 수 없는 넓은 화면과 키보드에서 제거 및 순서 변경을 실행하는 방식이 남아 있었다.
- 후속 모바일 요구는 길게 누르기 항목 추가와 다시 누르기 제거를 폐기했다. 목록 화면 헤더 아이콘으로 일괄 복사 상태를 시작하고 짧게 누른 순서를 기록한다.
- 최신 요구는 같은 메모를 반복해서 누르면 별도 항목을 추가하도록 확정했다. 상태의 헤더 뒤로가기, 하단 `초기화`와 클릭 횟수가 붙은 `다음`으로 조작을 바꿨다.
- 후속 요구에서 `다음`은 별도 확인 페이지로 이동하고, 확인 항목은 길게 누른 뒤 touch drag로 재정렬하며 우측 상단 동작 선택창에서 복제 또는 삭제하도록 확정했다. 이 편집은 원본 메모에 영향을 주지 않는다. 당시에는 확인 작업과 저장 목록의 관계 및 복제 항목의 삽입 위치가 남아 있었다.
- 구현 필수 결정 재검토에서 키보드 단축키만으로는 WCAG의 단일 pointer 대안이 되지 않고, 위아래 버튼을 다시 항상 표시하면 간소화 요구를 되돌린다는 점을 확인했다. 동작 선택창에서 `위치 변경`을 고른 뒤 항목 사이의 삽입 위치를 누르는 방식을 채택했다.
- 같은 재검토에서 hover를 사용할 수 없는 환경에는 항목 동작 버튼을 항상 표시하고, 키보드에서는 `focus-within`에서 표시하기로 했다. 모바일 확인 작업은 저장 목록과 분리하고 복제 항목은 대상 바로 뒤에 넣는다.
- 2026년 9월 3일 데스크톱 사용 검토에서는 항목 동작 선택창을 거쳐 `위치 변경` 또는 `제거`를 실행하는 흐름이 불필요하다고 확인했다. 넓은 패널에서는 선택창과 `위치 변경`을 없애고, 항목 우측 상단의 붉은 삭제 버튼과 drag 재정렬을 직접 제공하기로 했다. 모바일 확인 페이지의 선택창은 그대로 유지한다.
- 같은 검토에서 목록 요소가 아니라 패널 전체를 삭제 판단 영역으로 정했다. 패널 안에 놓은 항목은 사라지지 않고, 패널 밖에 놓았을 때만 제거한다. 다른 항목 위를 지나는 동안에는 해당 항목 전체를 현재 놓기 대상으로 표시한다.
- 후속 요구는 넓은 패널의 항목을 클릭해 하나만 선택하고, 선택된 항목의 위쪽 및 아래쪽 방향키로 한 자리씩 재정렬하도록 했다. Button 및 Listbox 패턴을 비교해 항목 본문을 `aria-pressed`가 있는 toggle button으로 만들고, 방향키가 탐색을 뜻하는 listbox 역할은 사용하지 않기로 했다.
- 같은 변경에서 메모와 일괄 복사 항목 선택은 독립적으로 유지하되 상위 임시 조작이 없을 때 한 번의 `Escape`로 함께 해제하기로 했다. drag 취소나 열린 동작 선택창 닫기가 먼저 필요한 경우에는 해당 조작이 우선한다.
- 2026년 9월 4일 코드 검토에서 선택하지 않은 항목의 drag가 click을 억제하면서 선택도 만들지 않고, 저장 목록 관리 route의 제거 및 다시 실행이 패널과 달리 선택 ID를 정리하지 않는 차이를 확인했다. drag 거리 기준을 처음 넘는 시점에는 대상을 해제 가능한 toggle이 아니라 명시적인 선택으로 바꾸고, 저장 성공 결과의 제거 ID를 조립 지점에서 한 번 정리하도록 결정했다.
- 같은 검토에서 서로 다른 이동이 같은 위치 문구를 만들면 문자열 state가 바뀌지 않아 live region에 새 알림이 생기지 않을 수 있음을 확인했다. 이동 성공마다 별도 알림 식별자로 새 DOM 추가를 만들고 실패, 취소와 범위 밖 방향키 입력에는 알림을 만들지 않기로 했다.

## 승인된 결정과 이유

- 일괄 복사 항목은 고유 ID, 원본 메모와 content revision, 추가 당시 원문을 보관한다.
- 배열 순서가 결합 순서이며 기본 구분자는 줄바꿈이다. 같은 원문도 별도 ID를 가진 항목으로 여러 번 추가할 수 있다.
- 넓은 패널 안에 놓으면 순서를 바꾸고 패널 전체의 외곽을 벗어난 곳에 놓으면 제거한다. 패널 밖에 있는 동안 제거 예정 상태를 표시하며 `Escape`, `pointercancel`과 `lostpointercapture`는 드래그를 취소한다.
- 넓은 메모 화면의 일괄 복사 패널에서는 항목 전체를 pointer로 드래그해 순서를 바꾼다. 순서 번호, 위로 이동, 아래로 이동, 상시 이력 버튼과 항목 동작 선택창을 표시하지 않는다.
- 드래그 중 pointer가 다른 항목 위에 있으면 그 항목 전체를 현재 놓기 대상으로 식별할 수 있게 표시한다. 단순 hover 상태와 놓기 대상 상태를 색 하나에만 의존하지 않고 구분한다.
- 항목 우측 상단에는 삭제만 실행하는 붉은 아이콘 버튼을 둔다. pointer hover와 항목 내부 `focus-within`에서 표시하고, hover가 없거나 coarse pointer인 환경에서는 항상 표시한다. 버튼은 접근 가능한 이름과 키보드 포커스 표시를 제공한다.
- 넓은 패널의 키보드 재정렬 동작은 유지하되 pointer용 `위치 변경` 선택창과 삽입 위치 버튼은 제공하지 않는다.
- 넓은 패널의 항목 본문은 네이티브 toggle button으로 만들고, 클릭, `Enter`와 `Space`로 한 항목을 선택하거나 같은 항목의 선택을 해제한다. 선택 상태는 안정된 접근 가능한 이름과 `aria-pressed`로 전달하며, 우측 상단 삭제 버튼은 본문 버튼 안에 중첩하지 않는다.
- 한 번에 일괄 복사 항목 하나만 선택한다. 다른 항목을 선택하면 이전 항목의 선택을 해제하고, drag를 시작한 항목도 선택한다. 선택된 항목 전체는 메모 선택과 같은 의미의 굵고 끊기지 않는 붉은 실선으로 표시하되 `focus-visible` 및 drag 놓기 후보와 형태를 구분한다.
- drag는 거리 기준을 넘거나 유효한 놓기 상태에 처음 들어간 시점에 대상 항목을 선택한다. 이미 선택된 항목을 drag해도 선택을 해제하지 않으며, drag 뒤 억제되는 click에 선택 결과를 맡기지 않는다.
- 선택된 항목 본문에 포커스가 있을 때 `ArrowUp`과 `ArrowDown`은 같은 재정렬 명령으로 항목을 한 자리 옮긴다. 첫 항목의 위쪽 방향키와 마지막 항목의 아래쪽 방향키는 자료를 바꾸지 않는다. 이동 뒤 같은 항목 ID의 선택과 DOM 포커스를 유지하고 새 위치와 전체 항목 수를 정중한 live region으로 알린다. 삭제 버튼, 입력과 다른 하위 제어에서는 방향키를 가로채지 않는다.
- 메모 선택과 일괄 복사 항목 선택은 별도 ID로 유지하고 동시에 존재할 수 있다. drag, 열린 동작 선택창이나 다른 상위 임시 조작이 없을 때 보조 키 없는 `Escape`는 두 선택을 함께 해제한다. 선택 해제는 항목, 순서, 제거 이력, 속성 패널 대상과 최근 활성 패널을 바꾸지 않는다.
- 저장 목록 관리 표현에서는 각 항목 왼쪽에 재정렬을 시작하는 네이티브 버튼을 두고 충분한 pointer 조작 크기와 접근 가능한 이름을 제공한다. 각 항목의 위로 이동, 아래로 이동과 제거 버튼도 유지한다.
- 모바일 일괄 복사 확인 페이지에서는 항목의 동작 버튼이 아닌 영역을 500ms 동안 누르고 10 CSS px 이내에 머문 뒤에만 touch drag를 시작한다. 그 전에 이동, 스크롤, `pointercancel`과 `lostpointercapture`가 발생하면 순서를 바꾸지 않는다.
- 확인 항목 우측 상단의 아이콘 버튼은 `위치 변경`, `복제`와 `삭제`를 제공하는 작은 동작 선택창을 연다. 복제는 같은 원본 메모 참조와 원문 스냅샷을 가진 새 항목 ID를 대상 바로 뒤에 만들고, 삭제는 대상 ID 하나만 작업 초안에서 제거한다.
- 확인 페이지의 재정렬, 복제와 삭제는 원본 메모, 저장된 메모 revision 및 사용 횟수를 바꾸지 않고 저장 목록의 제거 실행 취소 및 다시 실행 이력에도 추가하지 않는다.
- 실행 취소는 제거된 항목을 이전 index에 복원하고, 다시 실행은 같은 ID의 항목을 다시 제거한다.
- 직접 제거와 다시 실행의 저장 성공 결과는 실제로 없어진 항목 ID를 포함한다. route와 패널별 callback을 중복하지 않고 일괄 복사 명령의 조립 지점에서 해당 선택 ID를 한 번 정리한다. 저장 실패와 변경 없음은 선택을 바꾸지 않는다.
- 모바일 일괄 복사 작업은 저장 목록에 반영하지 않는 별도 IndexedDB 초안이다. 같은 메모의 반복 클릭도 별도 항목과 클릭 횟수로 기록하고, `초기화`는 이번 작업만 비운다. 이전 long-press 연결을 새 흐름에 재사용하지 않는다.
- 제거 이력은 라우트를 이동해도 유지하지만 새로고침하면 지운다. 실행 취소 뒤 추가, 재정렬 또는 제거가 성공하면 다시 실행 이력을 지운다.
- 메모 편집기에 포커스가 있으면 애플리케이션의 실행 취소 단축키가 텍스트 편집 이력을 가로채지 않는다. 넓은 일괄 복사 패널에는 실행 취소와 다시 실행 버튼을 표시하지 않지만, 패널 밖에서 사용하는 키보드 단축키와 이력 규칙은 유지한다.
- 방향키 이동 성공은 같은 문구가 연속돼도 live region에 새 DOM 변경을 만든다. 알림은 새 위치와 전체 항목 수를 전달하고 현재 포커스 및 선택을 바꾸지 않는다.

[WCAG Dragging Movements 설명](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)은 drag와 같은 결과를 내는 단일 pointer 조작을 요구한다. 넓은 패널에는 키보드 재정렬이 남지만 단일 pointer로 drag와 같은 결과를 만드는 대안은 없으므로 현재 데스크톱 요구와 WCAG 2.5.7 사이의 충돌을 해소한 것으로 간주하지 않는다. 모바일 확인 페이지는 동작 선택창의 `위치 변경`을 그 대안으로 유지한다. [WCAG Target Size 설명](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)은 pointer 조작 대상이 원칙적으로 최소 `24 × 24` CSS px 영역을 포함하도록 요구한다.

[데스크톱 입력과 피드백 복원력 조사](../references/desktop-input-and-feedback-resilience-research.md)는 패널 전체를 기준으로 한 제거 판정, 현재 놓기 대상 피드백과 직접 삭제 동작의 근거 및 남은 접근성 제한을 정리한다. [모바일 일괄 복사 확인과 오른쪽 패널 우선순위 조사](../references/mobile-batch-copy-confirmation-and-panel-priority-research.md)는 모바일 Pointer Events 취소 처리, 동작 선택창과 작업 사본 구분을 추가로 정리한다. [Carbon Common actions](https://carbondesignsystem.com/patterns/common-actions/)은 목록에서 항목을 없애는 remove를 과도하게 강조하지 않는 버튼이나 아이콘으로 표현하고, close 아이콘은 요소 우측 상단에 두는 사례를 보여준다. [Apple의 Drag and drop 지침](https://developer.apple.com/design/human-interface-guidelines/drag-and-drop)은 drag 결과를 계속 보여주고 가능하면 되돌릴 수 있게 하도록 안내하며, [Undo and Redo 지침](https://developer.apple.com/design/human-interface-guidelines/undo-and-redo)은 되돌릴 대상과 결과를 사용자가 예측할 수 있게 표시하도록 안내한다.

## 예상 결과와 계획 영향

현재 저장된 일괄 복사 목록은 IndexedDB에 두고 제거 이력과 데스크톱 항목 선택 ID는 애플리케이션 실행 동안 메모리에 둔다. 모바일 확인 작업은 별도 IndexedDB 초안으로 분리한다. 선택 전이, 방향키 한 자리 이동과 경계, 제거 결과 ID, 복원, 다시 제거와 이력 분기, 모바일 확인 작업의 재정렬, 새 ID 복제 및 삭제와 삽입 위치 선택 명령은 TDD 대상으로 삼는다. 데스크톱의 패널 안 재정렬과 패널 밖 제거 판정은 순수 규칙으로 분리할 때 TDD 대상으로 삼고, `aria-pressed`, drag 시작 선택, 실제 포커스 유지, 반복되는 live announcement, route를 오간 뒤 선택 정리, 선택 및 놓기 후보 표현과 직접 삭제 버튼은 실제 브라우저에서 검증한다. 모바일의 길게 누른 뒤 drag, 동작 선택창 위치와 단일 pointer 대안도 실제 브라우저에서 검증한다. 패널과 확인 페이지의 위치 및 반응형 표현은 [일괄 복사 패널과 모바일 확인 페이지 결정](accumulator-workspace-panel.md)을 따른다.

## 다시 검토할 조건

- 순서 변경과 추가도 실행 취소해야 한다는 요구가 생기는 경우
- 새로고침 뒤에도 제거 이력을 복원해야 하는 경우
- 목록 밖 drop이 제거로 자주 잘못 해석되는 경우
- hover가 없는 환경에서 항목 동작 버튼을 찾거나 실행할 수 없는 경우
- `위치 변경`과 삽입 위치 선택이 drag와 같은 결과를 만들지 못하는 경우
- 500ms 또는 10 CSS px 기준이 모바일 스크롤 및 길게 누르기 기본 동작과 반복해서 충돌하는 경우
- 데스크톱 목표 접근성 수준에서 drag와 같은 단일 pointer 대안을 반드시 제공해야 하는 경우
- 방향키 재정렬의 설명, 포커스 유지 또는 새 위치 알림을 화면 읽기 프로그램에서 이해하기 어려운 경우
