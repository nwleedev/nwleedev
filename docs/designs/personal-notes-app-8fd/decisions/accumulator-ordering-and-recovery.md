# 일괄 복사 순서와 제거 복구 결정

일괄 복사 항목은 두 항목의 자리를 맞바꾸지 않고 사용자가 가리킨 앞뒤 위치로 삽입한다. 저장 목록, 넓은 패널과 모바일 확인 작업은 같은 순서 계산을 사용하며, 제거 실행 취소 및 다시 실행의 기존 수명은 유지한다.

## 질문과 이유

일괄 복사는 추가 당시 원문 스냅샷을 줄바꿈으로 이어 붙이고 같은 텍스트의 반복 추가를 허용한다. 순서를 바꿀 때 항목이 어디로 이동할지 미리 알 수 있어야 하며 pointer drag를 사용할 수 없는 사용자도 같은 결과를 만들 수 있어야 한다. 현재 `moveBatchCopyItem`과 `moveMobileBatchCopyEntry`는 제거 후 삽입 계산을 이미 사용하므로 승인된 동작과 구현을 다시 어긋나게 만들지 않아야 한다.

## 검토한 선택지

- 두 항목의 위치 교환은 구현 규칙이 짧지만 이동 사이에 있던 항목의 상대 순서를 예상하기 어렵고 일반적인 정렬 목록의 삽입 위치 표시와 맞지 않는다.
- 제거 후 삽입은 이동 결과를 앞뒤 선으로 보여줄 수 있고, 이동하지 않은 항목의 상대 순서를 유지하며 현재 순서 계산을 재사용한다.
- 위아래 버튼만 제공하면 인접 이동은 분명하지만 긴 목록에서 많은 반복 입력이 필요하다.

## 승인된 결정과 이유

- pointer 위치가 가리키는 대상 항목의 앞이나 뒤를 삽입 위치로 정한다. `[A, B, C, D]`에서 A를 D 뒤에 놓으면 `[B, C, D, A]`, D 앞에 놓으면 `[B, C, A, D]`가 된다.
- drag는 항목 왼쪽의 이동 핸들에서만 시작한다. 항목 본문과 동작 버튼은 drag 시작점으로 사용하지 않는다.
- drag 중 실제 결과가 생기는 위치에만 삽입선을 표시하고 평상시 drop zone, 삽입선과 안내 문구를 표시하지 않는다.
- `위치 변경`은 대상 항목의 앞뒤 삽입 위치를 선택하게 하고 drag와 같은 명령을 호출한다. 키보드 방향키는 선택한 항목을 한 자리씩 옮기되 같은 삽입 계산을 사용한다.
- 재정렬은 이동한 항목의 ID, 텍스트 스냅샷, 선택, 포커스와 항목 수를 유지한다. 자기 자신, 사라진 대상, 내부 여백과 유효하지 않은 위치는 순서를 바꾸지 않는다.
- 저장 목록과 모바일 확인 작업은 각자의 저장 대상만 바꾼다. 확인 작업의 복제와 삭제는 원본 메모, 저장 목록과 사용 횟수를 바꾸지 않는다.
- 패널 바깥 제거, 제거 실행 취소 및 다시 실행, 저장 실패 복구와 revision 검사는 기존 규칙을 유지한다.

## 구현 및 검증 영향

`entities/batch-copy`, `features/edit-batch-copy`와 모바일 초안의 기존 삽입 명령을 보존하고 UI의 이동 핸들 및 대체 조작을 이 명령에 연결한다. 순서 검사는 네 항목의 비인접 이동, 중복 텍스트의 서로 다른 ID, 앞뒤 삽입, 자기 자신, 대상 제거, 저장 실패, 스크롤 끝과 새로고침 뒤 전체 복사 문자열을 포함한다. 실제 브라우저에서는 삽입선, drag preview, 키보드 포커스, touch scroll 취소와 동작 선택창 복귀를 확인한다.

## 다시 검토할 조건

- 저장 목록, 넓은 패널과 모바일 확인 작업에서 같은 조작이 다른 순서를 만드는 경우
- drag 대체 조작으로 앞뒤 삽입 위치를 선택할 수 없는 경우
- 긴 목록에서 삽입 위치 표시가 화면 밖 결과를 잘못 알리는 경우
