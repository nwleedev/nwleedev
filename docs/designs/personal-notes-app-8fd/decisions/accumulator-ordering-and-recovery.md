# 누적 순서와 제거 복구 결정

누적 항목은 추가 당시의 원문 스냅샷을 줄바꿈으로 이어 붙이고 같은 텍스트의 중복을 허용한다. 실행 취소와 다시 실행은 제거에만 적용하며 새로고침 전 애플리케이션 실행 동안 유지한다.

## 결정 질문과 요구 결과

[요구사항의 누적 순서와 복구 조건](../requirements.md#반드시-지킬-조건)은 클릭 순서, 드래그 재정렬, 목록 밖 제거와 제거의 실행 취소 및 다시 실행을 요구한다. 구분자, 중복, 드래그 없이 실행할 방법과 이력 수명도 정해야 했다.

## 검토한 선택지

- 원본 메모의 최신 내용을 매번 읽으면 이미 만든 누적 결과가 나중 편집으로 바뀐다.
- 같은 텍스트를 자동 제거하면 사용자가 같은 문구를 반복하려는 의도를 잃는다.
- 누적 전체 snapshot을 이력으로 저장하면 제거를 되돌릴 때 그 뒤의 순서 변경까지 함께 되돌릴 수 있다.
- 제거 명령만 역연산으로 보관하면 제거된 항목과 위치를 복원하면서 다른 동작과 구분할 수 있다.

## 결정 이력

- 초기 권장안은 줄바꿈 구분자, 중복 허용과 새로고침 전 제거 이력이었다.
- 재검토에서는 목록 밖 제거가 실수인지 알 수 있는 예정 상태, 드래그 없는 대안과 제거 명령 전용 이력이 필요하다는 점을 보완했다.
- 현재 결정은 스냅샷 항목, 명시적인 드래그 상태, 버튼 대안과 애플리케이션 실행 동안 유지하는 제거 이력을 함께 제공하는 것이다.

## 승인된 결정과 이유

- 누적 항목은 고유 ID, 원본 메모와 content revision, 추가 당시 원문을 보관한다.
- 배열 순서가 결합 순서이며 기본 구분자는 줄바꿈이다. 같은 원문도 별도 ID를 가진 항목으로 여러 번 추가할 수 있다.
- 목록 안에 놓으면 순서를 바꾸고 목록 밖에 놓으면 제거한다. 목록 밖에 있는 동안 제거 예정 상태를 표시하며 `Escape`와 `pointercancel`은 드래그를 취소한다.
- 각 항목에 위로 이동, 아래로 이동과 제거 버튼을 제공한다.
- 실행 취소는 제거된 항목을 이전 index에 복원하고, 다시 실행은 같은 ID의 항목을 다시 제거한다.
- 제거 이력은 라우트를 이동해도 유지하지만 새로고침하면 지운다. 실행 취소 뒤 추가, 재정렬 또는 제거가 성공하면 다시 실행 이력을 지운다.
- 메모 편집기에 포커스가 있으면 애플리케이션의 실행 취소 단축키가 텍스트 편집 이력을 가로채지 않는다.

[WCAG Dragging Movements 설명](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)은 드래그와 같은 결과를 내는 단일 포인터 조작을 요구한다. [Apple의 Undo and Redo 지침](https://developer.apple.com/design/human-interface-guidelines/undo-and-redo)은 되돌릴 대상과 결과를 사용자가 예측할 수 있게 표시하도록 안내한다.

## 예상 결과와 계획 영향

현재 누적 목록은 IndexedDB에 저장하고 제거 이력은 애플리케이션 실행 동안 메모리에 둔다. 제거, 복원, 다시 제거와 이력 분기를 다루는 명령 모듈은 TDD 대상으로 삼는다. 드래그 상태, 포커스와 상태 알림은 브라우저에서 검증한다.

## 다시 검토할 조건

- 순서 변경과 추가도 실행 취소해야 한다는 요구가 생기는 경우
- 새로고침 뒤에도 제거 이력을 복원해야 하는 경우
- 목록 밖 drop이 제거로 자주 잘못 해석되는 경우
