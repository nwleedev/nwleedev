# 일괄 복사 패널과 모바일 확인 페이지 결정

메모 작업 영역의 inline size가 `48rem` 이상이면 일괄 복사 항목의 선택, 순서 편집과 제거를 메모 화면의 오른쪽 보조 패널 또는 같은 route의 모달로 제공한다. 패널은 항목 목록과 전체 복사 동작만 보여주고 합친 텍스트 미리보기, 실행 취소 및 다시 실행 버튼을 표시하지 않는다. 속성 패널과 일괄 복사 패널 가운데 마지막으로 활성화한 패널 하나만 오른쪽 영역에 표시한다. `48rem` 미만의 목록 표현에서는 화면 헤더에서 일괄 복사 상태를 시작하고 `다음`으로 `/batch-copy` 확인 페이지에 이동한다. 저장된 항목도 우측 하단의 항목 수 제어로 같은 route에서 관리하며, 이 route는 전역 탐색에 추가하지 않는다.

## 결정 질문과 요구 결과

[일괄 복사 기능의 위치 요구사항](../requirements.md#반드시-지킬-조건)은 넓은 화면에서는 메모를 고르는 문맥을 떠나지 않고 선택 결과를 확인하고 편집하며, 작은 화면에서는 일괄 복사 상태와 저장된 목록 관리 화면을 제공하도록 요구한다. 각 화면에서 목록에 접근하는 방식, 자료와 이력 수명, 키보드 포커스 및 하단 동작의 결과를 정해야 했다.

## 검토한 선택지

- 독립 페이지는 일괄 복사 목록에 넓은 공간을 제공하지만 메모를 추가할 때마다 원본 메모와 결합 결과 사이를 오가게 하고, 일괄 복사 상태를 최상위 탐색 항목으로 만든다.
- 메모 위에 항상 떠 있는 패널은 누적 결과를 즉시 보여주지만 공간형 보드와 작은 화면의 메모 목록을 계속 가린다.
- 충분한 공간에서는 나란한 패널을 사용하고 공간이 부족하면 같은 화면의 모달 패널로 전환하면, 메모와 결과를 함께 볼 수 있는 환경을 활용하면서 작은 화면에서는 한 과업에 집중할 수 있다.
- 작은 popover는 순서가 있는 목록과 제거 조작을 다루기에 공간과 읽기 구조가 부족하다.
- `48rem` 미만에서도 모달을 사용하면 메모 목록 위에 목록을 다시 겹치고 브라우저 뒤로 가기와 페이지 하단 동작을 활용하기 어렵다.
- 작은 화면에서만 별도 관리 페이지를 사용하면 메모 선택 화면과 순서 편집 화면을 한 번에 하나씩 보여주면서 넓은 화면의 나란한 패널을 유지할 수 있다.

## 결정 이력

- 초기 화면 구조는 선택한 텍스트를 독립 route와 Pages slice로 두었다.
- 요구사항 재검토에서 누적은 메모 선택과 바로 이어지는 부가 작업이므로 메모 화면 안에서 제공해야 한다는 방향이 추가됐다.
- Fluent 2의 inline drawer와 Material 3의 supporting pane을 비교해, 메모와 누적 결과를 동시에 참조할 수 있을 때는 나란한 패널이 적합하다고 판단했다.
- 작은 작업 영역에서는 메모 목록을 더 줄이지 않고 WAI-ARIA 모달 dialog의 포커스 및 닫기 규칙을 따르는 같은 route의 모달 패널로 전환하기로 했다.
- 구현 전 검토에서 결합된 전체 텍스트의 복사 동작은 목록에 있었지만, 복사할 문자열과 실패 처리 및 사용 빈도 영향이 작업 계획에 배정되지 않은 공백을 확인했다.
- 현재 결정은 일괄 복사 전용 route와 탐색 항목을 제거하고, 메모 화면의 하나의 보조 패널을 inline 및 modal 표현으로 바꾸는 것이다.
- 화면 검토 뒤 별도 `메모` 제목과 상단 작업 행을 제거하고 캔버스가 상단 탐색 아래의 나머지 화면을 채우도록 요구사항이 변경됐다. 선택 목록 제어는 화면 우측 상단에 유지하고, 넓은 화면에서 항목을 추가하면 결과가 우측 패널에 나타나야 한다.
- 이후 모바일 일괄 복사 요구사항은 작은 화면에서 저장된 항목을 별도 페이지의 목록으로 관리하고 메모 화면 우측 하단의 항목 수 제어로 이동하도록 변경했다. 이 변경은 `48rem` 이상에서 승인된 우측 상단 제어, 나란한 패널과 모달 표현을 유지하고 `48rem` 미만에만 적용한다.
- 화면 사용 검토 뒤 넓은 화면의 패널에서 합친 텍스트 미리보기, 실행 취소, 다시 실행, 순서 번호, 위로와 아래로 버튼을 제거하도록 변경했다. 전체 복사는 현재 목록을 내부에서 결합해 실행하며, 결과 알림은 패널 안이 아니라 메모 작업 영역의 고정 알림으로 이동한다.
- 같은 검토에서 패널 머리 영역은 변경 전 실제 계산 높이 `63 CSS px`의 60%인 약 `38 CSS px`로 줄이고, 누적 성공 알림은 항목과 항목 수 변화가 이미 결과를 보여주므로 제거하기로 했다.
- 후속 모바일 요구에서 길게 누르기 항목 추가를 개별 복사로 바꾸고, 목록 화면 헤더 아이콘으로 별도 일괄 복사 상태를 시작하기로 했다. 당시 하단 동작은 `일괄 복사하기`와 `취소`였으며, 저장된 목록을 편집하는 `/accumulator` 화면은 유지했다.
- 최신 요구에서는 평상시 헤더 오른쪽 아이콘으로 일괄 복사 상태에 들어가고, 상태 안의 헤더 왼쪽 뒤로가기가 취소 역할을 맡도록 변경했다. 하단에는 `초기화`와 클릭 횟수가 붙은 `다음`을 둔다.
- 후속 요구에서 `다음`은 `/accumulator`의 별도 확인 페이지로 이동하도록 확정했다. 확인 페이지는 현재 작업 항목을 순서대로 보여주고 길게 누른 뒤 touch drag로 재정렬하며, 항목 우측 상단의 동작 선택창에서 복제와 삭제를 제공한다. 세 동작은 원본 메모에 영향을 주지 않는다.
- 내려받은 Material 3, Fluent 2, Primer Web과 Atlassian `.fig`의 menu, list와 action menu 표현을 다시 비교해 항목 동작 선택창은 브라우저 기본 외형에 맡기지 않고 개인 메모 디자인 시스템의 표면, 행, 상태와 간격을 사용하도록 구체화했다. `.fig`에서 확인할 수 없는 길게 누르기 인식과 취소 조건은 Pointer Events, Android와 Flutter 공식 자료로 따로 검증했다.
- 같은 변경에서 넓은 화면의 메모 속성 패널과 일괄 복사 패널은 마지막으로 활성화한 패널 하나만 표시하도록 확정했다.
- 후속 요구에서 한 번의 메모 헤더 클릭과 `Tab` 선택은 최근 활성 패널을 바꾸지 않고, 속성 패널을 여는 입력을 이동이 아닌 헤더 더블클릭 또는 선택된 메모의 선택 지점에서 실행한 `Enter`로 제한했다. 빈 캔버스 클릭, `Escape`와 `Command`의 선택 해제도 최근 활성 패널을 바꾸지 않는다.
- 사용자에게 보이는 화면 제목, 버튼과 상태 이름은 `누적 복사` 대신 `일괄 복사`를 사용한다.
- 표시 이름과 주소가 어긋나지 않도록 `/batch`와 `/batch-copy`를 비교했다. 처리 대상을 생략한 `/batch` 대신 주소를 `/batch-copy`로 정했다.
- 후속 결정에서 당시 사용하던 `/accumulator`를 호환 주소로 남기는 안을 폐기했다. 현재 일괄 복사 확인 및 저장 목록 관리 화면은 `/batch-copy`에서만 제공한다.
- 구현 필수 결정 재검토에서 최근 패널을 닫은 뒤 이전 패널을 자동 복원하면 사용자가 끝낸 과업이 다시 나타나는 문제가 확인됐다. 닫은 뒤에는 아무 패널도 표시하지 않고 각 패널의 자료만 유지하기로 했다.
- 같은 재검토에서 모바일 확인 작업은 저장 목록과 분리해 IndexedDB 초안으로 복원하고, 명시적인 취소만 초안을 지우기로 했다. drag 없는 재정렬은 동작 선택창의 `위치 변경`과 삽입 위치 선택으로 제공한다.
- 나란한 패널 전환값을 다시 검토해 목록과 보드가 바뀌는 `48rem`, 현재 패널 너비 `22rem`과 영역 사이 여유 `2rem`을 합친 `72rem`을 초기값으로 정했다. 이 값은 표준이 아니라 현재 화면 구성에 따른 제품값이며 확대 검증에서 다시 판단한다.
- HTML Popover와 WAI menu 패턴을 비교해 항목 동작 선택창은 `popover="auto"` 안의 일반 네이티브 버튼 묶음으로 정했다. 방향키 합성 위젯이 필요하지 않은 세 동작에 `menu` 역할만 붙이지 않고 외부 접근성 부품도 추가하지 않는다.
- 전체 복사 알림의 수명도 재검토했다. 7초 뒤 사라지는 Fluent 2의 동작 없는 toast와 시간 제한 정보를 다른 곳에서도 확인할 수 있어야 한다는 WCAG 조건을 비교했다. 복사 성공 여부를 애플리케이션 안의 다른 화면에서 다시 확인할 수 없으므로 자동 만료 없이 한 알림을 유지하고, 다음 복사 시도가 같은 영역을 갱신하도록 정했다.
- 2026년 9월 3일 데스크톱 사용 검토에서는 모든 toast를 3초 뒤 닫도록 요구가 바뀌었다. 이전의 자동 만료 없는 전체 복사 알림은 이 요구로 대체하며, 새 알림이 오면 기존 알림의 표시 시간을 다시 시작한다.
- 같은 검토에서 넓은 패널의 항목 동작 선택창과 `위치 변경`을 제거했다. 패널 항목은 우측 상단의 붉은 삭제 버튼으로 직접 제거하고, drag 중에는 다른 항목 전체를 현재 놓기 대상으로 표시한다. 패널 안에 놓은 항목은 삭제하지 않고 패널 전체의 외곽을 벗어난 곳에 놓았을 때만 삭제한다.
- 후속 요구에서 모든 toast의 수명을 3초에서 5초로 늘렸다. Radix의 기본 5000ms와 일치하지만 삭제 취소 동작이 사라진 뒤 같은 기능을 실행할 곳이 없다는 WCAG 위험은 해소되지 않았으므로 별도 재검토 조건으로 남긴다.
- 같은 요구에서 넓은 패널 항목을 클릭해 하나만 선택하고, 선택된 항목 본문의 위쪽 및 아래쪽 방향키로 한 자리씩 재정렬하도록 확정했다. 메모와 패널 항목 선택이 함께 있으면 상위 임시 조작이 없는 한 번의 `Escape`로 둘 다 해제한다.

## 승인된 결정과 이유

- `48rem` 이상의 메모 화면에서는 항목 수를 함께 보여주는 `일괄 복사` 버튼을 우측 상단에 고정해 같은 화면의 패널을 열고 닫는다. 버튼은 열림 상태와 제어하는 패널을 보조 기술에 전달하며 별도 제목 또는 작업 행을 만들지 않는다.
- 패널에는 `일괄 복사` 제목과 닫기 동작, 선택 항목 목록과 전체 복사 동작만 둔다. 실행 취소, 다시 실행과 합친 전체 텍스트 미리보기는 표시하지 않는다.
- 패널 머리 영역의 계산 높이는 변경 전 `63 CSS px`에서 약 `38 CSS px`로 줄인다. 제목과 닫기 동작의 접근 가능한 이름 및 pointer 목표 크기를 유지하면서 장식 여백을 줄인다.
- 전체 복사는 현재 배열 순서와 현재 구분자로 내부에서 만든 문자열 전체를 Clipboard에 쓴다. 성공 또는 원인별 실패 알림은 패널 내부가 아니라 전역 상단 탐색 아래, 열려 있는 일괄 복사 패널의 왼쪽에 남는 메모 작업 영역 우측 상단에 고정한다.
- 전체 복사 알림은 나타난 뒤 5초가 지나면 사라지고 포커스를 가져가지 않는다. 새 복사 결과가 오면 기존 알림을 교체하고 5초를 다시 센다. 성공은 `role="status"`에 해당하는 정중한 상태로, 실패는 원인과 다시 시도 또는 설정 확인 동작을 가진 중요한 상태로 전달한다.
- 전체 복사는 일괄 복사 항목, 순서와 제거 이력을 바꾸지 않는다. 개별 복사나 항목 추가도 아니므로 두 사용 횟수 가운데 어느 것도 늘리지 않는다.
- 메모 작업 영역의 inline size가 `72rem` 이상이면 너비 `22rem`의 패널을 메모 영역 옆에 배치한다. `48rem` 보드 기준에 패널 너비와 두 영역의 여유 `2rem`을 더한 초기 제품값이며, `72rem` 직전과 직후 및 확대 상태에서 실제 한국어 콘텐츠로 검증한다.
- 나란한 패널은 상단 탐색 아래부터 보이는 화면 하단까지 이어지는 오른쪽 영역을 사용한다. 패널이 닫히면 캔버스가 전체 너비를 사용하고, 패널이 열리면 캔버스가 남은 너비를 사용한다.
- 작업 영역이 `48rem` 이상 `72rem` 미만이면 같은 메모 route 위의 모달 패널로 전환한다. 이 범위에서는 별도 페이지로 이동하거나 URL을 바꾸지 않는다.
- inline 표현은 메모와 패널을 동시에 조작할 수 있다. modal 표현은 바깥 메모 영역을 조작할 수 없게 하고, 열 때 패널 제목 또는 첫 조작으로 포커스를 옮긴다. 메모 또는 일괄 복사 항목 선택이 남아 있으면 첫 `Escape`는 두 선택만 해제하고 모달을 유지한다. 선택이 없는 다음 `Escape` 또는 명시적인 닫기 버튼은 모달을 닫고 실행 버튼으로 포커스를 돌려보낸다.
- 메모와 패널을 나란히 표시할 공간이 충분하면 첫 항목 추가 성공 때 오른쪽 패널을 열어 새 항목을 바로 보여주되 현재 포커스를 옮기지 않는다. 이미 열린 패널에는 이후 항목을 갱신한다.
- inline 오른쪽 영역에는 메모 속성 패널과 일괄 복사 패널 가운데 마지막으로 활성화한 패널 하나만 표시한다. 이동이 아닌 메모 헤더 더블클릭 또는 선택된 메모의 선택 지점에서 실행한 `Enter`는 속성 패널을, `Command+Option+클릭`, 항목 추가와 일괄 복사 제어 실행은 일괄 복사 패널을 활성화한다. 한 번의 헤더 클릭, `Tab` 선택과 선택 해제는 최근 활성 패널을 바꾸지 않는다. 패널 전환은 선택한 메모, 속성 패널 대상, 속성 초안, 항목이나 제거 이력을 지우지 않는다.
- 최근 활성 오른쪽 패널을 닫으면 이전 패널을 자동 복원하지 않고 아무 패널도 표시하지 않는다. 다시 열 때 유지한 대상, 초안, 항목과 이력을 사용한다.
- `48rem` 이상 `72rem` 미만에서는 항목 추가 성공만으로 모달 패널을 열거나 현재 포커스를 옮기지 않는다. 항목 수를 갱신하고 사용자가 우측 상단 제어로 모달을 연다.
- 항목 추가 성공 때 `누적했습니다`와 같은 별도 알림은 표시하거나 읽어주지 않는다. 패널 항목, 일괄 복사 상태와 항목 수가 바뀌는 결과만 사용한다.
- 패널을 닫거나 inline 및 modal 표현 사이를 바꿔도 일괄 복사 자료와 제거 실행 취소 및 다시 실행 이력을 지우지 않는다. 새로고침만 실행 중 이력을 지운다.
- 항목 선택, 재정렬과 패널 밖 제거 규칙은 [일괄 복사 순서와 제거 복구 결정](accumulator-ordering-and-recovery.md)을 그대로 따른다. 넓은 패널에서는 항목 본문을 클릭, `Enter` 또는 `Space`로 선택하고 선택된 본문의 `ArrowUp` 및 `ArrowDown`이나 pointer drag로 순서를 바꾼다. 우측 상단의 붉은 삭제 아이콘으로 항목을 직접 제거하며 데스크톱 항목 동작 선택창과 `위치 변경`은 제공하지 않는다. 삭제 아이콘은 hover와 `focus-within`에서 보이고, hover가 없거나 coarse pointer인 환경에서는 계속 보인다. 패널 전체의 외곽을 벗어난 항목에만 제거 예정 상태를 표시하며, 다른 항목 위에 있는 동안에는 그 항목 전체를 현재 놓기 대상으로 표시한다.
- `48rem` 미만의 평상시 메모 목록 화면 헤더 오른쪽에는 일괄 복사 상태를 시작하는 아이콘 버튼을 둔다. 상태 안에서는 헤더 왼쪽 뒤로가기로 평상시 목록에 돌아가며, 짧게 누른 메모를 순서대로 모으고 화면 아래에 `초기화`와 클릭 횟수가 붙은 `다음`을 고정한다. `다음`은 Clipboard에 쓰지 않고 `/batch-copy` 확인 페이지로 이동한다.
- `48rem` 미만의 메모 화면에서는 저장된 일괄 복사 항목이 하나 이상일 때 현재 항목 수를 표시하는 고정 버튼을 우측 하단에 둔다. 이 버튼을 실행하면 `/batch-copy`로 이동하며, 페이지를 전역 탐색 항목에 추가하지 않는다.
- 일괄 복사 상태의 `다음`으로 연 `/batch-copy`는 이번 작업의 원문 스냅샷을 현재 결합 순서의 세로 목록으로 제공한다. 각 항목은 일반 터치가 아니라 길게 누른 뒤에만 touch drag로 재정렬할 수 있다.
- 길게 누르기 대기 중에는 짧은 터치와 같은 기본 상태를 유지하고, drag가 활성화되면 항목이 들린 상태임을 색 이외의 변화로 보여준다. 이동 중에는 현재 삽입 위치를 선 또는 같은 의미의 표시로 보여주며, `pointercancel`이나 유효하지 않은 놓기에서는 원래 순서와 시각 상태로 복원한다. 항목 우측 상단의 동작 아이콘에서는 길게 누르기 재정렬을 시작하지 않는다.
- 확인 항목 우측 상단의 아이콘 버튼은 버튼 가까이에 해당 항목의 `위치 변경`, `복제`와 `삭제`를 제공하는 작은 동작 선택창을 연다. 이 선택창은 개인 메모 디자인 시스템의 실행 버튼에 연결된 표면과 조밀한 세로 행을 사용하며, 각 행의 보이는 텍스트, 키보드 포커스 및 pressed 상태를 제공하고 `삭제`를 다른 동작과 시각적으로 구분한다. 브라우저 기본 popover 외형만으로 완료하지 않는다. 재정렬, 복제와 삭제는 작업 사본만 바꾸고 원본 메모, 메모 revision과 사용 횟수를 바꾸지 않는다.
- 동작 선택창은 `popover="auto"`와 이름 있는 `role="group"` 안의 네이티브 버튼을 사용한다. 열면 첫 동작으로 포커스를 옮기고 실행, `Escape` 또는 light dismiss로 닫으면 해당 항목의 실행 버튼으로 돌려준다. 일반 `Tab` 순서를 사용하며 `menu` 및 `menuitem` 역할이나 외부 접근성 부품은 현재 범위에 추가하지 않는다.
- 우측 하단 저장 항목 수 제어로 연 `/batch-copy`는 저장된 목록을 관리한다. `다음`으로 연 모바일 확인 작업은 이 목록을 추가하거나 교체하지 않는 별도 IndexedDB 초안이다.
- `다음`으로 연 `/batch-copy` 하단에는 `취소`와 `일괄 복사하기` 버튼을 고정한다. `취소`는 Clipboard와 저장된 목록을 바꾸지 않고 이번 작업 초안을 지운 뒤 메모 화면으로 돌아간다. 브라우저 뒤로가기는 편집한 항목과 순서를 보존한 채 수집 단계로 돌아간다. `일괄 복사하기`는 결합된 전체 텍스트를 Clipboard에 쓰고 결과를 알리되 현재 확인 페이지와 작업 초안을 유지한다.
- 우측 하단 항목 수 제어로 연 저장 목록 관리 화면의 `취소`는 Clipboard와 저장된 목록을 바꾸지 않고 메모 화면으로 돌아간다.
- 작은 화면에서 `/batch-copy`를 연 뒤 작업 영역이 넓어져도 사용 중인 페이지를 강제로 닫지 않는다. 사용자가 메모 화면으로 돌아가면 이후에는 현재 inline size에 맞는 우측 패널 또는 모달 표현을 사용한다.
- 나란한 패널, 모달 패널과 저장 항목 관리로 연 모바일 페이지는 같은 IndexedDB 일괄 복사 자료와 애플리케이션 실행 중 제거 이력을 사용한다. `다음`으로 연 확인 페이지는 이 자료와 분리된 IndexedDB 작업 초안을 사용하고 명시적 취소 전의 route 이동과 새로고침에서 복원한다.

[Fluent 2 Drawer 지침](https://fluent2.microsoft.design/components/web/react/core/drawer/usage)은 주 콘텐츠와 보조 내용을 함께 조작할 필요가 있을 때 inline drawer를 나란히 두고, 공간이 부족한 overlay drawer는 가리는 영역과 modality를 분명히 하라고 안내한다. [Material 3 canonical layout](https://m3.material.io/foundations/layout/canonical-examples/overview)은 primary pane과 supporting pane을 나란히 두는 구성을 설명하고, 작은 화면에서는 보조 영역을 겹쳐 표시하는 적응 방식을 제시한다. [WAI-ARIA 모달 dialog 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)은 모달 안의 포커스 순환, `Escape`, 명시적인 닫기 버튼과 실행한 요소로의 포커스 복귀를 설명한다.

[Fluent 2 Toast 지침](https://fluent2.microsoft.design/components/web/react/core/toast/usage)은 알림을 주 콘텐츠를 가리지 않는 일관된 우측 상단 또는 우측 하단에 두라고 안내한다. [Carbon notification pattern](https://carbondesignsystem.com/patterns/notification-pattern/)은 작업에서 생긴 알림을 관련 화면 영역에 두고, 짧은 toast를 보통 페이지 우측 상단에 고정하는 사례를 보여준다. [WAI-ARIA Alert 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/alert/)은 중요한 실패 알림이 포커스를 옮기지 않아야 하고 너무 빨리 사라지지 않아야 한다고 설명한다.

[WCAG 2.2 Reflow 설명](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)은 확대 및 작은 화면에서 기능 손실 없이 한 방향으로 읽을 수 있는 재배치를 요구한다. [Android의 Floating Action Button 지침](https://developer.android.com/develop/ui/compose/components/fab)은 화면 우측 하단의 고정 버튼을 하나의 주요 동작에 사용하는 방식을, [Badge 지침](https://developer.android.com/develop/ui/compose/components/badges)은 사용자 동작에 따라 바뀌는 항목 수를 버튼과 함께 표시하는 방식을 설명한다. 현재 구현은 이 라이브러리나 기본 테마를 가져오지 않고 위치와 정보 역할만 자체 디자인 시스템으로 구현한다.

[메모 Tab 순서, 항목 동작 팝오버와 모바일 지연 재정렬 조사](../references/tab-order-popover-and-mobile-reorder-research.md)는 이전에 내려받은 여러 `.fig`의 component surface와 상태를 교차검증하고, Popover API, WAI menu pattern, Pointer Events와 모바일 플랫폼 문서에서 동작 조건을 확인한 결과를 기록한다. `.fig`는 팝오버의 표면과 행, drag 활성 및 삽입 위치 같은 시각 상태를 판단하는 자료로만 사용하고 길게 누르기 시간이나 pointer 취소 동작의 근거로 사용하지 않는다.

[데스크톱 입력과 피드백 복원력 조사](../references/desktop-input-and-feedback-resilience-research.md)는 5초 toast, 제한된 motion, 항목 선택과 방향키 재정렬, 직접 삭제 버튼, 패널 전체를 기준으로 한 외부 놓기와 현재 놓기 대상 피드백을 교차검증한다. 삭제 취소를 토스트에서만 5초 동안 제공하는 방식은 공식 접근성 사례의 대체 실행 조건을 충족하지 않으므로 현재 요구를 적용하되 실제 사용 검증과 재결정 대상으로 남긴다.

## 예상 결과와 계획 영향

공통 화면 구조 작업은 다섯 주요 route, 모바일 메모 상세 route와 `/batch-copy`, 상단 탐색 아래를 채우는 메모 캔버스, 넓은 화면의 우측 상단 제어, 약 `38 CSS px` 높이의 패널 머리, 작은 화면의 일괄 복사 상태와 우측 하단 항목 수 제어를 만든다. 항목 추가 작업은 성공 뒤 현재 표현에 맞는 항목 수만 갱신한다. `_pages/batch-copy`는 `다음`으로 받은 확인 작업 초안과 저장 항목 수 제어로 연 목록을 구분하고, 확인 작업의 재정렬, 복제 및 삭제가 원본 메모 repository 또는 저장 목록을 호출하지 않게 한다.

일괄 복사 목록 구현에는 항목 선택, 방향키 한 자리 재정렬, 전체 복사, 5초 알림, 직접 삭제와 패널 안 재정렬 및 패널 밖 제거 판정을 포함한다. 통합 검증에서는 전체 복사 결과가 사용 횟수를 바꾸지 않는지, 선택, 키보드 포커스, 드래그 중 놓기 대상과 삭제 예정 상태가 서로 구분되는지 확인한다.

## 다시 검토할 조건

- 실제 콘텐츠 검증에서 inline 패널이 메모 보드 또는 목록의 필수 조작 영역을 계속 가리는 경우
- `72rem` 직전과 직후 또는 200% 및 400% 확대에서 `22rem` 패널과 남은 보드가 각각 필요한 내용을 전달하지 못하는 경우
- 누적 편집이 단일 보조 패널에서 감당할 수 없는 여러 단계의 독립 과업으로 늘어나는 경우
- modal 패널이나 모바일 확인 페이지의 drag가 목록 순서와 취소 결과를 안정적으로 전달하지 못하는 경우
- 모바일 확인 항목의 동작 선택창이 버튼과의 연결, 키보드 포커스, pressed 상태 또는 삭제 구분을 잃는 경우
- 약 `38 CSS px` 머리 영역에서 닫기 동작의 이름, 포커스 또는 pointer 목표가 손상되는 경우
- 5초 복사 알림이 열려 있는 패널, 상단 탐색 또는 메모의 주요 내용을 가리거나 결과를 확인하기 전에 사라지는 경우
- 방향키 재정렬이 일반 목록 탐색으로 오해되거나 이동 뒤 선택, 포커스 또는 위치 안내가 끊기는 경우
- 작은 화면에서 우측 하단 항목 수 제어가 메모 조작이나 시스템 안전 영역을 반복해서 가리는 경우
