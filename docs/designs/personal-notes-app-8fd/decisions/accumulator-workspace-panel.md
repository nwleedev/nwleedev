# 누적 작업 패널과 모바일 관리 페이지 결정

메모 작업 영역의 inline size가 `48rem` 이상이면 누적 항목의 순서 편집, 제거 복구와 결합 결과 확인을 메모 화면의 오른쪽 보조 패널 또는 같은 route의 모달로 제공한다. `48rem` 미만의 목록 표현에서는 우측 하단의 항목 수 제어로 `/accumulator` 관리 페이지에 이동한다. 이 route는 전역 탐색에 추가하지 않는다.

## 결정 질문과 요구 결과

[누적 기능의 위치 요구사항](../requirements.md#반드시-지킬-조건)은 넓은 화면에서는 메모를 고르는 문맥을 떠나지 않고 누적 결과를 확인하고 편집하며, 모바일 누적 표현에서는 목록에 집중하는 별도 페이지를 제공하도록 요구한다. 각 화면에서 누적 목록으로 이동하는 방식, 자료와 이력 수명, 키보드 포커스 및 하단 동작의 결과를 정해야 했다.

## 검토한 선택지

- 독립 페이지는 누적 목록에 넓은 공간을 제공하지만 메모를 추가할 때마다 원본 메모와 결합 결과 사이를 오가게 하고, 누적 상태를 최상위 탐색 항목으로 만든다.
- 메모 위에 항상 떠 있는 패널은 누적 결과를 즉시 보여주지만 공간형 보드와 작은 화면의 메모 목록을 계속 가린다.
- 충분한 공간에서는 나란한 패널을 사용하고 공간이 부족하면 같은 화면의 모달 패널로 전환하면, 메모와 결과를 함께 볼 수 있는 환경을 활용하면서 작은 화면에서는 한 과업에 집중할 수 있다.
- 작은 popover는 순서가 있는 목록, 결합 미리보기, 실행 취소와 다시 실행을 다루기에 공간과 읽기 구조가 부족하다.
- `48rem` 미만에서도 모달을 사용하면 메모 목록 위에 목록을 다시 겹치고 브라우저 뒤로 가기와 페이지 하단 동작을 활용하기 어렵다.
- 작은 화면에서만 별도 관리 페이지를 사용하면 메모 선택 화면과 순서 편집 화면을 한 번에 하나씩 보여주면서 넓은 화면의 나란한 패널을 유지할 수 있다.

## 결정 이력

- 초기 화면 구조는 누적 텍스트를 독립 route와 Pages slice로 두었다.
- 요구사항 재검토에서 누적은 메모 선택과 바로 이어지는 부가 작업이므로 메모 화면 안에서 제공해야 한다는 방향이 추가됐다.
- Fluent 2의 inline drawer와 Material 3의 supporting pane을 비교해, 메모와 누적 결과를 동시에 참조할 수 있을 때는 나란한 패널이 적합하다고 판단했다.
- 작은 작업 영역에서는 메모 목록을 더 줄이지 않고 WAI-ARIA 모달 dialog의 포커스 및 닫기 규칙을 따르는 같은 route의 모달 패널로 전환하기로 했다.
- 구현 전 검토에서 결합된 전체 텍스트의 복사 동작은 목록에 있었지만, 복사할 문자열과 실패 처리 및 사용 빈도 영향이 작업 계획에 배정되지 않은 공백을 확인했다.
- 현재 결정은 누적 전용 route와 탐색 항목을 제거하고, 메모 화면의 하나의 누적 작업 패널을 inline 및 modal 표현으로 바꾸는 것이다.
- 화면 검토 뒤 결정 책임자는 별도 `메모` 제목과 상단 작업 행을 제거하고 캔버스가 상단 탐색 아래의 나머지 화면을 채우도록 요청했다. `누적 텍스트` 제어는 화면 우측 상단에 유지하고, 넓은 화면에서 누적을 시작하면 결과가 우측 패널에 나타나야 한다.
- 이후 모바일 누적 요구사항은 작은 화면에서 누적 항목을 별도 페이지의 목록으로 관리하고 메모 화면 우측 하단의 항목 수 제어로 이동하도록 변경했다. 이 변경은 `48rem` 이상에서 승인된 우측 상단 제어, 나란한 패널과 모달 표현을 유지하고 `48rem` 미만에만 적용한다.

## 승인된 결정과 이유

- `48rem` 이상의 메모 화면에서는 누적 항목 수를 함께 보여주는 `누적 텍스트` 버튼을 우측 상단에 고정해 같은 화면의 패널을 열고 닫는다. 버튼은 열림 상태와 제어하는 패널을 보조 기술에 전달하며 별도 제목 또는 작업 행을 만들지 않는다.
- 패널에는 제목과 닫기 동작, 누적 항목 목록, 실행 취소 및 다시 실행, 결합된 전체 텍스트 미리보기와 전체 복사 동작을 둔다.
- 전체 복사는 현재 배열 순서와 현재 구분자로 만든 미리보기 문자열 전체를 Clipboard에 쓴다. 성공 여부를 사용자가 확인할 수 있게 알리고, 실패하면 다시 시도할 수 있는 다음 행동을 안내한다.
- 전체 복사는 누적 항목, 순서와 제거 이력을 바꾸지 않는다. 일반 메모 복사나 누적 추가도 아니므로 두 사용 횟수 가운데 어느 것도 늘리지 않는다.
- 메모 작업 영역이 메모 보드 또는 목록의 필요한 너비와 누적 패널의 읽을 수 있는 너비를 함께 제공하면 패널을 메모 영역 옆에 배치한다. 정확한 전환값은 U4에서 실제 한국어 콘텐츠, `48rem` 메모 표현 기준과 확대 상태를 함께 검증해 정한다.
- 나란한 패널은 상단 탐색 아래부터 보이는 화면 하단까지 이어지는 오른쪽 영역을 사용한다. 패널이 닫히면 캔버스가 전체 너비를 사용하고, 패널이 열리면 캔버스가 남은 너비를 사용한다.
- 작업 영역이 `48rem` 이상이지만 두 영역을 함께 표시할 공간이 부족하면 같은 메모 route 위의 모달 패널로 전환한다. 이 범위에서는 별도 페이지로 이동하거나 URL을 바꾸지 않는다.
- inline 표현은 메모와 패널을 동시에 조작할 수 있다. modal 표현은 바깥 메모 영역을 조작할 수 없게 하고, 열 때 패널 제목 또는 첫 조작으로 포커스를 옮기며, `Escape`와 명시적인 닫기 버튼으로 닫고 실행 버튼으로 포커스를 돌려보낸다.
- 메모와 패널을 나란히 표시할 공간이 충분하면 첫 누적 성공 때 오른쪽 패널을 열어 새 항목을 바로 보여주되 현재 포커스를 옮기지 않는다. 이미 열린 패널에는 이후 항목을 갱신한다.
- `48rem` 이상에서 나란한 표시 공간이 부족하면 누적 성공만으로 모달 패널을 열거나 현재 포커스를 옮기지 않는다. 항목 수와 상태 알림을 갱신하고 사용자가 우측 상단 제어로 모달을 연다.
- 패널을 닫거나 inline 및 modal 표현 사이를 바꿔도 누적 자료와 제거 실행 취소 및 다시 실행 이력을 지우지 않는다. 새로고침만 실행 중 이력을 지운다.
- 항목 재정렬과 목록 밖 제거 규칙은 [누적 순서와 제거 복구 결정](accumulator-ordering-and-recovery.md)을 그대로 따른다. modal 표현에서도 목록 경계를 벗어난 항목에 제거 예정 상태를 표시하고 드래그 없는 대안을 유지한다.
- `48rem` 미만의 메모 화면에서는 누적 항목이 하나 이상일 때 현재 항목 수를 표시하는 고정 버튼을 우측 하단에 둔다. 이 버튼을 실행하면 `/accumulator`로 이동하며, 페이지를 전역 탐색 항목에 추가하지 않는다.
- `/accumulator`는 현재 누적 순서의 세로 목록을 제공한다. 각 항목 왼쪽의 네이티브 버튼을 재정렬 손잡이로 사용하고, 같은 항목에 위로 이동, 아래로 이동과 제거 버튼을 제공한다.
- `/accumulator` 하단에는 `취소`와 `복사` 버튼을 고정한다. `취소`는 Clipboard를 바꾸지 않고 메모 화면으로 돌아가며 현재 누적 항목, 순서와 제거 이력을 유지한다. `복사`는 결합된 전체 텍스트를 Clipboard에 쓰고 결과를 알리되 현재 페이지와 누적 상태를 유지한다.
- 작은 화면에서 `/accumulator`를 연 뒤 작업 영역이 넓어져도 사용 중인 페이지를 강제로 닫지 않는다. 사용자가 메모 화면으로 돌아가면 이후에는 현재 inline size에 맞는 우측 패널 또는 모달 표현을 사용한다.
- 나란한 패널, 모달 패널과 모바일 관리 페이지는 같은 IndexedDB 누적 자료와 애플리케이션 실행 중 제거 이력을 사용한다. route 이동으로 자료나 이력을 초기화하지 않는다.

[Fluent 2 Drawer 지침](https://fluent2.microsoft.design/components/web/react/core/drawer/usage)은 주 콘텐츠와 보조 내용을 함께 조작할 필요가 있을 때 inline drawer를 나란히 두고, 공간이 부족한 overlay drawer는 가리는 영역과 modality를 분명히 하라고 안내한다. [Material 3 canonical layout](https://m3.material.io/foundations/layout/canonical-examples/overview)은 primary pane과 supporting pane을 나란히 두는 구성을 설명하고, 작은 화면에서는 보조 영역을 겹쳐 표시하는 적응 방식을 제시한다. [WAI-ARIA 모달 dialog 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)은 모달 안의 포커스 순환, `Escape`, 명시적인 닫기 버튼과 실행한 요소로의 포커스 복귀를 설명한다. [WCAG 2.2 Reflow 설명](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)은 확대 및 작은 화면에서 기능 손실 없이 한 방향으로 읽을 수 있는 재배치를 요구한다. [Android의 Floating Action Button 지침](https://developer.android.com/develop/ui/compose/components/fab)은 화면 우측 하단의 고정 버튼을 하나의 주요 동작에 사용하는 방식을, [Badge 지침](https://developer.android.com/develop/ui/compose/components/badges)은 사용자 동작에 따라 바뀌는 항목 수를 버튼과 함께 표시하는 방식을 설명한다. 현재 구현은 해당 라이브러리나 기본 테마를 가져오지 않고 이 위치와 정보 역할만 자체 디자인 시스템으로 구현한다.

## 예상 결과와 계획 영향

U4는 다섯 주요 route와 `/accumulator`, 상단 탐색 아래를 채우는 메모 캔버스, 넓은 화면의 우측 상단 제어 및 작은 화면의 우측 하단 항목 수 제어를 만든다. U6은 누적 성공 뒤 현재 표현에 맞는 항목 수와 상태를 갱신한다. U7은 `_pages/notes`의 패널과 `_pages/accumulator`의 관리 페이지가 같은 누적 자료와 제거 이력을 사용하게 한다. U11은 세 표현의 자료, 이력과 전체 복사 결과가 같은지 확인한다.

누적 목록 구현에는 전체 복사를 포함하고, 통합 검증에서는 전체 복사 결과가 사용 횟수를 바꾸지 않는지 확인한다.

## 다시 검토할 조건

- 실제 콘텐츠 검증에서 inline 패널이 메모 보드 또는 목록의 필수 조작 영역을 계속 가리는 경우
- 누적 편집이 단일 보조 패널에서 감당할 수 없는 여러 단계의 독립 과업으로 늘어나는 경우
- modal 패널이나 모바일 관리 페이지의 드래그 제거가 목록 경계를 안정적으로 전달하지 못하는 경우
- 작은 화면에서 우측 하단 항목 수 제어가 메모 조작이나 시스템 안전 영역을 반복해서 가리는 경우
- 포트폴리오 연결 백로그에서 호스트가 메모 route의 사용 가능한 inline size를 예측할 수 없는 경우
