# 공간형 보드와 작은 화면 목록 결정

메모 작업 영역이 `48rem` 이상이면 공간형 보드와 마지막으로 활성화한 오른쪽 패널을, 그보다 작으면 같은 메모의 생성 순서 목록, 메모 상세 화면과 모바일 일괄 복사 확인 화면을 제공한다. 전환은 실제 컨테이너 크기로 판단하고 기기 종류를 사용하지 않는다. 넓은 화면에서는 메모가 아닌 빈 캔버스 어느 지점에서나 시작한 drag가 같은 캔버스 시점 이동을 만들어야 한다.

## 결정 질문과 요구 결과

[요구사항의 공간형 메모와 작은 화면 결과](../requirements.md#의도한-결과)를 충족하려면 보드 탐색, 목록 전환 기준, 배치 복원, 목록 메모 높이와 상세 편집 흐름을 정해야 했다. 후속 모바일 요구에서는 짧은 누르기 상세 이동, 길게 누르기 개별 복사와 일괄 복사 상태를 같은 전환 기준 아래에 배치해야 했다.

## 검토한 선택지

- 모든 너비에서 공간형 보드를 유지하면 메모 영역이 좁을 때 읽기와 기본 조작까지 이차원 탐색에 의존한다.
- 모바일 User-Agent로 전환하면 화면 분할, 확대와 큰 글자 설정을 반영하지 못한다.
- 실제 메모 컨테이너 너비를 기준으로 전환하면 독립 실행 화면의 탐색 폭과 사용자 확대를 함께 반영할 수 있다.
- 작은 화면 목록을 직접 편집 가능한 카드로 만들면 짧은 누르기 상세 이동, 길게 누르기 개별 복사, 텍스트 선택과 세로 스크롤이 같은 표면에서 경쟁한다.
- 제한된 높이 미리보기와 상세 편집을 분리하면 목록 밀도를 유지하고 전체 원문은 별도 화면에서 편집할 수 있다.

## 결정 이력

- 초기 권장안은 내용에 따라 확장되는 보드와 화면 표시 영역 `768px` 미만의 목록이었다.
- 재검토에서는 `768px` 자체에 보편적인 근거가 없고 전체 표시 영역보다 실제 메모 영역의 폭이 동작 가능성을 더 잘 설명한다는 점이 확인됐다.
- 현재 결정은 컨테이너의 `48rem`을 초기 전환값으로 한 곳에서 관리하고 생성 순서와 geometry 보존 규칙을 함께 적용하는 것이다.
- 첫 모바일 일괄 복사 요구에서는 `48rem` 미만의 목록에서 길게 누르기 선택, 우측 하단 항목 수 제어와 별도 관리 화면을 사용하기로 했다.
- 화면 사용 검토에서 일부 빈 영역만 캔버스 시점을 이동하는 문제가 확인돼 시점 이동 책임을 보이는 캔버스 전체로 옮겼다.
- 메모의 이동 및 크기 버튼과 메모 표면의 숫자 geometry UI를 제거하고 가장자리와 꼭짓점에서 직접 크기를 바꾸기로 했다. 후속 요구에서 짧은 메모 헤더가 이동 시작 영역을 맡아 이동 입력의 미결정 상태를 해소했다.
- 모바일 요구 변경으로 목록의 상시 편집과 길게 누르기 일괄 복사 항목 추가를 폐기했다. 목록은 제한된 높이 미리보기, 일반 터치는 상세 화면, 길게 누르기는 개별 복사로 바뀌고 일괄 복사는 목록 화면 헤더 아이콘으로 시작하는 별도 상태가 맡는다.
- 이전 요구에서 넓은 화면의 메모는 `Tab`과 헤더 click으로 선택할 수 있고, 오른쪽 속성 패널에서 X, Y, 너비와 높이를 바꾸도록 변경됐다. 이는 메모 표면의 수치 UI를 되돌리지 않으며 가장자리와 꼭짓점의 직접 크기 조절도 유지한다.
- 작은 화면의 상태 이름은 `일괄 복사 상태`로 정정하고, 하단 `일괄 복사하기`와 `취소`를 헤더 뒤로가기 및 하단 `초기화`와 `다음`으로 바꿨다.
- 후속 요구에서 `다음`은 `/accumulator` 일괄 복사 확인 화면으로 이동하고, 확인 항목은 길게 누른 뒤 touch drag로 재정렬하며 항목별 동작 선택창에서 복제와 삭제를 제공하도록 확정했다.
- 넓은 화면의 속성 패널과 일괄 복사 패널은 마지막으로 활성화한 패널 하나만 표시하도록 확정했다.
- 이전 요구에서 한 번의 헤더 click은 선택 테두리만 새로 표시하고, 이동이 아닌 더블클릭이 속성 패널을 열도록 분리했다. 헤더 drag 중에는 패널을 전환해 캔버스 크기를 바꾸지 않으며, `Command`를 누르는 동안에는 메모 크기를 유지한 채 헤더를 숨긴다.

## 승인된 결정과 이유

### `48rem` 이상의 공간형 화면

- 공간형 보드, 시점 이동, 확대와 모든 메모 맞춤을 제공한다.
- 주 pointer가 메모와 다른 조작 요소가 아닌 빈 캔버스에서 눌린 뒤 이동하면 보이는 캔버스 시점을 같은 거리와 방향으로 바꾼다. 시작한 빈 지점이 보드 요소의 현재 경계 안인지에 따라 동작이 달라지지 않아야 한다.
- 각 메모의 짧은 헤더에서 아이콘 버튼이 아닌 영역을 drag하면 메모 위치를 바꾼다. 헤더 클릭은 복사 또는 일괄 복사 항목 추가를 실행하지 않는다.
- 이동이 아닌 한 번의 헤더 click 또는 각 메모의 양의 `tabindex`를 따르는 Tab으로 메모를 선택하고 얇은 붉은 테두리만 새로 표시한다. 이동이 아닌 헤더 더블클릭 또는 선택된 메모의 선택 지점에서 실행한 `Enter`가 오른쪽 속성 패널을 열며, 패널에서 X, Y, 너비와 높이를 바꾼다. 빈 캔버스 click, `Escape`와 `Command`는 메모 선택만 해제한다. 탐색 순서는 시각적 겹침 순서와 독립적이고 선택 테두리와 현재 키보드 포커스는 서로 구분한다.
- 오른쪽에는 속성 패널과 일괄 복사 패널 가운데 마지막으로 활성화한 패널 하나만 표시한다. 패널 전환으로 숨겨진 패널의 자료를 지우지 않는다.
- 헤더 drag 중에는 선택과 오른쪽 패널을 바꾸지 않고 캔버스의 계산 크기를 애플리케이션 동작으로 유지한다. `Command`를 누르는 동안에는 헤더 행의 높이와 메모 외곽 크기를 유지한 채 헤더와 아이콘을 숨기고 조작을 막는다.
- 메모 표면에서 크기 변경을 직접 시작할 수 있는 곳은 네 가장자리와 네 꼭짓점이다. 숫자 입력, 단계 조절과 텍스트 크기 버튼은 메모 표면에 표시하지 않고 오른쪽 속성 패널에서 대상 메모의 수치 geometry를 제공한다.
- 메모 본문은 항상 편집 가능한 `textarea`이며 내용이 정한 크기를 넘으면 메모 안에서 스크롤한다.

### `48rem` 미만의 목록과 상세 화면

- 메모를 생성 순서의 세로 목록으로 표시한다.
- 각 메모는 같은 의미 기반 최대 세로 길이를 사용하는 읽기 미리보기다. 넘치는 원문을 카드 안에서 별도 스크롤하지 않고, 전체 내용은 상세 화면에서 확인한다.
- 평소 짧은 누르기는 메모 상세 화면으로 이동하고 길게 누르기는 원문 전체를 개별 복사한다.
- 상세 화면에서만 원문 전체를 편집하고 명시적으로 저장한다.
- 평상시 목록 화면 헤더 오른쪽의 아이콘 버튼으로 일괄 복사 상태를 시작한다. 이 상태에서는 짧게 누른 메모를 조작 순서대로 이번 작업에 추가하고 상세 화면으로 이동하지 않는다.
- 일괄 복사 상태에서는 헤더 왼쪽 뒤로가기로 상태를 끝내고 화면 아래의 `초기화`와 클릭 횟수가 붙은 `다음`을 사용한다.
- `다음`은 현재 원문 스냅샷을 순서대로 보여주는 `/accumulator` 확인 화면으로 이동한다. 확인 항목은 길게 누른 뒤 touch drag로 재정렬하고 항목 우측 상단 동작 선택창에서 복제하거나 삭제할 수 있다.
- 저장된 일괄 복사 항목이 있으면 우측 하단 항목 수 제어로 `/accumulator` 관리 화면에 이동한다.

### 표현 전환

- 목록 전환은 저장된 geometry와 겹침 순서를 바꾸지 않으며 컨테이너가 다시 넓어지면 기존 공간 배치를 복원한다.
- User-Agent나 모바일 기기 판별은 사용하지 않는다. coarse pointer 정보는 실행 영역 크기와 hover 대체 표현에만 사용할 수 있다.
- 목록 카드의 최대 높이와 일괄 복사 상태는 IndexedDB의 메모 geometry를 바꾸지 않는다.

[Figma Design 파일 안내](https://help.figma.com/hc/en-us/articles/15297425105303-Explore-design-files)는 `Space+드래그`, 두 손가락 이동과 Hand tool을 캔버스 시점 이동에 사용하며 객체 변경과 탐색을 구분한다. 현재 요구는 빈 캔버스 주 pointer drag도 시점 이동으로 사용하므로 메모와 조작 요소에서 시작한 event만 제외한다. [WCAG Reflow 설명](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)과 [CSS Containment Level 3](https://www.w3.org/TR/css-contain-3/)은 실제 공간에 맞춘 표현 전환 근거를 제공한다. 목록과 모바일 조작의 세부 근거는 [메모 조작과 모바일 일괄 복사 조사](../references/note-interaction-and-mobile-batch-copy-research.md)를 따른다.

## 예상 결과와 계획 영향

보드와 목록은 같은 메모 자료를 서로 다르게 보여준다. 넓은 화면은 상시 본문 편집, 한 번 클릭 또는 Tab 선택, 헤더 더블클릭과 선택 지점의 `Enter` 속성 패널 활성화, 빈 캔버스 click, `Escape` 및 `Command` 선택 해제, 헤더 이동, edge resize와 최근 활성 오른쪽 패널을 제공한다. 작은 화면은 제한된 높이 목록, 메모 ID에 대응하는 상세 route, 명시적 저장, 일괄 복사 상태와 확인 route를 추가한다. 상세 route와 확인 route는 목록 표현에서만 일반 진입을 제공하더라도 직접 URL 접근과 필요한 실행 중 자료가 없는 경우를 처리해야 한다.

목록 전환, CSS 배치, 빈 캔버스 시점 이동, header drag, edge resize, 짧은 누르기와 길게 누르기는 TDD 대상이 아니며 실제 브라우저에서 확인한다. 생성 순서, 일괄 복사 추가 순서나 geometry 불변 조건을 순수 규칙으로 분리해야 할 때에만 그 규칙에 TDD를 적용한다.

## 다시 검토할 조건

- 200% 또는 400% 확대에서 헤더 아이콘이나 하단 작업 영역이 내용을 가리는 경우
- 최소 크기 메모 두 개를 `48rem` 영역에서 다룰 수 없는 경우
- `48rem` 이상의 터치 화면에서 보드 조작 실패가 반복되는 경우
- 캔버스 시점 이동이 메모의 본문 편집, 복사, 이동 또는 크기 조절과 함께 실행되는 경우
- 제한된 목록 높이 때문에 메모를 구분할 정보가 부족하거나 상세 화면 이동이 지나치게 잦아지는 경우
- 모바일 길게 누르기가 스크롤 또는 상세 이동과 반복해서 충돌하는 경우
- 독립 실행 화면의 탐색 구조가 바뀌어 실제 메모 컨테이너 폭이 크게 달라지는 경우
