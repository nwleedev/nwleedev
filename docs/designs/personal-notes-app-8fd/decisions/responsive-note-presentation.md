# 공간형 보드와 작은 화면 목록 결정

메모 작업 영역이 `48rem` 이상이면 확장형 공간 보드를, 그보다 작으면 같은 메모의 생성 순서 목록을 제공한다. 전환은 실제 컨테이너 크기로 판단하고 기기 종류를 사용하지 않는다.

## 결정 질문과 요구 결과

[요구사항의 공간형 메모와 작은 화면 결과](../requirements.md#의도한-결과)를 충족하려면 보드의 크기, 탐색 방식, 목록 전환 기준과 배치 복원 규칙을 정해야 했다.

## 검토한 선택지

- 고정 작업 페이지는 메모가 늘어날 때 사용자가 페이지 크기를 계속 관리해야 한다.
- 모든 너비에서 공간 보드를 유지하면 메모 영역이 `48rem`보다 작을 때 읽기와 기본 조작까지 이차원 탐색에 의존한다.
- 모바일 User-Agent로 전환하면 화면 분할, 확대와 큰 글자 설정을 반영하지 못한다.
- 실제 메모 컨테이너 너비를 기준으로 전환하면 독립 실행 화면의 탐색 폭과 사용자 확대를 함께 반영할 수 있다.

## 결정 이력

- 초기 권장안은 내용에 따라 확장되는 보드와 화면 표시 영역 `768px` 미만의 목록이었다.
- 재검토에서는 `768px` 자체에 보편적인 근거가 없고 전체 표시 영역보다 실제 메모 영역의 폭이 동작 가능성을 더 잘 설명한다는 점이 확인됐다.
- 현재 결정은 컨테이너의 `48rem`을 초기 전환값으로 한 곳에서 관리하고, 생성 순서와 geometry 보존 규칙을 함께 적용하는 것이다.

## 승인된 결정과 이유

- 넓은 화면에는 내용에 따라 확장되는 보드, 이동, 확대와 모든 메모 맞춤을 제공한다.
- 메모 이동은 본문과 분리된 손잡이에서 시작하고 크기는 선택 상태의 크기 조절부로 바꾼다.
- 선택한 메모의 위치와 크기를 숫자 및 단계 조절 UI에서도 바꿀 수 있게 해 드래그 없는 단일 포인터와 키보드 동작을 제공한다.
- 사용자가 정한 크기보다 내용이 길면 메모 안에서 스크롤한다.
- 메모 작업 컨테이너의 inline size가 `48rem` 미만이면 생성 순서 목록으로 전환한다.
- 목록 전환은 저장된 geometry를 바꾸지 않으며 컨테이너가 다시 넓어지면 기존 공간 배치를 복원한다.
- User-Agent나 모바일 기기 판별은 사용하지 않는다. coarse pointer 정보는 조작부 크기와 표시 방식에만 사용할 수 있다.

[WCAG Reflow 설명](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)은 메모 영역이 작아져도 정보와 동작을 유지해야 한다고 설명한다. [CSS Containment Level 3](https://www.w3.org/TR/css-contain-3/)의 container query는 구성요소가 실제로 받은 크기에 따라 표현을 바꾸는 수단을 정의한다.

## 예상 결과와 계획 영향

보드와 목록은 같은 메모 자료를 서로 다르게 보여준다. 목록 전환과 CSS 배치는 TDD 대상이 아니며, 전환 직전과 직후, 320 CSS px, 브라우저 확대, 화면 분할과 왕복 복원을 실제 브라우저에서 확인한다. 생성 순서와 geometry 불변 조건을 별도 순수 함수로 만들 필요가 생기면 그 함수에만 TDD를 적용한다.

## 다시 검토할 조건

- 200% 또는 400% 확대에서 조작 버튼이 가려지는 경우
- 최소 크기 메모 두 개를 `48rem` 영역에서 다룰 수 없는 경우
- `48rem` 이상의 터치 화면에서 보드 조작 실패가 반복되는 경우
- 독립 실행 화면의 탐색 구조가 바뀌어 실제 메모 컨테이너 폭이 크게 달라지는 경우
