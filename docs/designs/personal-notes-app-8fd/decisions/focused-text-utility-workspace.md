# 텍스트 재사용 작업 화면 결정

개인 메모 애플리케이션은 자주 쓰는 텍스트를 기록하고, 찾아서 복사하며, 원하는 순서로 모아 재사용하는 작업 화면으로 디자인한다. 메모 본문이 가장 높은 시각 우선순위를 가지며, 좁은 화면 목록에서는 메모를 누르는 기본 동작으로 복사한다.

## 결정 질문과 요구 결과

[개인 메모 애플리케이션 요구사항](../requirements.md)은 자유 배치, 편집, 복사, 일괄 복사와 보조 기능을 유지하면서 화면마다 같은 시각 및 조작 규칙을 사용해야 한다. 이전의 목재 캔버스, 노란 메모, 짙은 탐색 영역과 상시 관리 버튼은 텍스트보다 장식을 먼저 드러내고 조밀한 작업을 방해하므로 새 기준으로 사용하지 않는다.

## 검토한 선택지

- 기존 Figma식 프레임과 밝은 목재 및 sticky note 표현을 다듬는 방법은 구현 변경이 적지만 장식과 관리 버튼이 본문 및 복사와 계속 경쟁한다.
- 외부 UI kit의 기본 테마로 교체하는 방법은 구성요소를 빨리 통일할 수 있지만 개인 메모의 텍스트 재사용 과업보다 kit의 외형과 명명법을 앞세운다.
- 자체 구성요소와 저장 기능을 유지하면서 역할 기반 토큰, 명시적인 이동 핸들, 항상 발견 가능한 복사와 상황별 관리 동작으로 재구축하면 기능을 줄이지 않고 시각 우선순위와 조작 충돌을 함께 바로잡을 수 있다.

## 승인된 결정과 이유

### 시각 방향

- 전체 방향은 `Focused Text Utility Workspace`다. Pretendard를 유지하고 메모 본문을 일반 UI label보다 높은 글자 위계로 둔다.
- 브랜드 accent는 `#EE5165`다. 현재 탐색 위치, 주요 동작, 선택, 포커스, 드래그 삽입 위치와 짧은 상태 확인에 제한해 사용한다.
- 화면 배경과 캔버스는 따뜻한 중립색, 메모와 입력은 흰색에 가까운 표면을 사용한다. 목재 무늬, 노란 메모, 장식용 grid, glassmorphism, glow와 넓은 gradient를 사용하지 않는다.
- 기본 메모와 고정 panel은 flat 깊이를 사용한다. 드래그 중인 대상은 raised, popover, toast와 dialog는 overlay 깊이를 사용한다.
- 간격은 4px 리듬을 기본으로 하고 2, 6, 10px은 반복되는 광학 보정에만 사용한다. 선, 카드와 둥근 모서리를 정보 묶음의 기본 수단으로 삼지 않는다.

### 메모와 복사

- 넓은 화면의 메모는 왼쪽 위 이동 핸들, 오른쪽 위 복사와 더보기 동작, 항상 편집 가능한 본문으로 구성한다. 본문, 텍스트 선택과 이동 입력을 같은 실행 영역에 겹치지 않는다.
- 더보기는 속성, 맨 앞으로, 맨 뒤로와 삭제를 제공한다. 이 관리 동작을 메모마다 항상 나열하지 않는다.
- 좁은 화면의 메모 미리보기는 제목, note icon, 별도 헤더와 `내용 더 있음` badge를 만들지 않는다. 본문을 제한된 줄로 자르고 수정 아이콘 버튼을 메모 전체의 복사 동작과 구분한다.
- 좁은 화면에서 평상시 메모를 짧게 누르면 즉시 복사하고, 수정 아이콘 버튼은 상세 이동만 실행한다. 길게 누르기도 복사하되 뒤따르는 click이 복사를 반복하거나 상세로 이동하지 않는다. 일괄 복사 수집 중에는 메모별 복사 아이콘을 표시하지 않고, 메모 누르기는 클립보드에 쓰지 않고 현재 작업에 추가한다.
- 별도 title, emoji와 note icon 자료는 추가하지 않는다. 화면 식별 문구가 필요하면 첫 번째 비어 있지 않은 본문 줄을 사용하고 빈 메모는 `빈 메모`로 표시한다.

### 일괄 복사

- 일괄 복사는 drop zone이 아니라 정렬 가능한 텍스트 모음으로 표현한다. 평상시 drop line과 drag 안내 문구를 표시하지 않는다.
- 항목 왼쪽에는 이동 핸들, 오른쪽에는 더보기 동작을 둔다. 더보기는 위치 이동, 복제와 삭제를 제공하고 드래그를 수행하기 어려운 사용자가 같은 결과를 만들 수 있게 한다.
- 드래그 중인 항목에는 미리보기와 raised 깊이를 적용한다. 실제 앞뒤 결과가 생기는 위치에만 삽입선을 표시하고 놓은 뒤 화면 순서를 즉시 바꾼다.
- 재정렬은 두 항목의 자리를 교환하지 않는다. 선택한 항목을 pointer 또는 대체 조작으로 지정한 삽입 위치로 옮기고 사이 항목을 한 칸씩 이동한다.

### 상태와 문구

- focus, selection과 properties target을 서로 다른 상태로 유지한다. 키보드 `focus-visible`은 선택 표시와 겹쳐도 구분할 수 있어야 한다.
- 복사 성공은 포커스를 옮기지 않는 `복사됨`으로 알린다. 복사 실패와 저장 실패는 입력을 유지하고 다시 시도하거나 설정을 확인할 수 있는 다음 행동을 제공한다.
- 자동 저장 성공에는 반복 toast를 사용하지 않는다. 모바일 상세의 명시적 저장 성공은 저장 제어의 짧은 상태 변화로 알린다.
- 화면 문구는 내용 식별, 이동할 곳, 실행할 동작, 입력 조건, 중요한 결과와 오류 복구에만 사용한다. UI 구조가 이미 알려주는 동작 과정을 문장으로 다시 설명하지 않는다.

### 반응형 탐색

- 넓은 메모 화면은 애플리케이션 bar를 제외한 영역을 캔버스로 사용한다. 별도 `메모` 제목, 메모 수와 안내 banner를 캔버스 위에 반복하지 않는다.
- 좁은 메모 목록과 상세 화면에는 한 줄의 주 헤더만 표시한다. 애플리케이션, 페이지와 상세 헤더를 여러 줄로 쌓지 않는다.
- 좁은 화면의 메모 목록과 보조 화면은 Drawer에서 다른 주요 화면으로 이동한다. 메모 상세와 일괄 복사 확인 및 저장 목록 관리에는 Drawer를 두지 않는다.
- 모든 route를 하나의 공통 프레임으로 감싸지 않는다. 공간형 보드, 좁은 목록, 상세 편집, 일괄 복사 작업과 보조 화면의 헤더, 스크롤 및 하단 동작을 각 과업에 맞게 배치하고, 같은 목적의 구성만 재사용한다.
- 평상시 좁은 메모 목록에서만 새 메모 아이콘 버튼을 화면 우측 하단에 둔다. 저장된 일괄 복사 항목 수 링크는 같은 화면의 Drawer로 옮기고, 수집 상태의 하단 작업 제어는 그대로 유지한다. 우측 하단에 두 제어를 함께 배치하지 않는다.

## 예상 결과와 계획 영향

이 결정은 [이전 시각 방향의 대체 기록](figma-inspired-visual-direction.md)이 폐기한 화면 표현, [개인 메모 디자인 시스템과 UI 기반 결정](application-design-system.md)의 물체별 색 토큰과 [메모 선택과 오른쪽 속성 패널 결정](note-selection-and-properties.md)의 이전 붉은 선택선을 대체한다. [일괄 복사 순서와 제거 복구 결정](accumulator-ordering-and-recovery.md)은 이 결정의 삽입식 재정렬을 구체화한다. 자료 저장, 자동 저장, 선택과 속성 대상의 독립 상태, 삭제 복구와 사용 횟수 규칙은 유지한다.

`apps/notes/DESIGN.md`가 구현자가 따를 화면 규칙을 관리하고, [조작 피드백과 실패 복구 결정](interaction-feedback-and-recovery.md)이 비동기 동작, 알림과 오류 표시의 수명을 정한다. [텍스트 재사용 작업 화면의 디자인 근거](../references/focused-text-utility-design-system-research.md)와 [상용 수준의 조작 경험 조사](../references/commercial-service-ux-research.md)는 공식 자료와 현재 저장소 연결 지점을 관리한다. 실행 순서와 검증은 [계획](../plan.md#ui-디자인-재구축)에 따른다.

## 다시 검토할 조건

- Drawer가 메모 목록의 본문 또는 보조 화면의 주요 동작을 가리거나, 화면 이동 중 저장되지 않은 입력과 일괄 복사 작업 초안을 보존하지 못하는 경우
- 대표 화면의 대비 검사에서 `#EE5165` 파생 색이나 foreground 조합이 WCAG 2.2 AA를 충족하지 못한 경우
- 복사와 더보기 동작을 상황별로 표시한 결과 keyboard, touch 또는 pointer 사용자가 핵심 동작을 찾지 못하는 경우
- 이동 핸들 조작 영역과 본문 선택 영역이 겹쳐 편집, scroll 또는 drag가 함께 실행되는 경우
- 선택, 포커스와 속성 대상을 색 이외의 변화로 구분하지 못하는 경우
