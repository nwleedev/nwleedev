# 메모 복사와 편집 동작 결정

읽기 상태의 메모 본문 클릭은 전체 원문 복사로 유지하고, 복사, 누적과 편집 버튼은 본문과 나란한 독립 조작 버튼으로 항상 제공한다. 텍스트 범위를 선택하는 드래그는 전체 복사를 실행하지 않는다.

## 결정 질문과 요구 결과

[요구사항의 의도한 결과와 반드시 지킬 조건](../requirements.md#의도한-결과)은 일반 클릭 복사와 메모 편집을 모두 요구한다. 같은 포인터 동작에 두 결과를 겹치지 않게 배정하면서 키보드, 터치와 텍스트 선택도 유지해야 했다.

## 검토한 선택지

- 본문 클릭으로 편집하고 별도 버튼으로 복사하는 방식은 일반 클릭 복사 요구와 맞지 않는다.
- 한 번 클릭으로 복사하고 두 번 클릭으로 편집하면 첫 클릭의 복사를 늦추거나 원하지 않은 복사를 허용해야 한다.
- 본문 전체를 하나의 긴 버튼으로 만들면 읽을 텍스트와 버튼 이름이 섞이고 다른 조작 버튼을 안에 둘 수 없다.
- 읽기 본문 클릭을 포인터용 복사 단축 동작으로 두고 별도 버튼을 제공하면 각 동작의 이름과 결과를 일치시킬 수 있다.

## 결정 이력

- 초기 조사에서는 본문 클릭으로 복사하고 선택한 메모의 편집 버튼 또는 `Enter`로 편집을 시작하는 방안을 제안했다.
- 재검토에서는 복사 영역의 `Enter`를 편집으로 바꾸면 현재 포커스를 받은 버튼의 이름과 결과가 어긋나며, 텍스트 선택 드래그도 일반 클릭과 구분해야 한다는 문제가 확인됐다.
- 검증 방식을 다시 검토한 결과, 클릭과 선택을 별도 순수 함수로 흉내 내면 브라우저가 실제로 만든 선택 범위와 이벤트 순서를 확인할 수 없었다. 이 상호작용은 실제 브라우저에서 검증하기로 했다.
- 현재 결정은 본문 클릭 복사와 독립된 복사 및 편집 버튼을 함께 제공하고, `Enter`와 `Space`는 포커스를 받은 버튼의 이름대로 동작하게 하는 것이다.

## 승인된 결정과 이유

- 읽기 본문을 일반 클릭하면 원문 전체를 복사한다.
- 포인터 이동으로 텍스트 범위를 선택했으면 전체 복사를 실행하지 않는다.
- 복사, 누적과 편집 버튼은 마우스를 올리거나 보조 키를 누르지 않아도 사용할 수 있어야 한다.
- 편집 버튼의 `Enter` 또는 `Space`로 편집을 시작한다. 편집 중 본문은 일반 텍스트 입력 영역으로 동작하고 `Escape` 또는 완료 버튼으로 읽기 상태로 돌아온다.
- URL 형식 문자열도 본문 안의 일반 텍스트로 유지한다.

[WAI-ARIA 버튼 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/button/)은 `Enter`와 `Space`가 포커스를 받은 버튼을 실행해야 한다고 설명한다. [Clipboard API](https://www.w3.org/TR/clipboard-apis/)의 사용자 활성화 조건을 고려해 실제 복사는 클릭 또는 버튼 실행을 처리하는 이벤트 안에서 시작한다.

## 예상 결과와 계획 영향

메모 본문, 이동 영역과 조작 버튼을 형제 요소로 구성한다. 본문 클릭, 텍스트 선택, 편집 전환, 실제 Clipboard, IME와 포커스 동작은 브라우저에서 검증한다. 복사 명령이 Clipboard와 사용 횟수 저장의 성공 및 실패를 처리하는 규칙은 별도의 TDD 대상으로 둔다.

## 다시 검토할 조건

- 사용자가 복사 의도 없이 본문을 자주 클릭하는 경우
- 텍스트 범위 선택과 전체 복사의 충돌이 반복되는 경우
- 작은 메모에서 항상 접근 가능한 조작 버튼이 본문을 지나치게 가리는 경우
