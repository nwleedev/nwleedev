# 메모 복사와 편집 동작 결정

넓은 공간형 화면의 메모 본문은 항상 편집 가능한 `textarea`로 제공한다. 일반 클릭과 drag는 커서 이동 및 텍스트 선택, `Command+클릭`은 원문 전체 개별 복사, `Command+Option+클릭`은 일괄 복사 목록 추가를 실행한다. 별도 읽기 상태, 편집 시작과 완료 UI는 만들지 않는다. 원문은 마지막 입력 800ms 뒤 자동 저장하고 이탈 신호에서는 즉시 저장한다. `48rem` 미만의 목록에서는 본문을 직접 편집하지 않고 짧게 누르면 상세 화면으로 이동하며, 길게 누르면 원문 전체를 개별 복사한다.

복사 및 저장 명령은 유지한다. 새 메모의 이동 핸들, 바로 보이는 복사 버튼과 더보기 배치는 [집중형 텍스트 유틸리티 작업 화면 결정](focused-text-utility-workspace.md)이 이 문서의 이전 헤더 설명보다 우선한다.

## 결정 질문과 요구 결과

[요구사항의 의도한 결과와 반드시 지킬 조건](../requirements.md#의도한-결과)은 macOS Stickies처럼 별도 편집 단계를 없애면서 개별 복사와 일괄 복사를 같은 메모에서 제공하도록 요구한다. 공간형 메모의 본문 편집, 헤더 이동, 크기 조절, 보조 키 클릭과 작은 화면의 상세 이동 및 길게 누르기가 서로 중복 실행되지 않게 입력 책임을 나눠야 한다.

## 검토한 선택지

- 일반 클릭 복사와 별도 편집 상태를 유지하면 커서 이동 및 텍스트 선택을 기본 pointer 동작으로 사용할 수 없고, 화면에 편집 시작 UI가 다시 필요하다.
- 읽기 요소와 `textarea`를 전환하면 저장 전후에 DOM, 포커스와 선택 범위가 바뀌지만 현재 메모는 여러 줄 일반 텍스트이므로 얻는 이점이 없다.
- 넓은 화면의 본문을 항상 `textarea`로 두면 붙여넣기, 커서 이동과 선택을 네이티브 동작에 맡길 수 있고, 복사는 명시적인 보조 키 조합으로 분리할 수 있다.
- 모바일 목록까지 상시 `textarea`로 만들면 짧은 누르기 상세 이동, 길게 누르기 복사, 세로 스크롤 및 텍스트 선택이 같은 표면에서 경쟁한다.
- 모바일 목록은 제한된 높이 미리보기와 상세 편집 route로 나누면 목록 조작을 단순화하지만 저장 전 이탈과 저장 실패 규칙이 새로 필요하다.

## 결정 이력

- 초기 조사에서는 본문 일반 클릭으로 복사하고 선택한 메모의 편집 버튼 또는 `Enter`로 편집을 시작하는 방안을 제안했다.
- 화면 검토 뒤 메모 표면의 이동, 복사, 일괄 복사, 편집과 크기 텍스트 버튼을 제거하고 가장자리 및 꼭짓점에서만 크기를 바꾸기로 했다.
- 당시에는 일반 클릭 복사를 유지해 편집과 이동 시작 입력이 결정되지 않는 충돌이 남았다.
- 후속 요구에서 넓은 화면의 본문을 항상 편집 가능하게 하고, 개별 복사는 `Command+클릭`, 일괄 복사 목록 추가는 `Command+Option+클릭`으로 옮겼다. 짧은 헤더가 메모 이동을 맡아 기존 충돌을 해소했다.
- 모바일 요구가 바뀌면서 작은 화면의 상시 편집과 길게 누르기 일괄 복사 선택을 폐기했다. 일반 터치는 상세 화면 이동, 길게 누르기는 개별 복사, 화면 헤더 아이콘으로 시작한 일괄 복사 상태의 짧은 누르기는 일괄 복사 항목 추가로 나눴다.
- 이전 요구에서 `Command`를 누르는 동안 헤더 행의 자리는 유지하되 헤더와 아이콘을 숨기고 조작을 막도록 했다.
- 최신 요구에서 `Command` keydown은 메모 선택도 해제한다. 본문의 보조 키 복사는 메모를 다시 선택하거나 속성 패널 대상을 바꾸지 않는다.
- 사용자에게 보이는 기능명은 `일괄 복사`로 바꿨다. 저장 자료와 내부 TypeScript 이름의 migration은 자료 구조 결정에서 별도로 다룬다.
- 구현 필수 결정 재검토에서 입력마다 저장하는 방식, 대기 뒤 저장만 하는 방식과 복구 초안을 먼저 기록하는 방식을 비교했다. 800ms 대기와 이탈 시 즉시 저장, IndexedDB 복구 초안을 함께 사용해 쓰기 경쟁과 입력 손실 위험을 줄이기로 했다.
- 같은 재검토에서 모바일 상세 입력은 명시적 저장을 유지하되 복구 초안을 기록하고, 저장 전 애플리케이션 내부 이동에는 계속 편집과 변경사항 버리기를 선택하게 했다. 일괄 복사 수집 상태의 길게 누르기는 평상시 개별 복사와 구분하기 위해 아무 동작도 실행하지 않는다.

## 승인된 결정과 이유

### 넓은 공간형 화면

- 본문은 항상 편집 가능한 여러 줄 일반 텍스트 `textarea`이며 별도 읽기 상태, 편집 시작, 완료와 저장 버튼을 표시하지 않는다.
- 일반 클릭과 drag는 커서 이동과 텍스트 선택에 맡긴다.
- `Command+클릭`은 현재 메모 원문 전체를 Clipboard에 쓰고 성공한 경우에만 개별 복사 횟수를 늘린다.
- `Command+Option+클릭`은 개별 복사를 함께 실행하지 않고 현재 원문 스냅샷을 일괄 복사 목록에 추가한다. 더 구체적인 두 보조 키 조합을 먼저 판정한다.
- 헤더, 헤더의 아이콘 버튼, 가장자리 및 꼭짓점, 탐색과 다른 제어의 클릭은 본문 복사 단축 조작으로 해석하지 않는다.
- `Command` keydown은 메모 선택을 해제하고 헤더를 보이지 않고 조작할 수 없게 하되 헤더 높이, 본문 위치와 메모 외곽 크기를 유지한다. event의 기본 동작은 막지 않는다. `keyup`, 창의 포커스 상실과 문서 숨김에서는 헤더만 복원하고 선택은 되살리지 않는다.
- 본문의 `Command+클릭`과 `Command+Option+클릭`은 상위 메모의 pointer 또는 focus event로 전파돼 메모를 다시 선택하거나 속성 패널 활성화를 실행하지 않는다.
- URL 형식 문자열도 일반 텍스트로 유지한다.
- 입력한 원문은 마지막 입력 800ms 뒤 자동 저장한다. `blur`, 애플리케이션 내부 화면 이동, 문서가 숨겨질 때와 `pagehide`에서는 같은 저장 흐름을 즉시 실행한다.
- 입력할 때 화면의 제어 초안은 동기적으로 갱신하고 저장 완료 응답이 더 최신 입력을 덮어쓰지 않게 한다. 최신 원문을 IndexedDB 복구 초안에 먼저 기록하고 메모 저장 transaction이 완료되면 복구 초안을 지운다.
- 저장 실패는 본문을 가리지 않는 상태 알림으로 원인과 재시도를 제공하고 입력 및 복구 초안을 유지한다. 복구 초안도 기록되지 않은 변경이 있을 때만 `beforeunload` 경고를 사용한다.

### 작은 화면 목록과 상세 화면

- 목록 카드는 내용에 따라 짧아지고 `12rem`을 넘지 않는 읽기 미리보기이며 직접 편집 입력을 제공하지 않는다.
- 일반적인 짧은 누르기는 선택한 메모의 상세 화면으로 이동한다.
- 500ms 동안 시작점에서 `10 CSS px` 안에 누른 뒤 같은 카드 안에서 손을 떼면 원문 전체를 개별 복사하고 뒤따르는 상세 이동을 막는다.
- 상세 화면은 원문 전체를 편집할 `textarea`와 명시적인 저장 동작을 제공한다.
- 상세 화면의 입력도 IndexedDB 복구 초안에 기록한다. 저장하지 않은 입력을 둔 애플리케이션 내부 이동에는 `계속 편집`과 `변경사항 버리기`를 제공하고, 후자를 고른 경우에만 초안을 지운다.
- 저장 중에는 저장 동작을 다시 시작하지 않는다. 저장 실패 뒤에도 원문과 복구 초안을 유지하고 같은 화면에서 재시도할 수 있게 한다.
- 일괄 복사 상태에서는 짧은 누르기를 상세 이동이 아니라 이번 작업의 추가 순서 기록으로 사용한다. 같은 메모를 다시 누르면 별도 항목을 추가한다. 길게 누르기는 개별 복사, 항목 추가 또는 상세 이동을 실행하지 않는다.

[메모 조작과 모바일 일괄 복사 조사](../references/note-interaction-and-mobile-batch-copy-research.md)는 Apple Stickies, HTML `textarea`, Pointer Events, WCAG pointer 취소와 Next.js 동적 route를 비교한다. 브라우저가 실제로 생성하는 선택 범위, IME, Clipboard 사용자 활성화, 길게 누르기와 뒤따르는 `click`은 순수 함수만으로 판정하지 않고 실제 지원 브라우저에서 검증한다.

## 예상 결과와 계획 영향

기존 읽기 본문, 편집 전환 버튼과 완료 UI를 제거하고 넓은 화면에는 상시 `textarea`와 자동 저장을 연결한다. 이동이 아닌 한 번의 헤더 click은 [메모 선택과 오른쪽 속성 패널 결정](note-selection-and-properties.md)에 따라 메모를 선택하고, 더블클릭 또는 선택 지점의 `Enter`는 속성 패널을 열지만 본문 복사를 실행하지 않는다. `Command`는 선택을 해제한다. 작은 화면에는 제한된 높이 목록, 메모 상세 route와 명시적 저장 흐름을 추가한다. `Command+클릭`, `Command+Option+클릭`, 짧은 누르기, 길게 누르기, 헤더 선택, 더블클릭 및 drag와 가장자리 resize가 같은 pointer sequence에서 중복 실행되지 않도록 화면 통합 검증을 수행한다.

Clipboard와 사용 횟수 저장의 성공 및 실패를 처리하는 application command는 TDD 대상으로 유지한다. 입력 대기, 최신 revision 병합, 복구 초안 판정, 즉시 저장과 실패 복구의 순수 상태 전이에만 TDD를 적용하고, 실제 IME, 문서 수명 event 및 route 이동은 브라우저에서 확인한다.

## 다시 검토할 조건

- `Command+클릭`이 지원 브라우저의 기본 동작과 반복해서 충돌하는 경우
- `Command+Option+클릭`이 개별 복사와 함께 실행되는 경우
- 상시 `textarea`의 자동 저장이 IME 조합 중인 원문이나 포커스 이동 시점의 입력을 잃는 경우
- 모바일 길게 누르기가 스크롤, 브라우저 편집 메뉴 또는 상세 이동과 함께 실행되는 경우
- 제한된 높이의 목록 카드가 상세 이동 전에 메모를 구분할 정보를 충분히 보여주지 못하는 경우
