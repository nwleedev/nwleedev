# 텍스트 사용 빈도 집계 결정

사용 빈도는 메모 ID, 텍스트 전용 revision과 실행 당시 원문 스냅샷별로 집계한다. 개별 복사와 일괄 복사 항목 추가 횟수만 저장하고 합계는 두 값에서 계산한다.

## 결정 질문과 요구 결과

[요구사항의 사용 빈도 조건과 완료 증거](../requirements.md#완료를-확인할-증거)는 개별 복사, 일괄 복사와 합계를 구분하도록 요구한다. 메모 편집과 배치 변경, 실패한 작업, 제거 및 같은 원문의 반복 추가가 집계에 미치는 영향도 정해야 했다.

## 검토한 선택지

- 메모 ID만 사용하면 편집 전후의 서로 다른 원문이 한 항목에 섞인다.
- 메모 ID와 전체 revision을 사용하면 위치나 크기 변경도 새 빈도 항목을 만든다.
- 원문만 사용해 모든 메모를 합치면 어느 메모 상태에서 사용했는지 잃는다.
- 모든 click event를 저장하면 현재 요구에 필요하지 않은 이력과 자료량이 생긴다.

## 결정 이력

- 초기 권장안은 메모 ID, revision과 복사 당시 원문으로 집계하고 성공한 동작만 증가시키는 것이었다.
- 재검토에서는 전체 revision이 geometry 변경에도 증가할 수 있으므로 같은 원문의 통계가 갈라진다는 문제가 확인됐다.
- 일괄 복사 패널 검토에서는 결합된 전체 텍스트 복사를 개별 복사나 항목 추가로 잘못 집계할 여지가 확인됐다.
- 현재 결정은 `note.id`, `note.contentRevision`과 `textSnapshot`을 집계 단위로 사용하고 두 종류 횟수만 저장하는 것이다.
- 후속 조작 변경에서 넓은 화면의 `Command+클릭`과 모바일 목록의 길게 누르기는 모두 개별 복사로, `Command+Option+클릭`과 모바일 일괄 복사 상태의 항목 추가는 일괄 복사로 분류했다. 화면에 보이는 집계 이름도 이 두 용어를 사용한다.
- 최신 모바일 요구는 짧은 누르기를 즉시 저장된 항목으로 만드는 대신 작업 초안과 클릭 횟수에 먼저 반영하고 `다음`으로 진행하게 했다. `다음`의 저장 결과가 정해지지 않아 모바일 일괄 복사 횟수를 증가시킬 시점도 아직 확정하지 않았다.

## 승인된 결정과 이유

- 위치와 크기만 바꾸면 같은 사용 빈도 항목을 유지하고, 원문을 편집하면 새 content revision의 항목을 만든다.
- 서로 다른 메모의 같은 원문은 현재 범위에서 하나로 합치지 않는다.
- `Command+클릭` 또는 모바일 목록의 길게 누르기로 실행한 개별 복사는 Clipboard 쓰기가 성공한 뒤 횟수 저장을 시작하고 IndexedDB transaction이 완료됐을 때 횟수에 반영한다.
- Clipboard는 성공했지만 횟수 저장이 실패하면 복사 성공은 유지하고 빈도 기록 실패를 별도로 알린다.
- 저장된 일괄 복사 항목 추가와 해당 횟수 증가는 같은 transaction에서 완료한다. 모바일 작업 초안의 클릭 횟수는 사용 빈도 자료가 아니며, `다음`의 반영 방식이 승인될 때 저장 항목과 횟수를 함께 처리한다.
- 실패한 Clipboard 쓰기와 실패한 항목 추가 transaction은 횟수에 포함하지 않는다.
- 제거, 순서 변경, undo와 redo는 횟수를 바꾸지 않는다. 같은 원문을 다시 추가하면 성공한 항목 추가를 한 번 더 기록한다.
- 일괄 복사 패널이나 모바일 관리 페이지의 `일괄 복사하기`는 개별 복사와 항목 추가 어느 쪽도 아니므로 두 횟수를 모두 바꾸지 않는다. Clipboard 성공과 실패는 해당 화면의 동작 결과로만 알린다.

[Clipboard API의 `writeText`](https://www.w3.org/TR/clipboard-apis/#dom-clipboard-writetext)는 쓰기 절차가 성공한 뒤 promise를 resolve한다. IndexedDB transaction 완료는 개별 request 성공과 별도로 확인해야 한다.

## 예상 결과와 계획 영향

집계 규칙과 개별 복사 및 일괄 복사 항목 추가 명령의 결과는 TDD 대상으로 삼고, Clipboard와 IndexedDB 사이의 부분 실패는 실제 브라우저 통합으로 확인한다. 사용 빈도 화면은 이전 content revision의 스냅샷도 기록으로 표시한다.

## 다시 검토할 조건

- 같은 원문을 가진 여러 메모의 전체 사용량을 합쳐야 하는 경우
- 원문을 이전 문구로 되돌렸을 때 과거 횟수와 합쳐야 하는 경우
- 기간별 추이나 개별 event 이력이 요구되는 경우
- 모바일 일괄 복사 상태의 `다음`이 작업 초안을 저장 목록에 반영하는 방식이 정해지는 경우
