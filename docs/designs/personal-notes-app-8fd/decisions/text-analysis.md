# 줄 단위 텍스트 분석 결정

텍스트 분석은 원문을 줄 단위로 나눈 뒤 정확한 반복, 포함 관계와 extended grapheme 3-gram Jaccard 점수의 문자열 근접 후보를 계산한다. 고정된 유사성 합격 임계값과 의미 동일성 판정은 사용하지 않는다. 화면, route, slice, Worker와 TypeScript 식별자에는 이 전체 작업을 나타내는 `analysis`를 사용한다.

## 결정 질문과 요구 결과

[요구사항의 줄 단위 텍스트 분석 조건](../requirements.md#반드시-지킬-조건)은 LLM 없이 메모 줄의 정확한 반복, 포함 관계와 문자열 근접 점수를 보여줘야 한다. 분석 단위, 정규화, 짧은 줄, 점수의 뜻과 오래된 결과 판정이 필요했다.

## 검토한 선택지

- 완전 일치만 비교하면 포함 관계와 부분적인 생김새 반복을 놓친다.
- 단어 token은 한국어와 URL을 함께 다룰 때 별도 분리 규칙이 필요하다.
- 편집 거리는 작은 철자 변화에 유용하지만 포함 관계의 이유를 따로 설명해야 한다.
- 문자 n-gram은 형태소 분석기 없이 혼합 문자열의 공통 조각을 비교할 수 있지만 의미는 판정하지 못한다.

## 결정 이력

- 초기 권장안은 NFC, 공백 정리와 소문자 변환 뒤 문자 3-gram Jaccard를 사용하는 것이었다.
- 재검토에서는 모든 메모에 통하는 최적 임계값이 없고 UTF-16 code unit보다 사용자에게 보이는 grapheme 단위가 알맞다는 점을 보완했다.
- 현재 결정은 점수를 정렬과 설명에만 사용하고 0보다 큰 후보를 보여주며, 의미 유사성은 백로그로 유지하는 것이다.
- 구현 용어 재검토에서는 부분 점수 하나만 뜻하는 이름보다 전체 작업을 나타내는 `analysis`를 route, slice, Worker와 자료형 이름에 사용하기로 했다.
- 구현 전 검토에서는 한 메모 안의 서로 다른 줄을 비교하는지, 같은 두 줄을 몇 번 비교하는지와 동점 정렬 기준이 정해지지 않은 공백을 확인했다.
- 구현 검토에서는 같은 줄의 grapheme 분리와 3-gram 집합을 줄 쌍마다 다시 만들고, 표시할 원문을 모든 결과 쌍에 반복하면 계산량과 Worker 메시지 크기가 함께 늘어나는 문제를 확인했다.
- 문자열 근접 계산 대상 120줄을 브라우저 엔진에서 측정했을 때 줄별 분석값 재사용 전후 계산 시간은 Chromium 227.2ms에서 15.5ms, Firefox 157ms에서 48ms, WebKit 160ms에서 27ms로 줄었다. 이 측정은 순수 분석 계산만 비교했으며 Worker 메시지 전달, 결과 화면 생성과 메모리 사용량을 포함하지 않는다.

## 승인된 결정과 이유

각 분석 단위는 `note.id`, `note.contentRevision`과 원래 줄 위치로 식별한다. 빈 줄을 제외한 단위를 `note.id`의 코드 포인트 순서와 줄 위치 오름차순으로 정렬한 뒤, 서로 다른 두 위치의 순서 없는 조합을 정확히 한 번씩 만든다. 같은 메모 안의 서로 다른 줄도 비교하고, 한 위치를 자신과 비교하지 않으며, A-B와 B-A를 중복 생성하지 않는다. 내용이 같아도 위치가 다르면 정확한 반복 후보로 비교한다. 따라서 유효한 줄이 하나면 후보는 없고, 둘이면 하나, 셋이면 세 조합이 생긴다.

분석은 다음 순서를 사용하며 이 규칙 전체를 algorithm version으로 식별한다.

1. CRLF, LF와 CR을 줄바꿈으로 인식하고 원래 line index를 유지한다.
2. 앞뒤 공백을 제거하고 내부 공백 묶음을 하나로 정리한다. 빈 결과는 제외한다.
3. NFC로 정규화하고 locale 비의존 소문자 변환 뒤 NFC를 다시 적용한다. 문장부호는 유지한다.
4. 정규화 문자열이 같으면 정확한 반복, 한쪽이 다른 쪽을 포함하면 포함 관계로 분류한다.
5. 나머지 3 grapheme 이상인 줄은 extended grapheme 3-gram 집합의 Jaccard 점수를 계산한다.
6. 점수가 0보다 큰 후보를 점수 내림차순으로 보여준다. 점수는 의미가 같다는 판정이나 자동 합격 기준으로 쓰지 않는다.
7. 3 grapheme 미만인 줄은 정확한 반복과 포함 관계만 판정한다.

결과는 관계를 정확한 반복, 포함 관계, 문자열 근접 후보 순서로 정렬한다. 같은 관계 안에서는 점수 내림차순을 먼저 사용하고, 동점이면 앞 줄의 `note.id`와 줄 위치, 뒤 줄의 `note.id`와 줄 위치 순서를 보조 기준으로 사용한다. 점수가 없는 정확한 반복과 포함 관계에는 위치 보조 기준만 적용한다.

원문은 표시와 템플릿 제안을 위해 그대로 유지한다. 분석 결과는 참조한 content revision이 바뀌면 오래된 결과로 처리하고, geometry 변경만으로는 폐기하지 않는다.

정확한 반복이나 포함 관계로 분류되지 않은 줄만 grapheme 분석값을 지연 생성한다. 같은 분석 실행에서는 줄마다 grapheme 수와 3-gram 집합을 한 번 만들고 모든 줄 쌍에서 재사용한다. Worker 응답의 `sourceLines`에는 결과가 참조하는 원문을 줄마다 한 번만 넣고, 각 결과 쌍은 원문을 복제하지 않고 두 줄의 메모 참조와 줄 위치만 가진다. 주 실행 흐름은 이 목록을 결과 쌍과 연결할 뿐 원문 정규화, grapheme 분리, 조합 생성이나 결과 정렬을 반복하지 않는다.

Worker 응답은 요청 ID만 일치한다고 수락하지 않는다. 알고리즘, 중복 없는 입력 메모 집합, 원래 요청에 존재하는 줄과 원문, 서로 다른 두 줄의 정규 순서, 중복 없는 결과 쌍과 결정적 정렬을 함께 검증한다. 검증에 실패하면 응답을 보낸 Worker를 종료하고 다음 분석에서 새 Worker로 다시 시도한다.

[Unicode UAX #15](https://www.unicode.org/reports/tr15/)는 NFC의 canonical equivalence와 NFKC를 임의 적용할 때의 정보 손실 위험을 설명한다. [Unicode UAX #29](https://www.unicode.org/reports/tr29/)는 extended grapheme cluster를 정의한다. [Broder의 resemblance 연구](https://www.cs.princeton.edu/courses/archive/spr05/cos598E/bib/broder97resemblance.pdf)는 조각 집합의 교집합과 합집합으로 유사도를 계산하는 근거를 제공하지만 보편 임계값을 정하지 않는다.

## 예상 결과와 계획 영향

정규화, 줄 조합 생성, 관계 분류, 점수와 결정적인 정렬은 TDD 대상으로 삼는다. 한 줄, 두 줄과 세 줄, 같은 메모 안의 조합, 서로 다른 위치의 같은 원문 및 동점 순서를 포함한다. Worker 메시지와 원래 요청의 결합, 잘못된 줄과 오류 뒤 재시도도 메시지 스키마 입력으로 확인한다. 실제 메모 규모의 계산 시간, 오래된 응답, Worker 자산 실패와 분석 요청 직후 탐색은 브라우저 통합으로 검증한다.

## 다시 검토할 조건

- 한국어, 영어, 숫자, URL과 반복 문자열의 대표 입력에서 후보가 지나치게 많거나 필요한 후보가 빠지는 경우
- 다국어 full case folding이 필요한 경우
- 반복 n-gram 횟수를 반영해야 하는 사례가 확인되는 경우
- 의미 유사성 판정이 현재 범위로 승인되는 경우
- 실제 메모에서 Worker 메시지 전달이나 결과 화면 생성이 긴 작업으로 측정되는 경우
