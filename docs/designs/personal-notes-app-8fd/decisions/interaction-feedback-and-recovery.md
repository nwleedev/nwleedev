# 조작 피드백과 실패 복구 결정

## 결론

개인 메모 애플리케이션은 입력 직후 화면을 갱신하고, 비동기 저장이 실패하면 입력 전 상태를 복원한다. 일시 결과는 애플리케이션 범위의 공유 알림 영역 한 곳에 한 건만 표시하고, 사용자가 읽거나 다시 시도해야 하는 실패는 해당 작업 가까이의 지속 상태로 남긴다. 공유 알림 영역은 화면 위쪽 중앙에 고정하고 내부 페이지 이동에도 같은 알림의 남은 시간을 유지한다. 드래그와 길게 누르기는 항상 보이는 단일 포인터 동작을 보완하는 빠른 입력으로만 사용한다.

## 결정할 질문과 필요한 결과

복사, 저장, 삭제와 재정렬이 끝났거나 실패했을 때 어떤 화면 요소가 얼마나 오래 상태를 알려야 하는지 정해야 한다. 사용자는 현재 작업 맥락과 입력을 잃지 않고 성공, 진행, 실패와 복구 방법을 구분할 수 있어야 한다. pointer drag나 touch 제스처를 사용하지 못해도 같은 자료 결과를 만들 수 있어야 한다.

## 검토한 선택지

- 모든 결과를 같은 5초 토스트로 알리는 방식은 구현 규칙이 단순하지만, 저장 실패와 자료 불러오기 실패처럼 사용자가 계속 확인해야 하는 내용을 놓치게 한다.
- 성공과 오류마다 별도 화면 위치와 구성요소를 만드는 방식은 개별 화면을 조정하기 쉽지만, 알림이 동시에 쌓이고 사용자가 결과를 찾을 위치가 달라진다.
- 일시 결과는 공유 알림 한 건으로, 계속 확인할 실패는 작업 가까이의 지속 상태로, 반드시 선택해야 하는 경우는 dialog로 나누면 중요도와 다음 행동에 맞는 수명을 제공할 수 있다.
- 항목 전체를 드래그 영역으로 쓰면 이동을 시작하기 쉽지만 본문 선택, 링크, 버튼과 scroll 입력이 충돌한다. 명시적인 이동 핸들과 더보기의 위치 변경을 함께 제공하면 시작 영역과 대체 조작을 구분할 수 있다.

## 결정한 규칙

- 이동 가능한 메모와 일괄 복사 항목은 명시적인 핸들에서만 드래그를 시작한다. 본문, 링크와 실행 버튼은 드래그 시작 영역이 아니다.
- 일괄 복사 재정렬은 놓는 즉시 화면에 반영하고 저장 실패에서 이전 순서, 선택과 포커스를 복원한다. 실제로 놓을 수 있는 위치에만 드래그 중 삽입선을 표시한다.
- 목록 가장자리에서는 현재 스크롤 영역을 자동으로 이동한다. 유효하지 않은 놓기, 스크롤 취소, `pointercancel`과 완료 전 `lostpointercapture`는 순서를 바꾸지 않는다.
- 더보기의 위치 변경은 드래그와 같은 삽입식 명령을 사용한다. 완료 뒤 같은 항목의 실행 지점에 포커스를 유지하고, 항목과 새 위치를 live region으로 알린다.
- 복사 성공과 실행 취소 가능한 삭제는 공유 알림 영역을 사용한다. 새 결과는 이전 결과를 바꾸며 여러 알림을 쌓지 않는다.
- 공유 알림 상태와 절대 만료 시각은 공통 layout 수명에서 관리한다. 내부 페이지 이동은 알림을 숨기거나 시간을 다시 시작하지 않으며 닫히거나 만료된 알림은 이전 페이지로 돌아왔을 때 다시 나타나지 않는다.
- 공유 알림 영역은 화면 위쪽 중앙에 fixed로 배치한다. inline 전체 너비 안에서 가운데 정렬하고 양쪽 디자인 간격, safe area와 토스트 최대 inline size를 함께 적용해 작은 화면과 글자 확대에서도 한쪽으로 치우치거나 잘리지 않게 한다.
- 모든 토스트의 오른쪽에 닫기 아이콘 버튼을 둔다. 닫기는 알림 표시만 끝내고 완료된 동작, 실행 취소 이력과 다시 시도 가능성을 바꾸지 않는다. 실행 취소나 다시 시도 동작이 있는 알림은 5초를 기본값으로 삼되 hover와 `focus-within`에서 타이머를 멈춘다.
- 자동 저장 성공에는 알림을 표시하지 않는다. 좁은 화면의 명시적 저장 성공은 저장 버튼 상태로 보여준다.
- 자동 저장 실패, 화면 자료 불러오기 실패와 사용자가 조치해야 하는 저장 실패는 자동으로 사라지지 않는 상태와 다시 시도 동작을 해당 작업 가까이에 둔다.
- 저장하지 않은 변경으로 화면을 떠나는 경우처럼 반드시 선택해야 하는 상황에만 modal dialog를 사용한다.

## 유지하는 기능과 바꾸는 표현

자유 배치, 자동 저장, 좁은 화면 명시적 저장, 개별 및 일괄 복사, 삭제 취소, 속성, 사용 기록, 분석, 템플릿과 설정 기능은 유지한다. `ActionToast`, `ActionPopover`, 일괄 복사 목록과 상세 저장 화면의 현재 외형이나 상태 수명은 호환 대상으로 삼지 않는다.

이 결정은 [텍스트 재사용 작업 화면 결정](focused-text-utility-workspace.md)의 피드백 방향을 구체화하고, [일괄 복사 순서와 제거 복구 결정](accumulator-ordering-and-recovery.md)의 재정렬 결과를 화면 및 실패 복구 수명에 연결한다. 모든 토스트를 5초 뒤 닫고 전체 복사 알림을 별도 오른쪽 위 영역에 고정한 이전 계획은 이 결정으로 대체한다. 구현 방식과 위치 근거는 [토스트 알림 수명, 배치와 구현 방식 조사](../references/toast-lifecycle-placement-and-library-research.md), 현재 화면 차이는 [상용 수준의 조작 경험 조사](../references/commercial-service-ux-research.md)에서 관리한다. 현재 기능 범위에는 외부 토스트 라이브러리를 추가하지 않고 기존 `ActionToast`와 타이머를 공통 알림 상태 및 영역에 연결한다.

## 아직 정하지 않은 사항

- 모바일 일괄 복사 항목의 여러 관리 동작은 touch용 action sheet 방향을 사용한다. 정확한 크기, 위치 이동 단계와 닫기 제스처는 대표 화면 비교 뒤 정한다.
- 좁은 화면 전역 탐색은 이 결정에서 다루지 않는다.

미정 사항은 임의의 구현값으로 확정하지 않는다. 해당 작업 단위에서 선택지와 실제 화면 결과를 비교하고 요구사항, 이 결정과 계획을 갱신한 뒤 구현한다.

## 다시 검토할 조건

- 한 알림 영역 때문에 주요 본문 또는 고정 실행 제어가 가려지는 경우
- 즉시 화면 갱신 뒤 저장 실패에서 정확한 이전 상태를 복원할 수 없는 경우
- 모바일 action sheet가 화면 키보드, safe area 또는 뒤로가기와 충돌하는 경우
- 포커스 복원과 live region 알림이 같은 결과를 중복해 읽거나 이동한 항목을 잃게 만드는 경우
