# Pretendard와 Figma식 작업 화면 결정

개인 메모 애플리케이션은 Pretendard를 모든 인터페이스 글꼴의 기준으로 사용하고, Figma Design 편집기의 정보 배치와 도구 구성을 참고한 중립적인 애플리케이션 프레임을 사용한다. 메모가 놓이는 캔버스만 밝은 목재 인상을 가지며, 메모와 제어 요소는 캔버스와 구분되는 중립색 표면으로 표현한다.

## 결정 질문과 요구 결과

[시각 언어 요구사항](../requirements.md#반드시-지킬-조건)은 흔한 AI SaaS 화면을 피하면서 공간형 메모 작업에 맞춘 일관된 시각 언어를 요구한다. 2026년 8월 31일의 시각 조사 뒤 결정 책임자는 serif 제목과 종이 및 짙은 목재 중심 표현을 사용하지 않고 Pretendard와 Figma식 화면 구성을 사용하도록 승인했다. 이어서 메모 작업 캔버스에는 밝은 목재 인상을 남기도록 승인했다.

이 결정은 Figma 브랜드를 복제하는 것이 아니라 사용자의 작업을 중앙에 두고 도구와 속성을 주변에 배치하는 구조를 현재 요구사항에 맞게 적용한다. 메모 화면에서 왼쪽 사이드바를 표시하지 않는 조건과 작은 작업 영역에서 목록으로 전환하는 동작은 바꾸지 않는다.

## 검토한 선택지

- 기존 화면처럼 serif 제목, 따뜻한 종이색, 짙은 갈색 탐색 영역과 어긋난 종이 그림자를 유지하는 선택은 현재 구현의 성격을 보존하지만 새로 승인된 글꼴과 화면 분위기를 충족하지 못한다.
- Figma Design 편집기처럼 전체 화면을 중립적인 회색 캔버스로 통일하는 선택은 도구와 콘텐츠의 관계를 분명히 하지만, 메모 작업 캔버스에 밝은 목재 인상을 두라는 승인 사항을 반영하지 못한다.
- 중립적인 애플리케이션 프레임과 밝은 목재 메모 캔버스를 분리하면 Figma식 정보 배치와 사용자가 요청한 재질 인상을 함께 유지할 수 있다. 이 구성을 승인된 방향으로 선택했다.

## 승인된 시각 방향과 이유

### 글자

- 제목, 본문, 버튼, 입력, 수치와 상태 문구는 `Pretendard Variable`, `Pretendard`와 sans-serif 대체 글꼴을 같은 순서로 사용한다.
- serif display 글꼴은 사용하지 않는다. 제목과 본문의 차이는 글꼴 계열을 바꾸지 않고 크기, 굵기, 행간과 자간으로 만든다.
- 한글과 라틴 문자가 섞인 실제 메모에서 같은 위계가 유지되는지 확인한다.

### 애플리케이션 프레임

- 탐색과 도구 영역은 중립적인 짙은 회색 또는 차가운 회색 표면, 얇은 구획선과 조밀한 간격을 사용한다.
- 메모 화면은 왼쪽 사이드바 대신 낮은 높이의 상단 탐색을 사용하고 그 바로 아래에서 캔버스를 시작한다. 별도 페이지 제목과 작업 행을 두지 않으며, 필요한 제어는 캔버스 위에 조밀하게 배치한다. 사용 빈도, 텍스트 분석, 템플릿과 설정 화면의 왼쪽 탐색은 같은 색과 상태 규칙을 사용한다. 모바일 메모 상세 및 일괄 복사 관리 화면은 왼쪽 탐색을 두지 않고 메모 목록으로 돌아가는 동작과 저장 또는 하단 작업을 우선한다.
- 선택, 포커스와 현재 위치는 파란 계열의 강조색, 선과 형태를 함께 사용해 배경색만으로 구분하지 않는다.
- `48rem` 이상의 메모 화면에서 `일괄 복사` 제어는 우측 상단에 유지하고 보조 패널은 상단 탐색 아래의 오른쪽 높이를 사용한다. `48rem` 미만에서는 화면 헤더 오른쪽에 선택 상태 시작 아이콘을, 저장된 항목 수 제어를 우측 하단에 고정하고 일괄 복사 관리 화면은 같은 중립색 표면과 조밀한 목록을 사용한다. 캔버스 위 제어와 패널은 큰 장식 그림자나 반투명 재질로 콘텐츠를 가리지 않는다.
- 일괄 복사 패널의 머리 영역은 약 `38 CSS px` 높이로 줄이고, 합친 텍스트 미리보기와 상시 편집 버튼을 제거해 항목 목록과 전체 복사 동작을 우선한다. 전체 복사 결과 알림은 이동 및 확대되는 캔버스나 패널 안이 아니라 두 영역과 분리된 메모 작업 영역 우측 상단에 둔다.

[Figma의 현재 인터페이스 안내](https://help.figma.com/hc/en-us/articles/15297425105303-Explore-design-files)는 화면을 navigation bar, left sidebar, canvas, right sidebar와 toolbar로 구분한다. [UI3 안내](https://help.figma.com/hc/en-us/articles/23954856027159-Navigating-UI3-Figma-s-new-UI)는 도구 모음을 화면 아래로 옮겨 캔버스 공간을 늘리고, 패널을 접거나 크기를 바꾸며, 선택한 객체의 문맥에 따라 속성 제어가 달라지는 구성을 설명한다. 현재 Figma 데스크톱 화면에서도 어두운 양쪽 패널, 차가운 밝은 캔버스, 화면 아래 도구 모음과 파란 선택선을 직접 확인했다.

### 메모 작업 캔버스와 객체

- 메모 작업 캔버스는 밝은 베이지와 옅은 황갈색을 바탕으로 낮은 대비의 길고 불규칙한 결을 사용해 밝은 목재 인상을 만든다.
- 목재 결은 메모 내용, 포커스 표시, 정렬선과 drag preview를 읽는 데 방해되지 않아야 한다. 고대비 모드에서는 장식 결보다 색 구분과 테두리를 우선한다.
- 메모는 종이 질감이나 어긋난 짙은 그림자 대신 중립적인 밝은 표면, 얇은 테두리와 절제된 깊이를 사용한다.
- 넓은 화면의 메모는 짧은 헤더와 항상 편집 가능한 본문만 보여준다. 헤더 오른쪽에는 맨 앞으로, 맨 뒤로와 삭제 아이콘만 두고 이동, 복사, 일괄 복사, 편집, 크기와 숫자 geometry 텍스트 제어를 표시하지 않는다. 가장자리와 꼭짓점의 크기 조절 가능성은 pointer cursor, 선택 외곽선과 조절 중 피드백으로 전달하되 텍스트 버튼을 추가하지 않는다.
- 작은 화면의 목록 메모는 같은 최대 높이의 읽기 미리보기로 보여주며, 선택 상태에서는 색 하나에만 의존하지 않는 표시를 추가한다. 상세 화면은 전체 원문 편집과 저장을 우선한다.
- 일괄 복사 패널, 입력과 알림은 목재 재질을 반복하지 않고 애플리케이션 프레임과 같은 중립색 표면을 사용한다.

## 예상 결과와 계획 영향

공통 화면 구조 작업은 글꼴 및 색 토큰, 공통 탐색, 상단 탐색 아래를 채우는 메모 캔버스, 캔버스 위 제어, 모바일 메모 상세 및 일괄 복사 관리 화면, 짧은 헤더와 본문으로 된 메모 표면을 이 결정에 맞게 다시 검토한다. 기존 구현의 메모 작성, 배치, 개별 복사, 일괄 복사와 반응형 전환은 승인된 변경 범위 밖에서 유지한다. 통합 검증은 계산된 글꼴, 데스크톱과 작은 화면의 정보 배치, 우측 상단 및 우측 하단 고정 제어, 약 `38 CSS px`의 패널 머리, 메모 및 패널과 분리된 알림, 목재 결 위의 콘텐츠 대비를 실제 브라우저에서 확인한다.

현재 `paper`, `rail` 또는 display 글꼴처럼 이전 인상을 전제로 한 토큰 이름이 새 역할과 맞지 않으면 의미를 나타내는 이름으로 바꾼다. 이름 변경이 업무 자료, 저장 형식이나 외부 API를 바꾸지는 않는다.

## 다시 검토할 조건

- 밝은 목재 결 때문에 긴 한국어 메모, 포커스, 정렬선이나 drag 상태의 대비가 부족한 경우
- 작은 화면에서 도구 모음과 탐색이 메모 작성 영역을 가리는 경우
- 우측 하단 일괄 복사 항목 수 제어나 하단 선택 작업 영역이 메모 목록의 상세 이동, 개별 복사 또는 스크롤을 가리는 경우
- Pretendard를 불러오지 못했을 때 대체 글꼴의 폭 차이로 주요 제어가 잘리는 경우
- 어두운 도구 영역과 밝은 캔버스의 대비가 확대, 고대비 또는 forced colors 환경에서 상태 식별을 방해하는 경우
- Figma식 화면 구성이 메모 화면의 왼쪽 사이드바 금지나 넓은 작업 영역 우선 조건을 약화하는 경우
