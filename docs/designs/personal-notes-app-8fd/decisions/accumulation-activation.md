# 메모 누적 실행 동작 결정

각 메모의 누적 버튼을 기본 접근 수단으로 항상 제공한다. `Command+클릭`은 설정에서 켜거나 끌 수 있는 추가 동작으로 제공하고, `48rem` 미만의 메모 목록에서는 길게 누른 메모를 누적 선택하며 선택된 메모를 다시 짧게 누르면 해당 선택을 해제한다. 다른 modifier 조합은 자동 대체값으로 정하지 않는다.

## 결정 질문과 요구 결과

[요구사항의 의도한 결과와 반드시 지킬 조건](../requirements.md#반드시-지킬-조건)은 여러 메모의 텍스트를 조작한 순서대로 누적하고, `Command+클릭`이 충돌하거나 터치 입력을 사용해도 같은 결과를 얻을 방법을 요구한다. 작은 화면에서는 길게 누르기와 짧게 누르기가 일반 복사, 누적 선택과 선택 해제 가운데 어떤 동작을 실행하는지도 정해야 했다.

## 검토한 선택지

- `Command+클릭`만 제공하면 터치와 키보드 환경에서 누적할 수 없다.
- 설정에서 `Command+클릭`과 누적 버튼 중 하나만 선택하면 설정에 따라 발견 가능한 동작이 사라진다.
- `Ctrl`, `Shift` 또는 `Alt+클릭`을 자동으로 대입하면 운영체제와 브라우저의 기존 동작과 새 충돌을 만들 수 있다.
- 누적 버튼을 항상 두고 `Command+클릭`을 가속 동작으로 추가하면 두 입력 방식이 같은 누적 명령을 호출할 수 있다.
- 작은 화면에서 별도 선택 모드를 먼저 켜게 하면 누적을 시작하기 위한 단계와 화면 상태가 늘어난다.
- 길게 누르기를 추가하면서 누적 버튼을 유지하면 빠른 터치 조작과 시간 제한 없는 단일 pointer 및 키보드 대안을 함께 제공할 수 있다.

## 결정 이력

- 초기 권장안은 설정에서 `Command+클릭`과 항상 보이는 누적 버튼 가운데 주 조작을 선택하는 방식이었다.
- 재검토에서는 접근 가능한 버튼이 설정에 따라 사라질 이유가 없고, 보조 키는 기본 동작보다 선택적인 가속 동작에 알맞다는 결론을 얻었다.
- 현재 결정은 누적 버튼을 항상 유지하고 설정은 `Command+클릭` 가속 동작의 사용 여부만 바꾸는 것이다.
- 누적 기능의 위치 재검토에서는 성공 뒤 별도 페이지로 이동하지 않고 메모 화면의 누적 작업 패널과 상태 알림으로 결과를 전달하기로 했다. 이후 화면 검토에서 넓은 화면의 첫 누적 성공 때 오른쪽 패널을 열고, 나란한 표시 공간이 부족하면 모달을 자동으로 열지 않는 방식으로 구체화했다.
- 모바일 누적 요구사항이 추가되면서 `48rem` 미만의 목록 표현에는 길게 누르기 선택, 선택된 메모의 짧은 누르기 해제와 우측 하단 항목 수 제어를 사용하기로 했다. 이 화면에서는 누적 성공으로 페이지를 자동 이동하지 않고 사용자가 항목 수 제어를 실행할 때 관리 페이지로 이동한다.

## 승인된 결정과 이유

- 각 메모에 누적 버튼을 항상 제공한다.
- 읽기 상태의 메모 복사 영역에서 `metaKey`와 주 포인터 클릭이 함께 들어오면 누적한다.
- 설정 화면에서 이 추가 동작을 켜거나 끌 수 있다.
- 다른 보조 키 조합과 별도 누적 모드는 초기 범위에서 제공하지 않는다.
- 편집 상태와 메모 안의 다른 조작 버튼에서 발생한 클릭은 누적 단축 동작으로 해석하지 않는다.
- 메모 작업 영역의 inline size가 `48rem` 미만이면 읽기 상태의 메모를 길게 누른 뒤 같은 메모 안에서 pointer를 놓을 때 누적한다. 길게 누르기 기준 시간과 허용 이동 거리는 U5에서 이름 있는 상수로 정하고 실제 터치 브라우저에서 검증한다.
- 길게 누르는 동안 pointer가 메모 밖으로 이동하거나 스크롤, `pointercancel`, `lostpointercapture` 또는 다른 취소가 발생하면 누적하지 않는다. `pointerdown`만으로 누적을 완료하지 않는다.
- 길게 눌러 추가한 누적 항목의 고유 ID를 해당 메모의 선택 상태와 연결한다. 선택된 메모를 짧게 누르면 연결된 항목만 제거하고 선택을 해제하며, 선택되지 않은 메모를 짧게 누르면 일반 복사를 실행한다.
- 누적 버튼은 길게 누르기의 시간 제한 없는 대안으로 유지하고 키보드의 `Enter`와 `Space`로 실행할 수 있게 한다.
- `48rem` 이상의 누적 성공은 현재 포커스를 옮기지 않고 우측 상단 누적 작업 패널 버튼의 항목 수와 상태 알림을 갱신한다. 메모와 패널을 나란히 표시할 공간이 충분한 첫 누적에서는 오른쪽 패널을 열고, 그렇지 않으면 사용자가 직접 모달을 연다.
- `48rem` 미만의 누적 성공은 현재 포커스를 옮기거나 페이지를 자동 이동하지 않고 메모의 선택 상태, 상태 알림과 우측 하단 고정 제어의 항목 수를 갱신한다.

[UI Events](https://www.w3.org/TR/uievents/)는 마우스 이벤트의 보조 키 상태를 정의하고, [Pointer Events Level 3](https://www.w3.org/TR/pointerevents3/)은 마우스, 펜과 터치를 같은 이벤트 모형으로 다루면서 `pointercancel`, pointer capture와 `touch-action`을 정의한다. [WCAG Pointer Cancellation 설명](https://www.w3.org/WAI/WCAG22/Understanding/pointer-cancellation.html)은 짧게 누르기와 길게 누르기를 요소 안에서 손을 뗄 때 완료하는 예를 제시한다. [WCAG 입력 방식 지침](https://www.w3.org/WAI/WCAG22/Understanding/input-modalities.html)은 길게 누르기를 복잡한 pointer 입력의 예로 다루므로, [WAI-ARIA Button 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/button/)에 맞는 항상 보이는 버튼을 터치와 키보드 대안으로 유지한다.

## 예상 결과와 계획 영향

버튼, `Command+클릭`과 길게 누르기는 하나의 누적 명령을 호출한다. 누적 항목과 메모 선택 상태의 연결 및 선택 해제 명령에는 TDD를 적용한다. 길게 누르기의 시간, 이동, 스크롤 및 취소 이벤트와 실제 macOS Safari의 기본 동작은 브라우저에서 검증한다. 성공 뒤 패널 또는 관리 페이지로 이동하는 방식은 [누적 작업 패널과 모바일 관리 페이지 결정](accumulator-workspace-panel.md)을 따른다.

## 다시 검토할 조건

- 누적 버튼 때문에 메모 control이 지나치게 복잡해지는 경우
- 반복 누적에서 버튼과 `Command+클릭`만으로 작업 비용이 높다고 확인되는 경우
- 다른 운영체제용 보조 키 조합을 실제 대상 환경에서 충돌 없이 검증한 경우
- 길게 누르기가 브라우저의 스크롤 또는 텍스트 선택과 반복해서 충돌하거나 선택 해제 의도를 안정적으로 구분하지 못하는 경우
