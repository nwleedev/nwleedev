# 일괄 복사 실행 동작 결정

넓은 공간형 화면에서는 메모 본문의 `Command+Option+클릭`으로 일괄 복사 목록에 원문을 추가한다. `Command+클릭` 개별 복사보다 두 보조 키 조합을 먼저 판정하며, 설정에서 일괄 복사 단축 조작만 켜거나 끌 수 있다. `48rem` 미만의 목록에서는 평상시 화면 헤더 오른쪽 아이콘으로 일괄 복사 상태를 시작하고, 그 상태에서 짧게 누른 메모를 조작 순서대로 현재 작업에 추가한다.

## 결정 질문과 요구 결과

[요구사항의 반드시 지킬 조건](../requirements.md#반드시-지킬-조건)은 메모 표면에 일괄 복사 텍스트 버튼을 두지 않으면서 넓은 화면과 작은 화면에서 여러 메모를 선택한 순서대로 복사할 수 있게 한다. 넓은 화면의 보조 키 조합, 작은 화면의 상태 전환, 개별 복사 및 상세 이동과의 우선순위를 정해야 했다.

## 검토한 선택지

- `Command+클릭`을 일괄 복사에 사용하면 새 요구의 개별 복사와 충돌한다.
- `Command+Option+클릭`은 개별 복사 조합을 확장해 두 동작을 구분할 수 있지만 터치 환경에서 사용할 수 없다.
- 각 메모에 일괄 복사 버튼을 반복하면 공간형 메모가 텍스트 중심이어야 한다는 요구와 맞지 않는다.
- 작은 화면에서 메모를 길게 눌러 선택하면 새로 승인된 길게 누르기 개별 복사와 충돌한다.
- 작은 화면의 목록 헤더에서 명시적으로 일괄 복사 상태를 시작하면 평소 짧은 누르기 상세 이동을 유지하면서 상태 안의 짧은 누르기를 항목 추가에 사용할 수 있다.

## 결정 이력

- 초기 권장안은 설정에서 `Command+클릭`과 항상 보이는 일괄 복사 버튼 가운데 주 조작을 고르는 방식이었다.
- 재검토에서는 접근 가능한 버튼을 유지하고 `Command+클릭`을 선택적인 빠른 조작으로 추가했다.
- 화면 사용 검토 뒤 메모 표면의 일괄 복사 버튼과 `누적했습니다` 성공 알림을 제거하고 `Command+클릭`만 남겼다. 이때 키보드와 설정을 끈 상태의 대안이 결정되지 않았다.
- 모바일 요구가 처음 추가됐을 때에는 작은 화면에서 길게 누른 메모를 선택하고 다시 짧게 눌러 해제하기로 했다.
- 후속 요구에서 넓은 화면의 `Command+클릭`은 개별 복사로 바뀌고 일괄 복사는 `Command+Option+클릭`으로 옮겨졌다.
- 같은 변경에서 모바일 길게 누르기는 개별 복사, 짧은 누르기는 상세 이동으로 바뀌었다. 일괄 복사는 목록 화면 헤더 아이콘으로 별도 상태를 시작한 뒤 짧게 누른 순서대로 항목을 모으는 방식으로 대체됐다.
- 후속 요구에서 이 상태의 이름을 `일괄 복사 상태`로 확정하고 선택 상태라는 표현을 폐기했다. 평상시 헤더 오른쪽 아이콘으로 시작하며, 상태 안에서는 헤더 왼쪽 뒤로가기와 하단 `초기화` 및 클릭 횟수가 붙은 `다음`을 사용한다.
- 같은 메모를 반복해서 누르면 누른 횟수만큼 별도 항목을 추가하고 클릭 횟수를 증가시키도록 확정했다. `다음`의 목적지와 저장된 기존 목록에 반영하는 방식은 아직 승인되지 않았다.
- 사용자에게 보이는 기능명은 `누적 복사` 대신 `일괄 복사`를 사용한다.

## 승인된 결정과 이유

### 넓은 공간형 화면

- 각 메모에 일괄 복사 텍스트 버튼을 표시하지 않는다.
- 본문의 주 pointer 클릭에서 `metaKey`와 `altKey`가 모두 참이면 일괄 복사 목록에 현재 원문 스냅샷을 추가한다.
- `metaKey && altKey`를 판정한 뒤 `metaKey && !altKey`인 경우에만 개별 복사를 실행한다.
- 설정 화면에서 `Command+Option+클릭` 일괄 복사 추가를 켜거나 끌 수 있다.
- `Ctrl`, `Shift`, `Option+클릭`만을 자동 대체 조작으로 정하지 않는다.
- 헤더, 헤더 아이콘, 가장자리 및 꼭짓점과 다른 제어에서 시작한 클릭은 일괄 복사 단축 조작으로 해석하지 않는다.
- 성공하면 현재 포커스를 옮기지 않고 일괄 복사 항목과 항목 수만 갱신한다. 나란히 표시할 공간이 충분한 첫 추가에서는 오른쪽 패널을 열고, 그렇지 않으면 사용자가 직접 모달 패널을 연다.
- `누적했습니다`와 같은 별도 성공 알림을 표시하거나 읽어주지 않는다.

### 작은 화면 목록

- 평상시 화면 헤더 오른쪽의 아이콘 버튼으로 일괄 복사 상태를 시작한다.
- 일괄 복사 상태에서는 헤더 왼쪽에 뒤로가기 아이콘 버튼을 둔다. 이 버튼은 화면 아래의 취소 버튼을 대신하며 Clipboard를 바꾸거나 다음 단계로 이동하지 않고 평상시 목록으로 돌아간다.
- 일괄 복사 상태에서 메모를 짧게 누르면 상세 화면으로 이동하지 않고 현재 원문을 조작 순서대로 이번 작업에 추가한다. 같은 메모를 다시 누르면 별도 항목을 추가한다.
- 일괄 복사 상태의 화면 아래에는 `초기화`와 `다음`을 고정한다. `초기화`는 상태를 유지한 채 이번 작업과 클릭 횟수를 0으로 만들고, `다음` 텍스트 옆에는 현재 클릭 횟수를 표시한다.
- 이번 작업에 추가된 메모와 일괄 복사 상태를 색 하나에만 의존하지 않게 표시하고 보조 기술에 전달한다.
- 기존 저장 목록과의 관계, `다음`의 목적지 및 반영 방식, 헤더 뒤로가기 뒤 이번 작업 수명과 상태 안에서 길게 누르기의 결과는 아직 승인되지 않았다.

[UI Events](https://www.w3.org/TR/uievents/)는 `metaKey`와 `altKey`를 정의하고, [Pointer Events Level 3](https://www.w3.org/TR/pointerevents3/)은 짧은 누르기, 길게 누르기와 취소를 같은 pointer sequence에서 판정할 수 있게 한다. [Apple toolbar 지침](https://developer.apple.com/design/human-interface-guidelines/toolbars)은 modal state에서 현재 작업에 맞는 도구를 제공하고 종료 시 원래 도구를 복원하도록 안내한다. 세부 조사와 미결정 사항은 [메모 조작과 모바일 일괄 복사 조사](../references/note-interaction-and-mobile-batch-copy-research.md)에 기록했다.

## 예상 결과와 계획 영향

기존 `metaClickEnabled`처럼 `Command+클릭` 의미가 드러나는 preference는 새 조합의 의미를 표현하지 못한다. 자료 migration을 정한 뒤 `Command+Option+클릭` 일괄 복사 사용 여부를 나타내는 이름으로 바꾼다. 넓은 화면의 modifier 판정, Clipboard 및 IndexedDB transaction은 application command와 브라우저 통합 검증으로 나누고, 두 명령이 한 클릭에서 함께 실행되지 않는지 확인한다.

작은 화면은 이전 long-press 흐름을 제거하고 목록 헤더 아이콘, 상태별 짧은 누르기, 헤더 뒤로가기 및 하단 동작을 추가한다. 추가 순서, 반복 추가, 초기화와 클릭 횟수의 순수 상태 전이에는 TDD를 적용하고, 짧은 누르기, route 이동 억제와 고정 UI는 실제 터치 브라우저에서 확인한다. `다음`의 목적지와 저장 목록 반영은 남은 결정을 받은 뒤 구현한다.

## 다시 검토할 조건

- `Command+Option+클릭`이 지원 브라우저나 운영체제 기본 동작과 반복해서 충돌하는 경우
- 설정을 끈 넓은 화면 또는 키보드 환경에서 일괄 복사를 시작할 수 없어 접근성 완료 조건을 충족하지 못하는 경우
- 작은 화면의 일괄 복사 상태가 평소 상세 이동과 구분되지 않는 경우
- 일괄 복사 상태의 헤더 뒤로가기 또는 하단 작업 영역이 320 CSS px 및 확대 화면에서 메모와 포커스를 가리는 경우
- 미결정 자료 수명 때문에 기존 일괄 복사 목록이 예기치 않게 바뀌는 경우
