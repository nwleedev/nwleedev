# 메모 누적 실행 동작 결정

각 메모의 누적 버튼을 기본 접근 수단으로 항상 제공하고, `Command+클릭`은 설정에서 켜거나 끌 수 있는 추가 동작으로 제공한다. 다른 modifier 조합은 자동 대체값으로 정하지 않는다.

## 결정 질문과 요구 결과

[요구사항의 의도한 결과와 반드시 지킬 조건](../requirements.md#반드시-지킬-조건)은 여러 메모의 텍스트를 클릭 순서대로 누적하고, `Command+클릭`이 충돌할 때도 같은 결과를 얻을 방법을 요구한다.

## 검토한 선택지

- `Command+클릭`만 제공하면 터치와 키보드 환경에서 누적할 수 없다.
- 설정에서 `Command+클릭`과 누적 버튼 중 하나만 선택하면 설정에 따라 발견 가능한 동작이 사라진다.
- `Ctrl`, `Shift` 또는 `Alt+클릭`을 자동으로 대입하면 운영체제와 브라우저의 기존 동작과 새 충돌을 만들 수 있다.
- 누적 버튼을 항상 두고 `Command+클릭`을 가속 동작으로 추가하면 두 입력 방식이 같은 누적 명령을 호출할 수 있다.

## 결정 이력

- 초기 권장안은 설정에서 `Command+클릭`과 항상 보이는 누적 버튼 가운데 주 조작을 선택하는 방식이었다.
- 재검토에서는 접근 가능한 버튼이 설정에 따라 사라질 이유가 없고, 보조 키는 기본 동작보다 선택적인 가속 동작에 알맞다는 결론을 얻었다.
- 현재 결정은 누적 버튼을 항상 유지하고 설정은 `Command+클릭` 가속 동작의 사용 여부만 바꾸는 것이다.

## 승인된 결정과 이유

- 각 메모에 누적 버튼을 항상 제공한다.
- 읽기 상태의 메모 복사 영역에서 `metaKey`와 주 포인터 클릭이 함께 들어오면 누적한다.
- 설정 화면에서 이 추가 동작을 켜거나 끌 수 있다.
- 다른 보조 키 조합과 별도 누적 모드는 초기 범위에서 제공하지 않는다.
- 편집 상태와 메모 안의 다른 조작 버튼에서 발생한 클릭은 누적 단축 동작으로 해석하지 않는다.

[UI Events](https://www.w3.org/TR/uievents/)는 마우스 이벤트의 보조 키 상태를 정의하고, [WCAG 키보드 기준](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)은 모든 동작을 키보드로 실행할 수 있어야 한다고 설명한다. 버튼은 포인터, 터치와 키보드가 함께 사용할 수 있는 기본 수단이다.

## 예상 결과와 계획 영향

버튼과 `Command+클릭`은 하나의 누적 명령을 호출한다. 입력 상태를 명령으로 분류하는 순수 판정 규칙에는 TDD를 적용하고, 실제 macOS Safari의 기본 동작과 터치 및 키보드 입력은 브라우저에서 검증한다.

## 다시 검토할 조건

- 누적 버튼 때문에 메모 control이 지나치게 복잡해지는 경우
- 반복 누적에서 버튼과 `Command+클릭`만으로 작업 비용이 높다고 확인되는 경우
- 다른 운영체제용 보조 키 조합을 실제 대상 환경에서 충돌 없이 검증한 경우
