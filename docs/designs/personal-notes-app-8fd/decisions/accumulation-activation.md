# 일괄 복사 실행 동작 결정

넓은 공간형 화면에서는 메모 본문의 `Command+Option+클릭`으로 일괄 복사 목록에 원문을 추가한다. 모바일 목록에서는 평상시 메모를 길게 누르거나 더보기의 `일괄 복사에 추가`를 실행해 현재 작업에 담는다. 헤더 오른쪽의 아이콘과 항목 수 링크는 현재 작업의 확인 페이지를 바로 연다. 별도 수집 상태의 시작과 하단 `다음`은 사용하지 않는다.

## 결정 질문과 요구 결과

[요구사항의 반드시 지킬 조건](../requirements.md#반드시-지킬-조건)은 메모 표면에 일괄 복사 텍스트 버튼을 두지 않으면서 넓은 화면과 작은 화면에서 여러 메모를 선택한 순서대로 복사할 수 있게 한다. 넓은 화면의 보조 키 조합, 작은 화면의 상태 전환, 개별 복사 및 상세 이동과의 우선순위를 정해야 했다.

## 검토한 선택지

- `Command+클릭`을 일괄 복사에 사용하면 새 요구의 개별 복사와 충돌한다.
- `Command+Option+클릭`은 개별 복사 조합을 확장해 두 동작을 구분할 수 있지만 터치 환경에서 사용할 수 없다.
- 각 메모에 일괄 복사 버튼을 반복하면 공간형 메모가 텍스트 중심이어야 한다는 요구와 맞지 않는다.
- 작은 화면에서 메모를 길게 눌러 선택하면 새로 승인된 길게 누르기 개별 복사와 충돌한다.
- 작은 화면의 목록 헤더에서 명시적으로 일괄 복사 상태를 시작하면 평소 짧은 누르기 상세 이동을 유지하면서 상태 안의 짧은 누르기를 항목 추가에 사용할 수 있다.

## 결정 이력

- 초기 권장안은 설정에서 `Command+클릭`과 항상 보이는 일괄 복사 버튼 가운데 주 조작을 고르는 방식이었다.
- 재검토에서는 접근 가능한 버튼을 유지하고 `Command+클릭`을 선택적인 빠른 조작으로 추가했다.
- 화면 사용 검토 뒤 메모 표면의 일괄 복사 버튼과 `누적했습니다` 성공 알림을 제거하고 `Command+클릭`만 남겼다. 당시에는 키보드와 설정을 끈 상태의 대안이 결정되지 않았다.
- 모바일 요구가 처음 추가됐을 때에는 작은 화면에서 길게 누른 메모를 선택하고 다시 짧게 눌러 해제하기로 했다.
- 후속 요구에서 넓은 화면의 `Command+클릭`은 개별 복사로 바뀌고 일괄 복사는 `Command+Option+클릭`으로 옮겨졌다.
- 같은 변경에서 모바일 길게 누르기는 개별 복사, 짧은 누르기는 상세 이동으로 바뀌었다. 일괄 복사는 목록 화면 헤더 아이콘으로 별도 상태를 시작한 뒤 짧게 누른 순서대로 항목을 모으는 방식으로 대체됐다.
- 후속 요구에서 이 상태의 이름을 `일괄 복사 상태`로 확정하고 선택 상태라는 표현을 폐기했다. 평상시 헤더 오른쪽 아이콘으로 시작하며, 상태 안에서는 헤더 왼쪽 뒤로가기와 하단 `초기화` 및 클릭 횟수가 붙은 `다음`을 사용한다.
- 같은 메모를 반복해서 누르면 누른 횟수만큼 별도 항목을 추가하고 클릭 횟수를 증가시키도록 확정했다.
- 후속 요구에서 `다음`은 이번 작업 항목을 순서대로 보여주는 별도 일괄 복사 확인 페이지로 이동하도록 확정했다. 확인 페이지의 재정렬, 복제와 삭제는 원본 메모를 바꾸지 않는다. 당시에는 확인 작업을 저장된 기존 목록에 반영하는 방식이 남아 있었다.
- 사용자에게 보이는 기능명은 `누적 복사` 대신 `일괄 복사`를 사용한다.
- 구현 필수 결정 재검토에서 저장 목록을 이어 쓰는 방식과 별도 작업 초안을 비교했다. 모바일 수집 및 확인은 기존 저장 목록과 합치지 않는 하나의 IndexedDB 작업 초안으로 정하고, 명시적 취소가 아닌 이탈과 새로고침에서는 복원하기로 했다.
- 같은 재검토에서 일괄 복사 상태의 길게 누르기는 평상시의 개별 복사와 입력 의미가 충돌하므로 아무 동작도 실행하지 않기로 했다. 확인 단계의 복제 항목은 대상 바로 뒤에 넣는다.
- 보조 키 클릭 설정을 끈 경우와 pointer를 사용하기 어려운 경우의 추가 입력도 재검토했다. 메모 선택 지점에서 `Command+Option+Enter`를 실행하는 키보드 동작을 항상 제공하고, 설정은 pointer 클릭 조합만 제어하기로 했다.
- `Command` keydown이 선택 ID를 먼저 비우므로 키보드 추가 명령은 선택 ID에 의존할 수 없다는 충돌도 확인했다. 명령 대상은 현재 포커스가 있는 메모 선택 지점의 ID로 정하고, 붉은 선택 테두리가 사라진 뒤에도 같은 key sequence를 완료하게 했다.
- 표시 용어와 내부 이름의 범위도 재검토했다. 새 TypeScript 자료형과 기능에는 `BatchCopy`를 사용하되, 기존 자료를 보존하기 위해 물리 IndexedDB object store `accumulators`는 현재 schema 이름으로 유지하고 repository 연결부에서 변환하기로 했다. 이름만 바꾸기 위한 저장소 migration은 하지 않는다.
- 후속 요구에서 이전 저장소 이름을 유지하는 결정을 폐기했다. 현재 IndexedDB object store는 `batchCopyLists`이며, schema 변경에서는 기존 일괄 복사 record를 보존한 채 저장소 이름을 바꾸고 이전 저장소와 이중 읽기를 남기지 않는다.

## 승인된 결정과 이유

- 저장된 일괄 복사 목록은 `batchCopyLists` object store와 `BatchCopyList` 자료형으로 다룬다. repository와 항목 추가 저장 동작도 `BatchCopy` 이름을 사용하며 이전 저장소 이름은 schema 변경이 끝난 뒤 존재하지 않아야 한다.

### 넓은 공간형 화면

- 각 메모에 일괄 복사 텍스트 버튼을 표시하지 않는다.
- 본문의 주 pointer 클릭에서 `metaKey`와 `altKey`가 모두 참이면 일괄 복사 목록에 현재 원문 스냅샷을 추가한다.
- `metaKey && altKey`를 판정한 뒤 `metaKey && !altKey`인 경우에만 개별 복사를 실행한다.
- 설정 화면에서 `Command+Option+클릭` 일괄 복사 추가를 켜거나 끌 수 있다.
- 포커스가 있는 메모 선택 지점에서 `Command+Option+Enter`를 누르면 그 메모의 현재 원문 스냅샷을 일괄 복사 목록에 추가한다. `Command` keydown으로 선택 ID가 비워져도 포커스 대상 ID를 사용해 같은 key sequence를 완료한다. 이 동작은 pointer 클릭 설정과 관계없이 제공하며 본문 줄바꿈 또는 속성 패널 열기를 함께 실행하지 않는다.
- `Ctrl`, `Shift`, `Option+클릭`만을 자동 대체 조작으로 정하지 않는다.
- 헤더, 헤더 아이콘, 가장자리 및 꼭짓점과 다른 제어에서 시작한 클릭은 일괄 복사 단축 조작으로 해석하지 않는다.
- 성공하면 현재 포커스를 옮기지 않고 일괄 복사 항목과 항목 수만 갱신한다. `72rem` 이상의 첫 추가에서는 너비 `22rem`의 오른쪽 패널을 열고, `48rem` 이상 `72rem` 미만에서는 사용자가 직접 모달 패널을 연다.
- `누적했습니다`와 같은 별도 성공 알림을 표시하거나 읽어주지 않는다.

### 모바일 목록의 현재 조작

- 평상시 목록에서 길게 누르거나 메모 더보기의 추가를 실행하면 당시 원문 스냅샷을 현재 작업의 끝에 한 번 추가한다. 같은 메모를 다시 추가하면 별도 항목으로 담는다. 짧은 터치는 개별 복사로 유지한다.
- 헤더 오른쪽의 아이콘 링크는 별도 수집 상태를 열지 않고 `/batch-copy`의 현재 작업 확인 화면으로 바로 이동한다. 추가를 접수한 뒤 이동해도 앞선 입력 순서와 중복을 보존하고 원본이나 저장 목록을 바꾸지 않는다.
- 링크에는 현재 작업의 실제 항목 수를 표시하고 보조 기술에도 전달한다. 복제와 삭제 후의 수를 반영하며 누적 클릭 횟수를 그대로 표시하지 않는다. 별도 수집 헤더와 하단 `다음`은 제거한다. 확인 화면 하단에는 초기화를 두지 않고 취소로 현재 작업을 비운 뒤 메인 목록으로 돌아간다. 헤더 뒤로가기는 작업을 유지한다.
- 항목 수는 아이콘 오른쪽 아래에 겹친 붉은 원형 배지 안에 흰색 숫자로 표시한다. 0개일 때에는 숫자와 붉은 배경을 함께 숨기고 아이콘을 유지하되 링크를 비활성화한다. 터치, 클릭과 키보드 이동을 모두 막고 보조 기술에도 비활성 상태와 항목 수를 전달한다. 초기화 후 다시 추가하면 실제 항목 수로 배지를 표시하고 링크를 활성화한다. 빈 현재 작업 확인 화면을 여는 초기 제안은 적용하지 않는다.
- 추가 성공의 항목 수 반영과 사용 횟수 기록은 기존 성공 조건을 따른다. 저장이 진행되는 동안 메모 목록 전체를 깜빡이거나 연속 추가를 누락하지 않으며 실패하면 같은 작업에서 재시도할 수 있어야 한다.
- 확인 페이지의 편집은 실행 중 작업 사본만 바꾸고 원본 메모, 메모 revision과 사용 횟수를 바꾸지 않는다.
- 현재 작업은 저장된 기존 목록과 분리한다. 앱 내부 이동과 확인 화면의 뒤로가기에서는 항목과 순서를 유지하고, 새로고침이나 브라우저 재실행에서는 복원하지 않는다. 확인 페이지의 `취소`는 현재 작업을 버리고 목록으로 돌아간다. 저장 목록 관리의 Drawer 링크와 직접 URL 접근은 기존 동작을 유지한다.
- 확인 페이지에서 복제한 항목은 대상 바로 뒤에 새 ID로 넣는다. 전체 복사 성공 뒤에는 확인 작업을 유지해 다시 편집하거나 복사할 수 있게 한다.
- 현재 작업의 항목 수와 추가된 메모를 색 하나에만 의존하지 않게 표시하고 보조 기술에 전달한다.

[UI Events](https://www.w3.org/TR/uievents/)는 `metaKey`와 `altKey`를 정의하고, [Pointer Events Level 3](https://www.w3.org/TR/pointerevents3/)은 짧은 누르기, 길게 누르기와 취소를 같은 pointer sequence에서 판정할 수 있게 한다. [Apple toolbar 지침](https://developer.apple.com/design/human-interface-guidelines/toolbars)은 modal state에서 현재 작업에 맞는 도구를 제공하고 종료 시 원래 도구를 복원하도록 안내한다. 수집 단계의 세부 조사는 [메모 조작과 모바일 일괄 복사 조사](../references/note-interaction-and-mobile-batch-copy-research.md), 확인 단계는 [모바일 일괄 복사 확인과 오른쪽 패널 우선순위 조사](../references/mobile-batch-copy-confirmation-and-panel-priority-research.md)에 기록했다.

## 예상 결과와 계획 영향

기존 `metaClickEnabled`처럼 `Command+클릭` 의미가 드러나는 preference는 새 조합의 의미를 표현하지 못한다. 자료 migration에서 `batchCopyShortcutEnabled`와 `batchCopyLists`로 바꾼다. 넓은 화면의 modifier 판정, Clipboard 및 IndexedDB transaction은 application command와 브라우저 통합 검증으로 나누고, 두 명령이 한 클릭에서 함께 실행되지 않는지 확인한다. schema 변경 뒤 `objectStoreNames`와 저장된 항목 및 순서를 확인해 이전 저장소가 남지 않고 자료가 보존됐는지 판정한다.

모바일은 별도 수집 모드 대신 평상시 목록의 길게 누르기와 더보기로 항목을 담고 헤더 링크로 확인 페이지를 연다. 기존 시작, 수집 및 확인 상태의 사용처를 다시 확인하며 현재 작업을 잃지 않게 전환한다. 추가 순서, 반복 추가, 실제 항목 수, 초기화와 작업 사본 수명의 순수 규칙은 TDD 후보이며 터치, 페이지 이동, 핸들 및 헤더 표시는 실제 브라우저에서 확인한다. [모바일 메모와 고정 높이 바텀 시트](../references/mobile-note-sheet-design.md)는 현재 코드와 시안의 차이 및 구현 전에 확인할 조건을 설명한다.

## 다시 검토할 조건

- `Command+Option+클릭`이 지원 브라우저나 운영체제 기본 동작과 반복해서 충돌하는 경우
- 설정을 끈 넓은 화면 또는 키보드 환경에서 일괄 복사를 시작할 수 없어 접근성 완료 조건을 충족하지 못하는 경우
- 작은 화면의 일괄 복사 상태가 평소 상세 이동과 구분되지 않는 경우
- 일괄 복사 상태의 헤더 뒤로가기 또는 하단 작업 영역이 320 CSS px 및 확대 화면에서 메모와 포커스를 가리는 경우
- 모바일 작업 초안의 복원이나 명시적 취소가 기존 저장 목록을 예기치 않게 바꾸는 경우
