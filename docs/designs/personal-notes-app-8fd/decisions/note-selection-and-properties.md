# 메모 선택과 오른쪽 속성 패널 결정

넓은 공간형 화면에서는 한 번의 헤더 클릭과 `Tab` 탐색이 메모 하나를 선택하고 메모 전체를 감싸는 굵은 붉은 실선 테두리만 새로 표시한다. 이동으로 판정되지 않은 헤더 더블클릭과 선택 지점에 포커스가 있는 선택된 메모의 `Enter`가 오른쪽 속성 패널을 연다. 빈 캔버스 클릭과 `Command`는 메모 선택을 해제한다. 상위 임시 조작이 없는 `Escape`는 메모와 일괄 복사 항목 선택을 함께 해제한다.

상단 제어와 메모 선택 지점의 양의 `tabindex` 범위를 분리하며 `zIndex`와 섞지 않는다. 속성 패널의 위치는 고정 캔버스와 분리하고 크기 제한은 유지한다. 메모 선택, 일괄 복사 항목 선택, 속성 패널 대상과 마지막으로 활성화한 오른쪽 패널은 서로 다른 실행 중 상태로 다룬다.

## 결정 질문과 요구 결과

[메모 선택 및 속성 편집 요구사항](../requirements.md#반드시-지킬-조건)은 한 번의 헤더 클릭, 더블클릭, 헤더 drag, `Enter`, 선택 해제, `Command` 보조 키 복사와 키보드 탐색이 각각 실행하는 동작을 분리한다. 메모마다 설정 UI를 반복하지 않고 오른쪽 패널에서 위치와 크기를 바꾸되, 이동을 시작한 pointer 연속 입력이 선택이나 패널 활성화로 이어져 캔버스 크기를 바꾸지 않아야 한다.

## 검토한 선택지

- 메모마다 X, Y, 너비와 높이 입력을 두면 메모 표면이 텍스트 중심이어야 한다는 요구를 다시 위반한다.
- 가장자리와 꼭짓점 drag만 유지하면 키보드로 정확한 수치를 입력할 방법이 없다.
- 선택한 메모의 속성만 오른쪽 패널에 표시하면 메모 표면을 단순하게 유지하면서 같은 위치에서 수치 값을 편집할 수 있다.
- 포커스와 선택을 같은 테두리 하나로 표현하면 속성 패널로 포커스를 옮겼을 때 어떤 메모를 편집하는지와 현재 키보드 위치를 구분할 수 없다.
- 한 번의 헤더 클릭에서 속성 패널까지 열면 drag를 시작하려는 pointer 입력도 선택과 패널 전환을 일으킬 수 있고, 오른쪽 열의 출현으로 캔버스 크기가 바뀔 수 있다.
- 한 번 클릭한 뒤 선택 표시를 늦추고 더블클릭 여부를 기다리면 모든 선택에 운영체제의 더블클릭 시간만큼 지연이 생긴다. 브라우저가 단일 `click` 뒤 `dblclick`을 따로 보내므로 선택은 즉시 처리하고 패널 활성화만 `dblclick`에서 처리할 수 있다.
- `Command` 상태에서 헤더 요소를 레이아웃에서 제거하면 본문과 메모 외곽 크기가 움직인다. 헤더의 자리는 유지하면서 보이지 않고 조작할 수 없게 만드는 편이 복사 입력과 화면 안정성을 함께 지킨다.
- 메모 선택 지점의 `Enter`를 상위 메모 전체나 전역에서 처리하면 본문 줄바꿈, 헤더 아이콘과 속성 입력의 고유 동작을 함께 실행할 수 있다. 포커스가 선택 지점 자체에 있고 입력기 조합 중이 아닐 때만 속성 패널 활성화를 처리해야 한다.
- 빈 캔버스 클릭을 캔버스의 상위 click handler에서 무조건 처리하면 메모와 패널의 하위 조작에서 전파된 클릭도 선택을 해제한다. 빈 배경 자체에서 이동 없이 끝난 클릭만 선택 해제 입력으로 판정해야 한다.

## 결정 이력

- 이전 결정은 메모 표면의 숫자 geometry 제어를 제거하고 네 가장자리와 네 꼭짓점 drag로만 크기를 바꾸는 것이었다.
- 후속 요구는 마우스를 사용하기 어려운 사용자가 `Tab`과 헤더 클릭으로 메모를 선택하고, 오른쪽 패널에서 크기와 좌표를 바꾸도록 했다.
- 이 변경은 메모 표면에 설정 UI를 되돌리지 않는다. 직접 resize와 별도로 속성 패널 대상 메모의 수치 geometry를 편집하는 방법을 추가한다.
- 선택 표시는 얇은 붉은 테두리로 승인됐고, 키보드 포커스는 접근성 기준에 따라 별도 표시를 유지한다.
- 후속 요구에서 Tab 순서는 시각적 겹침 우선순위가 아니라 각 메모의 양의 `tabindex`를 따르도록 변경됐다. 맨 앞으로 또는 맨 뒤로 보내기는 이 값을 바꾸지 않는다.
- 같은 변경에서 속성 패널과 일괄 복사 패널은 마지막으로 활성화한 패널 하나만 표시하고, 패널 전환으로 숨겨진 자료를 지우지 않도록 확정했다.
- 좌표와 크기의 새 입력은 `0`보다 커야 하고 애플리케이션 상한을 넘을 수 없다고 정했지만 정확한 수치와 기존 `0` 좌표 record의 migration은 남아 있었다.
- 이전 요구에서 한 번의 헤더 클릭은 얇은 붉은 선택 테두리만 표시하고, 헤더 더블클릭만 속성 패널을 열도록 바뀌었다. 헤더 drag는 선택과 패널 활성화를 실행하지 않으며 drag 중 패널 전환으로 캔버스 크기를 바꾸지 않는다.
- 같은 요구에서 `Command`를 누르는 동안 헤더를 보이지 않게 해 본문 복사 및 일괄 복사 입력이 메모 선택으로 이어지지 않도록 했다. 헤더의 자리는 유지해 메모 크기와 본문 위치는 바꾸지 않는다.
- 이 변경으로 `Tab` 선택과 속성 패널 활성화를 자동으로 묶지 않는다.
- 최신 요구에서 `Tab`으로 선택 지점에 도달해 선택된 메모의 보조 키 없는 `Enter`를 더블클릭과 동등한 속성 패널 진입 동작으로 확정했다. 빈 캔버스 클릭, 보조 키 없는 `Escape`와 `Command`는 메모 선택만 해제하도록 확정했다.
- 구현 필수 결정 재검토에서 양의 `tabindex`가 네이티브 순서를 앞서는 위험을 확인했다. 명시된 양수 요구를 유지하되 상단 탐색 및 주 작업 제어는 `1..999`, 메모 선택 지점은 `1000..32767`로 분리하고 메모 값만 저장하기로 했다.
- 같은 재검토에서 속성 입력 범위, 이전 자료 보정, 패널을 연 입력별 포커스, 패널 닫기 결과와 선택 및 패널 대상의 시각 구분을 확정했다. 제품 수치인 geometry 범위는 실제 화면 검증에서 다시 볼 조건을 남겼다.
- Pointer Events와 Android touch slop, Atlassian의 웹 drag 사례를 비교해 헤더 이동과 빈 캔버스 시점 이동은 mouse 및 pen `5 CSS px`, touch `10 CSS px`를 넘은 뒤 시작하도록 정했다. 브라우저와 운영체제의 더블클릭 판정은 별도 타이머로 다시 만들지 않는다.
- 2026년 9월 3일 화면 검토에서 얇은 선택 테두리가 헤더와 꼭짓점에서 끊기고, 고정 높이 상한 때문에 위쪽 가장자리 resize가 조기에 멈추는 문제가 확인됐다. 선택 테두리는 메모 전체를 감싸는 굵은 실선으로 바꾸고, 메모 크기 상한은 작은 고정값 대신 논리 캔버스 경계에서 계산하도록 변경했다.
- 같은 검토에서 운영체제의 `Shift+Command+5` 뒤 `Command` keyup을 받지 못해 헤더가 계속 숨는 문제가 확인됐다. 창과 문서가 다시 활성화될 때와 다음 신뢰할 수 있는 입력에서도 헤더 상태를 복원하고, 실제 복사 조합은 해당 event의 modifier 값으로 판정하도록 변경했다.
- 후속 요구에서 메모와 일괄 복사 항목이 각각 선택될 수 있고, 상위 임시 조작이 없을 때 `Escape`가 두 선택을 한 번에 해제하도록 변경됐다. 빈 캔버스 클릭과 `Command`는 기존처럼 메모 선택에만 적용한다.
- 운영체제 단축키를 추가 조사한 결과 문서가 계속 `visible`일 수 있고, Sticky Keys와 modifier 재지정으로 물리 키 입력 순서도 달라질 수 있음을 확인했다. 헤더 상태는 의미가 `Meta`인 신뢰할 수 있는 event로 다시 맞추며 합성 event나 한 번 저장한 전역 modifier 값에 의존하지 않는다.
- 2026년 9월 4일 코드 검토에서 pointer 종료 event가 누락되면 캔버스 pan 시작 자료가 남아 다음 hover에서 시점 이동을 재개할 수 있음을 확인했다. 창과 문서의 비활성화 및 재활성화, 주 버튼이 풀린 pointer 이동과 다음 pointer 시작을 보조 종료 신호로 사용하되 마지막으로 표시한 시점은 유지하기로 했다.
- 같은 날 Playwright WebKit 교차검증에서 `buttons`와 `pressure`를 함께 사용한 보조 판정이 정상 mouse drag를 중단시켰다. 두 속성은 종료 증거에서 제외하고 pointer 수명 event, 창과 문서 재진입 및 다음 pointer 시작으로 남은 제스처를 정리하기로 했다.
- 이어진 교차검증에서는 창 `focus`를 단독 종료 신호로 사용해도 WebKit의 첫 mouse 입력이 취소됐다. `focus`는 캔버스 pan 종료 조건에서 제외하고 창 `blur`, `pageshow`, 양방향 `visibilitychange`, pointer 수명 event와 다음 pointer 시작을 사용하기로 했다.
- 2026년 9월 12일 브라우저 검증에서 보조 키를 누른 본문 pointer 입력이 실제 focus를 옮기지 않아도 pointer 포커스 상태를 남기는 문제가 확인됐다. 보조 키 없는 primary pointer만 pointer 상태를 기록하고, 그 상태가 없는 `focus`에서는 키보드 포커스 표시를 복원하기로 했다.
- 같은 검증에서 멀리 떨어진 메모를 전체 맞춤할 때 저장 좌표 차이를 CSS `left`에 먼저 넣고 부모 배율을 적용하면 브라우저의 CSS 좌표 한계로 메모가 겹치는 문제가 확인됐다. 화면 배율을 상대 좌표에 먼저 적용하고 보드는 시점 이동만 변환하도록 정해 저장 좌표와 화면 좌표를 분리한다.
- 안전 수치 범위를 넘는 이동 또는 크기 계산은 pointer event에서 예외를 전파하지 않고 현재 gesture, 미리보기와 pointer capture를 정리한 뒤 저장하지 않도록 정했다. 저장된 geometry와 revision은 유지하고 실패 안내를 표시한다.

## 승인된 결정과 이유

위치 제한 제거는 이전 고정 캔버스 및 양수 좌표 결정을 대체한다. 근거와 추가 이슈는 [좌표 제한 제거 조사](../references/free-note-placement-research.md)를 따른다.

- 한 번에 메모 하나만 선택하고, 속성 패널도 한 번에 메모 하나만 편집한다. 선택한 메모와 속성 패널 대상은 서로 다른 상태로 유지할 수 있다.
- 상단 탐색과 새 메모 및 일괄 복사 같은 주 작업 제어에는 `1..999`의 양의 `tabindex`를 DOM 의미 순서대로 부여한다. 메모 선택 지점은 저장된 `1000..32767` 값을 사용한다. `Tab`은 낮은 값부터 높은 값 순으로, `Shift+Tab`은 반대로 이동한다. 본문, 헤더 아이콘과 패널 입력은 양수 구간 뒤에 네이티브 DOM 순서로 탐색한다.
- 첫 메모의 `tabIndex`는 `1000`이고 새 메모는 현재 최댓값 다음 값을 받는다. 누락, 중복, 정수가 아닌 값 또는 범위 밖 값이 있으면 기존 유효 값, 생성 시각과 ID 순으로 안정 정렬한 뒤 `1000`부터 빈틈없이 다시 배정한다. 이 변경은 `zIndex`를 읽거나 바꾸지 않는다.
- 헤더의 아이콘이 아닌 부분을 한 번 클릭해도 같은 메모를 선택한다.
- `zIndex`는 시각적 겹침만 나타낸다. 맨 앞으로 또는 맨 뒤로 보내기와 선택 표시를 위한 일시적 layer 변경은 `tabindex`를 바꾸지 않는다.
- 이동으로 판정되지 않은 한 번의 헤더 클릭은 선택과 선택 테두리만 바꾸며 속성 패널을 새로 열거나 대상으로 바꾸지 않는다. 메모 원문 개별 복사와 일괄 복사 항목 추가도 실행하지 않는다.
- 이동으로 판정되지 않은 헤더 더블클릭은 더블클릭한 메모를 선택하고 속성 패널을 그 메모 대상으로 활성화한다. 별도 클릭 지연 타이머를 만들지 않고 브라우저의 `dblclick` 판정을 사용한다.
- `Tab`으로 포커스가 도달해 선택된 메모의 선택 지점에서 보조 키 없는 `Enter`를 누르면 속성 패널 대상과 최근 활성 패널을 해당 메모와 `note-properties`로 바꾼다. 포커스 도달만으로는 패널을 열지 않는다.
- 선택 지점의 `Enter`로 속성 패널을 열면 첫 X 입력으로 포커스를 옮긴다. pointer 헤더 더블클릭으로 열면 브라우저가 정한 현재 pointer 포커스를 유지한다.
- 속성 패널 활성화용 `Enter`는 선택 지점 자체에 포커스가 있을 때만 처리한다. 메모 본문, 헤더 아이콘 버튼, 크기 조절 지점, 패널 입력과 다른 하위 조작 요소의 `Enter`는 전파로 활성화하지 않고, 입력기 조합 중이거나 키가 반복되는 event도 처리하지 않는다.
- 메모와 다른 조작 요소가 아닌 빈 캔버스에서 이동 없이 끝난 클릭은 메모 선택 ID를 비우고 캔버스 viewport로 포커스를 옮긴다. 하위 요소에서 전파된 클릭은 선택을 해제하지 않는다.
- drag, 열린 항목 동작 선택창이나 다른 상위 임시 조작이 없을 때 보조 키 없는 `Escape`는 메모 선택 ID와 일괄 복사 항목 선택 ID를 함께 비우고 현재 포커스를 유지한다. 모달 일괄 복사 패널에 선택이 남아 있으면 이 동작을 먼저 수행하고, 선택이 없는 다음 `Escape`가 모달을 닫는다.
- `Command` keydown은 선택 ID를 비우고 헤더 비노출 상태를 시작한다. 숨겨질 헤더 아이콘에 포커스가 있으면 같은 메모의 선택 지점으로 먼저 옮기고, 그 밖의 포커스는 유지한다. 이 event의 기본 동작을 막지 않으며 `keyup`, 창의 포커스 상실 및 회복, 문서 숨김 및 다시 표시와 다음 신뢰할 수 있는 입력에서 헤더 상태를 복원한다. 복원해도 해제된 선택을 되살리지 않는다.
- 선택 해제는 대응하는 붉은 선택 테두리만 제거한다. 속성 패널 대상, 속성 초안, 최근 활성 패널, 일괄 복사 항목과 순서는 그대로 유지한다.
- 헤더 drag는 pointer capture로 이어가며 시작점부터 mouse 및 pen `5 CSS px`, touch `10 CSS px`를 넘은 뒤에만 위치를 바꾼다. 선택과 활성 패널을 바꾸지 않고 같은 연속 입력 뒤의 `click`과 `dblclick`은 무시하며, drag가 끝나거나 취소될 때까지 오른쪽 패널의 표시 여부와 캔버스 계산 크기를 애플리케이션 동작으로 바꾸지 않는다.
- 빈 캔버스 pan은 `pointerup`, `pointercancel`, `lostpointercapture`, 창 `blur`, `pageshow` 및 양방향 `visibilitychange`에서 마지막 시점을 유지한 채 종료한다. 새 pointer 입력이 시작될 때에도 남은 제스처를 먼저 정리하며 이전 시작점에서 이동을 재개하지 않는다. 창 `focus`만으로는 활성 pan을 종료하지 않는다.
- 선택한 메모에는 메모 전체의 네 변과 네 꼭짓점에서 끊기지 않고 일반 경계보다 굵은 붉은 실선 테두리를 표시한다. 선택 테두리는 포커스 외곽선을 대신하지 않으며 고대비 환경에서도 선택과 포커스를 각각 구분할 수 있어야 한다. 보조 키 클릭 뒤 `Tab` 또는 `Shift+Tab`으로 본문에 진입한 경우에도 키보드 포커스 표시를 숨기지 않는다.
- 속성 패널 대상에는 선택 테두리 바깥의 중립색 점선 표시를 사용하고, 패널 머리에는 대상 메모 원문의 첫 비어 있지 않은 줄을 잘라 표시한다. 선택된 메모와 패널 대상이 다르거나 같을 때에도 실선 선택, 점선 패널 대상과 포커스 표시를 색에만 의존하지 않고 구분한다.
- 속성 패널로 포커스를 옮겨도 메모 선택을 유지한다.
- 메모 선택 ID와 속성 패널 대상 ID를 분리한다. 헤더 더블클릭 또는 선택된 메모의 선택 지점에서 실행한 `Enter`는 속성 패널 대상과 최근 활성 패널을 함께 바꾸고, `Command+Option+클릭`, 일괄 복사 항목 추가 또는 일괄 복사 제어 실행은 일괄 복사 패널을 활성화한다. 마지막으로 활성화한 패널만 오른쪽 영역에 표시한다.
- 한 번의 헤더 클릭과 `Tab` 선택은 최근 활성 패널을 바꾸지 않는다. 일괄 복사 패널이 보일 때 이 입력만으로 속성 패널로 전환하지 않는다.
- 패널 전환은 선택한 메모, 속성 패널 대상, 속성 초안, 일괄 복사 항목과 제거 이력을 지우지 않는다. 전환 계기가 속성 입력의 `blur` 또는 패널 밖 클릭을 만들면 같은 검증 및 적용 동작을 먼저 사용한다.
- 최근 활성 오른쪽 패널을 닫으면 이전 패널을 다시 표시하지 않고 활성 패널을 비운다. 패널 자료와 이력은 지우지 않는다.
- `Command`가 눌린 동안 선택을 해제하고 헤더의 시각 요소와 아이콘 조작을 숨기되 기존 헤더 높이를 유지한다. 메모 본문의 `Command+클릭`과 `Command+Option+클릭`은 메모를 다시 선택하거나 속성 패널 대상과 최근 활성 패널을 메모 선택 동작으로 바꾸지 않는다. 복사 동작은 해당 click 또는 pointer event의 `metaKey`와 `altKey`를 사용한다. `keyup`, 창과 문서의 비활성화 및 재활성화와 다음 신뢰할 수 있는 입력으로 보조 키 표시 상태가 끝나면 헤더만 복원한다.
- 오른쪽 속성 패널의 현재 범위는 작업 공간 좌표 X와 Y, 너비와 높이다. 회전, 정렬, 비율 잠금과 수식 입력은 포함하지 않는다.
- 필드 입력은 저장된 geometry와 분리한 초안이다. `blur`, 패널 밖 클릭과 `Enter`는 같은 적용 명령을 사용하고, 유효하며 실제로 달라진 값만 한 번 저장한다.
- X와 Y의 양수 및 고정 상한 조건을 제거한다. 위치는 음수, 0과 이전 캔버스 바깥도 허용한다. 너비 `240..4095`와 높이 `180..4095`는 위치와 독립적으로 유지한다. 입력과 저장에서 유한성 및 계산 정밀도를 확인하고, 크기 조절은 반대편 변을 고정한다. 화면에는 카메라 원점과의 차이에 배율을 먼저 적용한 좌표를 사용하며, 계산이 안전 수치 범위를 넘으면 기존 geometry를 유지한다.
- 유효하지 않은 초안은 메모 geometry와 revision을 바꾸지 않고 오류가 난 필드에서 수정할 수 있게 표시한다. `blur`나 패널 밖 클릭은 포커스 이동 자체를 가로채지 않으며, `Enter`는 현재 오류 입력에 포커스를 유지한다.
- 패널 닫기 전에 유효하고 달라진 초안은 같은 적용 명령으로 한 번 저장한다. 유효하지 않은 초안이 있으면 패널을 유지하고 첫 오류 입력으로 포커스를 옮긴다. 사용자가 `저장값으로 되돌리기`를 실행한 뒤에만 잘못된 초안을 버리고 닫을 수 있다. 상위 임시 조작이 없는 `Escape`는 메모와 일괄 복사 항목 선택만 해제하며 패널 대상과 초안을 바꾸지 않는다.
- 기존 메모의 위치와 크기는 변경 없이 읽는다. 예전 0 좌표의 양수 보정과 캔버스 안으로 옮기는 보정은 새 위치 저장에 적용하지 않는다. 이미 소실된 과거 좌표를 추정하지 않으며, 좌표 정책 변경만으로 원문이나 revision을 올리지 않는다.
- 속성 패널에서 적용한 geometry 변경은 전체 revision만 증가시키고 content revision을 바꾸지 않는다.
- 가장자리와 꼭짓점 drag에 의한 직접 크기 조절을 계속 제공한다. 위쪽과 왼쪽을 포함한 resize는 좌표와 독립된 너비 및 높이 범위에서 반대편 변을 고정한다. 메모 표면에는 숫자 입력, 단계 조절 또는 설정 버튼을 추가하지 않는다.

## 예상 결과와 계획 영향

### 메모 선택선과 본문 포커스 표시

메모를 선택했을 때에는 헤더와 본문을 포함한 네 변과 네 모서리에 같은 두께의 붉은 실선이 이어져야 한다. 헤더 배경이나 본문이 선을 가리지 않아야 하며, 선택 전후에 메모의 크기와 본문 위치는 바뀌지 않아야 한다. 크기 조절을 시작하는 가장자리와 꼭짓점은 선택선 위에서도 조작할 수 있어야 한다.

본문을 마우스, 펜 또는 터치로 누를 때에는 파란 외곽선을 표시하지 않는다. 키보드로 본문에 도달하면 선택선과 겹치지 않는 포커스 표시를 제공한다. 선택선, 키보드 포커스와 속성 패널 대상의 점선은 같은 메모에 함께 나타나도 각각 구분할 수 있어야 한다. 전역 포커스 표시를 없애거나 본문 입력과 텍스트 선택을 막는 방법으로 처리하지 않는다.

U4에서 선을 그리는 순서와 포커스 스타일을 정리하고, U5에서 본문에 도달한 입력 방식과 기존 편집 동작을 연결한다. U11에서 화면 배율, 고대비 표시와 가장자리 조작을 함께 확인한다. 세부 수정과 완료 판정은 [실행 계획](../plan.md#메모-테두리-수정-순서)의 절차를 따른다.

### 기존 상호작용과 저장

U2는 `tabindex`, 메모 및 일괄 복사 항목 선택 ID, 속성 패널 대상 ID, 활성 오른쪽 패널, geometry 입력 초안과 적용 결과를 표현할 자료를 정한다. U4는 두 대상에 공통 의미를 갖는 붉은 선택 테두리, 별도 포커스 표시, `Command` 상태의 헤더 비노출과 오른쪽 패널의 공통 외형을 만든다. U5는 한 번의 헤더 클릭, `dblclick`, 선택 지점의 `Enter`, 빈 캔버스 클릭과 `Escape`, drag 판정, `tabindex` 순서의 Tab 선택, 드래그 중 캔버스 크기 유지, 최근 활성 패널 전환, X, Y, 너비 및 높이 입력과 geometry 저장을 연결한다. U6은 `Command`가 메모 선택을 해제하고 헤더를 숨기며 본문 복사가 선택으로 전파되지 않게 한다. U7은 일괄 복사 항목 선택, 방향키 재정렬과 두 선택을 함께 해제하는 `Escape`를 연결한다. 순수 선택 및 패널 전이, 입력 검증과 revision 불변 조건은 TDD로 개발하고 실제 이벤트 전파, 입력기 조합, 보조 키, pointer capture, 레이아웃 크기와 포커스는 브라우저에서 확인한다.

## 다시 검토할 조건

- 양의 `tabindex` 범위 때문에 상단 탐색, 메모 본문이나 헤더 아이콘에 도달하는 순서가 비논리적인 경우
- 붉은 선택 테두리와 키보드 포커스를 구분할 수 없는 경우
- 패널 밖 클릭이 같은 값을 두 번 저장하거나 새 메모 선택을 잃게 하는 경우
- 큰 좌표, 확대 및 메모 전체 맞춤에서 저장 위치와 화면 위치를 구분하기 어렵거나 계산 정밀도가 부족한 경우
- 속성 패널 대상의 점선 표시와 선택 및 포커스 표시를 함께 구분할 수 없는 경우
- `Command`를 누른 순간 헤더 아이콘에 키보드 포커스가 있을 때 포커스 표시와 복원 결과를 실제 브라우저에서 확인하지 못한 경우
