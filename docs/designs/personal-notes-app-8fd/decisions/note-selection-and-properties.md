# 메모 선택과 오른쪽 속성 패널 결정

넓은 공간형 화면에서는 한 번의 헤더 클릭과 `Tab` 탐색이 메모 하나를 선택하고 얇은 붉은 테두리만 새로 표시한다. 이동으로 판정되지 않은 헤더 더블클릭이 선택한 메모의 오른쪽 속성 패널을 연다. 헤더 drag 중에는 선택이나 패널 활성화를 실행하지 않고 애플리케이션의 패널 전환 때문에 캔버스 크기가 달라지지 않게 한다. `Command`를 누르는 동안에는 헤더의 자리와 메모 외곽 크기를 유지한 채 헤더와 아이콘을 숨기고 조작을 막는다. 메모 선택, 속성 패널의 대상과 마지막으로 활성화한 오른쪽 패널은 서로 다른 실행 중 상태로 다룬다.

## 결정 질문과 요구 결과

[메모 선택 및 속성 편집 요구사항](../requirements.md#반드시-지킬-조건)은 한 번의 헤더 클릭과 더블클릭, 헤더 drag, `Command` 보조 키 복사와 키보드 탐색이 각각 실행하는 동작을 분리한다. 메모마다 설정 UI를 반복하지 않고 오른쪽 패널에서 위치와 크기를 바꾸되, 이동을 시작한 pointer 연속 입력이 선택이나 패널 활성화로 이어져 캔버스 크기를 바꾸지 않아야 한다.

## 검토한 선택지

- 메모마다 X, Y, 너비와 높이 입력을 두면 메모 표면이 텍스트 중심이어야 한다는 요구를 다시 위반한다.
- 가장자리와 꼭짓점 drag만 유지하면 키보드로 정확한 수치를 입력할 방법이 없다.
- 선택한 메모의 속성만 오른쪽 패널에 표시하면 메모 표면을 단순하게 유지하면서 같은 위치에서 수치 값을 편집할 수 있다.
- 포커스와 선택을 같은 테두리 하나로 표현하면 속성 패널로 포커스를 옮겼을 때 어떤 메모를 편집하는지와 현재 키보드 위치를 구분할 수 없다.
- 한 번의 헤더 클릭에서 속성 패널까지 열면 drag를 시작하려는 pointer 입력도 선택과 패널 전환을 일으킬 수 있고, 오른쪽 열의 출현으로 캔버스 크기가 바뀔 수 있다.
- 한 번 클릭한 뒤 선택 표시를 늦추고 더블클릭 여부를 기다리면 모든 선택에 운영체제의 더블클릭 시간만큼 지연이 생긴다. 브라우저가 단일 `click` 뒤 `dblclick`을 따로 보내므로 선택은 즉시 처리하고 패널 활성화만 `dblclick`에서 처리할 수 있다.
- `Command` 상태에서 헤더 요소를 레이아웃에서 제거하면 본문과 메모 외곽 크기가 움직인다. 헤더의 자리는 유지하면서 보이지 않고 조작할 수 없게 만드는 편이 복사 입력과 화면 안정성을 함께 지킨다.

## 결정 이력

- 이전 결정은 메모 표면의 숫자 geometry 제어를 제거하고 네 가장자리와 네 꼭짓점 drag로만 크기를 바꾸는 것이었다.
- 후속 요구는 마우스를 사용하기 어려운 사용자가 `Tab`과 헤더 클릭으로 메모를 선택하고, 오른쪽 패널에서 크기와 좌표를 바꾸도록 했다.
- 이 변경은 메모 표면에 설정 UI를 되돌리지 않는다. 직접 resize와 별도로 속성 패널 대상 메모의 수치 geometry를 편집하는 방법을 추가한다.
- 선택 표시는 얇은 붉은 테두리로 승인됐고, 키보드 포커스는 접근성 기준에 따라 별도 표시를 유지한다.
- 후속 요구에서 Tab 순서는 시각적 겹침 우선순위가 아니라 각 메모의 양의 `tabindex`를 따르도록 변경됐다. 맨 앞으로 또는 맨 뒤로 보내기는 이 값을 바꾸지 않는다.
- 같은 변경에서 속성 패널과 일괄 복사 패널은 마지막으로 활성화한 패널 하나만 표시하고, 패널 전환으로 숨겨진 자료를 지우지 않도록 확정했다.
- 좌표와 크기의 새 입력은 `0`보다 커야 하고 애플리케이션 상한을 넘을 수 없다. 정확한 상한과 기존 `0` 좌표 record의 migration은 아직 정하지 않았다.
- 최신 요구에서 한 번의 헤더 클릭은 얇은 붉은 선택 테두리만 표시하고, 헤더 더블클릭만 속성 패널을 열도록 바뀌었다. 헤더 drag는 선택과 패널 활성화를 실행하지 않으며 drag 중 패널 전환으로 캔버스 크기를 바꾸지 않는다.
- 같은 요구에서 `Command`를 누르는 동안 헤더를 보이지 않게 해 본문 복사 및 일괄 복사 입력이 메모 선택으로 이어지지 않도록 했다. 헤더의 자리는 유지해 메모 크기와 본문 위치는 바꾸지 않는다.
- 이 변경으로 `Tab` 선택과 속성 패널 활성화를 자동으로 묶지 않는다. 더블클릭과 동등한 키보드 패널 진입 동작은 접근성 기준에 맞춰 별도로 승인해야 한다.

## 승인된 결정과 이유

- 한 번에 메모 하나만 선택하고, 속성 패널도 한 번에 메모 하나만 편집한다. 선택한 메모와 속성 패널 대상은 서로 다른 상태로 유지할 수 있다.
- 각 메모 선택 지점에는 메모 사이의 탐색 순서를 나타내는 양의 `tabindex`를 지정한다. `Tab`은 낮은 값부터 높은 값 순으로, `Shift+Tab`은 반대로 이동한다. 헤더의 아이콘이 아닌 부분을 한 번 클릭해도 같은 메모를 선택한다.
- `zIndex`는 시각적 겹침만 나타낸다. 맨 앞으로 또는 맨 뒤로 보내기와 선택 표시를 위한 일시적 layer 변경은 `tabindex`를 바꾸지 않는다.
- 이동으로 판정되지 않은 한 번의 헤더 클릭은 선택과 선택 테두리만 바꾸며 속성 패널을 새로 열거나 대상으로 바꾸지 않는다. 메모 원문 개별 복사와 일괄 복사 항목 추가도 실행하지 않는다.
- 이동으로 판정되지 않은 헤더 더블클릭은 더블클릭한 메모를 선택하고 속성 패널을 그 메모 대상으로 활성화한다. 별도 클릭 지연 타이머를 만들지 않고 브라우저의 `dblclick` 판정을 사용한다.
- 헤더 drag는 pointer capture로 이어가며 선택과 활성 패널을 바꾸지 않는다. 이동 기준을 넘은 연속 입력 뒤의 `click`과 `dblclick`은 무시하고, drag가 끝나거나 취소될 때까지 오른쪽 패널의 표시 여부와 캔버스 계산 크기를 애플리케이션 동작으로 바꾸지 않는다.
- 선택한 메모에는 얇은 붉은 테두리를 표시한다. 선택 테두리는 포커스 외곽선을 대신하지 않으며 고대비 환경에서도 선택과 포커스를 각각 구분할 수 있어야 한다.
- 속성 패널로 포커스를 옮겨도 메모 선택을 유지한다.
- 메모 선택 ID와 속성 패널 대상 ID를 분리한다. 헤더 더블클릭 또는 이후 승인할 키보드 동작은 속성 패널 대상과 최근 활성 패널을 함께 바꾸고, `Command+Option+클릭`, 일괄 복사 항목 추가 또는 일괄 복사 제어 실행은 일괄 복사 패널을 활성화한다. 마지막으로 활성화한 패널만 오른쪽 영역에 표시한다.
- 한 번의 헤더 클릭과 `Tab` 선택은 최근 활성 패널을 바꾸지 않는다. 일괄 복사 패널이 보일 때 이 입력만으로 속성 패널로 전환하지 않는다.
- 패널 전환은 선택한 메모, 속성 패널 대상, 속성 초안, 일괄 복사 항목과 제거 이력을 지우지 않는다. 전환 계기가 속성 입력의 `blur` 또는 패널 밖 클릭을 만들면 같은 검증 및 적용 동작을 먼저 사용한다.
- `Command`가 눌린 동안 헤더의 시각 요소와 아이콘 조작을 숨기되 기존 헤더 높이를 유지한다. 메모 본문의 `Command+클릭`과 `Command+Option+클릭`은 선택, 속성 패널 대상과 최근 활성 패널을 메모 선택 동작으로 바꾸지 않는다. `keyup`, 창의 포커스 상실 또는 문서 숨김으로 보조 키 상태가 끝나면 헤더를 복원한다.
- 오른쪽 속성 패널의 현재 범위는 작업 공간 좌표 X와 Y, 너비와 높이다. 회전, 정렬, 비율 잠금과 수식 입력은 포함하지 않는다.
- 필드 입력은 저장된 geometry와 분리한 초안이다. `blur`, 패널 밖 클릭과 `Enter`는 같은 적용 명령을 사용하고, 유효하며 실제로 달라진 값만 한 번 저장한다.
- X, Y, 너비와 높이는 유한한 수이고 `0`보다 크며 애플리케이션이 정한 해당 상한 이하여야 한다. HTML 입력 제약과 application command가 같은 범위를 검사한다.
- 유효하지 않은 초안은 메모 geometry와 revision을 바꾸지 않고 오류가 난 필드에서 수정할 수 있게 표시한다.
- 속성 패널에서 적용한 geometry 변경은 전체 revision만 증가시키고 content revision을 바꾸지 않는다.
- 가장자리와 꼭짓점 drag에 의한 직접 크기 조절을 계속 제공한다. 메모 표면에는 숫자 입력, 단계 조절 또는 설정 버튼을 추가하지 않는다.

[모바일 일괄 복사 확인과 오른쪽 패널 우선순위 조사](../references/mobile-batch-copy-confirmation-and-panel-priority-research.md)는 최근 활성 패널과 geometry 입력 범위를 보완한다. [`tabindex`, 항목 동작 팝오버와 모바일 지연 재정렬 조사](../references/tab-order-popover-and-mobile-reorder-research.md)는 키보드 탐색과 시각적 겹침을 분리한 근거와 전체 문서 포커스 순서의 위험을 기록한다.

## 예상 결과와 계획 영향

U2는 `tabindex`, 선택 ID, 속성 패널 대상 ID, 활성 오른쪽 패널, geometry 입력 초안과 적용 결과를 표현할 자료를 정한다. U4는 붉은 선택 테두리, 별도 포커스 표시, `Command` 상태의 헤더 비노출과 오른쪽 패널의 공통 외형을 만든다. U5는 한 번의 헤더 클릭, `dblclick`, drag 판정, `tabindex` 순서의 Tab 선택, 드래그 중 캔버스 크기 유지, 최근 활성 패널 전환, X, Y, 너비 및 높이 입력과 geometry 저장을 연결한다. U6은 `Command` 상태와 본문 복사가 선택으로 전파되지 않게 한다. 순수 패널 전이, 입력 검증과 revision 불변 조건은 TDD로 개발하고 실제 이벤트 순서, 보조 키, pointer capture, 레이아웃 크기와 포커스는 브라우저에서 확인한다.

## 다시 검토할 조건

- Tab 순서가 메모 본문이나 헤더 아이콘에 도달하지 못하게 하는 경우
- 붉은 선택 테두리와 키보드 포커스를 구분할 수 없는 경우
- 패널 밖 클릭이 같은 값을 두 번 저장하거나 새 메모 선택을 잃게 하는 경우
- 최근 활성 오른쪽 패널을 닫은 뒤 이전 패널을 다시 표시할지 정해지지 않아 화면 결과가 달라지는 경우
- 정확한 속성 입력 상한과 기존 `0` 좌표 record의 migration이 정해지지 않은 경우
- 새 메모의 `tabindex` 초기값, 값 정리, 이전 record migration과 페이지 전체 포커스 순서가 정해지지 않은 경우
- 더블클릭과 동등한 키보드 속성 패널 진입 동작이 정해지지 않은 경우
- 속성 패널 대상과 한 번 클릭으로 새로 선택한 메모가 다를 때 두 대상을 화면에서 구분하는 방법이 정해지지 않은 경우
- `Command`를 누른 순간 헤더 아이콘에 키보드 포커스가 있을 때 포커스 표시와 복원 결과를 실제 브라우저에서 확인하지 못한 경우
