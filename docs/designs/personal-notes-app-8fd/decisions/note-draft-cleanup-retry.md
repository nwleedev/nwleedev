# 메모 저장 뒤 초안 제거 재시도 결정

메모 원문 저장은 성공했지만 복구 초안을 지우지 못한 경우, 저장된 메모와 입력은 그대로 유지하고 다음 저장 기회에 초안 제거를 다시 시도한다.

## 결정 질문과 요구 조건

[구현에 적용할 결정 원칙과 기본값](../requirements.md#구현에-적용할-결정-원칙과-기본값)은 메모 저장 뒤 초안을 제거하도록 정한다. 메모 저장과 초안 제거가 분리된 저장 작업에서 제거만 실패했을 때, 저장한 원문을 실패로 되돌리지 않으면서 남은 초안을 정리할 규칙이 필요했다.

## 검토한 선택지

- 메모 저장을 실패로 처리하면 초안 제거 실패를 바로 알릴 수 있지만, 이미 저장된 원문과 화면에 표시된 저장 상태가 어긋난다.
- 저장 성공으로 끝내고 초안을 그대로 두면 원문은 보존하지만 이후에 초안을 정리할 기회가 없다.
- 메모 저장 성공은 유지하고 다음 저장 때 초안 제거를 다시 시도하면 저장된 원문을 보존하면서 남은 초안을 정리할 수 있다.

## 승인된 결정과 이유

- 메모 원문이 저장된 뒤 초안 제거만 실패하면 원문 저장은 성공으로 유지한다.
- 저장 상태는 초안 제거가 남았음을 보관한다. 다음 저장은 입력이 저장된 원문과 같아도 초안 제거를 다시 시도한다.
- 재시도에서 초안 제거가 성공하면 보류 상태를 끝낸다. 다시 실패하면 다음 저장 기회까지 보류 상태를 유지한다.

초안 저장소는 메모 ID를 key로 사용하므로 메모 하나에는 초안 한 건만 남는다. [IndexedDB 표준](https://w3c.github.io/IndexedDB/)은 같은 key를 가진 여러 record를 허용하지 않으며 transaction의 `complete`는 요청이 성공하고 commit된 뒤 발생한다고 설명한다. 따라서 다음 저장의 초안 쓰기와 제거는 같은 메모의 남은 초안을 대체하거나 제거한다. 이 결정은 현재 저장소의 key 구조에 맞추며, 초안을 여러 revision으로 보관하도록 바꾸지 않는다.

## 기대되는 변화와 계획 영향

변경된 원문 저장 뒤 초안 제거가 실패해도 메모의 content revision은 이미 저장한 값으로 유지한다. 같은 원문으로 다음 저장을 실행하면 revision을 늘리지 않고 초안 제거만 다시 시도한다. `save-note-content` 명령 검사와 저장 상태 검사, 모델 기반 탐색은 이 순서를 확인한다. 실제 IndexedDB와 화면에서의 확인은 [초안 복구와 제거 재시도 계획](../plan.md#초안-복구와-제거-재시도)에서 계속한다.

## 다시 검토할 조건

- 메모 하나에 revision별 초안을 동시에 보관해야 하는 요구가 추가되는 경우
- 초안 제거 실패를 저장 성공과 구분해 화면에 알려야 하는 요구가 추가되는 경우
- 다음 저장 기회가 오기 전에도 남은 초안을 정리해야 하는 요구가 추가되는 경우
