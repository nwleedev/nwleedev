# 메모 모델 기반 탐색 실행 결과

U12는 일부 테스트를 추가했으나 완료하지 않았다. 단계 1, 3, 4의 완료 표시는 독립적인 기대값, 결함 탐지와 재현 증거가 부족해 정정했다. 이 문서에 단계별 구현과 실행 증거를 계속 기록한다.

## 단계 1: 편집, 저장과 복구

보완이 필요하다. `note-content.model.test.ts`는 실제 저장 상태 함수와 `saveNoteContent`를 사용해 편집, 저장 요청, 저장 완료, 초안 복구 판정, 초안 저장 실패와 메모 저장 실패를 생성한다. 요청과 결과 일부를 실제 반환값에서 기대값으로 복사하므로 독립적인 판정이 부족하다.

명시적 순서는 저장 중 입력을 A에서 B로 바꾼 뒤 A를 완료하고, B 저장 실패와 재시도를 이어서 확인한다. 생성 탐색은 각 후보에 새 모델과 저장소 대역을 만들고 현재 원문, 원문 revision, 진행 중 요청, 초안과 저장 상태를 비교한다.

`test:model` 명령과 `local-fast`, `pr`, `main`, `nightly` 실행 프로필을 추가했다. 이번 단계의 실행은 `local-fast` 프로필로 확인한다. 실제 IndexedDB와 화면에서 초안이 복구되는지는 단계 4에서 확인한다.

## 단계 2: 생성, 배치, 삭제와 복원

보완이 필요하다. `note-lifecycle.model.test.ts`는 메모의 위치 변경, 앞뒤 겹침 순서 변경, 삭제와 최근 삭제 복원을 생성한다. 원문 revision, ID와 Tab 순서를 비교하지만 요청 좌표 적용과 복원 원문 및 geometry 비교는 빠져 있다. 새 메모 기본 크기 및 겹침 값과 만료된 이력 제거는 별도 사례가 있다. 생성형 시간 진행과 만료 직전 비교까지 완료한 것은 아니다.

삭제한 뒤 남은 메모의 겹침 순서를 바꾸고 삭제 메모를 복원하는 조합은 판정을 보류한다. 현재 복원은 저장한 geometry를 그대로 사용하므로 같은 `zIndex`가 생길 수 있다. 요구사항의 원래 겹침 순서 복원을 원래 숫자 복원과 동일시하지 않고, 재정렬 이후 복원의 상대 순서를 확인해야 한다.

## 단계 3: 개별 복사와 사용 기록

보완이 필요하다. `copy-note.model.test.ts`는 실제 `copyNote` 명령과 원문 revision을 갱신하는 운영 함수를 사용해 편집 뒤 복사, 반복 복사와 실패 뒤 재시도를 생성한다. 기록 revision을 현재 값 이하인지만 비교하므로 각 기록이 복사 당시 원문 버전을 가리키는지는 증명하지 못한다.

클립보드 쓰기 실패는 사용 기록을 추가하지 않고, 클립보드가 성공한 뒤 사용 기록만 실패하면 복사한 원문을 유지하는지 비교한다. 일괄 복사 목록의 항목이나 횟수는 이 검사에 넣지 않았다. 실제 Clipboard 권한과 집계 화면은 단계 4에서 확인한다.

## 단계 4: 실제 저장소와 메모 화면 연결

보완이 필요하다. `note-storage.model.indexeddb.test.ts`는 실제 IndexedDB 저장소 구현을 사용해 저장 원문과 초안 부재를 새 연결에서 읽는다. 두 메모 중 하나를 삭제 및 복원한 뒤 최종 목록도 읽지만 삭제 직후 부재는 확인하지 않는다. 각 사례의 시작과 종료에 저장 자료를 초기화하고 연결을 종료한다. 이 파일은 고정 사례 검사이며 행동 순서 생성 검사가 아니다.

`notes-model.spec.ts`는 데스크톱에서 생성, 편집, 800ms 진행, 새로고침, 삭제와 취소를 실행한다. fast-check의 원문 생성 사례는 각각 새 BrowserContext를 사용한다. 생성하는 대상은 문자열이며 행동 순서는 고정되어 있다. 실패 축소 기능은 연결했으나 실제 결함의 축소 및 재현 증거는 없다. 320px BrowserContext의 명시적 저장 및 새로고침 검사도 있다.

이전 실행에서 Browser Mode 12개 파일의 48개 검사, 추가 Playwright 파일의 9개 검사, 모델 검사와 타입 및 lint 검사 통과를 확인했다. 이 결과는 각 명령의 성공이며 U12 전체 완료 증거는 아니다.

전체 `pnpm notes:test:e2e` 96개 통과 기록은 미확인으로 정정한다. 최종 종료 코드와 전체 집계를 확보하지 못했다. Playwright가 기록한 `.last-run.json`에는 성공 상태가 있으나 명령, 검사 개수와 Git revision이 없어 전체 96개 실행으로 특정하지 않는다. 후속 실행에서 종료 코드와 집계를 함께 확보해야 한다.

## 검증력 조사와 보완 계획

2026년 9월 13일에 기대값, 결과 관찰, 행동 실행량, 비동기 및 저장, 완료 증거를 조사했다. [원인과 공식 자료](references/model-testing-validity-research.md)를 정리하고 [U12 보완 순서](plan.md#보완-순서와-단계별-완료-증거)를 추가했다. 테스트와 운영 코드, 의존성 및 CI는 변경하지 않았다. 결함 주입과 테스트 재실행도 이번 문서 작업의 결과로 보고하지 않는다.

현재 상태는 `needs revision`이다. 실제 반환값을 기대값으로 사용하는 부분과 중간 관찰 누락은 코드에서 확인했다. 통제된 결함의 탐지 및 축소, seed 재실행, 입력 직접 실행과 실행량 기록은 아직 없다. 근본 원인은 이미 정한 완료 조건을 실행 증거와 연결하지 않은 채 다음 기능으로 확장한 것으로 판단한다. 새로운 서비스 결함을 발견했다는 실행 증거는 없다.

## 남은 판정과 실행 환경

다음 작업은 단계 1의 독립적인 기대값과 결함 탐지 및 재현 증명을 완료하는 것이다. 단계 2의 재정렬 이후 복원 순서는 미정으로 남기되 이 문제로 다른 메모 검사를 보류하지 않는다. 단계 3과 4도 각각 원문 버전별 기록과 실제 저장 및 행동 연결의 보완이 필요하다.

CI 재현은 Git remote와 CI 서비스가 정해지지 않아 시작하지 않았다. 로컬 실행 기록을 특정 서비스의 workflow나 원격 저장소 설정으로 바꾸지 않았다.
