# 메모 모델 기반 탐색 실행 결과

이 문서는 U12를 실행하며 각 단계에서 추가한 검사와 검증 결과를 기록한다. 계획의 완료 표시는 구현 및 실행 증거가 갖춰진 단계에만 갱신한다.

## 단계 1: 편집, 저장과 복구

완료했다. `note-content.model.test.ts`는 실제 저장 상태 함수와 `saveNoteContent`를 사용해 편집, 저장 요청, 저장 완료, 초안 복구 판정, 초안 저장 실패와 메모 저장 실패를 생성한다.

명시적 순서는 저장 중 입력을 A에서 B로 바꾼 뒤 A를 완료하고, B 저장 실패와 재시도를 이어서 확인한다. 생성 탐색은 각 후보에 새 모델과 저장소 대역을 만들고 현재 원문, 원문 revision, 진행 중 요청, 초안과 저장 상태를 비교한다.

`test:model` 명령과 `local-fast`, `pr`, `main`, `nightly` 실행 프로필을 추가했다. 이번 단계의 실행은 `local-fast` 프로필로 확인한다. 실제 IndexedDB와 화면에서 초안이 복구되는지는 단계 4에서 확인한다.

## 단계 2: 생성, 배치, 삭제와 복원

진행 중이다. `note-lifecycle.model.test.ts`는 메모의 위치 변경, 앞뒤 겹침 순서 변경, 삭제와 최근 삭제 복원을 생성한다. 원문 revision과 Tab 순서가 위치 및 겹침 순서 조작으로 바뀌지 않는지, 삭제와 복원에서 ID, 원문, geometry와 Tab 순서가 유지되는지 확인한다. 새 메모 기본 위치와 5초 뒤 이력 만료도 별도 사례로 확인한다.

삭제한 뒤 남은 메모의 겹침 순서를 바꾸고 삭제 메모를 복원하는 조합은 판정을 보류한다. 현재 복원은 저장한 geometry를 그대로 사용하므로 같은 `zIndex`가 생길 수 있다. 원래 geometry 복원과 모든 메모의 연속된 겹침 순서 가운데 어느 규칙을 우선할지 요구사항에 정해져 있지 않다.

## 단계 3: 개별 복사와 사용 기록

완료했다. `copy-note.model.test.ts`는 실제 `copyNote` 명령과 원문 revision을 갱신하는 운영 함수를 사용해 편집 뒤 복사, 반복 복사와 실패 뒤 재시도를 생성한다.

클립보드 쓰기 실패는 사용 기록을 추가하지 않고, 클립보드가 성공한 뒤 사용 기록만 실패하면 복사한 원문을 유지하는지 비교한다. 일괄 복사 목록의 항목이나 횟수는 이 검사에 넣지 않았다. 실제 Clipboard 권한과 집계 화면은 단계 4에서 확인한다.
