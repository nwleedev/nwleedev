# 메모 좌표 제한 제거와 화면 탐색 조사

메모의 위치는 고정 캔버스 크기와 분리해야 한다. X와 Y에 음수, 0과 기존 캔버스 바깥 값을 허용하되, 저장 검증과 화면 변환을 함께 수정해야 한다. 위치 제한 제거는 메모 크기나 수치 검증까지 없애는 변경이 아니다.

2026년 9월 12일의 소스와 공식 자료를 확인했다. 적용 대상은 Next.js 16.3.3, React 19.2.8, Zod 4.4.3을 사용하는 `apps/notes/`다. 이 글은 구현 전 조사이며 아래 처리 방식은 실행 계획의 후보다. 승인된 배치 동작은 [요구사항](../requirements.md), 현재 결정은 [공간형 보드 결정](../decisions/responsive-note-presentation.md)이 관리한다.

## 기존 제한의 적용 지점

`entities/note/model/note.ts`의 `NoteGeometrySchema`, `note-geometry.ts`의 초안 검사와 `fitNoteGeometryToCanvas`, `note-card.tsx`의 이동 및 크기 계산, `note-properties-panel.tsx`의 입력 최댓값이 모두 4096과 양수 좌표에 의존한다. `migrate-personal-notes-database.ts`도 같은 보정 함수를 호출한다. 이동 계산만 바꾸면 화면에 잠시 보인 위치가 저장에서 거부되거나 불러올 때 달라질 수 있다.

`notes-board.tsx`는 고정 크기 보드를 이동시키고, `notes-collection.tsx`는 화면 전체에 같은 배경을 그린다. 캔버스를 아래로 이동한 뒤 메모를 위로 끌면 화면에 빈 공간이 남아도 내부 Y가 1에서 멈추는 동작을 브라우저에서 확인했다.

## 좌표 변환과 수치 정밀도

[tldraw 좌표 문서](https://tldraw.dev/sdk-features/coordinates)는 화면, 표시 영역과 저장 공간의 좌표를 나눈다. 짧은 원문 표현인 “page space”는 저장 공간의 좌표를 뜻한다. [CSS Transforms](https://www.w3.org/TR/css-transforms-1/#transform-rendering)는 변환 순서가 화면 위치에 영향을 준다는 근거다.

저장 좌표와 카메라 위치를 별도로 유지하고, 화면 좌표는 표시 영역의 시작 위치와 확대율을 반영해 계산하는 방식을 권한다. 메모 이동에는 누른 지점과 메모 원점 사이의 거리를 보존한다. 확대 중심, 패널 너비 변경과 시점 이동에서도 같은 변환을 사용한다. 큰 저장 좌표를 거대한 CSS 위치로 그대로 전달하지 않고 카메라 근처 기준점과의 차이를 렌더링에 사용한다.

[ECMAScript Number 명세](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-number.max_safe_integer)는 정수를 정확히 구분할 수 있는 한계가 있음을 정한다. 이 한계는 CSS가 정확히 그릴 수 있는 최대 좌표와 같다는 뜻이 아니다. `NaN`, 무한대, 계산 중 넘침과 이동량을 구분하지 못하는 계산은 저장하지 않고 기존 값을 유지해야 한다. 임의의 고정 배치 끝으로 좌표를 보정하는 대신 실패를 알린다. 극단적인 좌표의 허용 정밀도는 지원 브라우저에서 측정한 뒤 구현 기준으로 확정해야 한다.

확인할 사례는 음수에서 양수로 원점 통과, 4096 바깥 이동, 확대 후 같은 지점 잡기, 큰 좌표에서 최소 이동 구분과 저장 후 복원이다. 수치 안전성을 확인하지 않고 모든 유한 숫자에서 같은 정밀도를 약속하지 않는다.

## 메모를 잃어버리는 탐색 문제

`noteBounds`의 초기 최솟값 4096과 최댓값 1은 제한 없는 배치에서 실제 메모 외곽을 잘못 계산할 수 있다. 첫 메모의 실제 외곽에서 계산을 시작하고 빈 목록은 별도로 처리해야 한다. 현재 `findNewNoteGeometry`도 원점 근처의 고정 격자를 탐색하므로, 새 메모를 현재 표시 영역 안에 만드는 방식으로 바꾸는 것이 적절하다.

[tldraw 카메라 문서](https://tldraw.dev/sdk-features/camera)는 전체 맞춤과 특정 도형으로 이동을 별도로 제공한다. 멀리 흩어진 메모를 모두 맞추면 글씨가 지나치게 작아질 수 있으므로, 전체 맞춤 외에 선택한 메모를 읽을 수 있는 크기로 되돌리는 방법을 권한다. 사용 중인 확대율과 맞춤 확대율의 규칙도 통일해야 한다. 메모를 찾기 위해 저장 위치를 원점으로 다시 옮겨서는 안 된다.

[tldraw의 실제 복귀 버튼 오류 분석](https://tldraw.dev/blog/back-to-content)은 화면 밖에 있는 도형과 성능 때문에 그리기를 생략한 도형을 혼동하면 선택된 도형으로 돌아가기 동작이 사라질 수 있음을 설명한다. 메모 복귀 여부는 같은 좌표계에서 메모와 표시 영역의 겹침으로 판단하고, DOM 존재나 선택 여부로 대신하지 않는다.

## 크기 조절과 기존 자료

현재 너비 `240..4095`, 높이 `180..4095`는 위치와 분리해 유지할 수 있다. 위쪽 또는 왼쪽 크기 조절에서는 반대편 변을 고정하고 음수 위치도 계산해야 한다. 최대 크기를 늘리는 결정은 위치 제한 제거와 별개다.

기존 메모의 위치, 크기, 원문과 revision을 변경 없이 읽는 전환을 권한다. 예전 양수 보정을 새 좌표에 다시 적용하지 않는다. 이미 과거 보정으로 소실된 원래 위치는 추정해 복원할 수 없다. [IndexedDB 명세](https://www.w3.org/TR/IndexedDB-3/)에 따라 저장 전환은 transaction 완료 후 성공으로 처리하고, 이전 버전 탭과 충돌하면 조용히 덮어쓰지 않는다. 저장 형식 전환이 실제로 필요한지는 DB 버전과 이전 읽기 코드의 호환성으로 결정한다.

## 메모 수와 편집 상태

좌표가 넓어진다는 이유만으로 메모 수가 늘거나 성능 저하가 발생한다고 단정할 수는 없다. 현재 모든 메모를 렌더링하므로 메모 수와 본문 길이를 늘려 비용을 먼저 측정한다. 필요할 때만 화면 밖 그리기 생략을 적용한다.

[tldraw Culling](https://tldraw.dev/sdk-features/culling)은 선택 및 편집 중 도형을 그리기 생략 대상에서 제외한다. 이 앱에서는 자동 저장, 입력기 조합, 포커스와 양의 `tabindex` 탐색을 보존해야 하므로 화면 밖 메모를 무조건 언마운트하면 안 된다. 공간 인덱스나 외부 캔버스 라이브러리 도입은 이번 조사의 결론이 아니다.
