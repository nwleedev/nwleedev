# 모바일 메모의 본문 폭과 헤더 후보

본문 양옆의 핸들과 더보기를 낮은 상단 헤더로 옮기는 안을 권한다. 본문이 카드의 가로 폭을 더 많이 사용할 수 있고 조작 위치도 일정해진다. 현재 카드 헤더의 기본 높이는 데스크탑 패널 항목 약 34px, 모바일 메모 목록과 모바일 확인 목록 모두 44px다. 아래 44px 후보에서 측정한 본문 폭과 카드 전체 높이는 이전 배치의 비교 자료다. 배경색은 헤더에 따로 칠하지 않는 것으로 정했다. 적용 대상은 [모바일 메모의 본문 폭과 헤더 검토](../requirements.md#모바일-메모의-본문-폭과-헤더-검토)다.

## 변경 전 화면에서 확인한 문제

2026년 11월 5일 내장 브라우저에서 모바일 목록을 확인했다. 실제 CSS viewport 너비는 354px였고 본문 버튼 너비는 약 216.75px, 글자 크기는 16px였다. 두 문장으로 된 확인용 본문이 네 줄로 표시됐다. 이는 화면 전체 너비가 본문에 쓰이지 않는 사례이며 모든 모바일 기기의 측정값은 아니다.

변경 전 공통 카드는 핸들, 본문과 더보기를 세 열에 배치했다. [현재 토큰](../../../../apps/notes/src/_app/styles/tokens.css)은 터치 영역 2.75rem, 카드 최소 높이 3.5rem과 내부 여백 0.25rem을 정의한다. 양쪽 조작 영역을 별도 행으로 옮기면 본문 옆에 예약된 공간을 줄일 수 있다. 변경 후 측정은 다음 절에 구분한다.

## 구현 후보의 본문 폭과 카드 높이

상단 헤더로 조작을 옮긴 후보에서는 본문 양옆에 핸들과 더보기 공간을 따로 예약하지 않는다. [공통 카드](../../../../apps/notes/src/shared/ui/reorderable-text-card/index.tsx)의 헤더를 재사용하고 모바일 글자 크기는 16px로 유지한다.

2026년 11월 5일 내장 브라우저 측정에서 CSS viewport 320px, 390px와 430px의 본문 버튼 너비는 각각 286px, 356px와 396px였다. 좌우 내부 여백 12px씩을 제외한 텍스트 폭은 각각 262px, 332px와 372px다. 같은 두 문장 본문은 세 조건에서 두 줄로 표시됐고 줄 간격은 28px였다. 한 줄 메모의 전체 카드 높이는 세 조건 모두 90px였다.

변경 전 측정과는 화면 너비와 확인용 원문이 같지 않으므로 네 줄에서 두 줄로 줄었다는 개선율로 해석하지 않는다. 새 구성에서 본문과 두 조작 영역이 분리된 사실 및 짧은 카드의 높이를 비교 근거로 사용한다. 데스크탑 320px 패널의 본문은 17px 후보로 표시하며 일반 메모의 기본 16px와 구분한다.

현재 후보를 유지하는 안을 권한다. 본문 폭을 확보하고 버튼 위치를 일정하게 만들지만 한 줄 메모를 많이 사용하는 경우 화면에 보이는 항목 수가 줄어든다. 최종 채택과 실제 휴대전화에서의 손가락 조작 확인은 남아 있다.

## 배치와 색상 제안

- 이전 측정에서는 헤더 높이 44 CSS px를 시작 후보로 사용했다. 핸들과 더보기의 터치 영역은 각각 44×44 CSS px를 유지하고 아이콘은 기존 것을 사용한다. 높이를 낮추기 위해 터치 영역을 본문 위로 겹치게 하지 않는다.
- 헤더에는 왼쪽 핸들과 오른쪽 더보기만 둔다. 제목, 메모 번호와 안내 문구는 추가하지 않는다. 가운데 빈 부분은 본문 복사나 순서 이동을 실행하지 않고 세로 스크롤을 시작할 수 있게 한다.
- 본문은 헤더 아래에 놓고 좌우 12px 여백을 시작 후보로 비교한다. 글자 크기와 줄 간격을 줄이거나 원문을 변경해 폭 문제를 해결하지 않는다.
- 헤더와 본문 사이에 구분선이나 안쪽 그림자를 두지 않는다. 카드 자체의 배경이 헤더에도 보이게 하고 그 위에서 핸들과 더보기 아이콘이 식별되는지 확인한다.
- 메인 메모 목록과 일괄 복사 확인 목록에 같은 배치 후보를 적용해 비교한다. 데스크탑의 핸들 없는 헤더 이동 방식을 모바일에 그대로 가져오지 않는다. 모바일에서는 왼쪽 핸들에서만 순서 이동을 시작하고 본문 터치, 길게 누르기와 더보기는 기존 동작을 유지한다.

헤더를 추가하면 한 줄짜리 메모는 현재보다 높아질 수 있다. 반면 긴 문장은 본문 폭이 넓어져 줄 수가 줄 수 있으므로 모든 카드의 높이가 늘거나 줄어든다고 단정하지 않는다. 기존 카드 최소 높이를 새 구성 전체에 억지로 맞추지 않고 짧은 본문과 긴 본문의 읽기 및 조작을 함께 비교한다.

## 조사 근거와 적용 한계

2026년 11월 5일 확인한 [W3C의 Target Size (Enhanced)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)는 “at least 44 by 44 CSS pixels”를 제시한다. 이는 AAA 기준이며 모든 버튼의 AA 최소 크기가 44px라는 뜻은 아니다. 이 서비스에서는 기존 2.75rem 조작 영역을 유지하는 근거로 사용한다.

[W3C의 Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)는 조작과 상태 식별에 필요한 시각 정보에 인접 색 대비 3:1을 요구한다. 충분히 구별되는 아이콘이 있으면 버튼 외곽선 자체는 필수가 아니다. 따라서 구분선을 추가하기보다 핸들과 더보기 아이콘의 식별성을 확인한다. 헤더와 본문 배경끼리 반드시 3:1이어야 한다는 뜻은 아니다.

[W3C의 Dragging Movements](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements)는 드래그 없이 단일 포인터로 수행하는 대안을 설명한다. 핸들 위치를 바꾸는 것만으로 접근성 대응이 끝나지는 않는다. 기존 일괄 복사 이동 대안은 유지하고 원본 메모 목록의 드래그 대안은 현재 요구사항의 백로그 상태를 유지한다.

내장 브라우저에서 확인한 [Material 1의 카드 액션](https://m1.material.io/components/cards.html#cards-actions)은 카드 묶음 안에서 조작 위치를 일관되게 두고 더보기를 보통 오른쪽 위에 배치하는 구성을 보여준다. 이 문서는 유지보수가 종료된 자료이므로 현재 표준이나 치수의 근거로 사용하지 않는다. 상단 보조 조작과 본문을 분리하는 배치 비교에만 참고한다. 이 서비스의 헤더 색상과 높이를 그대로 지시하는 자료는 아니다.

## 후보 비교에서 확인할 결과

320px, 390px와 430px의 실제 CSS viewport에서 같은 원문과 글자 크기로 본문 너비 및 줄 수를 비교한다. 한 줄 메모의 높이 증가, 여러 줄 메모의 가독성과 마지막 카드 접근성을 함께 확인한다. 확대 상태에서도 두 버튼과 본문 조작 영역이 겹치지 않아야 한다.

핸들 이동, 헤더 빈 부분의 스크롤, 본문 복사와 길게 누르기 추가, 더보기 열기를 각각 확인한다. 드래그 중 원래 자리, 이동 카드와 삽입 표시에도 같은 헤더가 반영되는지 비교한다. 이미지 생성 없이 기존 화면과 이 배치 설명으로 먼저 판단할 수 있으며 실제 휴대전화의 손가락 조작은 별도 확인이 필요하다.
