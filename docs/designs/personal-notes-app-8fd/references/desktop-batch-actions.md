# 데스크탑 일괄 복사 액션 배치와 문구

데스크탑 일괄 복사 항목의 팝오버는 `복제`, 순서 이동 네 항목, `삭제`의 세 묶음으로 구성하는 안을 제안한다. 묶음 사이에만 직선 구분선을 두고 삭제를 마지막에 둔다. 이 배치와 아래 치수는 [요구사항](../requirements.md#데스크탑-일괄-복사-항목의-액션-팝오버)을 구체화할 후보이며 확정 시안이 아니다.

## 근거와 적용

2026년 11월 4일 기준 [Carbon 메뉴 지침](https://www.carbondesignsystem.com/building-blocks/core/components/menu/guidelines#dividers)은 관련 동작을 묶고 삭제처럼 자료에 영향을 주는 동작을 구분선으로 구별한다. 원문은 “categorizing related actions into appropriate sections”라고 설명한다. 내장 브라우저의 예시에서도 Create, Edit, View data as 다음에 수평 직선을 두고 Delete를 별도 행으로 표시했다. 이 사례는 그룹 구분의 근거이며 모든 행에 선을 넣어야 한다는 뜻은 아니다.

[Microsoft 메뉴 지침](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/menus)은 선택한 대상의 명령을 요청 시 표시하고 구분선으로 항목을 나누는 구성을 설명한다. [SharePoint 작업 이동 안내](https://support.microsoft.com/en-us/sharepoint/lists/indent-outdent-move-and-delete-tasks)는 드래그와 별도로 “Move Up and Move Down” 버튼을 사용한다. 후자는 SharePoint 2013 대상 자료이므로 현재 서비스 외형의 근거가 아니라 방향을 이름에 쓰는 기존 사례로만 사용한다.

[GOV.UK 버튼 지침](https://design-system.service.gov.uk/components/button/)은 실행할 행동을 버튼 이름에 쓰도록 한다. 이 서비스에는 한 자리 이동과 끝 위치 이동이 함께 있으므로 방향만 표시하는 아이콘보다 목적지를 포함한 텍스트를 함께 두는 편이 구분하기 쉽다는 판단이다. 이 문구의 효과를 사용자 조사로 측정한 것은 아니다.

## 액션 배치 후보

팝오버는 더보기 버튼 가까이에 열고 모든 행을 한 열로 배치한다. 왼쪽 아이콘과 텍스트 시작 위치를 맞춘다. 하위 메뉴와 2열 아이콘 격자는 추가하지 않는다. 여섯 동작은 한 번 열어서 찾을 수 있고, 긴 문구도 방향 아이콘만 보고 해석할 필요가 없다.

- 첫 묶음: `복제`
- 직선 구분선
- 둘째 묶음: `위로 이동`, `아래로 이동`, `맨 위로 이동`, `맨 아래로 이동`
- 직선 구분선
- 셋째 묶음: `삭제`

순서 이동 설정이 꺼져 있거나 항목이 하나뿐이면 복제와 삭제 사이에 선 하나만 남긴다. 첫 항목에는 위 방향 두 동작을, 마지막 항목에는 아래 방향 두 동작을 숨기는 기존 요구를 따른다. Carbon의 일시적으로 불가능한 동작을 비활성화하는 예시와 달리 이 서비스는 실행 가능한 이동만 표시하는 규칙을 유지한다.

구분선은 중립색 1 CSS px의 수평선, 좌우 여백은 같은 값으로 제안한다. 시작 후보는 좌우 8 CSS px, 선 위아래 4 CSS px다. 팝오버 바깥 테두리와 행의 둥근 모서리를 선에 적용하지 않는다. 행마다 선을 두면 같은 순서 변경 묶음이 갈라지므로 그룹 사이 두 곳에만 둔다. 선 자체에는 선택 상태나 그림자를 주지 않는다.

행 높이는 40 CSS px, 팝오버 너비는 208 CSS px를 시작 후보로 둔다. Carbon의 중간 행 크기 40px를 참고하되 너비는 한국어 여섯 문구를 읽을 수 있게 정한 제안이다. 글자 확대 시 텍스트를 자르기보다 너비나 행 높이를 늘린다. 삭제는 위험 동작 색으로, 나머지 동작은 기본 글자 및 아이콘 색으로 구분한다. 한 자리 이동은 단일 화살표, 끝 위치 이동은 끝 막대가 있는 화살표를 후보로 둔다.

## 이동 문구 후보 비교

- `위로 이동`, `아래로 이동`: 기존 표현을 유지한다. `한 칸 위로`, `한 칸 아래로`도 가능하지만 항목 크기가 다른 목록에서 칸이라는 단위를 새로 도입하지 않는다. 한 자리 이동이라는 실제 동작은 요구사항에 명시한다.
- `맨 위로 이동`, `맨 아래로 이동`: 목록의 첫 위치와 마지막 위치를 표현한다. `처음으로 이동`, `끝으로 이동`보다 수직 목록에서 보이는 방향과 직접 연결된다.
- `맨 앞으로`, `맨 뒤로`: 메모 캔버스의 겹침 순서에 이미 쓰는 이름이므로 일괄 복사 목록의 위치 이동에는 사용하지 않는다.

이동은 항목의 순서만 바꾼다. 복제와 삭제는 기존 의미를 유지한다. 메뉴의 시각 예시를 참고하는 것이 기존 키보드 조작이나 접근성 역할을 다른 프레임워크 방식으로 바꾼다는 뜻은 아니다.
