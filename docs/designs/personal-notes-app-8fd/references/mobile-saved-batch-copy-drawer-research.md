# 모바일 Drawer의 저장된 일괄 복사 이동 링크 조사

저장된 일괄 복사 항목의 관리 화면으로 가는 링크는 평상시 메모 목록의 모바일 Drawer에 두는 것이 적절하다. 메모 목록 우측 하단은 새 메모 동작에 남기고, Drawer 안에서는 주요 화면 링크와 구분되는 한 줄의 이동 링크로 보여준다. 이는 [좁은 화면의 탐색 및 일괄 복사 접근 요구사항](../requirements.md#반드시-지킬-조건)에 따른 표시 제안이며, 정확한 여백과 크기를 확정한 시각 시안은 아니다.

## 확인한 현재 동작과 변경 범위

2026년 9월 23일 현재 `apps/notes/src/_pages/notes/ui/batch-copy-workspace.tsx`는 저장 목록의 실제 항목 수가 양수이고 모바일 작업이 활성화되지 않았을 때만 `/batch-copy/`로 가는 우측 하단 링크를 표시한다. 항목 수는 `useBatchCopyEditor`가 제공한 항목 배열에서 계산한다. 링크는 관리 화면으로 이동할 뿐 복사하거나 항목을 추가하지 않는다. `mobile-notes-workspace.tsx`의 `다음` 옆 숫자는 저장 목록 수가 아니라 이번 수집 작업의 클릭 횟수다. 둘을 같은 수로 취급해서는 안 된다.

현재 Drawer는 아직 구현되지 않았다. [좁은 화면 탐색 조사](mobile-navigation-and-actions-research.md)는 기존 탐색이 넓은 화면 링크와 작은 화면 펼침 목록으로 나뉘어 있고, 메모 목록에서는 작은 화면 탐색 자체가 숨겨지는 상태를 기록한다. 따라서 기존 하단 링크를 지우기 전에 메모 목록의 Drawer 열기, 실제 저장 수 표시와 관리 화면 이동을 함께 연결해야 한다.

## 공식 자료와 시각 사례

[Android Developers의 Navigation drawer 문서](https://developer.android.com/develop/ui/compose/components/drawer)는 Drawer를 앱의 여러 화면으로 이동하는 슬라이드인 영역으로 설명하고, 섹션과 구분선, 이름 있는 행을 조합한 예시를 제공한다. 이 문서의 두 그룹 시각 사례에서는 항목들이 세로로 정렬되고 구분선이 다른 성격의 묶음을 나눈다. 같은 문서의 예시는 행 오른쪽에 숫자를 둘 수 있음을 보여준다. 다만 Android Compose 구현을 웹 앱에 그대로 옮기거나 모든 행에 구분선을 둘 이유는 없다.

[Android Developers의 NavigationDrawerItem API](https://developer.android.com/reference/kotlin/androidx/compose/material3/NavigationDrawerItem.composable)는 행의 본문 이름과 끝쪽의 선택적 숫자 표시를 별개로 제공한다. 이 구조를 참고하면 `일괄 복사`라는 이동 대상과 현재 저장된 `N개`라는 상태를 한 행에서 읽되, 숫자를 별도의 버튼으로 오인하지 않게 할 수 있다.

[U.S. Web Design System의 Side navigation 지침](https://designsystem.digital.gov/components/side-navigation/)은 현재 위치를 알 수 있게 하고 링크 이름은 짧게 유지하며, 탐색이 길어져 아래쪽 항목을 놓치지 않는지 실제 화면에서 확인하도록 권한다. 이는 저장 목록 링크를 긴 설명 문장이나 하단에 숨어 있는 별도 제어로 만들지 않고, Drawer를 열면 주요 화면 뒤에서 바로 찾을 수 있게 배치하는 근거다. 이 지침은 웹의 측면 탐색을 설명하므로 모바일 Drawer의 모양이나 고정 높이를 직접 정하지 않는다.

[WAI-ARIA의 접근 가능한 이름 작성 지침](https://www.w3.org/WAI/ARIA/apg/practices/names-and-descriptions/)은 이름이 제어의 목적을 설명해야 하고, 화면에 보이는 내용으로 이름을 만들 수 있으면 별도 `aria-label`로 그 내용을 덮지 않도록 안내한다. 따라서 한 링크의 보이는 `일괄 복사`와 `N개`를 함께 읽을 수 있게 하고, 아이콘을 추가한다면 장식 아이콘은 이름에서 제외하는 편이 맞다. 숫자만 있는 독립 제어는 목적을 전달하지 못한다.

## 배치 판단과 구현에 남길 확인

주요 탐색에는 기존의 다섯 화면만 남긴다. 그 아래에 구분선 하나를 두고 `일괄 복사`와 오른쪽에 맞춘 `N개`를 한 줄 링크로 표시한다. `/batch-copy`는 여섯 번째 주요 화면이 아니라 저장된 항목을 관리하는 화면으로 접근한다. 항목 수는 알림이나 미확인 건수가 아니라 실제 저장된 항목의 수이므로 붉은 알림 점이나 강한 색상의 배지로 표현하지 않는다. 현재 선택 화면을 나타내는 강조도 관리 링크에 적용하지 않는다.

항목 수가 0이면 기존 동작과 같이 링크를 표시하지 않는다. 자료를 읽는 중이거나 읽지 못했으면 0이라고 단정한 숫자를 그리지 않는다. 현재 Provider에는 읽기 실패 상태와 `retry` 명령이 있으나, 모바일 화면에서 패널 자체가 숨겨져 재시도가 보이지 않을 수 있다. 따라서 Drawer에 실패와 재시도 제어를 표시하는 방법을 계획에 포함한다.

링크는 평상시 메모 목록의 Drawer에만 두고, 별도의 모바일 일괄 복사 작업 초안이 진행 중인 Drawer와 보조 화면 Drawer에는 넣지 않는다. 상세 및 `/batch-copy` 화면에는 Drawer가 없으며, `/batch-copy` 안에 새 메모 제어를 추가하지 않는다. 이는 기존 하단 링크의 표시 조건과 화면별 Drawer 요구를 함께 따른다.

구현 시에는 기존 일괄 복사 Provider의 항목 수를 메모 목록에서 읽어 Drawer의 선택적 링크 입력으로 전달하고, 항목 수를 별도로 저장하거나 두 번째로 조회하지 않는다. Drawer의 주요 화면 목록은 그대로 재사용한다. 링크 실행은 기존 화면 이동 확인 절차를 따른다. 관리 화면에 들어갈 때 저장 목록과 현재 수집 초안을 혼동해서는 안 된다.

실제 320 CSS px, 글자 확대, 화면 키보드와 safe area에서 행의 이름과 수가 잘리지 않고 탭 순서와 포커스가 유지되는지 확인해야 한다. 외부 지침은 특정 px 여백이나 버튼 형태를 정하지 않으며, 이 값은 실제 화면으로 판단한다.
