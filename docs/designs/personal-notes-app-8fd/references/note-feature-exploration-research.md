# 메모 기능별 탐색과 실패 재현 방법

메모를 12개 기능으로 나누고 각 기능에서 행동 생성, 오류 탐지, 실패 순서 축소, 로그 기록과 재현을 끝까지 입증한다. 저장 기능 하나의 성공을 다른 기능의 성공으로 대신하지 않는다. 기존 테스트와 초안 제거 재시도 수정은 유지하고, 부족한 관찰과 재현 절차를 보완하는 것이 현재 근거에 맞다.

이 자료는 메모 탐색을 구현하고 결과를 판정할 때 사용할 조사 문서다. 2026년 9월 13일에 [모델 기반 탐색 요구사항](../requirements.md#모델-기반-탐색-테스트), [기존 테스트 목적](existing-test-purposes.md), [검증력 조사](model-testing-validity-research.md)와 공식 자료를 비교했다. 설치 버전은 fast-check 4.10.0, pure-rand 8.4.2, Vitest 4.1.11, Playwright 1.62.1이다. 아래 결함과 축소 사례는 구현 방안이며 새로 실행해 얻은 실패가 아니다.

## 기능을 나누는 기준과 완료 의미

기능은 테스트 파일이 아니라 사용자 행동과 관찰할 결과로 나눈다. 생성, 본문 편집, 자동 저장, 모바일 저장, 초안 복구, 위치 및 크기, 겹침 순서, 삭제 취소, 선택 및 포커스, 캔버스 보기, 개별 복사와 사용 기록이 대상이다. 일괄 복사 탐색은 보류하며 템플릿과 분석은 이번 메모 탐색에 포함하지 않는다. 기존 기능을 제거하거나 그 회귀 검사를 중단한다는 뜻은 아니다.

각 기능의 주 실행 계층에서 같은 행동 모델과 관찰식을 사용해 다섯 절차를 연결해야 한다. 도메인에서 한 결함을 찾고 무관한 E2E 통과를 붙여 브라우저 기능의 전체 과정을 입증했다고 하지 않는다. 순수 규칙은 Domain Adapter, 저장 자체는 실제 IndexedDB, 초점과 입력 및 제스처는 실제 화면이 주 실행 계층이다. 필요한 계층이 여러 개면 각각 증거를 연결하고 빠진 계층은 미완료로 남긴다.

첫 도메인 PoC의 정상 행동 3종, 비정상 시도 2종과 불변 조건 2종 이상은 메모 도메인에 대한 최소 조건이다. 모든 세부 기능에 같은 개수를 강제해 가짜 행동을 만들지 않는다. 메모 저장 요청, 완료와 재시도 및 초안 복구 판정을 기존 도메인 증거로 보완할 수 있다. 이 숫자 충족을 다른 기능 작업의 시작 조건으로 삼지는 않는다.

## 공통 실행 방법과 근거

### 행동 생성과 독립 판정

`fc.commands`로 행동 종류, 입력과 순서를 함께 생성한다. 초기 자료, 정상 전이, 거부되어야 할 시도와 환경 실패 주입을 구분한다. 필요한 선행 행동은 모델의 실행 조건으로 표현하되, 거부 결과를 확인할 명령까지 `check`로 생략하지 않는다. [fast-check 모델 문서](https://fast-check.dev/docs/advanced/model-based-testing/)는 모델이 실제 구현의 복제본이 아니어야 한다고 설명한다. 각 기능에는 필요한 ID 관계, 입력과 보존값만 두고 실제 반환 요청과 Promise는 실행 대상에 따로 보관한다.

행동마다 요구사항 문장, 입력, 허용 조건, 바뀔 값과 유지할 값, 관찰 시점을 연결한다. 다른 메모의 원문, ID와 content revision처럼 보호할 값도 읽는다. 파일명, 함수 호출 수나 예외 발생만으로 판정하지 않는다. 정상 실행과 통제된 결함 실행은 같은 검증문을 사용하고, 실패한 불변 조건과 예상값 및 관찰값의 차이를 확인한다. [Stryker의 실행 상태 구분](https://stryker-mutator.io/docs/mutation-testing-elements/mutant-states-and-metrics/)처럼 검증 실패를 컴파일 및 실행 오류와 구분하되, 별도 mutation 도구나 점수 목표는 추가하지 않는다.

### 실패 순서 축소

일반 생성 탐색에서 발견한 실패를 같은 property로 축소한다. 최초 실패와 축소 결과의 **실제로 실행한 행동**을 비교한다. 준비 자료와 입력값 축소도 기록하지만, 문자열만 짧아지고 행동 순서가 고정된 검사는 순서 축소의 완료 증거가 아니다.

기능마다 불필요한 행동이 제거된 생성 사례를 하나 이상 확보하고 같은 불변 조건 위반이 남는지 확인한다. 이미 더 줄일 수 없는 사례만 발견했다면 그 실패는 유효하되 순서 축소 증거는 아직 없다고 기록한다. 아래 예시는 축소가 향할 수 있는 순서이지 생성기의 순서를 고정할 틀이 아니다. 전역 최단 순서를 찾았다고 주장하지 않는다.

`fc.commands`는 실제 실행한 명령을 반영해 축소하며 재현에는 seed와 path 외에 replayPath가 필요할 수 있다. [명령 축소 및 재현 설명](https://fast-check.dev/docs/advanced/model-based-testing/#replay-model-based-tests)의 “shrink only” 대상은 실행된 명령이다. 삭제된 선행 행동 때문에 목표 동작도 생략된 후보는 같은 실패의 재현으로 세지 않는다.

### 로그 기록과 두 가지 재현

일반 탐색의 실패에도 다음 정보를 남긴다. 통제된 결함 검사뿐 아니라 예상하지 못한 실패의 로그에도 기록해야 한다.

- 기능 이름, 적용 요구사항, 실행 계층과 정상 또는 결함 실행의 구분
- 앱과 모델의 Git revision, 잠금 파일 및 도구 버전, 브라우저 버전, 실제 프로필과 모든 실행 상한
- 합성 초기 메모, 초안과 사용 기록, 논리 ID와 실행에서 발급된 ID의 대응, 시작 시각, viewport, 권한과 실패 주입 설정
- 최초 실패의 생성 및 실행 행동, 축소된 행동과 각 입력, 불변 조건 이름, 실패 직전 및 직후 모델, 예상값과 실제 관찰값
- seed, path, 필요한 replayPath, 축소 횟수와 종료 이유, 탐색 및 축소 소요 시간
- 명령 종류별 후보 수, 실행 수, 실행 조건 거절 수, UI에서 실행 불가한 수와 fast-check 속성 검사 생략 수

ID는 `note-a` 같은 논리 식별자로 행동에 연결한다. 새 실행에서 실제 ID가 달라져도 같은 대상을 조작하게 하고, 모델의 기대 메모 객체를 실제 입력으로 복사하지 않는다. 직접 재현에는 표시용 `toString()`만이 아니라 행동 종류와 입력을 다시 읽을 수 있는 자료가 필요하다.

한 번은 같은 버전에서 seed, path와 replayPath로, 또 한 번은 저장된 초기 자료와 축소 행동을 읽어 난수 없이 실행한다. 두 실행에서 같은 불변 조건이 실패하고 정상 구현에서는 같은 자료로 통과해야 한다. 관찰 대상과 실패 종류가 달라지면 재현 실패다. 실제 서비스 오류와 통제된 결함은 별도 분류하며 실제 버그 발견을 의무 목표로 만들지 않는다.

실패 자료는 개인 메모가 아닌 합성 입력만 사용한다. 읽기 가능한 로그와 반복 실행할 회귀 입력만 저장하고 모든 축소 결과를 예제 테스트로 복사하지 않는다. 실행 결과 요약은 [기존 단일 기록](../model-based-testing-execution.md)에 모으며 기능별 결과 문서를 따로 만들지 않는다.

### 후보 격리와 실행 비용

[Playwright 격리 문서](https://playwright.dev/docs/browser-contexts)는 테스트마다 새 BrowserContext를 제공한다. fast-check의 한 property 안에서는 여러 생성 및 축소 후보가 실행되므로 **후보마다** context를 새로 만들고 실행 후 종료해야 한다는 것이 이 저장소에 적용할 결론이다. 한 후보 안의 새로고침과 내부 이동은 같은 저장소를 유지한다. 실제 IndexedDB 검사도 후보별 데이터베이스와 연결을 분리한다.

[fast-check 4.10.0 ModelRunner 소스](https://github.com/dubzzz/fast-check/blob/v4.10.0/packages/fast-check/src/check/model/ModelRunner.ts)는 명령의 `check` 뒤 `run`을 호출한다. 따라서 `numSkips`와 별개로 명령 시도와 거절을 계측해야 한다. `check`의 내부 호출 횟수를 행동 수로 세지 않고 후보 안의 명령 위치별 판정을 기록한다. 최초 탐색과 축소 중 실행량도 분리한다.

현재 네 프로필을 재사용하되 기능과 실행 계층별 시간을 측정한다. [fast-check 시간 제한](https://fast-check.dev/docs/configuration/timeouts/)은 시간 초과가 진행 중 Promise를 취소하지 않으며, 전체 제한으로 중단한 실행은 설정에 따라 성공으로 처리될 수 있다고 설명한다. 정상 완료, 예산 중단과 환경 시간 초과를 구분하고 미완료 실행을 합격으로 표시하지 않는다. 실패 보고 전에 context, 저장소 연결과 대기 작업을 정리하며 정리 실패도 기록한다.

브라우저 후보를 직접 생성한 context에서는 실패 trace 보존도 명시적으로 연결한다. [Playwright Tracing](https://playwright.dev/docs/api/class-tracing)은 `context.tracing`이 브라우저 동작을 기록하지만 assertion을 기록하지 않는다고 설명한다. 따라서 trace만으로 불변 조건 로그를 대신하지 않는다. 후보별 전체 trace를 무제한 보존하지 않고 실패 및 최종 재현 자료를 남긴다.

### 통제된 결함을 넣을 위치

도메인 명령은 기존 의존성 대역에서 저장 무시, 잘못된 ID 또는 revision 전달 같은 한 가지 결함을 적용한다. 실제 운영 함수를 계속 실행하고, 기대값이나 관찰 함수에 결함 여부를 알려 실패시키지 않는다. 이 검사는 해당 연결의 오류 감지 능력이지 실제 IndexedDB나 브라우저의 고장을 발견한 증거가 아니다.

UI 이벤트 연결이나 실제 저장 모듈의 결함은 대역만으로 입증할 수 없다. 구현 단계에서 해당 모듈 한 곳을 바꾼 격리된 테스트 빌드 또는 기존 주입 가능한 연결을 선택하고, 어느 코드가 달라졌는지 식별한 상태에서 같은 생성 순서를 실행한다. 운영 빌드에 테스트용 분기나 전역 함수를 추가하지 않는다. 격리 빌드에 의도한 변경이 반영됐는지 먼저 확인하고 정상 빌드로 동일 사례를 통과시킨다. 이런 실행 방법을 확보하지 못한 기능의 탐지 및 재현은 미입증으로 남긴다.

## 기능별 적용 방안

다음 항목의 관찰값은 [의도한 결과와 완료 증거](../requirements.md#완료를-확인할-증거), 수치와 실패 처리는 [승인된 기본값](../requirements.md#구현에-적용할-결정-원칙과-기본값)을 따른다. 각 항목의 로그는 공통 필드에 필요한 정보만 더한다.

### 생성

실제 생성은 `notes-data-provider.tsx`의 명령과 메모 화면에서 확인한다. `note-lifecycle.model.test.ts`의 초기 메모 준비는 생성 기능의 증거가 아니다.

- 행동 생성: 빈 목록과 여러 메모에서 생성, 반복 생성, 재조회와 새로고침을 조합한다. 저장 거부는 환경 실패로 별도 주입한다.
- 오류 탐지: 성공한 생성마다 별도 ID의 메모 한 건이 저장되고 기존 메모가 유지되는지 확인한다. 초기 배치와 Tab 순서는 승인된 규칙으로 비교한다. 생성 저장 누락 또는 이전 ID 재사용을 결함 후보로 둔다.
- 순서 축소: 두 번 생성한 뒤 한 건만 남는 결함이라면 관련 없는 조회와 다른 메모 행동이 제거되고 두 생성이 남는지 확인한다. 생성 자체를 fixture 삽입으로 바꾸지 않는다.
- 로그 기록: 생성 전후 ID 집합, 실제 발급 ID 대응, 반환 메모와 재조회 레코드를 기록한다.
- 재현: 빈 저장소 또는 기록한 초기 자료에서 실제 생성 명령과 화면 제어를 다시 실행한다. 새 연결 및 새로고침 뒤 정확한 개수와 각 메모 값을 기다려 비교한다.

### 본문 편집과 원문 revision

`note.test.ts`의 순수 변경 규칙과 `notes.spec.ts`의 실제 입력을 함께 사용한다. 저장 예약 시점은 자동 저장 기능에서 따로 판정한다.

- 행동 생성: 입력, 선택 범위 교체, 붙여넣기, 원래 원문으로 되돌리기, 같은 값 반복, 위치만 변경을 조합한다. 빈 문자열, 공백, 줄바꿈, Unicode와 URL 모양 문자열을 포함한다.
- 오류 탐지: 화면 원문과 저장된 원문을 구분하고 실제 본문 변경만 content revision을 바꾸는지 확인한다. 자동 trim, 다른 메모 편집 또는 위치 변경 시 content revision 증가를 결함 후보로 둔다. URL은 링크로 이동하지 않아야 한다.
- 순서 축소: 원문을 저장한 뒤 위치만 바꿔 revision이 달라지는 사례는 불필요한 다른 입력을 제거한다. 문자열 축소와 함께 본문 및 비본문 변경의 필요한 순서를 보존한다.
- 로그 기록: 변경 전후 원문과 content revision, 편집 대상, 선택 범위와 적용한 행동을 기록한다.
- 재현: 순수 변경은 실제 `reviseNote`로, 입력 동작은 실제 textarea로 실행한다. 테스트의 문자열 대입으로 브라우저 붙여넣기를 입증하지 않는다. 실제 외부 앱에서의 붙여넣기는 별도 수동 증거로 구분한다.

### 데스크톱 자동 저장

`note-content.model.test.ts`, 저장 상태 및 명령 검사, `notes-data-provider.browser.test.tsx`와 `notes-model.spec.ts`를 연결한다. 대역 저장 완료와 실제 IndexedDB 완료를 구분한다.

- 행동 생성: 입력, 800ms 전후 시간 진행, 저장 중 재입력, 중복 저장 시도, 완료 및 실패 후 재시도를 조합한다. blur, 내부 이동, hidden과 pagehide는 서로 다른 저장 계기로 표현한다.
- 오류 탐지: 800ms가 되기 전의 보존값과 이후 저장값을 **blur나 이탈 전에** 읽는다. A 저장 중 B 입력 뒤 A가 완료돼도 B 입력과 다음 저장이 유지돼야 한다. 타이머 저장 누락과 이전 완료값으로 최신 입력 덮어쓰기를 결함 후보로 둔다.
- 순서 축소: 타이머 결함은 입력, 시간 진행과 저장 조회가 남아야 하며 새로고침 저장으로 구제되면 안 된다. 최신 입력 손실은 요청 A, 입력 B와 완료 A의 선후 관계를 남긴다.
- 로그 기록: 마지막 입력 및 가상 시각, 저장 계기, 실제 요청 ID와 요청 원문, 완료 순서 및 이탈 전 조회값을 기록한다.
- 재현: 앱의 타이머 사용 전에 Clock을 설치한다. [Clock의 설치 순서](https://playwright.dev/docs/clock)는 뒤늦은 설치가 정의되지 않은 동작을 만든다고 경고한다. 타이머 진행과 저장 commit은 별도 관찰하며 강제 종료의 보존을 자동 저장 성공으로 일반화하지 않는다.

### 모바일 명시적 저장과 이탈

기존 모바일 상세 검사에 실제 행동 순서 생성을 연결한다. 320 CSS px 및 `48rem` 전후 작업 영역에서 목록과 상세의 차이를 확인한다.

- 행동 생성: 상세 열기, 편집, 저장, 저장 중 반복 시도, 내부 이동, 계속 편집, 변경사항 버리기와 재진입을 조합한다. 저장 실패 뒤 입력 유지도 포함한다.
- 오류 탐지: 명시적 저장의 원문이 재진입 뒤 남고, 계속 편집은 입력을 유지하며 버리기는 저장값을 유지해야 한다. 계속 편집 선택을 무시하는 이동과 저장 버튼의 쓰기 누락을 결함 후보로 둔다. 너비 전환은 저장된 geometry를 바꾸지 않아야 한다.
- 순서 축소: 상세 열기, 입력, 내부 이동과 계속 편집 또는 버리기의 판정에 필요한 행동만 남긴다. 축소 중 데스크톱 자동 저장 사례로 바뀌지 않게 표현 조건을 보존한다.
- 로그 기록: 작업 영역 크기, 현재 주소, 원문 및 입력, 이탈 선택과 저장 전후 값을 기록한다.
- 재현: 같은 viewport에서 화면 버튼과 내부 탐색을 실행한다. 브라우저 강제 종료나 미정인 이탈 정책은 이 검사에 포함했다고 보고하지 않는다.

### 초안 복구와 제거 재시도

`note-draft.test.ts`, `save-note-content.test.ts`, 저장 모델과 실제 저장소 검사를 확장한다. [다음 저장 기회의 제거 재시도](../decisions/note-draft-cleanup-retry.md)를 유지한다.

- 행동 생성: 정상 및 오래된 revision의 초안 준비, 복구 시도, 초안 쓰기 실패, 메모 쓰기 실패, 정리 실패, 같은 원문 및 새 원문의 다음 저장을 조합한다. 잘못된 메모 ID와 revision의 복구 시도는 안전한 거부를 확인한다.
- 오류 탐지: 초안 쓰기 직후에는 해당 원문이 있고 제거 뒤에는 없어야 한다. 메모 저장 후 정리만 실패하면 저장 성공을 유지하고 다음 기회에 정리하며 같은 원문은 revision을 늘리지 않는다. 초안 쓰기 무시, 오래된 초안 복구와 재시도 누락을 결함 후보로 둔다.
- 순서 축소: 메모 저장, 초안 제거 실패와 같은 원문 재시도를 남기고 무관한 편집을 제거한다. 기존 초안이 남은 상태에서 초안 쓰기가 다시 실패하는 경우에는 이전 초안을 초기 자료에 보존한다.
- 로그 기록: 메모 ID와 content revision, 초안의 기준 revision과 원문, 실패한 저장 작업과 정리가 남은 상태를 기록한다.
- 재현: 기록한 초안을 실제 저장소에 준비하고 새 연결 및 화면 재진입으로 복구 결과를 확인한다. [IndexedDB transaction 수명](https://www.w3.org/TR/IndexedDB/#transaction-lifecycle)의 완료 이후 읽기로 저장을 확인하며 최종 초안 부재만으로 쓰기 성공을 판단하지 않는다.

### 위치와 크기 및 속성 적용

`note-geometry.test.ts`, 생명 주기 모델과 `notes.spec.ts`를 사용한다. 순수 수치 판정, 속성 폼과 실제 drag가 같은 저장 결과를 만드는지 구분해 확인한다.

- 행동 생성: 속성 입력 및 blur, Enter, 패널 밖 클릭, 헤더 이동, 네 변과 네 꼭짓점 resize, 취소와 새로고침을 조합한다. 음수 및 4096 밖 위치는 정상이고 너비 `240..4095`, 높이 `180..4095` 바로 안팎 및 유한하지 않은 수치는 별도로 생성한다.
- 오류 탐지: 요청한 geometry, 반대편 변 보존, content revision 불변과 잘못된 입력 뒤 저장값 및 오류 입력을 확인한다. 허용 좌표의 강제 보정, 적용 무시와 resize 반대편 이동을 결함 후보로 둔다.
- 순서 축소: 필요한 배율과 원점 통과 조건을 보존한 채 입력 또는 pointer 시작, 이동과 종료까지 줄인다. 취소 사례에서 성공한 종료가 사라진 경우는 같은 실패인지 다시 확인한다.
- 로그 기록: 시작 geometry, 속성 원문 입력, 실제 저장값, 배율, pointer 종류 및 종료 신호를 기록한다.
- 재현: 실제 폼과 pointer 조작으로 재현하고 새 연결 및 새로고침 뒤 geometry를 읽는다. 저장된 숫자만으로 drag 성공을 대신하지 않는다.

### 겹침 순서

`note-order.test.ts`, 생명 주기 모델과 실제 IndexedDB 및 겹친 메모 화면을 사용한다. 순서 계산을 운영 알고리즘 그대로 복제하지 않는다.

- 행동 생성: 여러 메모에서 맨 앞, 맨 뒤, 같은 명령 반복과 재조회를 조합한다. 같은 `zIndex`를 가진 합성 초기 자료도 포함한다.
- 오류 탐지: 명시적 이동 후 대상의 위치, 다른 메모의 상대 순서, `1..N` 고유 번호, Tab 순서 및 content revision 보존을 비교한다. 명령 무시와 일부 메모만 저장하는 결함을 구분한다.
- 순서 축소: 구분되는 세 메모와 한 번의 순서 변경까지 줄여도 나머지 상대 순서 오류가 남는지 확인한다. 두 메모만 남아 검사할 상대 순서가 없어지면 해당 증거가 아니다.
- 로그 기록: ID의 기대 상대 순서, 실제 ID별 저장 번호, Tab 순서, 실제 겹친 위치에서 입력을 받은 메모를 기록한다.
- 재현: 한 transaction의 저장 성공 뒤 새 연결에서 전부 읽고 화면의 겹친 지점에서 실제 입력 대상을 확인한다. 중복값의 표시와 명시적 이동의 동률 처리 차이가 요구사항과 충돌하면 해당 정책만 확인 대상으로 남긴다.

### 삭제와 취소 및 만료

`note-removal-history.test.ts`, 생명 주기 모델, IndexedDB 검사와 삭제 E2E를 연결한다. [삭제 복원 결정](../decisions/note-removal-recovery.md)의 원래 숫자와 절대 만료 시각을 기준으로 삼는다.

- 행동 생성: 서로 다른 시각의 연속 삭제, 최근 삭제 취소, 빈 이력 취소 시도, 5초 직전 및 만료 후 실행, 내부 이동, 새로고침과 삭제 사이의 순서 변경을 조합한다. 복원 진행 중 다른 삭제는 시작한 스냅샷만 제거하는 기존 규칙으로 판정한다.
- 오류 탐지: 삭제 직후 대상 부재, 같은 ID의 스냅샷 복원, 원래 `zIndex`, 다른 메모 불변과 복원 포커스를 읽는다. `A=1,B=2,C=3`에서 B 삭제, A 앞으로, B 복원 뒤에는 `C=1,A=2,B=2`다. 복원 번호 증가, 다른 메모 복원과 route 이동 시 기한 재시작을 결함 후보로 둔다.
- 순서 축소: 숫자 보존은 삭제, 다른 메모 순서 변경과 취소를 남긴다. 만료 오류는 삭제 완료 시각과 시간 진행을, 진행 중 복원 오류는 두 스냅샷의 ID 및 시각을 남긴다.
- 로그 기록: 삭제 완료 및 만료 시각, 스냅샷의 보존 필드, 실제 삭제 및 복원 레코드, 취소 대상과 포커스를 기록한다. 모델 메모를 실제 삭제 이력 입력으로 전달하지 않는다.
- 재현: 같은 가상 시각에서 실제 삭제 및 취소를 실행한다. route는 기한을 늘리지 않고 새로고침은 이력만 없애야 한다. 복원해 저장한 중복 번호는 새 연결에서도 유지한다. 같은 번호 자체는 결함이 아니다.

### 선택과 포커스 및 속성 대상

`note-workspace-state.test.ts`는 자료 전이의 보조 증거다. 사용자 선택, 키보드 포커스와 속성 대상의 분리는 실제 화면에서 다섯 절차를 입증한다.

- 행동 생성: 헤더 click 및 double click, Tab 및 Shift+Tab, 선택 지점 Enter, 본문 Enter, 빈 캔버스, Escape, Command와 패널 닫기를 조합한다. 입력기 조합과 하위 버튼에서의 Enter를 별도로 다룬다.
- 오류 탐지: 한 번 선택은 패널을 바꾸지 않고 패널 열기 행동만 대상을 바꾸는지 확인한다. 선택 해제 뒤 속성 초안을 유지하고 실제 포커스 대상을 읽는다. 단일 click에서 패널 열기와 선택 해제 시 속성 초안 삭제를 결함 후보로 둔다.
- 순서 축소: A 속성 열기, B 선택과 선택 해제처럼 서로 다른 선택 및 속성 대상을 구분하는 순서만 남긴다. 단일 메모로 줄여 차이를 지워서는 안 된다.
- 로그 기록: 행동 대상, 실제 포커스, 열린 패널 대상 및 입력값, modifier와 관찰 시점을 기록한다.
- 재현: 같은 논리 ID의 메모를 준비하고 실제 키보드 및 pointer 입력으로 실행한다. 합성 composition event의 결과를 실제 한글 입력기 동작으로 일반화하지 않는다. 일괄 복사 선택과의 기존 상호작용 검사는 보존하되 새 탐색 대상에는 추가하지 않는다.

### 캔버스 이동과 확대 및 축소

화면 변환과 pointer 종료는 `notes.spec.ts`의 기존 과업을 바탕으로 생성한다. 카메라 계산을 테스트 안에 다시 구현해 비교하지 않는다.

- 행동 생성: 빈 캔버스 drag, 기준 거리 전후 이동, 확대, 축소, 전체 맞춤, 패널 및 너비 전환, pointerup 뒤 capture 상실과 중복 종료를 조합한다. 메모에서 시작한 drag와 구분한다.
- 오류 탐지: 메모의 저장 좌표는 유지하고 화면 시점만 바뀌는지 확인한다. 완료한 pointerup 뒤 종료 신호가 와도 마지막 시점이 유지돼야 한다. 종료 뒤 시작점 복귀, 캔버스 이동 시 메모 저장 좌표 변경을 결함 후보로 둔다.
- 순서 축소: 빈 캔버스 시작, 기준 초과 이동, 종료와 후속 종료 신호를 남긴다. 목표가 확대 후 동작이라면 배율 변경을 제거해 다른 오류로 바뀌지 않는지 확인한다.
- 로그 기록: viewport, 시작 및 마지막 관찰 위치, 배율, 저장 geometry와 전달한 종료 신호를 기록한다.
- 재현: 의미가 정해진 보기 제어와 실제 pointer 입력으로 실행한다. 인위적으로 전달한 capture 신호는 브라우저가 자연 발생시킨 신호와 구분한다. 운영체제 캡처 도구의 event 누락은 별도 실제 환경 증거로 남기며 자동화만으로 완료하지 않는다.

### 개별 복사

`copy-note.model.test.ts`와 `copy-note.test.ts`는 명령 판정에, `clipboard-permissions.spec.ts`와 `touch-interactions.spec.ts`는 실제 쓰기 및 입력에 사용한다.

- 행동 생성: 저장한 원문 복사, 반복 복사, 위치 변경 후 복사, Clipboard 실패 및 재시도, Command click과 모바일 long press 및 취소를 조합한다. 일반 click과 짧은 터치는 복사가 아닌 행동으로 확인한다.
- 오류 탐지: 성공 시 원문 전체가 Clipboard에 있고 쓰기 거부 시 성공 횟수가 늘지 않는지 확인한다. 읽기 권한이 있는 환경에서는 이전 Clipboard의 보존도 비교한다. 모바일 500ms 및 10 CSS px 조건과 복사 후 상세 이동 억제를 판정한다. 빈 원문 쓰기, 다른 메모 복사와 long press 뒤 click 이동을 결함 후보로 둔다.
- 순서 축소: 원문 준비와 복사까지 줄이거나 long press 및 뒤따른 click을 남긴다. 축소된 원문이 실제 원문과 결함 출력의 차이를 없애면 실패 사례가 아니다.
- 로그 기록: 입력 방식, 읽기 및 쓰기 권한 설정, pointer 거리 및 시간, 복사 대상 ID와 content revision, 관찰 가능한 이전 및 이후 Clipboard 원문과 주소를 기록한다. 읽기도 거부되면 미관찰로 기록하며 빈 문자열로 대체하지 않는다.
- 재현: 도메인에서는 같은 대역 실패를, 권한과 gesture는 해당 브라우저 프로젝트에서 재현한다. [Clipboard 표준](https://www.w3.org/TR/clipboard-apis/)의 권한 및 사용자 활성화 조건 때문에 대역 성공을 실제 권한 증거로 삼지 않는다. Chromium 전용 Clipboard 및 touch 결과를 Firefox와 WebKit의 같은 결과로 확대하지 않는다.

### 사용 기록과 집계 화면

`text-usage-record.test.ts`는 자료 형식, `usage-projection.test.ts`는 집계 규칙을 확인한다. `copy-note.model.test.ts`의 전달 기록만으로 실제 저장 횟수를 입증하지 않는다.

- 행동 생성: 같은 원문 반복 복사, 편집 및 저장 후 복사, 위치만 변경 후 복사, Clipboard 실패, 기록 저장 실패와 사용 화면 재조회를 조합한다.
- 오류 탐지: 성공 시점의 메모 ID와 content revision별 개별 복사 횟수, 원문 스냅샷 및 화면 합계를 비교한다. 기록 저장 실패 시 복사 원문은 유지하되 횟수는 늘지 않아야 한다. revision을 잘못 연결하거나 실패한 복사까지 더하는 결함을 후보로 둔다. 기존 일괄 복사 횟수는 바꾸지 않는다.
- 순서 축소: revision 구분은 편집 전후 성공 복사 두 건을, 부분 실패는 복사 성공과 기록 실패를 남긴다. 집계와 무관한 위치 변경은 제거할 수 있지만 위치 변경으로 잘못 분리되는 결함에서는 유지한다.
- 로그 기록: 복사 시점 원문, ID 및 content revision, 쓰기 성공 여부, 저장된 횟수와 화면의 개별 및 합계 값을 기록한다.
- 재현: 같은 합성 초기 기록에서 명령, 실제 사용 기록 repository와 집계 화면을 다시 실행한다. 과거 기록이 새 원문으로 바뀌지 않는지 확인하고 페이지를 다시 열어 정확한 그룹 및 횟수를 비교한다.

## 기존 작업의 제거 필요성

2026년 9월 13일 변경분을 직전 날짜의 상태와 비교한 결과, 전부 제거하거나 되돌릴 근거는 없다. 이 판단은 코드와 기록을 읽은 결과이며 각 검사가 의도한 오류를 찾는지 새로 실행해 확인한 것은 아니다.

- 초안 제거 재시도의 운영 수정은 승인된 제거 재시도를 구현한다. 이를 되돌리면 같은 원문의 다음 저장 기회에서 제거를 재시도할 정보를 잃으므로 유지한다.
- fast-check와 `test:model`, 네 프로필은 이번 기능별 탐색에도 필요하다. 선택 프로필 표시, 명령 계측과 중단 판정은 보완 대상이지 전체 설정을 제거할 이유가 아니다.
- 세 모델의 원문 및 revision 비교, 부분 실패와 복원 숫자 검사는 기존 규칙의 일부를 보호한다. 모델 자료를 실제 입력에 쓰는 연결, 복제에 가까운 순서 계산, 일반 실패 로그 누락과 고정 순서 결함 검사는 목적을 보존하며 수정할 대상이다.
- 실제 IndexedDB의 삭제 직후 조회와 중복 번호 재조회는 유지한다. 초안 쓰기 직후 관찰을 추가할 필요와 기존 저장소 검사의 가치는 별개다.
- 기존 E2E의 실제 생성, 입력, 삭제 취소와 새로고침은 유지한다. 저장 원인, 정확한 메모 수, 겹침 조작과 복원 포커스의 관찰을 보완해야 한다.

중복 테스트를 줄일지는 같은 요구사항, 실행 계층, 관찰 시점과 실패 종류를 대체 검사가 모두 보호한 뒤 판단한다. 현재는 삭제를 결정하거나 실행하지 않는다. 먼저 바꿀 것은 저장 우선의 전체 진행 조건과 과도한 완료 표시이며, 이전 실행 수치와 확인된 제한은 삭제하지 않고 역사 기록으로 유지한다.

## 계획에 반영할 결론과 한계

기능별로 다섯 절차와 실제 실행 계층을 하나의 완료 단위로 묶는다. 공통 보고, 직렬화와 프로필 코드는 필요한 첫 기능에서 보완하고 실제 반복되는 책임만 재사용한다. 12개 기능마다 별도 실행기나 파일 묶음을 만들지 않는다. 다른 기능은 필요한 초기 메모를 fixture로 준비할 수 있으므로 생성이나 저장 기능의 전체 완료를 기다리지 않는다.

로컬 기능별 완료와 CI 재현은 분리한다. 원격 저장소 및 CI 서비스가 정해지기 전에는 로컬 구현을 계속할 수 있지만 CI 완료로 표시할 수 없다. 저장 중 삭제, 동일 ID 재사용과 동률 표시처럼 아직 정해지지 않은 결과는 영향을 받는 행동만 보류한다. HTTP API, 공통 패키지, XState, 임의 동시성 탐색과 LLM 실행 의존성은 추가하지 않는다.
