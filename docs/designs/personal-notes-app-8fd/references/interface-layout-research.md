# 화면 구성과 공간형 메모 상호작용 조사

## 후속 변경 안내

2026년 9월 3일 후속 요구는 이 조사에 남은 얇은 선택 테두리, `1280 × 960` 메모 상한, 데스크톱 항목 동작 선택창과 자동으로 사라지지 않는 복사 알림을 대체했다. 2026년 9월 4일 후속 요구는 토스트를 5초 동안 표시하고, 일괄 복사 항목 선택과 방향키 재정렬 및 두 선택을 함께 해제하는 `Escape`를 추가했으며, 접속 확인과 다른 화면의 장식용 카드 표면을 제거하도록 정했다. 2026년 9월 23일 모바일 결정은 아래의 우측 하단 저장 항목 수 제어를 평상시 메모 목록의 Drawer 링크로 대체했다. 현재 화면 기준은 [개인 메모 애플리케이션 요구사항](../requirements.md), [개인 메모 디자인 시스템과 UI 기반 결정](../decisions/application-design-system.md), [공간형 보드와 작은 화면 목록 결정](../decisions/responsive-note-presentation.md), [일괄 복사 패널과 모바일 확인 페이지 결정](../decisions/accumulator-workspace-panel.md)과 [Drawer 저장 목록 링크 조사](mobile-saved-batch-copy-drawer-research.md)를 따른다. 아래 내용은 앞선 화면 구조 결정의 근거와 변경 이력으로 유지한다.

## 결론

메모 화면은 초기 구현에서 `4096 × 4096` CSS px의 고정 논리 캔버스를 사용한다. 사용자는 캔버스 시점을 이동하고 확대해 탐색하며, 메모를 선택해 정해진 범위 안에서 위치와 크기를 바꾸고, 화면 맞춤으로 메모가 있는 범위를 다시 찾을 수 있어야 한다. 메모 작업 영역의 너비가 작으면 같은 메모를 공간형 보드 대신 일반적인 목록 형태로 제공한다. 논리 캔버스 크기 변경과 인쇄 및 내보내기 프레임은 현재 범위에 포함하지 않는다.

메모 화면은 왼쪽 사이드바를 사용하지 않는다. 다른 화면으로 가는 탐색은 메모 작업 영역의 가로 폭을 계속 차지하지 않는 상단 영역에 두고, 사용 빈도, 텍스트 분석, 템플릿과 설정 화면에서는 많은 자료를 읽는 동안 현재 위치를 유지할 수 있는 왼쪽 탐색을 사용한다. 작은 화면에서는 두 표현 모두 탐색을 접어 주 콘텐츠를 먼저 보여준다.

넓은 화면의 메모는 짧은 헤더와 항상 편집 가능한 본문으로 나눈다. 본문의 일반 클릭과 drag는 커서 이동 및 선택, `Command+클릭`은 개별 복사, `Command+Option+클릭`은 일괄 복사 목록 추가를 맡는다. 포커스가 있는 메모 선택 지점의 `Command+Option+Enter`도 pointer 설정과 관계없이 같은 추가 명령을 실행한다. `Command` keydown으로 선택이 해제돼도 포커스 대상 ID를 사용한다. 헤더 drag는 이동을 맡고 헤더 오른쪽에는 맨 앞으로, 맨 뒤로와 삭제 아이콘만 둔다. 크기는 네 가장자리와 네 꼭짓점에서도 직접 drag해 바꿀 수 있다.

이동이 아닌 한 번의 헤더 클릭 또는 각 메모의 양의 `tabindex`가 낮은 순서를 따르는 `Tab`은 메모를 선택해 굵고 끊기지 않는 붉은 테두리만 새로 표시하고, 헤더 더블클릭 또는 선택된 메모의 선택 지점에서 실행한 `Enter`는 오른쪽 속성 패널을 연다. 빈 캔버스 클릭과 `Command`는 메모 선택을 해제하고, 상위 임시 조작이 없는 `Escape`는 메모와 일괄 복사 항목 선택을 함께 해제한다. `Command`를 누르는 동안에는 메모 크기를 유지한 채 헤더를 숨긴다. 오른쪽에는 속성 패널과 일괄 복사 패널 가운데 마지막으로 활성화한 패널 하나만 표시한다.

`48rem` 미만의 목록에서는 같은 조작을 축소하지 않는다. 메모 카드는 제한된 높이의 미리보기이며 짧게 누르면 상세 화면, 길게 누르면 개별 복사를 실행한다. 목록 화면 헤더의 아이콘으로 일괄 복사 상태를 시작하고, 상태 안에서는 짧게 누른 횟수와 순서대로 항목을 모은다. 헤더 왼쪽의 뒤로가기 아이콘은 상태를 끝내고, 화면 아래에는 `초기화`와 클릭 횟수가 함께 표시되는 `다음`을 둔다. `다음`은 별도 확인 페이지로 이동하고, 사용자는 항목을 길게 누른 뒤 재정렬하거나 항목별 동작 선택창에서 복제 및 삭제할 수 있다.

현재 개발하는 로컬 애플리케이션은 메모 화면, `48rem` 이상에서 그 안에 표시하는 일괄 복사 패널, `48rem` 미만의 메모 상세 화면과 일괄 복사 확인 및 저장 목록 관리 페이지, 사용 빈도, 텍스트 분석, 템플릿과 설정을 제공한다. `/batch-copy`는 전역 탐색 항목에 추가하지 않고 일괄 복사 상태의 `다음` 또는 메모 목록의 우측 하단 저장 항목 수 제어로 이동한다. 계정과 동기화 탐색 항목 및 페이지는 제공하지 않고, 분석 화면에는 사용자가 누르는 분석 버튼을 둔다. 계정과 동기화를 추가하는 최우선 백로그를 시작하면 공통 화면 구조와 조작을 유지하는 방안을 다시 검증해야 한다.

라이브러리 패키지와 포트폴리오 라우트 연결은 현재 구현에서 다루지 않고 백로그로 둔다. 이 백로그를 시작하면 독립 실행 애플리케이션과 포트폴리오 라우트에 연결된 모듈이 개인 메모 내부의 정보 구조와 조작 방식을 공유하되, 바깥쪽 탐색과 개인 메모 내부 탐색이 중복되지 않도록 제공 영역을 먼저 나눠야 한다.

이 문서는 [개인 메모 애플리케이션 요구사항](../requirements.md)의 메모 편집, 자유 배치와 크기 변경, 작은 화면의 목록 및 상세 편집, 일괄 복사 패널과 모바일 확인 페이지, 보조 키 설정, 클립보드 알림 및 페이지 배치를 조사한 참고 자료다. 화면 흐름 초안과 상호작용 결정을 검토할 때 사용한다.

구성요소별 시각 특징, 2026년 디자인 흐름과 AI 생성 UI의 반복 패턴은 [2026년 웹 애플리케이션 시각 디자인과 AI 생성 UI 조사](web-visual-design-research-2026.md)에서 별도로 다룬다.

작은 화면의 목록과 링크 형식 문자열을 일반 텍스트로 다루는 것은 승인된 요구사항이다. [공간형 보드와 작은 화면 목록 결정](../decisions/responsive-note-presentation.md)은 메모 컨테이너 `48rem`을 초기 전환값으로 정하고 기기 종류 판별을 제외한다. 시각적 성격은 [Pretendard와 Figma식 작업 화면 결정](../decisions/figma-inspired-visual-direction.md)이 관리한다. 메모 헤더, 보조 키 조작과 모바일 일괄 복사 수집 근거는 [메모 조작과 모바일 일괄 복사 조사](note-interaction-and-mobile-batch-copy-research.md), 확인 페이지와 오른쪽 패널은 [모바일 일괄 복사 확인과 오른쪽 패널 우선순위 조사](mobile-batch-copy-confirmation-and-panel-priority-research.md)에 기록했다. 공식 도움말, 접근성 표준과 공식 화면 예시는 2026년 8월 30일에 처음 검토했고 최신 모바일 조작 변경을 반영해 2026년 9월 2일에 다시 검토했다.

## 접속 안내와 카드 표면 재검토

현재 접속 확인 UI는 진행 상태와 실패 안내를 하나의 둥근 테두리, 채운 배경과 그림자가 있는 표면으로 감싼다. 이 화면에는 서로 구분해야 할 여러 대상이나 선택 가능한 항목이 없으므로 카드 외곽이 정보 구조를 보태지 않는다. 진행 중에는 빈 주 화면 위에 간결한 상태만 표시하고, 실패하면 같은 읽기 위치에 제목과 해결 방법을 배치하는 편이 현재 내용의 위계에 맞는다.

[GOV.UK 오류 메시지 지침](https://design-system.service.gov.uk/components/error-message/)은 `valid`와 `invalid`처럼 해결 방법을 보태지 않는 표현을 피하고, 무엇이 일어났는지와 어떻게 바로잡을지를 구체적으로 쓰도록 안내한다. 접속 제한은 사용자가 입력한 폼 값의 오류가 아니므로 필드 오류처럼 표시하지 않고 별도 상태 화면에서 문제와 다음 행동을 설명한다. 후속 요구사항에 따라 제목은 `잘못된 접근입니다.`로 표시하고, 본문에서 HTTPS 주소 또는 `http://localhost`로 다시 열도록 안내한다. 제목이 주소 조건을 구체적으로 설명하지 않으므로 해결 방법을 본문에서 생략하면 안 된다.

[Fluent 2 Card 지침](https://fluent2.microsoft.design/components/web/react/core/card/usage)은 하나의 개념이나 대상에 관한 정보와 동작을 카드에 담고, [USWDS Card 지침](https://designsystem.digital.gov/components/card/)은 카드를 비슷한 항목의 모음 안에서 독립적으로 이해할 수 있는 요약 단위로 설명한다. [Carbon Tile 지침](https://carbondesignsystem.com/components/tile/usage/)은 관련 정보나 동작을 묶는 표면과 알림 및 이차 동작을 위한 modal, popover, dialog를 구분한다. [Apple Layout 지침](https://developer.apple.com/design/human-interface-guidelines/layout)은 정렬과 논리적인 구획을 사용해 위계를 만들도록 권한다. 공식 예시는 서로 다른 이름을 쓰지만 카드가 단순 장식이 아니라 독립된 대상 또는 관련 묶음의 역할을 가져야 한다는 점에서 일치한다.

현재 화면 소스를 이 기준으로 확인한 결과는 다음과 같다.

- 접속 확인 및 실패, 사용 빈도와 텍스트 분석의 빈 상태, 템플릿 원문이 없는 상태에서는 둥근 외곽, 채운 카드 배경과 그림자를 제거한다.
- 설정의 유일한 폼, 템플릿 편집 폼과 일회성 생성 폼은 페이지 안의 평평한 section과 구분선으로 나눈다. 폼 전체를 다시 카드 하나로 감싸지 않는다.
- 사용 빈도 표는 표의 행과 열 구분을 유지하되 둥근 그림자 컨테이너로 만들지 않는다. 분석 결과, 저장된 템플릿, 선택 원문과 플레이스홀더는 목록 행과 구분선을 기본으로 삼고 카드 안의 카드를 만들지 않는다.
- 공간에 놓인 메모는 애플리케이션의 핵심 대상이므로 메모 표면을 유지한다. 일괄 복사 항목도 항목 전체의 선택, drag와 개별 동작을 전달하므로 독립된 목록 항목 표면을 유지한다. Dialog, popover와 toast는 카드가 아니라 일시적인 상호작용 계층으로 분리한다.

카드 외곽을 없앤다는 이유로 모든 구분을 없애지는 않는다. 제목, 간격, 정렬, 배경 단계와 구분선 가운데 필요한 수단을 사용하고, 선택, 포커스, 오류 및 drag 상태 테두리는 해당 상태를 전달하므로 유지한다. 구현 뒤 각 표면이 독립적으로 순서를 바꿔도 의미가 유지되는 대상인지, 전체 표면에 하나의 선택 또는 이동 동작이 있는지, 아니면 페이지 내용을 습관적으로 감싼 것인지 실제 화면에서 다시 판정해야 한다.

## 유사 서비스에서 확인한 메모 편집 방식

### macOS Stickies

[Apple Stickies 사용 설명서](https://support.apple.com/en-ie/guide/stickies/welcome/mac)는 메모의 제목 막대를 드래그해 이동하고 위, 아래와 양옆 가장자리를 드래그해 크기를 바꾸며, 메모 창 자체에 바로 텍스트를 입력하고 자동 저장하는 동작을 안내한다. 이번 메모도 별도 편집 단계 없이 본문을 편집하고 짧은 헤더를 이동 영역으로 사용한다. 개별 복사와 일괄 복사만 Stickies에 없는 보조 키 클릭으로 분리한다.

### Apple Freeform

[Freeform에서 보드 만들기](https://support.apple.com/guide/freeform/create-a-board-frfm9474646a9/mac)는 보드가 내용 추가에 따라 확장되며 페이지 형식이나 크기에 제한되지 않는다고 설명한다. [도형에 텍스트 추가하기](https://support.apple.com/guide/freeform/add-a-shape-or-line-frfm8479c716/mac)는 도형을 이중 클릭해 텍스트를 입력하는 동작을 안내하고, [항목 크기 변경하기](https://support.apple.com/en-gb/guide/freeform/frfmaec1128f/mac)는 선택한 항목의 핸들을 드래그해 크기를 바꾸는 방식을 설명한다.

[Freeform 보드 보기 변경하기](https://support.apple.com/en-gb/guide/freeform/frfm000074a4e/mac)는 확대, 축소, 선택 항목으로 이동, 콘텐츠 전체 맞춤, Space 키를 누른 채 드래그하는 pan과 점 격자를 제공한다. 공식 화면 예시에서도 도구는 상단에, 보드 탐색과 zoom은 보드 가장자리의 작은 제어 영역에 배치되어 콘텐츠 공간을 우선한다.

### FigJam

[FigJam 파일 둘러보기](https://help.figma.com/hc/en-us/articles/15300412458647-Explore-FigJam-files)는 하나의 무한 보드, pan과 zoom, 파일 패널과 주 도구 막대로 화면을 나눈다. [FigJam 스티커 메모 도움말](https://help.figma.com/hc/en-us/articles/1500004414322-Sticky-notes-in-FigJam)은 스티커를 선택한 뒤 입력하고, 내용에 따라 세로로 커지며, 옆면이나 모서리를 드래그해 폭 또는 전체 크기를 바꾸는 동작을 설명한다. [화면 읽기 프로그램으로 FigJam 사용하기](https://help.figma.com/hc/en-us/articles/14477051168791-Use-FigJam-with-a-screen-reader)는 항목을 선택하고 `Enter`로 편집하는 키보드 흐름을 안내한다.

이 사례는 선택 상태와 편집 상태를 나눌 수 있고, 선택 뒤 `Enter`가 편집 진입으로 이해될 수 있음을 보여준다.

### Miro

[Miro 보드 콘텐츠 구조화 도움말](https://help.miro.com/hc/en-us/articles/360017730973-Structuring-board-content)은 보드가 끝없이 확장되며 프레임으로 콘텐츠를 묶고 발표나 내보내기 순서를 정하는 방식을 설명한다. [Miro 스티커 메모 도움말](https://help.miro.com/hc/en-us/articles/360017572054-Sticky-notes)은 스티커를 선택해 입력하고 선택 상태의 제어 UI로 크기와 모양을 바꾸는 동작을 안내한다. [Miro 프레임 도움말](https://help.miro.com/hc/en-us/articles/360018261813-Frames)은 무한 보드 안에 정해진 영역을 만들고 콘텐츠를 구성하는 별도 수단을 제공한다.

이 사례는 보드 전체의 페이지 크기를 사용자가 먼저 지정하지 않아도, 나중에 프레임으로 작업 영역이나 출력 범위를 만들 수 있음을 보여준다.

### Google Keep과 Microsoft Sticky Notes

[Google Keep의 메모 수정 도움말](https://support.google.com/keep/answer/2888246?co=GENIE.Platform%3DDesktop&hl=en-GB)은 목록이나 그리드에서 메모를 클릭해 편집 화면을 열고 실행 취소와 다시 실행을 제공한다. [Google Keep의 화면 읽기 프로그램 도움말](https://support.google.com/keep/answer/16914649?hl=en)은 `Enter`로 메모를 편집하고 `Escape`로 나오는 흐름을 설명한다. Keep은 클릭을 복사에 쓰지 않으므로 클릭 편집을 그대로 가져올 수 없지만, 편집 진입과 종료 상태를 구분하는 참고가 된다.

[Microsoft Sticky Notes 시작 안내](https://support.microsoft.com/en-us/windows/apps/stickynotes/get-started-with-sticky-notes)는 메모 상단을 드래그해 이동하고 가장자리를 드래그해 크기를 바꾸며 위치를 기억한다고 설명한다. Apple Stickies와 마찬가지로 이동 영역과 크기 조절 가장자리가 구분된다.

## 편집, 복사와 이동을 충돌 없이 나누는 결정

### 넓은 공간형 화면

- 본문은 항상 편집 가능한 여러 줄 `textarea`다. 일반 click과 drag는 커서 이동 및 텍스트 선택에 맡긴다.
- `Command+클릭`은 원문 전체 개별 복사를 실행하고, `Command+Option+클릭`은 개별 복사를 함께 실행하지 않고 일괄 복사 목록에 원문 스냅샷을 추가한다.
- 두 보조 키가 모두 눌린 조합을 `Command+클릭`보다 먼저 판정한다.
- URL처럼 보이는 문자열도 일반 텍스트로 유지하고 자동 링크, 미리보기 또는 클릭 이동을 만들지 않는다.
- 짧은 헤더의 아이콘 버튼이 아닌 영역을 drag하면 메모를 이동한다. 헤더 click은 복사, 항목 추가 또는 편집 상태 전환을 실행하지 않는다.
- 이동으로 판정되지 않은 한 번의 헤더 click과 `Tab` 탐색은 메모를 선택하고 선택 테두리만 새로 표시한다. 이동이 아닌 헤더 더블클릭 또는 선택된 메모의 선택 지점에서 실행한 `Enter`는 해당 메모의 속성 패널을 연다. 빈 캔버스 click, `Escape`와 `Command`는 선택만 해제한다. 선택 테두리와 키보드 포커스 표시는 서로 다른 상태로 식별할 수 있어야 한다.
- 헤더 drag가 시작되면 같은 pointer 연속 입력의 click과 더블클릭을 실행하지 않고, drag를 끝내거나 취소할 때까지 오른쪽 패널 전환으로 캔버스 계산 크기를 바꾸지 않는다.
- `Command`를 누르면 선택을 해제하고 헤더 행의 높이와 메모 외곽 크기를 유지한 채 헤더의 시각 요소와 조작을 숨긴다. 본문의 보조 키 복사는 메모를 다시 선택하거나 속성 패널 대상을 바꾸지 않는다.
- 헤더 오른쪽에는 `맨 앞으로`, `맨 뒤로`, `메모 삭제` 결과를 가진 아이콘 버튼만 둔다. 아이콘은 장식으로 숨기고 네이티브 버튼에 접근 가능한 이름을 제공한다.
- 오른쪽 속성 패널은 대상 메모의 `X`, `Y`, 너비와 높이 입력을 제공한다. 입력 초안은 `blur`, 패널 밖 click 또는 `Enter` 가운데 하나가 발생할 때 같은 적용 절차로 저장하고, 유효하지 않은 값은 기존 위치와 크기를 바꾸지 않은 채 해당 입력에서 고칠 수 있게 한다.
- 원문은 마지막 입력 `800ms` 뒤 자동 저장하고 `blur`, 애플리케이션 내부 route 이동, document hidden과 `pagehide`에서 대기 중인 최신 입력을 같은 흐름으로 즉시 저장한다. IndexedDB 복구 초안을 먼저 기록하며 저장 실패에서는 입력과 초안을 유지하고 재시도를 제공한다.

### 작은 화면 목록과 상세 화면

- 목록 카드는 제한된 높이의 읽기 미리보기이며 직접 편집하지 않는다.
- 평소 짧은 누르기는 메모 상세 화면으로 이동하고, `500ms` 동안 시작점에서 `10 CSS px` 안에 머문 뒤 카드 안에서 손을 떼면 원문 전체를 개별 복사한다.
- 상세 화면은 전체 원문 `textarea`와 명시적인 저장 동작을 제공한다.
- 목록 화면 헤더의 아이콘으로 일괄 복사 상태를 시작한다. 이 상태의 짧은 누르기는 상세 화면으로 이동하지 않고 누른 횟수와 순서대로 항목을 추가한다.
- 상태 안에서는 헤더 왼쪽의 뒤로가기 아이콘으로 나가고, 화면 아래의 `초기화`로 이번 작업을 비우거나 클릭 횟수가 함께 표시된 `다음`으로 후속 단계에 이동한다.
- 길게 누르기와 짧은 누르기는 `pointerup`에서 완료하고, 스크롤, 대상 밖 이동과 `pointercancel`이 발생하면 실행하지 않는다.

### 크기 변경

- 위, 아래, 왼쪽과 오른쪽 가장자리 및 네 꼭짓점에서 직접 드래그해 메모 크기를 바꾼다.
- 숫자 입력, 단계 조절과 `크기` 텍스트 버튼은 메모 표면에 표시하지 않는다. 선택한 메모의 숫자 입력은 오른쪽 속성 패널에서만 제공하고, 직접 조절 가능한 방향은 cursor와 조절 중 외곽선으로 알린다.
- 메모 너비는 `240..1280`, 높이는 `180..960`으로 제한하고 실제 화면 검증에서 조작 가능성을 다시 확인한다.
- 내용이 사용자가 정한 메모 크기를 넘으면 메모 안에서 스크롤한다.

## 보드 크기와 탐색 결정

Freeform, FigJam과 Miro는 고정 페이지 크기보다 내용에 따라 확장되는 보드를 사용한다. 현재 구현은 자유로운 캔버스 크기 변경을 범위에서 제외하고, [공간형 보드와 작은 화면 목록 결정](../decisions/responsive-note-presentation.md)에 따라 다음 동작을 `4096 × 4096` CSS px 논리 캔버스에 적용한다.

- 메모 위치와 크기는 zoom과 독립적인 작업 공간 좌표로 저장한다.
- 보이는 캔버스에서 메모와 다른 조작 요소가 없는 지점을 주 pointer로 드래그하거나 `Space+드래그`하면 시점을 이동한다. 이동 시작 지점이 변환되는 보드 요소의 현재 경계 밖이라는 이유로 동작을 막지 않는다.
- 트랙패드 두 손가락 이동으로 pan하고, 트랙패드와 제어 UI로 zoom한다.
- `모든 메모 맞춤`은 메모들의 외곽 범위를 계산해 viewport에 맞춘다.
- 메모를 추가하면 현재 보이는 영역 안의 예측 가능한 위치에 놓는다.
- 메모가 멀리 떨어져 보이지 않을 때 보드 전체 맞춤이나 메모 검색으로 돌아올 수 있게 한다.
- 출력 범위가 필요해지면 Miro의 frame처럼 이름 붙인 영역을 후속 기능으로 검토한다.

사용자는 캔버스의 폭과 높이를 직접 입력하지 않는다. 메모 너비는 `240..1280`, 높이는 `180..960`, X는 `1..(4096 - width)`, Y는 `1..(4096 - height)`로 제한한다. 고정 페이지가 필요한 인쇄, PDF 내보내기나 프레젠테이션 요구가 생기면 frame 크기 또는 콘텐츠 외곽 범위를 출력 단위로 검토한다.

[Figma Design 파일 안내](https://help.figma.com/hc/en-us/articles/15297425105303-Explore-design-files)는 mouse에서 `Space+드래그`, trackpad에서 두 손가락 이동, 도구 모음의 Hand tool 또는 `H`를 캔버스 탐색에 사용한다. 중요한 구분은 Hand tool이 객체 조작을 하지 않는 탐색 상태라는 점이다. 이번 요구는 별도 Hand tool을 먼저 켜지 않아도 빈 캔버스의 주 pointer 드래그를 시점 이동으로 사용하므로, 이벤트 시작 지점이 메모 또는 조작 요소인지 판정한 뒤 캔버스 viewport가 pointer capture를 가져야 한다. 변환되는 내부 보드에만 이벤트를 달면 내부 보드 크기 밖의 빈 viewport가 이동하지 않는 현재 문제가 반복된다.

## 일괄 복사 작업을 화면 크기에 맞게 나누는 근거

[Fluent 2 Drawer 지침](https://fluent2.microsoft.design/components/web/react/core/drawer/usage)은 보조 정보와 간단한 동작을 주 콘텐츠와 연결할 때 drawer를 사용하고, 두 영역을 동시에 보고 조작해야 하면 inline 표현을 나란히 두라고 설명한다. overlay 표현은 주 콘텐츠를 가리므로 modality와 닫기 동작을 분명히 해야 하며, 여러 overlay를 겹치지 않도록 경고한다. 일괄 복사 항목은 원본 메모를 고르는 작업과 결합 결과 확인이 반복되므로 넓은 화면에서는 inline 표현의 조건에 맞는다.

[Material 3 canonical layout](https://m3.material.io/foundations/layout/canonical-examples/overview)은 주 영역과 보조 영역을 나란히 배치하는 supporting pane을 정의하고, 보조 과업에 집중해야 하는 환경에서는 pane을 주 콘텐츠 위에 겹칠 수 있다고 설명한다. 일괄 복사 목록을 최상위 페이지로 승격하지 않고 메모 작업을 보조하는 영역으로 두는 근거다.

작은 화면에서 메모 목록과 누적 목록을 동시에 줄이면 두 영역 모두 읽기 어렵다. [WAI-ARIA 모달 dialog 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)은 모달을 열 때 내부로 포커스를 이동하고 `Tab` 순환, `Escape`, 명시적인 닫기 버튼과 실행 요소로의 포커스 복귀를 요구한다. 따라서 메모 작업 영역이 `48rem` 이상 `72rem` 미만이면 같은 route의 modal 표현으로 한 영역씩 조작하고, `72rem` 이상에서 너비 `22rem`의 패널을 나란히 표시한다.

`48rem` 미만에서는 [WCAG 2.2 Reflow 설명](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)이 요구하는 한 방향 읽기와 모바일 일괄 복사 요구사항을 함께 반영해 독립 관리 페이지를 사용한다. [Android의 Floating Action Button 지침](https://developer.android.com/develop/ui/compose/components/fab)은 화면 우측 하단 고정 버튼을 하나의 주요 동작에, [Badge 지침](https://developer.android.com/develop/ui/compose/components/badges)은 바뀌는 항목 수를 버튼과 함께 표시하는 데 사용한다. 현재 결정은 해당 UI 라이브러리를 설치하지 않고 이 위치와 정보 역할만 자체 디자인 시스템에 적용한다. 작은 popover는 순서가 있는 항목 목록과 제거 이력을 읽고 편집하기에 공간이 부족하므로 사용하지 않는다.

## 화면별 탐색과 공통 구성 제안

사용 빈도, 텍스트 분석, 템플릿과 설정 화면은 현재 페이지의 제목과 주요 동작, 주 콘텐츠 및 전체 상태 알림 영역을 유지한다. 메모 화면은 현재 위치가 상단 탐색에서 이미 드러나므로 별도 `메모` 제목과 메모 개수 행을 두지 않고 캔버스를 바로 시작한다. 메모 화면에는 왼쪽 사이드바를 두지 않고 상단 탐색을 사용해 공간형 보드와 오른쪽 보조 패널에 가로 폭을 우선 배정한다. 오른쪽에는 일괄 복사 패널 또는 선택한 메모의 속성 패널 가운데 가장 최근에 활성화한 하나만 표시한다. 한 번의 헤더 클릭, `Tab` 탐색과 선택 해제는 보이는 패널을 바꾸지 않는다. 나머지 화면은 왼쪽 탐색을 유지한다.

현재 로컬 애플리케이션의 전역 탐색에는 메모, 사용 빈도, 텍스트 분석, 템플릿과 설정만 둔다. `48rem` 이상에서 일괄 복사 목록은 메모 화면의 우측 상단 고정 버튼으로 열고, `48rem` 미만에서는 우측 하단 항목 수 버튼으로 `/batch-copy`에 이동한다. 메모 상세 및 일괄 복사 관리 route는 전역 탐색 항목으로 추가하지 않는다. 계정 및 동기화 항목도 감추는 데 그치지 않고 계정 및 동기화 route를 만들지 않아야 한다.

### 사용자에게 필요한 문구만 남기는 기준

화면 문구는 인터페이스를 설명하는 해설이 아니라 사용자가 현재 상황을 이해하고 다음 동작을 고르는 데 필요한 정보여야 한다. 페이지 제목, 버튼과 입력 이름, 현재 자료와 상태가 이미 역할을 드러내면 같은 내용을 소개 문단이나 도움말로 다시 쓰지 않는다. 반대로 클립보드 쓰기처럼 성공 결과가 화면에 직접 나타나지 않는 동작, 입력 형식, 오류 원인과 다음 행동은 문구가 맡아야 한다.

[Fluent 2 Content design](https://fluent2.microsoft.design/content-design)은 선택과 다음 단계를 분명하게 만드는 데 필요한 만큼만 쓰고 남는 단어를 덜어내라고 권한다. 같은 시스템의 [접근성 지침](https://fluent2.microsoft.design/accessibility)은 모든 문장이 새로운 의미를 전달해야 한다고 설명한다. [Apple의 Writing 지침](https://developer.apple.com/design/human-interface-guidelines/writing)은 각 단어가 필요한지 확인하고, 동작 이름에는 명확한 동사를 쓰며, 설정 이름만으로 충분하지 않을 때에만 설명을 추가하라고 안내한다. [Apple의 Alert 지침](https://developer.apple.com/design/human-interface-guidelines/alerts)은 보조 문구가 실제 가치를 더할 때에만 넣고, 문제가 생기면 구체적이되 장황하지 않게 쓰도록 한다.

[WCAG 2.2의 Labels or Instructions 이해 문서](https://www.w3.org/WAI/WCAG22/Understanding/labels-or-instructions.html)는 입력에 필요한 단서를 제공하되 너무 많은 정보와 지시도 해로울 수 있다고 명시한다. [GOV.UK Text input 지침](https://design-system.service.gov.uk/components/text-input/)은 대다수 사용자에게 필요한 정보만 한 문장의 힌트로 제공하고, 사라지는 placeholder로 label과 설명을 대신하지 않도록 한다. [GOV.UK Error message 지침](https://design-system.service.gov.uk/components/error-message/)은 이미 화면에 있는 예시를 오류 문구에서 되풀이하지 않고 무엇이 일어났으며 어떻게 고칠지 구체적으로 알리도록 한다. 여러 화면에서 같은 동작 이름을 유지하는 기준은 [WCAG 2.2 Consistent Identification 이해 문서](https://www.w3.org/WAI/WCAG22/Understanding/consistent-identification.html)와도 일치한다.

현재 화면에는 다음 기준을 적용한다.

- 페이지 제목과 탐색 이름은 현재 내용과 이동할 곳을 식별한다. 제목 아래 소개 문장은 그 제목에 없는 필수 조건이나 현재 상태를 더할 때만 둔다.
- 버튼, 링크와 입력 label은 동작이나 기대 입력을 직접 나타낸다. `아래 버튼을 누르세요`처럼 위치와 이미 보이는 이름을 되풀이하지 않는다.
- 빈 상태는 현재 자료가 없다는 사실과 지금 실행할 수 있는 동작이 있을 때 그 동작을 알린다. 빈 화면의 역할이나 향후 기능을 소개하지 않는다.
- 성공 알림은 클립보드 쓰기처럼 결과를 바로 볼 수 없거나 보조 기술에 별도 상태 전달이 필요한 동작에 사용한다. 같은 결과가 화면에서 이미 분명하게 바뀌고 live region도 같은 내용을 읽는다면 중복 알림을 만들지 않는다. 메모 삭제처럼 바로 되돌릴 수 있어야 하는 결과는 메인 패널 중앙 하단의 토스트에 결과와 `취소` 동작을 함께 제공하고 포커스를 강제로 옮기지 않는다.
- 오류는 기술 이름이나 내부 상태 코드 대신 사용자가 확인할 사실과 다음 행동을 알린다. 접속 방식이 클립보드 사용을 막는 경우처럼 실행 환경이 해결 방법에 직접 필요할 때에만 사용자 관점의 조건을 설명한다.
- Next.js, Worker, IndexedDB, 정적 내보내기, 의존성, 빌드 성공과 같은 구현 정보는 화면에 표시하지 않는다. 검증 도구와 개발 문서가 이 근거를 보관한다.
- 장식용 표어, 환영 문구와 기능을 홍보하는 문장은 현재 과업에 필요한 정보가 아니면 넣지 않는다.

대표 화면 검토에서는 보이는 문자열마다 `내용 식별`, `동작 또는 입력 이름`, `조건`, `상태 또는 결과`, `오류 뒤 행동` 가운데 역할을 하나 이상 지정한다. 어느 역할에도 해당하지 않거나 같은 영역의 다른 요소와 같은 역할을 반복하면 삭제하거나 두 문구를 합친다. 이 분류는 글자 수를 기계적으로 제한하지 않으며, 접근 가능한 이름과 사용자가 과업을 끝내는 데 필요한 설명을 짧게 만들겠다는 이유로 없애지 않는다.

### 백로그: 포트폴리오 라우트 연결

[로컬 실행 구조와 계정 및 라이브러리 백로그 조사](runtime-modes-and-architecture.md)는 백로그를 시작할 때 검토할 연결 방식을 제안한다. 다음 항목은 현재 화면 구현의 선행 조건이나 완료 기준이 아니다. 포트폴리오 연결 작업을 시작하면 개인 메모 UI는 자신의 주 콘텐츠와 내부 과업 구조를 유지하되, 포트폴리오 전체 탐색과 같은 바깥쪽 영역을 중복해서 그리지 않는 구성이 필요하다.

- 독립 실행 애플리케이션은 개인 메모의 최상위 탐색, 페이지 제목과 전체 상태 알림을 직접 제공할 수 있다.
- 포트폴리오 웹 애플리케이션은 포트폴리오 탐색과 라우트 위치를 제공하고, 개인 메모 모듈은 내부 페이지 탐색과 주 콘텐츠를 제공하는 방안을 검토한다.
- 호스트가 개인 메모의 각 내부 페이지를 하위 라우트로 연결하면 모듈의 탐색은 호스트 라우트 접두어를 기준으로 이동해야 한다.
- 호스트가 단일 라우트만 제공하면 사용 빈도, 텍스트 분석, 템플릿과 설정 사이의 전환을 URL에 반영할지 별도로 정해야 한다. 일괄 복사 패널은 메모 화면 내부 상태로 유지한다.
- theme, error boundary, loading UI와 전체 상태 알림을 호스트와 모듈이 각각 중복해서 만들지 않도록 한쪽의 책임을 승인해야 한다.

위 항목은 백로그에서 제공 영역을 비교하기 위한 제안이며, 포트폴리오 라우트에 연결된 최종 화면 구조로 승인되지 않았다.

### 넓은 화면의 메모 보드

목적은 메모 작성, 개별 복사, 일괄 복사와 공간 배치다.

- 왼쪽 사이드바를 두지 않는다. 메모, 사용 빈도, 텍스트 분석, 템플릿과 설정으로 가는 탐색은 작업 영역 위의 상단 영역에서 제공한다.
- 상단 탐색 바로 아래에서 캔버스를 시작하고 별도 `메모` 제목, 메모 개수 또는 상단 작업 행을 두지 않는다. 캔버스는 보이는 화면에서 상단 탐색을 제외한 너비와 높이를 채운다.
- 새 메모와 모든 메모 맞춤처럼 현재 보드에 필요한 동작은 캔버스 위의 조밀한 제어로 제공하고 캔버스의 시작 위치를 밀어내는 별도 행을 만들지 않는다.
- 중앙은 메모를 자유롭게 놓는 보드다.
- 메모 표면에는 짧은 헤더와 항상 편집 가능한 본문만 표시한다. 헤더 오른쪽의 맨 앞으로, 맨 뒤로와 삭제 아이콘 외에는 편집, 이동, 복사, 일괄 복사와 크기 변경을 위한 상시 버튼이나 숫자 입력을 두지 않는다.
- 이동이 아닌 한 번의 헤더 click 또는 각 메모의 양의 `tabindex`가 낮은 순서를 따르는 `Tab` 탐색으로 메모를 선택하면 얇은 붉은 테두리만 새로 표시하고, 키보드 포커스는 색과 형태를 달리한 별도 표시로 구분한다. 탐색 순서는 시각적 겹침 순서와 독립적으로 유지한다. 이동이 아닌 헤더 더블클릭 또는 선택된 메모의 선택 지점에서 실행한 `Enter`로 오른쪽 속성 패널을 열어 `X`, `Y`, 너비와 높이를 바꿀 수 있게 하되 직접 edge resize도 유지한다. 빈 캔버스 click, `Escape`와 `Command`는 메모 선택만 해제한다. 너비 `240..1280`, 높이 `180..960`, X `1..(4096 - width)`, Y `1..(4096 - height)` 밖의 값은 적용하지 않는다.
- 메모 삭제 직후에는 캔버스가 아니라 메인 패널 중앙 하단을 기준으로 결과 토스트를 표시하고, 오른쪽의 `취소`로 같은 원문, 위치, 크기와 겹침 순서를 복원한다.
- 확대와 보드 이동 상태는 콘텐츠를 가리지 않는 보드 모서리에 둔다.
- `일괄 복사` 버튼은 캔버스 스크롤과 무관하게 화면 우측 상단에 유지하고 현재 항목 수를 함께 보여준다. 충분한 inline size에서는 첫 항목 추가 성공 때 오른쪽 패널을 열어 새 항목을 바로 보여주되 현재 포커스를 옮기지 않는다.

### 작은 화면의 메모 목록

메모 작업 container의 inline size가 `48rem` 미만이면 메모 보드 대신 생성 순서 목록을 제공한다. [WCAG 2.2 Reflow 이해 문서](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)는 정보나 기능 손실 없이 320 CSS 픽셀 너비에 해당하는 화면에서도 내용을 한 방향으로 읽을 수 있어야 한다고 설명하고, 작은 화면에서는 구획을 한 열로 재배치하는 방식을 예로 든다. 공간형 보드 자체는 이차원 배치가 필요한 영역일 수 있지만, 메모 읽기와 기본 조작까지 이차원 스크롤에 의존하게 만들 필요는 없다.

- 목록에서는 내용에 따라 짧아지고 `12rem`을 넘지 않는 메모 미리보기를 제공하며, 원문이 길면 일부만 보여준다. 카드 안에 별도 스크롤 영역을 만들지 않는다.
- 평소 메모를 짧게 누르면 해당 상세 화면으로 이동하고, 길게 누른 뒤 같은 카드 안에서 손을 떼면 원문 전체를 개별 복사한다.
- 길게 누르기가 스크롤, 메모 밖 이동이나 `pointercancel`로 끝나면 복사하거나 상세 화면으로 이동하지 않는다.
- 상세 화면에서는 원문 전체를 편집하고 명시적으로 저장한다. 목록 카드는 직접 편집 입력을 제공하지 않는다.
- 목록 화면 헤더 오른쪽의 아이콘 버튼으로 일괄 복사 상태를 시작한다. 이 상태에서는 짧게 누른 횟수와 순서대로 항목을 추가하고 상세 화면으로 이동하지 않는다.
- 상태의 헤더 왼쪽에는 뒤로가기 아이콘 버튼을 두고 화면 아래에는 `초기화`와 `다음`을 고정한다. `다음` 문구 옆에는 이번 상태에서 메모를 누른 횟수를 표시하고, 실행하면 `/batch-copy` 확인 페이지로 이동한다. 예기치 않은 이탈과 새로고침에서는 IndexedDB 작업 초안을 복원하고 수집 화면 뒤로가기와 확인 페이지의 명시적 취소에서는 지운다.
- 위치 및 크기 조절 핸들, 보드 이동, 확대와 화면 맞춤처럼 공간 배치에만 필요한 제어 UI는 목록에서 표시하지 않는다.
- 목록은 같은 메모를 생성 순서로 보여주며, 목록 전환은 저장된 위치와 크기를 바꾸지 않는다. 작업 영역이 넓어지면 기존 공간 배치를 복원한다.
- 목록의 각 항목에는 제한된 원문 미리보기를 제공하고, 개별 복사 성공과 실패 알림은 넓은 화면과 같은 원인 구분을 사용한다.
- 저장된 일괄 복사 항목이 하나 이상이면 우측 하단 고정 버튼에 항목 수를 표시하고, 이 버튼으로 저장 목록 관리 표현의 `/batch-copy`에 이동한다.

[CSS Containment Level 3](https://www.w3.org/TR/css-contain-3/)은 구성요소가 실제로 받은 크기에 따라 표현을 바꾸는 container query를 정의한다. 전체 뷰포트나 User-Agent가 아니라 실제 메모 영역을 기준으로 목록을 전환한다.

### 넓은 메모 화면의 일괄 복사 패널

목적은 원본 메모를 고르는 문맥을 유지하면서 현재 선택 항목을 확인하고, 순서를 바꾸거나 제거한 뒤 한 번에 복사하는 것이다.

- `48rem` 이상의 메모 화면에서 `일괄 복사` 버튼은 항목 수를 함께 보여주고 패널의 열림 상태를 전달한다. 모바일 관리 route는 전역 탐색 항목에 추가하지 않는다.
- 현재 화면에서 `63px`인 패널 머리 높이는 그 값의 약 60%인 `38px`로 줄인다. 머리에는 제목과 닫기 동작만 두고 실행 취소 및 다시 실행 버튼을 두지 않는다.
- 메모 작업 영역이 `72rem` 이상이면 상단 탐색 아래의 오른쪽 영역에 너비 `22rem`의 패널을 나란히 둔다. 패널은 보이는 화면 높이를 사용하고 캔버스는 남은 너비와 전체 높이를 채운다. 본문에는 일괄 복사 항목 목록만 두고 결합된 전체 텍스트 미리보기는 표시하지 않는다.
- 공간이 부족하면 같은 route의 modal 패널로 바꾼다. 열 때 제목 또는 첫 조작으로 포커스를 옮기고 `Escape` 및 닫기 버튼으로 닫은 뒤 실행 버튼으로 포커스를 되돌린다.
- 항목은 drag로 순서를 바꾸고 목록 밖에 놓으면 제거한다. 목록 밖에 있는 동안 제거 예정 상태를 표시하고 `Escape`와 `pointercancel`은 작업을 취소한다.
- 항목의 숫자 순서, 위로 이동과 아래로 이동 버튼은 표시하지 않는다. drag가 어려운 경우에는 우측 상단 동작 선택창의 `위치 변경`을 누르고 항목 사이의 삽입 위치를 선택한다.
- 항목 동작 버튼은 pointer hover와 항목 내부 `focus-within`에서 우측 상단에 표시하고, hover가 없거나 coarse pointer인 환경에서는 항상 표시한다. 동작 선택창은 넓은 패널에서 `위치 변경`과 `제거`를 제공한다.
- 실행 취소와 다시 실행은 저장된 이력과 키보드 단축키로 유지하되 패널에 버튼을 표시하지 않는다.
- 넓은 패널의 `복사` 버튼은 목록의 현재 순서로 원문을 합쳐 Clipboard에 쓴다. 결과 알림은 변환되는 캔버스와 패널 내부가 아니라 상단 탐색 아래 주 작업 영역의 우측 상단에 고정한다.
- 패널을 닫거나 나란한 표현과 modal 표현 사이를 바꿔도 항목과 제거 이력은 유지한다.

[Atlassian Pragmatic drag and drop 설계 지침](https://atlassian.design/components/pragmatic-drag-and-drop/design-guidelines/)은 drag 대상의 보조 동작을 hover와 `focus-within`에서 드러내는 예시를 제공하며, drag 조작과 텍스트 선택의 충돌도 구분한다. [Carbon Common actions](https://carbondesignsystem.com/patterns/common-actions/)는 제거를 삭제와 구분하고, 목록 행의 제거 동작을 주 동작보다 덜 강조하도록 설명한다. 두 자료는 우측 상단 제거 아이콘의 시각 우선순위를 정하는 근거지만, hover 전용 조작을 접근 가능한 최종 입력 방식으로 승인하지는 않는다.

### 모바일 일괄 복사 확인과 저장 목록 관리 페이지

목적은 `48rem` 미만의 화면에서 현재 확인 작업 또는 저장된 일괄 복사 순서를 한 방향 목록으로 편집하고 결합된 텍스트를 복사하는 것이다.

- 일괄 복사 상태의 `다음`으로 연 `/batch-copy`는 현재 작업 사본을 순서대로 보여준다. 일반 터치는 drag를 시작하지 않고 길게 누른 뒤에만 touch drag로 순서를 바꾼다. 각 항목 우측 상단의 아이콘 버튼은 `복제`와 `삭제`가 있는 작은 동작 선택창을 연다.
- 확인 작업의 재정렬, 복제와 삭제는 원본 메모, 메모 revision과 사용 횟수를 바꾸지 않는다.
- 우측 하단 저장 항목 수 제어로 연 `/batch-copy`는 저장 목록을 보여준다. 기존 왼쪽 재정렬 버튼, 위로 이동, 아래로 이동과 제거 대안을 유지한다.
- 하단에는 `취소`와 `일괄 복사하기` 버튼을 고정한다. `취소`는 복사하지 않고 메모 화면으로 돌아가며 목록과 이력을 유지한다. `일괄 복사하기`는 현재 순서의 텍스트를 줄바꿈으로 합쳐 Clipboard에 쓰고 성공 또는 다시 시도할 수 있는 실패 상태를 알린다.
- 저장 목록 관리 페이지, 나란한 패널과 modal 패널은 같은 일괄 복사 자료와 제거 이력을 사용한다. 확인 작업은 저장 반영 방식을 승인할 때까지 별도 실행 중 작업 사본을 사용한다.

### 사용 빈도

목적은 개별 복사, 일괄 복사와 합계를 혼동 없이 비교하는 것이다.

- 각 텍스트 항목에 원문 식별 정보, 개별 복사 횟수, 일괄 복사 횟수와 계산된 합계를 같은 순서로 보여준다.
- 메모 ID, content revision과 실행 당시 원문별로 항목을 구분한다. 같은 원문을 가진 서로 다른 메모는 합치지 않는다.
- 개별 복사, 일괄 복사와 두 값에서 계산한 합계를 함께 보여준다. 기간 그래프, 순위와 마지막 갱신 시각은 현재 범위에 추가하지 않는다.

### 텍스트 분석

목적은 줄 단위 비교를 명시적으로 실행하고 결과의 근거를 확인하는 것이다.

- 상단에는 분석 실행 버튼, 분석 대상과 마지막 완료 시점을 둔다.
- 실행 중에는 진행 상태를 제공한다.
- 결과는 정확한 반복, 포함 관계와 생김새가 일부 겹치는 후보로 나누고, 각 결과에서 두 원문 줄, 원본 메모로 이동할 동작과 `이 두 줄로 템플릿 제안` 버튼을 제공한다.
- 점수만 보여주지 않고 어떤 줄의 어느 관계인지 함께 보여준다.
- 현재 로컬 애플리케이션은 명시적 분석 버튼과 브라우저 분석기를 사용한다. 최우선 계정 및 동기화 백로그에서 서버 분석을 도입하더라도 이 화면과 조작을 유지하고 실행 위치만 교체할 수 있는지 다시 검증한다.

### 템플릿

목적은 분석 제안 검토, 직접 플레이스홀더 지정과 일회성 텍스트 생성이다.

- 템플릿 목록과 선택한 템플릿 편집 영역을 분리한다.
- 제안은 저장된 템플릿과 시각적으로 구분하고 사용자가 승인해야 템플릿 목록에 들어간다.
- 분석 결과에서 들어오면 선택한 두 원문 줄과 원본 메모 이동 동작을 먼저 보여준다. 선택 없이 직접 들어오거나 새로고침으로 선택이 사라지면 수동 작성과 분석 결과로 돌아가기 동작을 제공한다.
- 수동 작성은 원문에서 범위를 선택하고 `플레이스홀더로 지정` 버튼을 실행하게 한다. 편집 영역에서는 일반 텍스트와 플레이스홀더의 구분을 확인하고 플레이스홀더 이름, 순서와 일반 텍스트로 되돌리기를 제공한다.
- 일회성 생성 영역은 필요한 입력값, 완성된 미리보기와 복사 동작을 함께 보여준다.

### 설정

목적은 일괄 복사 조작이 브라우저나 운영체제 동작과 충돌할 때 사용 여부를 바꾸고 클립보드 문제를 진단하는 것이다.

- `Command+Option+클릭` 일괄 복사 추가를 켜거나 끄는 UI를 둔다.
- 설정은 해당 보조 키 조합의 사용 여부를 바꾸지만 각 메모에 일괄 복사 텍스트 버튼을 표시하지 않는다. 설정을 끈 넓은 화면에서 사용할 대체 입력은 결정 전까지 구현하지 않는다.
- 현재 브라우저에서 secure context인지와 마지막 클립보드 실패를 설명하되, 권한 상태 사전 조회만으로 복사 가능 여부를 단정하지 않는다.
- 설정을 바꾸기 전에 새 조작을 시험할 수 있는 예제 메모 영역을 검토한다.
- 현재 로컬 설정에는 계정 및 동기화 항목을 표시하지 않는다. 해당 항목은 최우선 계정 및 동기화 백로그에서 검토한다.

### 최우선 백로그: 계정 및 동기화

계정 및 동기화 페이지는 현재 로컬 애플리케이션에 포함하지 않는다. 모든 백로그 가운데 가장 먼저 진행할 계정 기능 개발에서 로그인 상태, 마지막 동기화, 충돌, 로그아웃과 계정 데이터 관리 동작을 다룬다. 인증 방식, 충돌 UI와 삭제 범위가 정해지지 않았으므로 세부 레이아웃은 아직 만들 수 없다.

## 클립보드 알림 제안

[WAI-ARIA의 `status` role](https://www.w3.org/TR/wai-aria-1.2/#status)은 중요도가 낮은 상태 메시지를 polite live region으로 알리는 역할을 정의한다. 복사 결과는 focus를 옮기지 않는 status 알림으로 전달할 수 있다. 일괄 복사 항목 추가 성공은 항목 수와 목록 변화로 이미 드러나므로 `누적했습니다`와 같은 별도 알림을 만들지 않는다.

[WAI-ARIA Authoring Practices의 Alert 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/alert/)은 alert가 포커스를 옮기지 않으면서 즉시 알려야 할 메시지에 쓰이며, 너무 빨리 사라지면 안 된다고 설명한다. 클립보드 실패 알림에는 실패 사실, 다시 시도와 설정 열기를 제공하고 사용자가 내용을 읽거나 닫을 때까지 유지하는 방안을 제안한다. 반복 실패를 매번 겹쳐 띄우지 않고 같은 알림을 갱신해야 한다.

브라우저는 권한과 사용자 활성화를 다르게 처리하므로 실제 클립보드 쓰기 실패를 알림의 기준으로 삼는다. 사용자가 설정에서 조작 방법을 바꾸더라도 복사는 사용자 동작 안에서 실행되어야 한다.

[Fluent 2 Toast 지침](https://fluent2.microsoft.design/components/web/react/core/toast/usage)은 toast를 예측 가능한 위치에 두고 주 콘텐츠를 가리지 않도록 하며 우측 상단이나 우측 하단을 일반적인 위치로 설명한다. [Carbon 알림 패턴](https://carbondesignsystem.com/patterns/notification-pattern/)도 과업과 관련된 영역에서 짧은 toast를 보여주는 방식을 설명한다. 이번 화면에서는 전역 상단 탐색, 우측 일괄 복사 패널과 변환되는 캔버스를 피한 주 작업 영역 우측 상단을 복사 결과 알림의 기준점으로 사용한다.

Fluent 2는 동작이 없는 toast를 7초 뒤 닫고 pointer hover 동안 시간을 멈추는 방식을 제공한다. 반면 [WCAG Timing Adjustable 설명](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html)은 시간 제한으로 정보가 사라져도 사용자가 같은 정보를 다른 곳에서 확인할 수 있어야 한다고 설명한다. 이 애플리케이션에는 Clipboard 쓰기 성공 여부를 다시 조회하는 화면이 없으므로 전체 복사 알림에 자동 만료를 두지 않는다. 사용자가 직접 닫거나 다음 복사 시도가 같은 알림을 바꿀 때까지 한 영역을 유지하고, 성공은 정중한 status로 전달하며 원인별 실패에는 다시 시도 또는 설정 확인 동작을 제공한다.

## 드래그 전용 요구와 접근성 충돌

[WCAG 2.2의 Dragging Movements 이해 문서](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)는 drag가 필요한 기능에 drag 없이 단일 pointer로 수행할 수 있는 대안을 제공하도록 설명한다. 넓은 일괄 복사 패널과 모바일 확인 페이지에는 항목 동작 선택창의 `위치 변경`과 항목 사이의 삽입 위치 버튼을 제공하고, 메모 크기는 오른쪽 속성 패널의 수치 입력으로 바꿀 수 있게 한다.

저장 목록 관리 페이지의 왼쪽 drag 버튼과 위로 이동, 아래로 이동 및 제거 버튼은 유지한다. 키보드 조작은 dragging criterion과 별개의 접근성 요구이므로, 메모 편집과 이동 입력, 일괄 복사 항목 제거, 크기 변경 및 단축키 충돌을 실제 브라우저와 화면 읽기 프로그램에서 확인한다.

### 포트폴리오 연결 백로그에서 결정할 사항

- 독립 실행 애플리케이션과 포트폴리오 호스트가 최상위 탐색, 내부 페이지 탐색, 제목, theme, error boundary와 상태 알림을 나누는 방식
- 포트폴리오 호스트가 개인 메모의 단일 라우트만 제공할지 내부 페이지별 하위 라우트도 제공할지와 모듈 탐색이 사용할 라우트 접두어
