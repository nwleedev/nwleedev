# 개인 메모 애플리케이션 요구사항

현재 개발 범위는 백엔드 없이 동작하는 로컬 개인 메모 애플리케이션을 완성하는 것이다. 계정 생성, 로그인, 동기화, 백엔드와 데이터베이스는 초기 범위에서 제외하되 모든 백로그 가운데 가장 먼저 진행할 항목으로 둔다. 애플리케이션은 독립적인 웹 애플리케이션으로 실행할 수 있어야 한다. 라이브러리 패키지 빌드와 포트폴리오 웹 애플리케이션 연결도 초기 범위에서 제외한 백로그다. 이 문서는 요구사항 책임자가 요청한 결과를 정리한 기준선이며, 구현 담당자와 검토자는 현재 범위에서 사용자가 완료할 수 있어야 하는 과업과 완료 증거를 확인한다. 조사에서 도출한 구현 제안은 이 문서가 아니라 `references/` 아래 문서에서 다룬다.

## 의도한 결과

- 사용자는 여러 메모를 만들고 각 메모에 텍스트를 입력할 수 있다.
- 사용자는 다른 애플리케이션에서 복사한 텍스트를 애플리케이션에서 만든 메모에 붙여넣을 수 있다.
- 사용자는 메모 작업 영역이 충분히 넓을 때 메모를 단순 목록이나 그리드에만 배치하지 않고, 공간형 화면에서 각 메모의 위치와 크기를 자유롭게 바꿀 수 있다.
- 사용자는 메모 작업 영역의 너비가 작은 환경에서 공간형 화면 대신 일반적인 목록 형태로 메모를 확인할 수 있다.
- 사용자는 메모에 URL이나 링크처럼 보이는 문자열을 입력하더라도 다른 텍스트와 같은 방식으로 작성, 편집하고 복사할 수 있다.
- 사용자는 읽기 상태인 메모의 텍스트 복사 영역을 일반 클릭하거나 메모의 복사 버튼을 눌러 메모 원문 전체를 복사할 수 있다.
- 사용자는 여러 메모에서 한 번에 복사하려는 텍스트를 `Command+클릭`해 하나의 텍스트에 누적하고, 별도 화면에서 누적된 텍스트를 확인할 수 있다.
- 사용자는 각 메모의 누적 버튼으로 같은 누적 동작을 수행하고, 별도 설정 화면에서 `Command+클릭` 가속 동작을 켜거나 끌 수 있다.
- 사용자는 누적된 텍스트의 순서를 드래그 앤 드롭으로 바꾸고, 특정 텍스트를 누적 텍스트 목록 밖에 놓아 제거할 수 있다.
- 사용자는 잘못 제거한 누적 텍스트를 실행 취소하고, 실행 취소한 제거를 다시 실행할 수 있다.
- 사용자는 텍스트의 일반 클릭 횟수, 누적을 위한 클릭 횟수와 두 횟수의 합계를 별도 화면에서 확인할 수 있다.
- 사용자는 메모 안의 텍스트를 줄바꿈으로 나눈 각 줄이 생김새를 기준으로 정확히 같거나 포함되는지, 문자열 조각이 얼마나 겹치는지를 별도 화면에서 확인할 수 있다.
- 사용자는 생김새가 겹치는 텍스트를 바탕으로 템플릿 텍스트를 제안받을 수 있다.
- 사용자는 텍스트에서 원하는 여러 부분을 플레이스홀더로 표시하고 템플릿으로 만들 수 있다.
- 사용자는 템플릿 텍스트에 필요한 값을 입력해 일회성 텍스트를 만들 수 있다.
- 사용자는 백엔드 없이 동작하는 로컬 모드에서 메모 작성, 편집, 배치, 복사, 누적, 템플릿 생성과 명시적으로 요청한 텍스트 겹침 분석을 사용할 수 있다.
- 사용자는 개인 메모 애플리케이션을 독립적으로 실행해 사용할 수 있다.
- 사용자는 모든 화면에서 개인 메모의 공간 작업 특성에 맞춘 일관된 시각 언어와 조작 상태를 확인할 수 있다.

## 반드시 지킬 조건

- 위 과업은 LLM을 사용하지 않고 완료할 수 있어야 한다.
- 로컬 모드는 애플리케이션 백엔드나 데이터베이스 서버에 연결하지 않아도 동작해야 한다.
- 로컬 모드는 HTTPS URL 또는 호스트 이름이 `localhost`인 HTTP URL로 접속해야 한다. `file://` URL과 `localhost`가 아닌 호스트의 HTTP URL은 지원하지 않아야 한다.
- 개인 메모 애플리케이션 프로젝트는 `apps/notes/`에 두고, 애플리케이션의 패키지 매니페스트는 `apps/notes/package.json`이어야 한다.
- 프론트엔드 소스 구조는 FSD의 계층별 의존 방향과 slice public API 규칙을 따라야 한다. Next.js 라우트 디렉터리와 FSD의 App 및 Pages 계층은 서로 구분할 수 있어야 한다.
- 애플리케이션은 Tailwind CSS를 스타일 작성 기반으로 사용하고, 의미가 정해진 디자인 토큰과 자체 `shared/ui` 구성요소로 고유 디자인 시스템을 만들어야 한다. 외부 UI 라이브러리의 기본 테마를 애플리케이션의 시각 기준으로 사용하지 않아야 한다.
- 일반 폼 제어는 네이티브 `button`, `input`, `textarea`와 `select`를 바탕으로 만들고, checkbox는 `input[type="checkbox"]`로 렌더링해야 한다. 모든 폼 제어에는 고유 디자인 시스템의 스타일을 적용하며 브라우저 기본 외형을 그대로 보여주지 않아야 한다.
- 폼 값을 다루지 않는 복합 상호작용에만 외부 접근성 부품을 선택적으로 사용할 수 있다. 실제 요구와 네이티브 Web API의 한계를 먼저 확인하고, 선택한 부품은 자체 `shared/ui` 구성요소 안에서만 사용해야 한다.
- 로컬 모드의 텍스트 겹침 분석은 사용자가 분석 실행을 명시적으로 요청했을 때만 시작해야 한다.
- 현재 로컬 애플리케이션에는 계정 생성, 로그인, 동기화, 백엔드 또는 데이터베이스 연결을 위한 UI와 기능을 포함하지 않아야 한다.
- 메모 작업 영역의 inline size가 `48rem` 미만이면 공간형 메모 화면 대신 생성 순서의 목록 형태를 제공하고, 메모 작성, 편집, 일반 클릭 복사와 누적 조작을 계속 사용할 수 있어야 한다.
- 목록 전환 여부를 기기 종류나 User-Agent로 판단하지 않아야 하며, 목록으로 전환하거나 공간형 화면으로 돌아와도 저장된 메모 위치와 크기를 바꾸지 않아야 한다.
- 읽기 상태인 메모의 텍스트 복사 영역을 일반 클릭하면 클릭한 메모의 원문 전체를 클립보드에 복사해야 한다. 사용자가 텍스트 범위를 선택하기 위해 드래그한 경우에는 전체 복사를 실행하지 않아야 한다.
- 각 메모에는 hover, `Command` 키나 마우스 사용 여부에 기대지 않고 접근할 수 있는 복사, 누적과 편집 버튼을 제공해야 한다.
- 편집 버튼은 `Enter`와 `Space`로 실행할 수 있어야 한다. 편집 중에는 본문 클릭을 커서 이동과 텍스트 선택에 사용하고, `Escape` 또는 완료 버튼으로 읽기 상태로 돌아와야 한다.
- 메모 이동은 본문과 분리된 이동 영역에서 시작하고, 사용자가 정한 메모 크기보다 내용이 길면 메모 안에서 내용을 스크롤할 수 있어야 한다.
- 선택한 메모의 위치와 크기는 drag뿐 아니라 키보드와 단일 pointer로 실행할 수 있는 별도 조절 UI에서도 바꿀 수 있어야 한다.
- 메모 본문의 URL이나 링크처럼 보이는 문자열은 일반 텍스트로 취급해야 하며, 초기 범위에서는 자동 링크 변환, 클릭 이동, 미리보기 또는 별도 링크 UI를 제공하지 않아야 한다.
- 클립보드 권한 거부나 쓰기 실패로 복사를 완료하지 못하면 사용자가 실패 원인과 다음 행동을 알 수 있는 알림 UI를 제공해야 한다.
- 메모의 텍스트 복사 영역을 `Command+클릭`하면 클릭한 메모의 텍스트를 누적해야 한다.
- `Command+클릭` 누적은 메모의 텍스트 복사 영역에만 적용하고, 다른 화면으로 이동하는 탐색 항목이나 그 밖의 버튼 동작을 바꾸지 않아야 한다.
- 각 메모의 누적 버튼은 설정과 관계없이 항상 사용할 수 있어야 한다.
- 별도 설정 화면에서 `Command+클릭` 누적을 켜거나 끌 수 있어야 하며, `Ctrl`, `Shift` 또는 `Alt+클릭`을 자동 대체 동작으로 지정하지 않아야 한다.
- 서로 다른 여러 메모에서 선택한 텍스트를 하나의 누적 텍스트에 추가할 수 있어야 한다.
- 누적할 때의 메모 원문을 스냅샷으로 보관하고, 같은 텍스트를 여러 번 누적할 수 있어야 한다.
- 누적 항목 사이의 기본 구분자는 줄바꿈이어야 한다.
- 누적 텍스트의 최초 순서는 사용자가 누적 조작을 수행한 순서와 같아야 한다.
- 사용자가 누적된 텍스트를 드래그 앤 드롭하면 놓은 위치에 따라 순서가 바뀌어야 한다.
- 사용자가 누적된 특정 텍스트를 누적 텍스트 목록 밖에 놓으면 드래그한 텍스트가 목록에서 제거되어야 한다.
- 누적 항목이 목록 밖으로 이동하면 제거 예정 상태를 보여줘야 하며, `Escape` 또는 pointer 취소가 발생하면 제거하지 않아야 한다.
- 누적 항목마다 드래그 없이 실행할 수 있는 위로 이동, 아래로 이동과 제거 버튼을 제공해야 한다.
- 사용자가 누적 텍스트 제거를 실행 취소하면 제거된 텍스트가 이전 위치에 돌아와야 한다.
- 사용자가 실행 취소한 제거를 다시 실행하면 복원됐던 텍스트가 다시 제거되어야 한다.
- 제거 실행 취소와 다시 실행 이력은 애플리케이션 안에서 페이지를 이동해도 유지하되, 새로고침하면 지워져야 한다. 실행 취소 뒤 누적 목록을 다시 바꾸면 다시 실행 이력을 지워야 한다.
- 메모 입력 화면과 별도로 누적 텍스트, 텍스트 사용 빈도와 텍스트 겹침을 확인할 수 있어야 한다.
- 사용 빈도 화면은 메모와 복사 당시 원문 상태별로 일반 복사 횟수, 누적 횟수와 두 횟수에서 계산한 합계를 구분해 보여줘야 한다.
- 일반 복사는 클립보드 쓰기가 성공했을 때만 횟수에 포함하고, 누적은 항목 추가와 횟수 저장이 모두 성공했을 때만 포함해야 한다. 제거, 순서 변경, 실행 취소와 다시 실행은 횟수를 바꾸지 않아야 한다.
- 겹침 분석의 입력 단위는 메모 전체가 아니라 메모의 원문을 줄바꿈으로 나눈 각 줄이어야 한다.
- 비교용 줄은 앞뒤 공백 제거, 내부 공백 정리, NFC 정규화와 대소문자 무시를 적용하되 원문을 바꾸지 않아야 한다. 정리한 결과가 빈 줄이면 분석에서 제외해야 한다.
- 생김새가 겹치는 텍스트는 정확한 반복, 포함 관계와 문자 3-gram Jaccard 점수를 사용하는 문자열 근접 후보로 구분할 수 있어야 한다.
- 문자열 근접 점수는 의미가 같다는 판정이나 고정된 합격 임계값으로 사용하지 않아야 한다. 0보다 큰 점수의 후보를 점수가 높은 순서로 보여주고, 3개 미만의 사용자 인식 문자로 된 줄은 정확한 반복과 포함 관계만 판정해야 한다.
- 텍스트가 바뀌지 않은 위치와 크기 변경은 사용 빈도를 새 항목으로 나누거나 기존 분석 결과를 오래된 것으로 만들지 않아야 한다.
- 템플릿 제안은 사용자가 선택한 두 원문 줄의 공통 구간을 일반 텍스트로, 다른 연속 구간을 플레이스홀더로 제시해야 한다. 제안은 사용자가 저장하기 전까지 저장된 템플릿으로 취급하지 않아야 한다.
- 공통 일반 텍스트가 없거나 공백과 문장부호만 공통인 두 줄, 또는 차이 구간이 없는 같은 두 줄에는 자동 템플릿을 만들지 않고 이유와 수동 템플릿 작성 동작을 보여줘야 한다.
- 사용자가 한 템플릿 안의 여러 부분을 플레이스홀더로 지정할 수 있어야 한다.
- 서비스는 흔한 AI SaaS UI처럼 보여서는 안된다. 현대적인 웹 애플리케이션의 디자인 트렌드를 반영해야 한다.

## 완료를 확인할 증거

- 사용자가 메모를 두 개 이상 만들고 각 메모에 서로 다른 텍스트를 입력할 수 있다.
- 사용자가 다른 애플리케이션에서 복사한 텍스트를 메모에 붙여넣고 붙여넣은 내용을 확인할 수 있다.
- `48rem` 이상의 메모 작업 영역에서 사용자가 메모 두 개의 위치와 크기를 각각 바꾼 뒤에도 두 메모의 내용과 배치가 유지된다.
- `48rem` 미만의 메모 작업 영역에서 메모가 공간형 화면 대신 생성 순서의 목록으로 표시되고, 사용자가 목록에서 메모를 작성, 편집, 일반 클릭 복사하고 누적할 수 있다. 작업 영역을 다시 넓히면 기존 공간 배치가 복원된다.
- 사용자가 메모의 텍스트 복사 영역을 일반 클릭했을 때 클릭한 메모의 텍스트가 클립보드에 복사된다.
- 사용자가 메모의 텍스트 일부를 드래그해 선택했을 때 메모 원문 전체가 클립보드에 복사되지 않고 선택 범위를 유지할 수 있다.
- 사용자가 복사, 누적과 편집 버튼을 키보드로 실행할 수 있고, 편집 중 `Escape`를 누르면 입력한 텍스트를 유지한 채 읽기 상태로 돌아온다.
- 메모에 URL 형식 문자열을 입력해도 별도 링크 UI가 생기거나 클릭 이동이 실행되지 않고, 일반 클릭하면 URL을 포함한 메모 원문 전체가 복사된다.
- 클립보드 쓰기가 거부되거나 실패했을 때 알림 UI가 실패 사실과 다시 시도하거나 설정을 확인할 방법을 보여준다.
- 사용자가 서로 다른 여러 메모의 텍스트 복사 영역을 `Command+클릭`했을 때 다른 화면으로 이동하지 않고, 별도 화면에서 클릭한 순서대로 누적된 전체 텍스트를 확인할 수 있다.
- 사용자가 설정 화면에서 `Command+클릭` 누적을 끈 뒤에도 각 메모의 누적 버튼으로 텍스트를 누적할 수 있다.
- 사용자가 누적된 텍스트의 순서를 드래그 앤 드롭으로 바꾸면 누적된 전체 텍스트에 바뀐 순서가 반영된다.
- 사용자가 누적된 특정 텍스트를 누적 텍스트 목록 밖에 놓으면 드래그한 텍스트가 목록과 누적된 전체 텍스트에서 제거된다.
- 사용자가 방금 제거한 누적 텍스트를 실행 취소하면 이전 위치에 복원되고, 다시 실행하면 같은 텍스트가 다시 제거된다.
- 사용자가 누적 텍스트 화면을 벗어났다가 돌아와도 제거 실행 취소를 사용할 수 있고, 새로고침한 뒤에는 이전 실행의 제거 이력을 사용할 수 없다.
- 같은 텍스트를 일반 클릭 두 번, 누적 조작 세 번 했을 때 사용 빈도 화면에 일반 클릭 횟수 2회, 누적을 위한 클릭 횟수 3회와 합계 5회가 표시된다.
- 하나의 메모에 서로 다른 줄을 두 개 이상 입력하고 다른 메모에 그중 한 줄과 겹치는 줄을 입력했을 때, 분석 결과가 메모 전체가 아니라 줄별 관계를 보여준다.
- 정확한 반복, 포함 관계와 문자 조각이 일부 겹치는 두 줄을 각각 준비했을 때 사용자가 별도 화면에서 세 관계와 문자열 근접 점수를 구분해 확인할 수 있다.
- 생김새가 겹치는 텍스트가 있을 때 사용자가 서로 겹친 텍스트를 바탕으로 한 템플릿 제안을 확인할 수 있다.
- 사용자가 텍스트의 여러 부분을 플레이스홀더로 표시하고 플레이스홀더가 표시된 텍스트를 템플릿으로 만들 수 있다.
- 사용자가 각 플레이스홀더에 값을 입력했을 때 입력한 값이 반영된 일회성 텍스트를 확인할 수 있다.
- 로컬 모드에서 계정이나 동기화 UI가 보이지 않고, 애플리케이션 백엔드 연결 없이 사용자가 분석 실행을 누른 뒤 줄별 겹침 결과를 확인할 수 있다.
- 독립 실행용 빌드 결과를 시작한 뒤 사용자가 메모 작성, 편집, 일반 클릭 복사와 누적 조작을 완료할 수 있다.
- 같은 로컬 정적 빌드 결과를 HTTPS URL과 호스트 이름이 `localhost`인 HTTP URL에서 각각 열었을 때 메모 작성, 편집, 일반 클릭 복사와 누적 조작을 완료할 수 있다.
- `apps/notes/package.json`에서 독립 실행 애플리케이션의 의존성과 실행 명령을 확인할 수 있고, `apps/notes/`의 빌드 명령으로 정적 결과물을 만들 수 있다.
- 구조 검사에서 FSD 계층의 역방향 import, 허용된 Entities `@x` public API 외의 같은 계층 import와 public API 우회가 발견되지 않고, Next.js 라우트 파일과 FSD의 App 및 Pages 계층을 경로로 구분할 수 있다.
- 여섯 화면에서 같은 역할의 버튼, 입력과 알림이 같은 디자인 토큰 및 `shared/ui` 구성요소를 사용하고, 포커스 표현도 같은 규칙을 따른다. 실제 한국어 콘텐츠를 넣은 대표 구성요소에 적용 가능한 기본, hover, `focus-visible`, pressed, disabled, 오류와 진행 상태가 담당자의 시각 및 접근성 검토를 통과한다.
- DOM 검사에서 일반 폼 제어가 네이티브 HTML 요소로 렌더링되고, 각 입력의 이름, 설명, 오류와 키보드 포커스를 보조 기술이 확인할 수 있다. 외부 접근성 부품을 추가했다면 폼 값을 다루지 않는 승인된 구성요소에서만 사용하며 외부 기본 테마가 화면에 보이지 않는다.

## 초기 범위에서 제외한 백로그

### 최우선: 계정 및 동기화

계정 생성, 로그인, 동기화, 백엔드와 데이터베이스는 모든 백로그 가운데 우선순위가 가장 높다. 현재 로컬 애플리케이션을 완성한 뒤 다른 백로그보다 먼저 진행한다.

이 백로그에는 다음 결과가 포함된다.

- 사용자는 계정을 만들고 로그인할 수 있다.
- 사용자는 계정에 연결된 메모, 누적 텍스트와 템플릿을 여러 브라우저에서 동기화할 수 있다.
- 백엔드와 데이터베이스가 인증, 접근 권한, 동기화 상태와 데이터 보관을 처리한다.
- 로컬과 계정 실행 형태에서 공통으로 제공하는 과업은 같은 화면 구조와 조작 방식을 사용한다.
- 계정 동기화처럼 로컬에서 제공하지 않는 과업과 조작 UI는 로컬 애플리케이션에 표시하지 않는다.

백로그 작업을 시작하기 전에 다음 사항을 정해야 한다.

- 계정 생성과 로그인 방식
- 로컬과 계정 실행 형태를 빌드 시점 설정으로 나눌지, 배포 시점 설정으로 나눌지와 기능 가용성을 어떤 단위로 표현할지
- 동기화 충돌 해결 규칙, 삭제 전파와 계정 데이터 삭제 범위
- 서버 API, 데이터베이스 구조와 여러 기기 사이의 일관성 기준
- 계정 기능을 추가한 뒤 로컬과 계정 실행 형태의 공통 화면이 같은 정보 구조와 조작을 유지하는지 확인할 방법

### 그 밖의 후속 항목

- LLM을 사용하지 않고 의미가 비슷한 텍스트를 자동으로 판별하는 동작은 초기 개발 범위에 포함하지 않고 후속 개발 항목으로 남긴다.
- 의미가 비슷하다고 판별한 텍스트를 바탕으로 한 템플릿 제안도 후속 개발 항목으로 남긴다.
- 메모 안 URL의 자동 링크 변환, 클릭 이동, 미리보기와 링크 정보 불러오기는 초기 개발 범위에 포함하지 않는다.
- 로컬 자료의 내보내기와 가져오기, 브라우저가 지운 자료의 복구는 초기 개발 범위에 포함하지 않는다.

### 라이브러리 및 포트폴리오 연결

개인 메모 애플리케이션을 라이브러리 패키지로 빌드하고 포트폴리오 웹 애플리케이션이 선택한 라우트에서 불러오는 작업은 백로그로 남긴다. 현재 구현 범위와 완료 증거에는 라이브러리 빌드 및 포트폴리오 라우트 연결을 포함하지 않는다.

백로그 작업을 시작하기 전에 다음 사항을 정해야 한다.

- 라이브러리 패키지를 같은 저장소의 workspace에서만 사용할지, 별도로 배포해 다른 저장소에서도 설치할 수 있게 할지
- 라이브러리가 지원할 호스트를 Next.js App Router로 제한할지, 다른 React 기반 호스트에서도 사용할 수 있게 할지
- 포트폴리오 웹 애플리케이션이 개인 메모의 단일 라우트만 연결할지, 누적 텍스트, 사용 빈도, 겹침 분석, 템플릿과 설정의 하위 라우트까지 연결할지
- 독립 실행 형태와 포트폴리오 라우트 연결 형태에서 바깥쪽 탐색, 페이지 제목, 테마와 알림 영역 가운데 무엇을 개인 메모 모듈이 그리고 무엇을 호스트가 그릴지
- 포트폴리오 라우트 연결 형태에서 로컬 모드만 제공할지, 계정 모드와 서버 쪽 연결도 함께 제공할지
- 라이브러리 빌드의 공개 진입점, 스타일과 Web Worker 파일 제공 방식 및 호스트 버전 호환 범위
