# 개인 메모 애플리케이션 요구사항

현재 개발 범위는 별도의 백엔드와 데이터베이스 없이 동작하는 로컬 개인 메모 애플리케이션을 완성하는 것이다. 계정 생성, 로그인, 동기화, 백엔드와 데이터베이스는 초기 범위에서 제외하되 모든 백로그 가운데 가장 먼저 진행할 항목으로 둔다. 애플리케이션은 독립적인 웹 애플리케이션으로 실행할 수 있어야 한다. 라이브러리 패키지 빌드와 포트폴리오 웹 애플리케이션 연결도 초기 범위에서 제외한 백로그다.

이 문서는 요청된 결과를 정리한 기준선이다. 현재 범위의 과업과 완료 증거는 이 문서를 기준으로 확인한다. 조사에서 도출한 구현 제안은 이 문서가 아니라 `references/` 아래 문서에서 다룬다.

## 의도한 결과

- 사용자는 여러 메모를 만들고 각 메모에 텍스트를 입력할 수 있다.
- 사용자는 다른 애플리케이션에서 복사한 텍스트를 애플리케이션에서 만든 메모에 붙여넣을 수 있다.
- 사용자는 메모 작업 영역이 충분히 넓을 때 메모를 단순 목록이나 그리드에만 배치하지 않고, 공간형 화면에서 각 메모의 위치와 크기를 자유롭게 바꿀 수 있다.
- 사용자는 메모를 만들고 배치하는 화면에서 왼쪽 사이드바 없이 메모 작업 영역을 사용할 수 있다.
- 사용자는 메모 작업 영역의 너비가 작은 환경에서 공간형 화면 대신 일반적인 목록 형태로 메모를 확인할 수 있다.
- 사용자는 넓은 메모 화면에서 별도 편집 단계로 전환하지 않고 항상 메모 본문을 작성하고 고칠 수 있으며, 작은 화면에서는 메모 상세 화면에서 원문을 수정해 저장할 수 있다.
- 사용자는 메모에 URL이나 링크처럼 보이는 문자열을 입력하더라도 다른 텍스트와 같은 방식으로 작성, 편집하고 복사할 수 있다.
- 사용자는 메모 본문을 `Command+클릭`해 메모 원문 전체를 복사할 수 있다.
- 사용자는 여러 메모에서 한 번에 복사하려는 텍스트를 `Command+Option+클릭`해 일괄 복사 목록에 추가하고, 넓은 메모 화면의 보조 패널에서 선택한 텍스트를 확인할 수 있다.
- 사용자는 별도 설정 화면에서 `Command+Option+클릭` 일괄 복사 동작을 켜거나 끌 수 있다.
- 사용자는 각 메모의 이동 핸들을 드래그해 메모를 이동하고, 바로 보이는 복사 동작과 더보기에서 메모를 맨 앞이나 맨 뒤에 표시하거나 속성을 열고 삭제할 수 있다.
- 사용자는 넓은 화면에서 메모 이동 핸들을 한 번 클릭하거나 `Tab`으로 메모만 선택하고, 더보기 또는 선택 지점에 포커스가 있는 선택된 메모에서 `Enter`를 눌러 속성 패널을 열 수 있다.
- 사용자는 넓은 화면에서 빈 캔버스를 클릭하거나 `Command`를 눌러 선택된 메모를 해제할 수 있다. 메모와 일괄 복사 항목 가운데 하나 이상이 선택된 상태에서는 `Escape` 한 번으로 두 선택을 함께 해제할 수 있다.
- 사용자는 작은 화면의 제한된 높이 메모 목록에서 메모를 짧게 눌러 원문을 복사하고, 별도의 수정 아이콘 버튼으로 상세 화면에 이동해 원문을 수정하고 저장할 수 있다.
- 사용자는 작은 화면의 메모를 길게 눌러 해당 메모의 원문 전체를 개별 복사할 수 있다.
- 사용자는 작은 화면의 메모 목록 헤더에서 일괄 복사 상태를 시작하고, 상태가 활성화된 동안 메모를 짧게 누른 순서대로 텍스트를 모은 뒤 화면 아래에서 현재 작업을 초기화하거나 일괄 복사 확인 페이지로 이동할 수 있다.
- 사용자는 좁은 화면의 일괄 복사 확인 페이지에서 작업 항목의 이동 핸들을 drag하거나 항목별 액션 시트에서 가능한 방향으로 한 자리 옮겨 순서를 바꾸고, 항목을 복제하거나 삭제한 뒤 하나로 합친 텍스트를 복사할 수 있다. 이 편집은 원본 메모를 바꾸지 않는다.
- 사용자는 작은 화면의 평상시 메모 목록에서 Drawer를 열고 저장된 일괄 복사 항목 수가 표시된 링크로 관리 페이지에 이동할 수 있다.
- 사용자는 저장 목록 관리 화면에서 일괄 복사 항목을 현재 개인 메모 디자인 시스템에 맞춘 조밀한 작업 화면으로 확인하고 편집할 수 있다. 관리 기능, 항목별 조작, 키보드 포커스와 상태 안내는 유지해야 한다.
- 사용자는 넓은 화면에서 각 메모에 지정된 `tabindex` 순서를 따라 `Tab` 또는 `Shift+Tab`으로 메모를 선택하고, 별도로 연 오른쪽 패널에서 대상 메모의 좌표와 크기를 위치 제한 없이 바꿀 수 있다. 너비와 높이는 기존 크기 범위를 따른다.
- 사용자는 메모를 제거한 직후 주 작업 영역의 안내에서 제거를 취소하고 같은 메모를 복원할 수 있다.
- 사용자는 일괄 복사 목록의 순서를 드래그 앤 드롭으로 바꾸고, 넓은 화면에서는 특정 텍스트를 일괄 복사 패널 바깥에 놓아 제거할 수 있다.
- 사용자는 넓은 화면의 일괄 복사 패널에서 항목을 다른 항목 위로 드래그해 놓을 위치를 확인하고, 패널 내부에서는 항목을 잃지 않은 채 순서를 바꾸며 패널 바깥에 놓은 항목만 제거할 수 있다.
- 사용자는 넓은 화면의 일괄 복사 항목을 클릭해 하나를 선택하고, 선택된 항목을 위쪽 또는 아래쪽 방향키로 한 자리씩 옮길 수 있다.
- 사용자는 일괄 복사 목록에서 잘못 제거한 텍스트를 실행 취소하고, 실행 취소한 제거를 다시 실행할 수 있다.
- 사용자는 메모가 아닌 빈 캔버스를 드래그해 현재 바라보는 작업 위치를 바꿀 수 있다.
- 사용자는 노트북 터치패드 핀치 또는 키보드와 마우스를 함께 사용하는 입력으로 넓은 메모 화면의 캔버스를 확대하거나 축소할 수 있다.
- 사용자는 macOS 화면 캡처처럼 운영체제 단축키로 애플리케이션을 잠시 벗어난 뒤에도 메모 이동 및 관리 제어와 캔버스 시점이 올바른 상태로 복원된 화면을 계속 사용할 수 있다.
- 사용자는 텍스트의 개별 복사 횟수, 일괄 복사 횟수와 두 횟수의 합계를 별도 화면에서 확인할 수 있다.
- 사용자는 메모 안의 텍스트를 줄바꿈으로 나눈 각 줄이 생김새를 기준으로 정확히 같거나 포함되는지, 문자열 조각이 얼마나 겹치는지를 별도 화면에서 확인할 수 있다.
- 사용자는 생김새가 겹치는 텍스트를 바탕으로 템플릿 텍스트를 제안받을 수 있다.
- 사용자는 텍스트에서 원하는 여러 부분을 플레이스홀더로 표시하고 템플릿으로 만들 수 있다.
- 사용자는 템플릿 텍스트에 필요한 값을 입력해 일회성 텍스트를 만들 수 있다.
- 사용자는 별도의 백엔드와 데이터베이스 없이 동작하는 로컬 모드에서 메모 작성, 편집, 배치, 개별 복사, 일괄 복사, 템플릿 생성과 명시적으로 요청한 줄 단위 텍스트 분석을 사용할 수 있다.
- 사용자는 개인 메모 애플리케이션을 독립적으로 실행해 사용할 수 있다.
- 사용자는 현재 주소에서 애플리케이션을 열 수 없을 때 그 사실과 다시 열 수 있는 주소 조건을 이해할 수 있다.
- 사용자는 모든 화면에서 개인 메모의 공간 작업 특성에 맞춘 일관된 시각 언어와 조작 상태를 확인할 수 있다.
- 사용자는 화면마다 현재 내용, 실행할 동작, 필요한 상태와 오류 해결에 필요한 문구만 확인할 수 있다.
- 사용자는 넓은 메모 화면에서 캔버스 높이를 줄이는 빈 행 없이 새 메모와 일괄 복사 동작을 계속 사용할 수 있고, 두 제어가 메모 작업을 가리지 않아야 한다.
- 일괄 복사 선택 상태는 현재 앱 실행 중에만 유지한다. 새로고침하거나 브라우저를 다시 열면 선택 상태를 초기화한다.
- 사용자는 모바일 일괄 복사 확인 화면에서 브라우저 뒤로가기를 실행하면 메모 선택 화면으로 돌아가 현재 작업을 이어갈 수 있다.
- 사용자는 메모 전체를 읽어 일괄 복사에 계속 접근하면서도 메모 수가 늘어날 때 목록 화면이 느려지지 않아야 한다.
- 사용자는 사용 빈도, 텍스트 분석, 템플릿과 설정에서 중복 구분선 없이 정보 묶음과 조작 순서를 알아볼 수 있어야 한다.

## 반드시 지킬 조건

- 메모는 고정된 작업 공간 끝 없이 자유롭게 배치할 수 있어야 한다. 이동, 속성 입력, 새로고침과 화면 크기 변경에서 같은 저장 좌표를 유지해야 한다.
- 모든 일괄 복사 화면은 pointer 위치에 따라 대상 항목의 앞이나 뒤를 삽입 위치로 정해야 한다. `[A, B, C, D]`에서 A를 D 뒤에 놓으면 `[B, C, D, A]`가 되고 A를 D 앞에 놓으면 `[B, C, A, D]`가 되어야 한다. 넓은 패널, 저장 목록 관리와 모바일 확인 작업에 같은 규칙을 적용한다.
- 재정렬은 이동한 항목의 ID, 선택과 키보드 포커스를 유지하고 원본 메모, 텍스트 스냅샷 및 항목 수를 바꾸지 않아야 한다. 자기 자신이나 유효한 삽입 위치가 아닌 곳에 놓으면 순서를 바꾸지 않아야 한다.
- 화면을 먼저 갱신하는 재정렬, 복제와 제거는 저장 실패에서 동작 전 자료, 선택과 포커스를 복원하고 다시 시도할 수 있어야 한다. 정확한 이전 상태를 복원할 수 없는 동작은 저장 완료 전에 성공한 것처럼 표시하지 않아야 한다.

- 위 과업은 LLM을 사용하지 않고 완료할 수 있어야 한다.
- 로컬 모드는 별도의 애플리케이션 백엔드나 데이터베이스 서버에 연결하지 않아도 현재 범위의 모든 과업을 완료할 수 있어야 한다. 로컬 모드라는 이름은 정적 HTML 산출물이나 특정 Next.js 배포 형식을 뜻하지 않는다. 현재 과업에 필요하다면 같은 애플리케이션의 Next.js Server Actions와 Route Handlers를 사용할 수 있다.
- 독립 실행 애플리케이션은 정적 사이트 산출물을 만들 필요가 없다. 현재 배포 형식은 `next build`로 만든 운영용 빌드를 `next start`로 실행하는 Next.js Node.js 서버이며, 이 실행 과정에 별도의 애플리케이션 백엔드나 데이터베이스 서버를 추가하지 않아야 한다.
- 로컬 모드는 HTTPS URL 또는 호스트 이름이 `localhost`인 HTTP URL로 접속해야 한다. `file://` URL과 `localhost`가 아닌 호스트의 HTTP URL은 지원하지 않아야 한다.
- 접속 주소 검사를 통과하지 못한 화면에는 `잘못된 접근입니다.`를 제목으로 표시하고, 본문에는 HTTPS 주소 또는 `http://localhost`로 다시 열 수 있다는 다음 행동을 알려야 한다. `지원하지 않는 접속 주소`, `유효`, `유효하지 않음`, 내부 판정값과 Web API 이름처럼 사용자가 해결 방법을 알아내는 데 필요하지 않은 표현을 사용하지 않아야 한다.
- 지원하는 HTTPS 및 `http://localhost` 주소에서는 접속 판정 진행 문구를 표시하지 않고 애플리케이션 화면을 열어야 한다. 첫 화면의 서버 HTML과 브라우저 렌더링을 일치시키는 데 필요한 처리는 유지해야 한다.
- 지원하지 않는 주소에 대한 접근 제한과 다시 열 주소 안내는 유지해야 한다.
- 지원하는 접속 주소에서 애플리케이션이 만든 서버 HTML과 첫 브라우저 렌더링이 달라지는 hydration 오류 없이 메모 화면이 열려야 한다.
- 개인 메모 애플리케이션 프로젝트는 `apps/notes/`에 두고, 애플리케이션의 패키지 매니페스트는 `apps/notes/package.json`이어야 한다.
- 프론트엔드 소스 구조는 FSD의 계층별 의존 방향과 slice public API 규칙을 따라야 한다. Next.js 라우트 디렉터리와 FSD의 App 및 Pages 계층은 서로 구분할 수 있어야 한다. 정적 import와 동적 import에서 판정할 수 있는 FSD 위반은 ESLint가 실패로 알려야 한다.
- IndexedDB, Clipboard, Worker, 시계, 식별자 생성기와 외부 SDK처럼 실행 환경에 따라 바뀔 수 있는 동작은 호출하는 기능이 필요한 최소 함수 또는 interface로 표현하고 `_app` 조립 지점에서 구현을 선택해야 한다. 모든 외부 동작을 한 객체, 전역 registry 또는 범용 Context에 모으지 않아야 하며, 순수 함수, React 지역 상태, React Hook Form 상태, DOM ref와 단순 UI event를 의존성 주입 대상으로 바꾸지 않아야 한다.

- 일반 폼 제어는 네이티브 `button`, `input`, `textarea`와 `select`를 바탕으로 만들고, checkbox는 `input[type="checkbox"]`로 렌더링해야 한다. 모든 폼 제어에는 고유 디자인 시스템의 스타일을 적용하며 브라우저 기본 외형을 그대로 보여주지 않아야 한다.

- 모바일 목록 표현의 메모 상세 화면에서는 전체 원문을 편집하고 명시적으로 저장할 수 있어야 한다. 목록 카드 자체는 편집 입력을 제공하지 않아야 한다.
- 모바일 목록 표현의 평상시 화면 헤더 오른쪽에는 일괄 복사 상태를 시작하는 아이콘 버튼을 제공해야 한다. 버튼은 화면에 텍스트를 표시하지 않더라도 기능을 설명하는 접근 가능한 이름을 제공해야 한다.
- 모바일 목록 표현의 평상시 메모 목록에서만 새 메모 아이콘 버튼을 메모 개수와 무관하게 화면 우측 하단에서 사용할 수 있어야 한다. 버튼은 목록과 별도의 하단 행이나 버튼 높이만큼 항상 비워 둔 영역 없이 메모 위에 겹칠 수 있지만, 마지막 메모의 원문과 수정 동작은 스크롤해서 사용할 수 있어야 한다. 일괄 복사 수집 상태의 하단 동작과 충돌하지 않아야 하며, 저장된 일괄 복사 항목 수를 표시하는 별도 고정 제어는 우측 하단에 두지 않아야 한다.
- 모바일 목록 표현의 새 메모 아이콘 버튼은 타 UI와 구분되는 브랜드 동작 색의 원형 배경을 사용해야 한다. 원형 배경을 위해 조작 영역을 줄이거나 접근 가능한 이름과 `focus-visible` 상태를 없애지 않아야 한다.
- 모바일 목록 표현에서 새 메모를 만들면 현재 목록에 생성된 메모가 추가되고 상세 화면으로 자동 이동하지 않아야 한다. 생성된 메모의 수정 아이콘 버튼을 실행해야 상세 화면으로 이동할 수 있어야 한다.
- 평상시 목록과 일괄 복사 수집 상태에 같은 하단 padding 또는 margin을 무조건 적용하지 않아야 한다. 평상시에는 떠 있는 새 메모 버튼을 위한 별도 높이를 예약하지 않고, 수집 상태에는 실제 하단 동작 영역과 목록 스크롤 영역을 분리해야 한다. 두 상태 모두 마지막 메모의 원문과 사용 가능한 동작에 접근할 수 있어야 한다.
- 일괄 복사 상태에서는 평상시 헤더 아이콘 대신 헤더 왼쪽에 뒤로가기 아이콘 버튼을 제공해야 한다. 이 버튼은 화면 아래의 취소 버튼을 대신하며, 실행하면 클립보드를 바꾸거나 다음 단계로 이동하지 않고 일괄 복사 상태를 끝내야 한다.
- 새로고침하거나 브라우저를 다시 열면 진행 중이던 모바일 일괄 복사 항목, 순서, 클릭 횟수와 수집 또는 확인 단계를 복원하지 않아야 한다. `/`에서는 평상시 메모 목록을 표시하고 이어가기 UI를 제공하지 않아야 한다.
- 같은 앱 실행에서 모바일 확인 화면의 브라우저 뒤로가기를 실행하면 확인 화면이 아니라 메모 선택 화면을 표시하고, 편집한 작업 항목과 순서를 유지해야 한다.
- 일괄 복사 상태에서는 메모를 짧게 누를 때 상세 화면으로 이동하지 않고 누른 순서대로 현재 작업 목록에 추가해야 한다. 같은 메모를 반복해서 누르면 누를 때마다 별도 항목으로 추가되고 현재 클릭 횟수도 한 번씩 증가해야 한다.
- 일괄 복사 상태에서 메모를 누른 뒤 저장이 진행되는 동안 목록 전체의 투명도, 비활성 상태나 배경이 바뀌어 화면 전체가 깜빡이지 않아야 한다. 앞선 추가가 끝나기 전에 다른 메모 또는 같은 메모를 다시 눌러도 각 입력이 순서대로 저장되고 클릭 횟수에 빠짐없이 반영되어야 한다.
- 모바일 일괄 복사 수집 상태의 각 메모에는 개별 복사 아이콘 버튼을 표시하지 않아야 한다. 메모를 짧게 눌러 현재 작업에 추가할 때 클립보드에 개별 복사하지 않아야 한다.
- 일괄 복사 상태의 화면 아래에는 `초기화`와 `다음` 버튼을 고정해야 한다. `초기화`는 상태를 끝내지 않은 채 이번 작업 목록과 클릭 횟수를 0으로 만들고, `다음` 텍스트 옆에는 현재 클릭 횟수를 표시해야 한다. 이 횟수는 보조 기술에도 전달해야 한다.
- 좁은 화면의 메모 상세 저장 영역과 일괄 복사 상태의 `초기화` 및 `다음` 영역은 브라우저가 현재 보여주는 애플리케이션 영역의 아래쪽에 남아야 한다. 메모 또는 목록을 스크롤해도 본문과 함께 이동하지 않아야 하며, 화면 아래쪽 safe area를 침범하지 않아야 한다.
- 일괄 복사 상태에서 `다음`을 실행하면 Clipboard에 쓰거나 원본 메모를 바꾸지 않고 별도의 일괄 복사 확인 페이지로 이동해야 한다. 확인 페이지에는 이번 작업의 원문 스냅샷이 사용자가 메모를 누른 순서대로 나타나야 한다.
- 일괄 복사 상태에서 `다음`을 실행한 뒤 확인 페이지가 나타날 때까지 수집 목록과 하단 `초기화` 및 `다음` 영역을 유지해야 한다. 이 사이에 평상시 메모 헤더, 새 메모 버튼 또는 하단 동작이 없는 중간 화면을 표시하지 않아야 하며, 저장이나 이동이 실패하면 같은 수집 화면에서 다시 시도할 수 있어야 한다.
- 일괄 복사 확인 페이지에서 항목 본문을 누르거나 스크롤하는 동작은 drag를 시작하지 않아야 한다. 항목 왼쪽의 이동 핸들에서 drag를 시작하고 놓은 앞뒤 위치에 따라 이번 작업의 결합 순서가 바뀌어야 한다. `pointercancel` 또는 완료 전 이탈은 순서를 바꾸지 않아야 한다.
- 일괄 복사 확인 페이지의 각 항목 우측 상단에는 접근 가능한 이름을 가진 아이콘 버튼을 제공해야 한다. 버튼을 실행하면 해당 항목을 `복제`하거나 `삭제`할 수 있어야 한다. 설정 화면에서 직접 이동 동작 표시를 켠 경우에는 현재 실행할 수 있는 `위로 이동`과 `아래로 이동`도 같은 동작 선택 화면에 나타나야 한다.
- 직접 이동 동작은 한 번 실행할 때 항목을 한 자리 옮기고 drag와 같은 삽입식 재정렬 명령을 사용해야 한다. 첫 항목에는 `위로 이동`, 마지막 항목에는 `아래로 이동`을 표시하지 않고 항목이 하나뿐이면 이동 동작을 표시하지 않아야 한다. `위치 변경`, `N번째로 이동`과 별도 취소 영역은 표시하지 않아야 한다.
- 일괄 복사 확인 항목의 이동 핸들에서 drag가 시작되면 잡힌 항목, 미리보기와 실제 앞뒤 삽입 위치를 색에만 의존하지 않는 시각 변화로 구분해야 한다. 취소되면 원래 위치와 시각 상태로 돌아가야 한다.
- 넓은 화면의 항목 동작 선택창은 실행한 아이콘 버튼 가까이에 backdrop 없이 배치하고 개인 메모 디자인 시스템의 표면, 동작 행, 포커스와 위험 동작 표현을 사용해야 한다. 브라우저가 제공하는 기본 Popover 외형에 시각 완성도를 맡기지 않아야 한다.
- 좁은 화면의 일괄 복사 확인 및 저장 목록 관리에서는 항목 더보기 버튼 옆에 팝오버를 열지 않고 화면 아래에서 열리는 액션 시트를 사용해야 한다. `복제`와 `삭제`에는 보이는 동작 이름을 남기고, 설정을 켠 경우의 `위로 이동`과 `아래로 이동`은 각각 다른 방향 아이콘 버튼으로 표시하되 보이는 텍스트는 두지 않아야 한다. 두 이동 버튼에는 실행 결과를 설명하는 접근 가능한 이름이 있어야 한다. 시트 상단의 닫기 버튼, 시트 바깥 누르기, 기기 뒤로가기 또는 `Escape`로 자료를 바꾸지 않고 닫을 수 있어야 하며, 동작을 실행한 뒤에는 자동으로 닫혀야 한다. touch 조작 영역, safe area와 화면 키보드를 고려해야 한다.
- 넓은 화면의 항목 동작 선택창은 HTML `popover="auto"`와 이름 있는 `role="group"` 안의 네이티브 버튼으로 구성해야 한다. 일반 `Tab` 및 `Shift+Tab` 순서를 유지하고, 열면 첫 동작으로 포커스를 옮기며 실행, `Escape` 또는 light dismiss로 닫으면 해당 항목의 실행 버튼으로 포커스를 돌려줘야 한다. 이 동작에는 `menu` 및 `menuitem` 역할이나 외부 접근성 부품을 사용하지 않아야 한다.
- 확인 항목의 재정렬, 복제와 삭제는 이번 일괄 복사 작업 사본만 바꿔야 한다. 원본 메모의 원문, 위치, 크기, 겹침 순서와 revision을 바꾸거나 사용 횟수를 늘리지 않아야 한다. 복제한 항목은 별도 항목 ID를 가져야 한다.
- 일괄 복사 상태와 현재 작업에 추가된 메모는 색에만 의존하지 않는 방식으로 구분하고 보조 기술에도 전달해야 한다.
- 모바일 목록 표현의 평상시 메모 목록에서 저장된 일괄 복사 항목이 하나 이상이면 Drawer 안에 현재 저장 항목 수를 표시하는 `일괄 복사` 관리 링크가 나타나야 한다. 항목 수는 보조 기술에도 전달해야 하며, 링크를 실행하면 일괄 복사 관리 페이지로 이동해야 한다. 저장된 항목이 없거나 현재 앱 실행에서 모바일 일괄 복사 작업이 진행 중이면 이 링크를 표시하지 않아야 한다.
- `/`는 모바일 메모 목록과 일괄 복사 수집 상태를 표시해야 한다. `/batch-copy`는 현재 앱 실행에 확인 중인 모바일 작업이 있으면 확인 화면을, 그런 작업이 없으면 현재 저장된 일괄 복사 목록의 관리 화면을 표시해야 한다. 저장 목록 관리는 과거 작업 내역 화면이 아니며 별도의 일괄 복사 내역 URL을 만들지 않아야 한다.
- 일괄 복사 확인 화면에서 `취소`를 실행하면 현재 실행의 작업을 버리고 `/`로 이동하되, 이동이 끝날 때까지 확인 화면을 유지해야 한다. 저장 목록 관리의 `일괄 복사` 헤더나 본문을 중간에 표시하지 않아야 한다.
- 메모 작업 영역의 inline size가 `48rem` 이상이면 메모 본문은 항상 편집 가능한 여러 줄 일반 텍스트 입력이어야 한다. 별도 읽기 상태, 편집 시작 버튼, 완료 버튼과 저장 버튼을 표시하지 않아야 하며 입력한 내용은 자동으로 저장해야 한다. `48rem` 미만의 목록 표현에서는 상세 화면에서만 편집과 명시적 저장을 제공해야 한다.
- 넓은 화면의 자동 저장 성공은 별도 알림을 표시하지 않아야 한다. 저장 실패는 현재 입력과 복구 초안을 유지하고, 편집기 가까이에 자동으로 사라지지 않는 오류와 다시 시도 동작을 제공해야 한다.
- 좁은 화면 상세의 저장 버튼은 저장 중 중복 실행을 막고 진행, 성공과 실패를 구분해야 한다. 성공은 버튼의 짧은 상태 변화로 알리고 별도 토스트를 만들지 않으며, 실패는 입력과 복구 초안을 유지한 채 편집기 또는 저장 제어 가까이에 다시 시도할 수 있는 상태로 남겨야 한다.
- `48rem` 이상의 공간형 화면에서 각 메모 왼쪽 위에는 접근 가능한 이름이 있는 이동 핸들, 오른쪽 위에는 복사와 더보기 아이콘 버튼을 표시해야 한다. 별도 제목, emoji, note icon과 `이동`, `복사`, `누적`, `편집`, `크기` 텍스트 버튼을 표시하지 않아야 한다.
- 공간형 화면의 메모 이동 핸들을 시작점부터 mouse 및 pen `5 CSS px`, touch `10 CSS px`보다 멀리 드래그하면 메모 위치가 바뀌어야 한다. 이동으로 판정되지 않은 한 번의 클릭은 클릭한 메모만 선택하고 selection 상태를 새로 표시해야 하며, 속성 패널을 새로 열거나 대상으로 바꾸지 않아야 한다. 이 입력은 메모 원문 개별 복사나 일괄 복사 목록 추가도 실행하지 않아야 한다.
- 공간형 화면의 메모 이동 핸들을 더블클릭하면 더블클릭한 메모를 선택하고 오른쪽 속성 패널을 그 메모의 X, Y, 너비와 높이를 편집할 대상으로 열어야 한다. 브라우저와 운영체제가 정하는 더블클릭 시간 및 거리를 애플리케이션의 별도 타이머로 다시 판정하지 않아야 한다.
- 이동 핸들 drag가 시작되면 같은 pointer 연속 입력에서 발생하는 클릭 결과를 실행하지 않아야 한다. 이동을 시작한 뒤 끝내거나 취소할 때까지 애플리케이션이 오른쪽 패널을 열거나 닫아서 사용자가 보고 있는 캔버스의 inline size와 block size를 바꾸지 않아야 한다.
- 공간형 화면의 메모 더보기는 속성, 맨 앞으로 보내기, 맨 뒤로 보내기와 삭제를 보이는 동작 이름으로 제공해야 한다. 복사 아이콘과 더보기는 고유한 접근 가능한 이름을 제공하고 `Enter`와 `Space`로 실행할 수 있어야 한다.
- 공간형 화면에서 메모를 맨 앞으로 보내면 다른 모든 메모보다 위에 표시되고, 맨 뒤로 보내면 다른 모든 메모보다 아래에 표시되어야 한다. 바뀐 겹침 순서는 새로고침 뒤에도 유지되어야 하며 메모 원문 전용 revision은 바뀌지 않아야 한다.
- 공간형 화면의 메모는 네 가장자리와 네 꼭짓점에서 크기를 바꿀 수 있어야 한다. 반대편 변을 유지하면서 음수 좌표와 원점을 지나 조절할 수 있어야 하며, 크기 제한을 위치 제한으로 사용하지 않아야 한다. 같은 너비와 높이를 속성 패널에서도 적용할 수 있어야 한다.
- 공간형 화면의 각 메모 선택 지점에는 메모 사이의 탐색 순서를 나타내는 `tabindex`를 지정해야 한다. `Tab`은 낮은 양의 `tabindex`부터 높은 값 순으로, `Shift+Tab`은 그 반대로 이동해야 한다. 이 순서는 메모의 시각적 겹침 순서와 독립적이어야 하며 맨 앞으로 또는 맨 뒤로 보내기를 실행해도 바뀌지 않아야 한다. 키보드 포커스가 도달하면 해당 메모를 선택하되 포커스만으로 속성 패널을 열지 않아야 한다. selection, 현재 키보드 포커스와 속성 패널 대상은 색 하나에 의존하지 않고 서로 구분할 수 있어야 한다.
- `Tab`으로 포커스가 도달해 선택된 메모의 선택 지점에서 보조 키 없는 `Enter`를 누르면 해당 메모를 대상으로 오른쪽 속성 패널을 열어야 한다. 같은 동작은 일괄 복사 패널이 보이던 경우 최근 활성 패널을 속성 패널로 바꿔야 한다. 메모 본문, 헤더 아이콘 버튼, 크기 조절 지점, 오른쪽 패널 입력이나 다른 하위 조작 요소의 `Enter`는 이 동작을 실행하지 않아야 한다. 메모 본문에서는 줄바꿈 입력을, 아이콘 버튼에서는 해당 버튼의 동작을 유지해야 하며 한글을 비롯한 입력기 조합 중의 `Enter`는 속성 패널을 열지 않아야 한다.
- 메모 더보기의 `속성` 또는 선택된 메모의 선택 지점에서 실행한 `Enter`로 연 오른쪽 속성 패널에서는 대상 메모의 작업 공간 좌표 X와 Y, 너비와 높이를 바꿀 수 있어야 한다. 메모 표면에는 이 수치 입력을 표시하지 않아야 한다.
- 선택된 메모가 있을 때 메모와 조작 요소가 아닌 빈 캔버스를 drag 시작 기준 안에서 클릭하면 메모 선택을 해제하고 selection 표시를 제거해야 한다. 메모, 패널 또는 다른 조작 요소에서 시작한 클릭이 캔버스로 전파됐다는 이유로 선택을 해제하지 않아야 한다.
- 선택된 메모가 있을 때 `Command`를 누르면 메모 선택을 즉시 해제하고 selection 표시를 제거해야 한다. 이 동작은 운영체제와 브라우저의 `Command` 조합 기본 동작을 막지 않아야 한다.
- 빈 캔버스 클릭, `Escape` 또는 `Command`로 메모 선택을 해제해도 속성 패널 대상, 속성 초안, 최근 활성 패널과 일괄 복사 항목을 함께 지우지 않아야 한다.
- 오른쪽 속성 패널의 X와 Y는 음수와 0을 포함해 고정 캔버스 크기와 무관하게 적용할 수 있어야 한다. 너비와 높이의 기존 제한은 위치와 분리해 유지한다. 유한하지 않거나 이동량을 구분할 수 없는 수치는 저장하지 않고 기존 메모를 유지해야 한다.
- 오른쪽 속성 패널에서 바꾼 값은 해당 입력의 `blur`, 패널 밖 클릭 또는 `Enter`가 발생할 때 적용해야 한다. 잘못된 입력은 저장된 메모 좌표, 크기와 revision을 바꾸지 않고 사용자가 같은 입력에서 수정할 수 있게 알려야 한다.
- 넓은 화면의 오른쪽 영역에는 메모 속성 패널과 일괄 복사 패널 가운데 최근에 활성화한 패널 하나만 표시해야 한다. 메모 더보기의 `속성` 또는 선택된 메모의 선택 지점에서 실행한 `Enter`는 속성 패널을, 일괄 복사 동작은 일괄 복사 패널을 활성화해야 한다. 이동 핸들의 한 번 클릭이나 `Tab` 선택은 선택 표시만 바꾸고 최근 활성 패널의 종류, 표시 여부 및 대상을 바꾸지 않아야 하며, 패널 전환이나 선택 해제만으로 속성 패널 대상, 속성 초안 또는 일괄 복사 항목을 지우지 않아야 한다.
- 넓은 메모 화면의 본문을 일반 클릭하거나 drag하면 커서 이동과 텍스트 선택만 수행해야 한다. 일반 클릭으로 메모 전체 복사, 일괄 복사 목록 추가 또는 별도 편집 상태 전환을 실행하지 않아야 한다.
- 마우스, 펜 또는 터치로 메모 본문을 눌렀을 때 브라우저 기본 스타일이나 애플리케이션 스타일에서 생기는 파란 외곽선을 표시하지 않아야 한다. 키보드로 메모 본문이나 다른 조작 요소에 도달했을 때에는 selection과 구분되는 포커스 표시를 유지해야 한다.
- 사용자가 정한 메모 크기보다 내용이 길면 메모 안에서 내용을 스크롤할 수 있어야 한다.
- 메모 본문의 URL이나 링크처럼 보이는 문자열은 일반 텍스트로 취급해야 하며, 초기 범위에서는 자동 링크 변환, 클릭 이동, 미리보기 또는 별도 링크 UI를 제공하지 않아야 한다.
- 클립보드 권한 거부나 쓰기 실패로 복사를 완료하지 못하면 사용자가 실패 원인과 다음 행동을 알 수 있는 알림 UI를 제공해야 한다.
- 메모 본문을 `Command+클릭`하면 클릭한 메모의 원문 전체를 클립보드에 복사해야 한다. 복사가 성공했을 때만 개별 복사 횟수를 기록해야 한다.
- 메모 본문을 `Command+Option+클릭`하면 개별 복사를 함께 실행하지 않고 클릭한 메모의 원문을 일괄 복사 목록에 추가해야 한다. 두 modifier가 모두 눌린 조합은 `Command+클릭`보다 먼저 판정해야 한다.
- 포커스가 있는 메모 선택 지점에서 `Command+Option+Enter`를 누르면 그 메모 원문을 일괄 복사 목록에 추가해야 한다. `Command`를 눌러 선택이 해제된 뒤에도 현재 포커스 대상의 ID로 같은 key sequence를 완료해야 한다. 이 입력은 pointer의 `Command+Option+클릭` 설정을 꺼도 유지하고 개별 복사나 속성 패널 열기를 함께 실행하지 않아야 한다.
- 사용자가 공간형 화면에서 `Command`를 누르고 있는 동안 모든 메모의 헤더와 헤더 아이콘은 보이지 않고 pointer로 조작할 수 없어야 한다. 헤더가 차지하던 높이는 유지해 본문과 메모의 외곽 크기가 움직이지 않아야 한다. `Command`를 놓거나 창이 포커스를 잃거나 되찾을 때, 문서가 숨겨지거나 다시 보일 때에는 헤더가 다시 나타나야 한다. 다음 신뢰할 수 있는 키 또는 pointer 입력에서 `Command`가 눌리지 않은 것으로 확인돼도 비노출 상태를 복원해야 한다.
- 운영체제가 `Shift+Command+5` 같은 단축키를 처리해 애플리케이션이 대응하는 `Command` keyup을 받지 못해도 별도 `Command` 입력 없이 헤더가 다시 나타나야 한다. 개별 복사와 일괄 복사 추가는 오래 유지한 전역 modifier 상태가 아니라 실행한 pointer 또는 click event에서 확인한 `metaKey`와 `altKey`를 기준으로 판정해야 한다.
- 운영체제 단축키 전후에 `keydown`, `keyup`, 창 `blur`, 문서 `visibilitychange` 또는 pointer 종료 event가 모두 전달된다고 가정하지 않아야 한다. 헤더 표시와 진행 중 pointer 조작은 전달받은 신뢰할 수 있는 event마다 현재 상태를 다시 맞추고, 스크립트가 만든 event로 실제 보조 키 상태를 덮어쓰지 않아야 한다. `Command`는 물리 키 위치가 아니라 의미가 `Meta`인 키로 처리해야 한다.
- `Command+클릭` 개별 복사와 `Command+Option+클릭` 일괄 복사 추가는 넓은 화면의 메모 본문에만 적용해야 한다. `Command` keydown에서 메모 선택을 해제한 뒤 이 입력이 메모를 다시 선택하거나 속성 패널 대상을 바꾸지 않아야 한다. `Command+클릭`은 최근 활성 패널을 바꾸지 않고, `Command+Option+클릭`은 일괄 복사 패널을 최근 활성 패널로 바꿔야 한다. 헤더, 헤더 아이콘 버튼, 탐색 항목과 다른 조작 요소의 클릭 결과도 바꾸지 않아야 한다.
- 별도 설정 화면에서 `Command+Option+클릭` 일괄 복사 추가를 켜거나 끌 수 있어야 하며, `Ctrl`, `Shift` 또는 `Option+클릭`만을 자동 대체 동작으로 지정하지 않아야 한다.
- 별도 설정 화면에서 일괄 복사 항목의 `위로 이동`과 `아래로 이동` 표시를 켜거나 끌 수 있어야 한다. 이 설정은 처음에는 꺼져 있어야 하고 새로고침 뒤에도 선택값을 유지해야 한다. 설정과 관계없이 drag와 키보드 방향키 재정렬은 유지해야 한다.
- 서로 다른 여러 메모에서 선택한 텍스트를 하나의 일괄 복사 목록에 추가할 수 있어야 한다.
- 일괄 복사 목록에 추가할 때의 메모 원문을 스냅샷으로 보관하고, 같은 텍스트를 여러 번 추가할 수 있어야 한다.
- 일괄 복사 항목 사이의 기본 구분자는 줄바꿈이어야 한다.
- 일괄 복사 목록의 최초 순서는 사용자가 항목을 추가한 순서와 같아야 한다.
- 사용자가 일괄 복사 항목을 드래그 앤 드롭하면 놓은 위치에 따라 순서가 바뀌어야 한다.
- 넓은 메모 화면에서 사용자가 특정 항목을 일괄 복사 패널 전체의 바깥에 놓으면 드래그한 항목이 목록에서 제거되어야 한다. 항목을 목록의 여백, 머리, 바닥 또는 패널 안의 다른 영역에 놓았다는 이유로 제거하지 않아야 한다.
- 일괄 복사 항목이 패널 전체의 바깥으로 이동하면 제거 예정 상태를 보여줘야 하며, `Escape`, `pointercancel` 또는 `lostpointercapture`가 발생하면 제거하지 않아야 한다.
- 넓은 메모 화면의 일괄 복사 패널에서는 항목 왼쪽의 이동 핸들 drag를 주 재정렬 조작으로 사용해야 한다. 각 항목에 순서 번호와 상시 위아래 이동 버튼을 표시하지 않아야 하며, 설정을 켰을 때만 더보기에서 현재 실행할 수 있는 직접 이동 동작을 제공해야 한다. 키보드 재정렬 조작도 같은 삽입식 명령을 유지해야 한다.
- 넓은 메모 화면의 각 일괄 복사 항목 오른쪽에는 더보기 아이콘 버튼을 제공해야 한다. 더보기는 `복제`와 `삭제`를 항상 제공하고, 설정을 켠 경우에는 현재 실행할 수 있는 `위로 이동`과 `아래로 이동`을 추가해야 한다. 삭제는 위험 동작 표현으로 구분해야 한다.
- 넓은 메모 화면에서 항목을 드래그하는 동안 실제로 놓을 수 있는 앞뒤 위치에만 삽입선을 표시해야 한다. 이 표시는 평상시에 보이지 않고 메모 선택이나 항목의 영구 선택 상태를 만들지 않아야 한다.
- 넓은 패널과 좁은 화면 확인 목록에서 드래그한 항목이 현재 스크롤 영역의 위쪽 또는 아래쪽 가장자리에 가까워지면 해당 목록만 자동으로 스크롤해야 한다. pointer가 유효한 목록을 벗어나거나 scroll 취소, `pointercancel` 또는 완료 전 `lostpointercapture`가 발생하면 원래 순서를 유지해야 한다.
- drag와 직접 이동이 끝나면 같은 항목의 실행 지점에 키보드 포커스를 유지하고, 항목 이름과 이전 및 새 위치를 정중한 상태 메시지로 한 번 전달해야 한다.
- 넓은 메모 화면의 일괄 복사 항목 본문은 클릭, `Enter` 또는 `Space`로 한 항목을 선택하거나 같은 항목의 선택을 해제할 수 있어야 한다. 한 번에 일괄 복사 항목 하나만 선택하고, 선택된 항목에는 메모와 같은 의미의 selection 상태를 표시해야 한다. 삭제를 실행하거나 삽입 위치가 됐다는 이유만으로 항목 선택을 바꾸지 않아야 한다.
- 메모 선택과 일괄 복사 항목 선택은 서로 독립적이며 둘 다 유지될 수 있다. drag, 항목 동작 선택창이나 다른 상위 임시 조작이 활성화되지 않은 상태에서 보조 키 없는 `Escape`를 누르면 두 선택을 한 번에 해제하고 두 선택 테두리를 제거해야 한다. 이때 속성 패널 대상, 최근 활성 패널, 일괄 복사 항목과 순서는 바꾸지 않아야 한다. 모달 일괄 복사 패널에서는 선택이 하나라도 있으면 첫 `Escape`가 선택만 해제하고, 선택이 없는 다음 `Escape`가 모달을 닫아야 한다.
- 선택된 일괄 복사 항목의 본문 제어에 키보드 포커스가 있을 때 `ArrowUp` 또는 `ArrowDown`을 누르면 항목을 해당 방향으로 한 자리 옮겨야 한다. 첫 항목의 `ArrowUp`과 마지막 항목의 `ArrowDown`은 자료를 바꾸지 않아야 한다. 이동 뒤에도 같은 항목 ID의 선택과 포커스를 유지하고 새 위치와 전체 항목 수를 보조 기술에 전달해야 한다. 텍스트 입력, 삭제 버튼, 동작 선택창과 다른 하위 조작 요소에서는 이 방향키 동작으로 목록 순서를 바꾸거나 페이지 스크롤을 막지 않아야 한다.
- 사용자가 일괄 복사 항목 제거를 실행 취소하면 제거된 텍스트가 이전 위치에 돌아와야 한다.
- 사용자가 실행 취소한 제거를 다시 실행하면 복원됐던 텍스트가 다시 제거되어야 한다.
- 제거 실행 취소와 다시 실행 이력은 애플리케이션 안에서 페이지를 이동해도 유지하되, 새로고침하면 지워져야 한다. 실행 취소 뒤 일괄 복사 목록을 다시 바꾸면 다시 실행 이력을 지워야 한다.
- 메모 작업 영역의 inline size가 `48rem` 이상이면 일괄 복사 목록을 메모 화면에서 열고 닫을 수 있는 보조 패널로 확인해야 한다. `72rem` 이상이면 너비 `22rem`의 패널과 메모 영역을 나란히 사용하고, `48rem` 이상 `72rem` 미만이면 같은 메모 화면 위의 모달 패널로 전환해야 한다.
- 넓은 메모 화면의 일괄 복사 패널에는 실행 취소와 다시 실행 버튼을 표시하지 않아야 한다. 제거 이력과 키보드 단축키 동작은 유지해야 한다.
- 넓은 메모 화면의 일괄 복사 패널에서 `일괄 복사` 제목과 닫기 동작이 있는 머리 영역은 변경 전 계산 높이인 `63 CSS px`의 60%인 약 `38 CSS px` 높이로 줄여야 한다.
- 넓은 메모 화면의 일괄 복사 패널에는 항목을 하나로 합친 별도 미리보기 영역을 표시하지 않아야 한다. 전체 복사 동작은 현재 항목 순서와 줄바꿈 구분자로 합친 문자열을 계속 복사해야 한다.
- 일괄 복사 항목 추가에 성공했을 때 `누적했습니다`와 같은 별도 성공 알림을 표시하거나 읽어주지 않아야 한다. 항목, 일괄 복사 상태와 항목 수가 바뀐 결과로 성공을 확인할 수 있어야 한다.
- 전체 복사와 개별 복사의 성공은 캔버스 변환과 패널에 포함되지 않는 공유 알림 영역의 `복사됨`으로 전달해야 한다. 이 알림은 현재 포커스를 가져가지 않고 짧게 표시돼야 한다. 모든 토스트의 오른쪽에는 해당 토스트만 닫는 접근 가능한 이름의 아이콘 버튼을 제공해야 한다.
- 공유 알림 영역에는 현재 결과 한 건만 표시해야 한다. 다음 결과는 같은 영역의 내용을 바꾸고 표시 시간을 다시 세며 여러 알림을 쌓지 않아야 한다. 알림 영역은 페이지 구성요소가 아니라 현재 화면의 위쪽 중앙을 기준으로 배치하고, 화면 너비, 글자 확대와 safe area가 달라도 한쪽으로 치우치거나 화면 밖으로 잘리지 않아야 한다.
- 활성 토스트가 있는 동안 애플리케이션 내부 페이지를 이동해도 같은 알림과 원래 남은 표시 시간을 유지해야 한다. 원래 만료 시각이 지나거나 닫은 알림은 이전 페이지로 돌아왔을 때 다시 나타나지 않아야 한다.
- Clipboard API 부재, 권한 거절과 그 밖의 쓰기 실패는 원인과 다시 시도하거나 설정을 확인할 동작을 제공해야 한다. 사용자가 조작하는 오류 알림은 hover와 `focus-within`에서 자동 종료 시간을 멈춰야 하며, 다시 찾아볼 지속 표면이 없는 중요한 실패는 자동 종료 토스트에만 두지 않아야 한다.
- 메모가 아닌 빈 캔버스에서 시작해 mouse 및 pen `5 CSS px`, touch `10 CSS px`를 넘은 주 pointer 드래그는 캔버스 시점을 이동해야 한다. 메모 본문, 메모 가장자리 및 꼭짓점, 일괄 복사 패널이나 다른 조작 요소에서 시작한 pointer 동작은 캔버스 이동으로 해석하지 않아야 한다.
- 공간형 메모 화면의 시점 이동, 확대와 축소 및 전체 맞춤 제어는 캔버스의 좌측 하단에 고정해야 한다. 각 제어는 화면에 텍스트를 표시하지 않고 기능을 설명하는 아이콘과 접근 가능한 이름을 제공해야 하며, 현재 배율은 숫자 상태로 확인할 수 있어야 한다.
- 캔버스 확대와 축소는 저장된 메모의 좌표와 크기, 본문을 변경하지 않아야 한다. 노트북 터치패드와 키보드 및 마우스로 확대하거나 축소해도 메모 작성, 본문 스크롤, 메모 이동과 보기 제어를 계속 사용할 수 있어야 한다.
- 캔버스 시점 이동이 시작된 뒤 `pointerup`, `pointercancel`, `lostpointercapture`, 창 포커스 변화 또는 문서 가시성 변화로 연속 입력이 끝나도 마지막으로 화면에 표시한 유효 시점을 유지해야 한다. 이동 기준을 넘기기 전의 클릭 후보만 시작 시점으로 취소할 수 있어야 한다.
- 한 pointer 조작에서 `pointerup` 뒤 정상적인 `lostpointercapture`가 이어지거나 종료 신호가 중복돼도 시점 또는 geometry를 한 번만 확정해야 한다. `pointercancel`과 완료 전 capture 상실은 취소로 처리하되 이미 성공한 `pointerup` 결과를 되돌리지 않아야 하며, 활성 pointer가 아닐 때 capture 해제를 시도해 오류를 만들지 않아야 한다.
- 헤더의 삭제 아이콘을 실행하면 확인 대화상자를 먼저 표시하지 않고 대상 메모만 활성 메모 목록에서 제거해야 한다. 다른 메모의 원문, 위치, 크기와 상대 겹침 순서는 바꾸지 않아야 한다.
- 메모를 제거한 직후 앱 공통 화면 위쪽 중앙에 `메모를 제거했습니다.`를 표시해야 한다. 같은 알림의 오른쪽에는 `취소` 버튼을 제공해야 한다.
- 제거 알림은 나타날 때 현재 키보드 포커스를 강제로 옮기지 않아야 한다. `취소`를 실행하면 제거한 메모의 원문, 위치, 크기와 삭제 전 `zIndex`를 복원해야 한다. 그 사이 다른 메모의 순서가 바뀌었다면 같은 `zIndex`를 허용하며 삭제 전의 모든 상대 겹침 순서를 되돌리는 것은 아니다.
- 메모 제거 알림은 공유 알림 영역에서 5초 뒤 사라져야 한다. `실행 취소`에 pointer hover 또는 키보드 포커스가 있으면 남은 시간을 멈추고, pointer와 포커스가 모두 떠나면 남은 시간부터 다시 세야 한다. 실행 취소는 알림이 표시되는 동안만 실행할 수 있어야 한다.
- validation, 화면 자료 불러오기 실패, 자동 저장 실패, 저장하지 않은 변경과 사용자가 반드시 처리해야 하는 오류는 토스트에만 표시하지 않아야 한다. 화면 자료 불러오기 및 저장 실패는 해당 작업 가까이의 지속 상태, 저장하지 않은 변경으로 이동하는 선택은 modal dialog를 사용해야 한다.
- 메모 작업 영역의 inline size가 `48rem` 미만이면 일괄 복사 상태의 `다음`과 평상시 메모 목록 Drawer의 저장 항목 수 링크에서 별도 `/batch-copy` 페이지로 이동할 수 있어야 한다. 이 페이지는 다섯 주요 화면의 전역 탐색 항목으로 추가하지 않아야 한다.
- 일괄 복사 확인과 저장 목록 관리의 주소는 `/batch-copy`여야 한다. 애플리케이션이 만드는 링크와 이동 동작은 이 주소만 사용해야 하며, `/accumulator` route나 이 주소를 처리하는 redirect를 제공하지 않아야 한다.
- 저장된 일괄 복사 목록을 보관하는 IndexedDB object store 이름은 `batchCopyLists`여야 한다. 데이터베이스 초기화 또는 schema 변경이 끝난 뒤에는 `accumulators` object store가 없어야 한다.
- 모바일 일괄 복사 확인 페이지는 현재 작업의 원문 스냅샷을 현재 결합 순서의 세로 목록으로 제공해야 한다. 각 항목은 왼쪽 이동 핸들을 touch drag해 순서를 바꿀 수 있고, 우측 상단 아이콘 버튼이 여는 액션 시트에서 가능한 방향으로 한 자리 옮기거나 해당 항목을 복제 또는 삭제할 수 있어야 한다.
- 모바일 일괄 복사 확인 및 저장 목록 관리 페이지의 하단에는 `취소`와 `일괄 복사하기` 버튼을 두어야 한다. 확인 페이지의 `취소`는 텍스트를 복사하지 않고 현재 실행의 작업을 버린 뒤 메모 화면으로 돌아가며, 브라우저 뒤로가기는 같은 실행에서 편집한 순서를 유지한 채 수집 상태로 돌아가야 한다. 저장 목록 관리 페이지의 `취소`는 저장된 항목과 순서를 유지한 채 메모 화면으로 돌아가야 한다. `일괄 복사하기`는 현재 순서의 텍스트를 줄바꿈으로 합쳐 클립보드에 쓴 뒤 항목, 순서와 사용 횟수를 바꾸지 않아야 한다.
- 일괄 복사 패널과 모바일 일괄 복사 확인 및 관리 페이지의 표현은 기기 종류나 User-Agent가 아니라 실제 작업 영역의 inline size로 정해야 한다.
- 텍스트 사용 빈도와 줄 단위 텍스트 분석 결과는 메모 입력 화면과 별도의 화면에서 확인할 수 있어야 한다.
- 사용 빈도 화면은 메모와 조작 당시 원문 상태별로 개별 복사 횟수, 일괄 복사 항목 추가 횟수와 두 횟수에서 계산한 합계를 구분해 보여줘야 한다.
- 개별 복사는 `Command+클릭` 또는 모바일 목록의 길게 누르기로 클립보드 쓰기가 성공했을 때만 횟수에 포함하고, 일괄 복사는 항목 추가와 횟수 저장이 모두 성공했을 때만 포함해야 한다. 제거, 순서 변경, 실행 취소와 다시 실행은 횟수를 바꾸지 않아야 한다.
- 텍스트 분석의 입력 단위는 메모 전체가 아니라 메모의 원문을 줄바꿈으로 나눈 각 줄이어야 한다.
- 비교용 줄은 앞뒤 공백 제거, 내부 공백 정리, NFC 정규화와 대소문자 무시를 적용하되 원문을 바꾸지 않아야 한다. 정리한 결과가 빈 줄이면 분석에서 제외해야 한다.
- 생김새가 겹치는 텍스트는 정확한 반복, 포함 관계와 문자 3-gram Jaccard 점수를 사용하는 문자열 근접 후보로 구분할 수 있어야 한다.
- 문자열 근접 점수는 의미가 같다는 판정이나 고정된 합격 임계값으로 사용하지 않아야 한다. 0보다 큰 점수의 후보를 점수가 높은 순서로 보여주고, 3개 미만의 사용자 인식 문자로 된 줄은 정확한 반복과 포함 관계만 판정해야 한다.
- 텍스트가 바뀌지 않은 위치와 크기 변경은 사용 빈도를 새 항목으로 나누거나 기존 분석 결과를 오래된 것으로 만들지 않아야 한다.
- 템플릿 제안은 사용자가 선택한 두 원문 줄의 공통 구간을 일반 텍스트로, 다른 연속 구간을 플레이스홀더로 제시해야 한다. 제안은 사용자가 저장하기 전까지 저장된 템플릿으로 취급하지 않아야 한다.
- 공통 일반 텍스트가 없거나 공백과 문장부호만 공통인 두 줄, 또는 차이 구간이 없는 같은 두 줄에는 자동 템플릿을 만들지 않고 이유와 수동 템플릿 작성 동작을 보여줘야 한다.
- 사용자가 한 템플릿 안의 여러 부분을 플레이스홀더로 지정할 수 있어야 한다.
- 서비스는 흔한 AI SaaS UI처럼 보여서는 안된다. 현대적인 웹 애플리케이션의 디자인 트렌드를 반영해야 한다.

## 완료를 확인할 증거

- 사용자가 메모를 두 개 이상 만들고 각 메모에 서로 다른 텍스트를 입력할 수 있다.
- 사용자가 다른 애플리케이션에서 복사한 텍스트를 메모에 붙여넣고 붙여넣은 내용을 확인할 수 있다.
- `48rem` 이상의 메모 작업 영역에서 사용자가 메모 두 개의 위치와 크기를 각각 바꾼 뒤에도 두 메모의 내용과 배치가 유지된다.
- 메모 화면을 넓은 화면과 320 CSS px 너비에서 각각 열었을 때 왼쪽 사이드바가 없고, 메모 작업 영역을 가리지 않으면서 다른 화면으로 이동할 수 있다.
- 넓은 메모 화면을 열었을 때 application bar 바로 아래에서 낮은 대비의 중립색 캔버스가 시작해 보이는 화면의 나머지 너비와 높이를 채우며, 별도의 `메모` 제목, 메모 개수 또는 상단 작업 행이 보이지 않는다.
- `48rem` 이상의 메모 캔버스를 스크롤하거나 이동해도 `일괄 복사` 제어가 화면 우측 상단에 남고 캔버스의 시작 위치나 높이를 바꾸지 않는다.
- `48rem` 미만의 메모 작업 영역에서 메모가 공간형 화면 대신 생성 순서의 제한된 높이 목록으로 표시된다. 메모를 누르면 원문이 복사되고 수정 아이콘을 실행하면 상세 화면으로 이동해 전체 원문을 편집하고 저장할 수 있으며, 작업 영역을 다시 넓히면 기존 공간 배치가 복원된다.
- 넓은 화면에서 메모가 표시되는 동안 본문은 별도 전환 없이 계속 편집할 수 있고, 완료 또는 저장 버튼이 없어도 입력한 원문이 새로고침 뒤 유지된다.
- 넓은 화면에서 사용자가 메모 본문을 일반 클릭하거나 drag하면 커서 또는 선택 범위가 바뀌고, 메모 원문 전체가 클립보드에 복사되지 않는다.
- 넓은 화면의 각 메모에는 이동 핸들, 복사, 더보기와 본문만 보인다. 더보기는 속성, 맨 앞으로, 맨 뒤로 및 삭제를 제공하며, 좌표와 크기 입력은 오른쪽 속성 패널에만 보인다.
- 사용자가 포인터로 이동 핸들을 한 번 클릭하면 메모가 선택되고 selection 표시만 새로 나타난다. 포인터 입력에서는 같은 핸들을 이동 없이 더블클릭해야 그 메모의 오른쪽 속성 패널이 나타나며, 어느 입력도 메모 원문을 복사하지 않는다.
- 사용자가 메모 이동 핸들에서 mouse 및 pen `5 CSS px`, touch `10 CSS px`를 넘게 이동해 drag를 시작하면 pointer가 핸들 밖으로 이동해도 메모 위치 변경을 이어가고, 놓거나 취소할 때까지 속성 패널 표시 여부와 캔버스의 계산된 inline size 및 block size가 애플리케이션 동작 때문에 바뀌지 않는다. drag 뒤 발생할 수 있는 클릭도 선택이나 패널 활성화를 실행하지 않는다.
- 서로 다른 양의 `tabindex`를 가진 메모에서 사용자가 `Tab`을 반복하면 낮은 값부터 높은 값 순으로 선택되고, `Shift+Tab`은 반대 순서로 이동한다. 맨 앞으로 또는 맨 뒤로 보내기를 실행해 겹침 순서가 바뀐 뒤에도 메모의 `tabindex`와 다음 탐색 순서는 유지된다. 선택 테두리와 현재 `focus-visible` 표시를 동시에 구분할 수 있고, `Tab`으로 포커스가 도달한 것만으로 속성 패널이 열리거나 캔버스 크기가 바뀌지 않는다.
- `Tab`으로 메모 선택 지점에 포커스가 도달한 뒤 보조 키 없는 `Enter`를 한 번 누르면 해당 메모가 속성 패널 대상이 되고 오른쪽 속성 패널이 나타난다. 같은 `Enter`를 메모 본문에서 누르면 줄바꿈이 입력되고, 헤더 아이콘에서 누르면 해당 아이콘 동작만 실행되며, 입력기 조합 중에는 속성 패널이 열리지 않는다.
- 메모를 선택한 뒤 빈 캔버스를 이동 없이 클릭하거나 `Command`를 누르면 메모의 selection 표시가 사라진다. 메모와 일괄 복사 항목이 함께 선택된 상태에서 상위 임시 조작이 없을 때 보조 키 없는 `Escape`를 누르면 두 selection 표시가 함께 사라진다. 속성 패널 대상, 속성 초안, 최근 활성 패널, 일괄 복사 항목과 순서는 선택 해제만으로 사라지거나 바뀌지 않으며, `Command` 조합의 운영체제 및 브라우저 기본 동작도 계속 실행된다.
- 사용자가 겹친 메모 가운데 하나의 맨 앞으로 아이콘을 실행하면 그 메모가 다른 모든 메모 위에 나타나고, 맨 뒤로 아이콘을 실행하면 다른 모든 메모 아래에 나타난다. 새로고침 뒤에도 같은 겹침 순서가 유지된다.
- 사용자가 삭제 아이콘을 실행하면 대상 메모만 화면과 저장 자료의 활성 메모 목록에서 사라지고 앱 공통 화면 위쪽 중앙에 `메모를 제거했습니다.`와 `취소`가 나타난다. `취소`를 실행하면 같은 원문, 위치, 크기와 삭제 전 `zIndex`의 메모가 복원된다. 삭제 이후 순서를 바꿔 중복이 생기는 사례에서도 복원한 숫자와 다른 메모의 저장값을 유지하며 새로고침 뒤에도 같은 값을 확인한다.
- 메모의 네 가장자리와 네 꼭짓점을 각각 드래그하면 반대편 변이 고정된 채 크기가 바뀐다. 위쪽과 왼쪽으로 조절할 때 0이나 기존 캔버스 끝에서 멈추지 않으며 너비와 높이의 허용값 안에서 동작한다. 메모 표면에는 숫자 입력을 추가하지 않는다.
- 넓은 화면과 모바일 상세의 메모 본문, 템플릿 원문과 이름, 플레이스홀더 이름 및 치환값, 오른쪽 속성 패널의 X, Y, 너비 및 높이와 설정 checkbox를 편집해도 각 현재 값의 기준은 React Hook Form 한 곳이다. 저장 중 입력, 대상 전환, 변경사항 버리기, 저장 실패와 외부 revision 반영 뒤에도 각 화면에서 정한 값과 dirty 상태가 유지되며, 기존 IndexedDB 자료와 사용자 동작은 사라지지 않는다.
- 사용자가 오른쪽 속성 패널의 X, Y, 너비 또는 높이를 바꾸고 각 입력의 `blur`, 패널 밖 클릭과 `Enter`를 각각 실행하면 허용 범위의 값은 같은 메모에 한 번 적용된다. 유한하지 않거나 숫자 정밀도 범위를 벗어난 X와 Y, 그리고 너비와 높이의 상한을 넘는 값은 저장 geometry 및 revision을 바꾸지 않고 수정할 입력을 알려준다.
- 메모에 URL 형식 문자열을 입력해도 별도 링크 UI가 생기거나 클릭 이동이 실행되지 않고, `Command+클릭`하면 URL을 포함한 메모 원문 전체가 복사된다.
- 클립보드 쓰기가 거부되거나 실패했을 때 알림 UI가 실패 사실과 다시 시도하거나 설정을 확인할 방법을 보여준다.
- 사용자가 `Command`를 누르면 메모 선택 표시가 사라지고 메모 본문과 메모 외곽 크기는 움직이지 않은 채 이동, 복사와 더보기 제어가 보이지 않는다. 그 상태에서 서로 다른 메모 본문을 `Command+클릭`하면 각 원문이 개별적으로 복사되고, `Command+Option+클릭`하면 다른 화면으로 이동하거나 개별 복사를 함께 실행하지 않은 채 일괄 복사 패널에 조작 순서대로 추가된다. 이 두 동작은 메모를 다시 선택하거나 속성 패널 대상을 바꾸지 않으며 `Command`를 놓으면 제어만 다시 나타난다. macOS에서 `Shift+Command+5`로 Screenshot 도구를 열었다가 캡처하거나 닫으면 별도 `Command` 입력 없이 제어가 다시 나타나고 다음 보조 키 복사가 정상 작동한다.
- 넓은 메모 화면에서 첫 텍스트를 일괄 복사 목록에 추가하면 우측 패널이 나타나고 방금 선택한 원문이 보이며, 메모의 현재 포커스는 유지되고 캔버스는 패널을 제외한 나머지 영역을 채운다.
- 텍스트를 일괄 복사 목록에 추가해도 `누적했습니다`와 같은 별도 성공 알림이 나타나거나 보조 기술에 중복해서 전달되지 않고, 항목, 일괄 복사 상태와 항목 수 변화로 결과를 확인할 수 있다.
- 320 CSS px 너비에서 메모를 짧게 누르면 원문 전체가 한 번 복사되고, 수정 아이콘을 실행하면 복사 없이 상세 화면으로 이동해 원문을 편집하고 저장할 수 있다. 같은 메모를 길게 눌렀다가 카드 안에서 손을 떼도 원문 전체가 한 번만 복사되며 뒤따르는 click으로 중복 복사하거나 상세 화면으로 이동하지 않는다.
- 320 CSS px 너비에서 메모 목록과 보조 화면의 Drawer를 열면 주요 화면으로 이동할 수 있다. 메모 상세와 `/batch-copy`에서는 Drawer가 보이지 않고, 각 화면의 뒤로가기, 저장 전 이탈 확인과 작업 초안 처리 결과는 유지된다.
- 320 CSS px 너비의 평상시 메모 목록에서 메모가 없거나 여러 개여도 새 메모 제어는 화면 우측 하단에 남고 별도 하단 행을 만들지 않는다. 메모가 화면보다 많으면 각 카드의 미리보기 높이가 줄지 않은 채 목록이 스크롤되고, 마지막 메모의 원문과 수정 동작에 접근할 수 있다. 저장된 일괄 복사 항목 수는 Drawer 안에서만 보이며, 일괄 복사 수집 상태에서는 새 메모 제어가 하단의 `초기화` 및 `다음`을 가리지 않는다.
- 320 CSS px 너비의 평상시 메모 목록에서 새 메모 아이콘은 브랜드 동작 색의 원형 배경으로 다른 아이콘과 구분된다. 각 메모의 수정 아이콘에는 그림자가 없고 메모와 같은 깊이로 보이며, 두 아이콘 모두 접근 가능한 이름, 24 CSS px 이상의 조작 영역과 `focus-visible` 표시를 유지한다.
- 320 CSS px 너비의 평상시 목록에서 새 메모를 만들면 주소와 목록 화면이 유지되고 새 메모가 목록에 나타난다. 생성된 메모의 수정 아이콘을 실행할 때만 그 메모의 상세 화면으로 이동한다. 일괄 복사 수집 중에는 실제 하단 동작 영역 위에서 목록의 마지막 메모까지 스크롤할 수 있고, 평상시 목록에는 그 영역의 높이만큼 비운 공간이 남지 않는다.
- 320 CSS px 너비에서 메모 원문이 `12rem`을 넘어도 목록 행은 그 높이를 넘지 않고 별도 `내용 더 있음` badge 없이 제한된 줄에서 잘리며, 상세 화면에서 원문 전체를 확인할 수 있다.
- 320 CSS px 너비에서 평상시 화면 헤더 오른쪽의 일괄 복사 아이콘을 실행하면 헤더 왼쪽에 뒤로가기 아이콘이 나타나고 일괄 복사 상태가 시작된다. 각 메모의 개별 복사 아이콘은 보이지 않는다. 첫 메모를 두 번, 둘째 메모를 한 번 짧게 누르면 상세 화면으로 이동하거나 클립보드에 쓰지 않고 세 원문 스냅샷이 같은 순서와 중복을 유지해 현재 작업에 추가되며, 화면 아래에는 `초기화`와 클릭 횟수 3이 붙은 `다음`이 나타난다.
- 첫 항목의 저장이 끝나기 전에 같은 메모와 다른 메모를 연속해서 눌러도 목록 전체의 투명도, 배경과 비활성 상태가 바뀌지 않는다. 모든 입력은 누른 순서와 중복을 유지하고 `다음`의 클릭 횟수에 빠짐없이 반영된다.
- 320 CSS px의 일괄 복사 상태에서 `초기화`를 실행하면 상태를 유지한 채 현재 작업과 클릭 횟수가 0이 된다. 헤더의 뒤로가기를 실행하면 클립보드를 바꾸거나 다음 단계로 이동하지 않고 평상시 메모 목록으로 돌아간다.
- 320 CSS px 너비의 메모 상세와 일괄 복사 상태에서 내용이 짧거나 화면보다 길어도 저장 영역 또는 `초기화` 및 `다음` 영역은 현재 보이는 애플리케이션 영역의 아래쪽에 남는다. 내용을 스크롤하고 모바일 브라우저 도구 모음으로 보이는 높이가 달라져도 해당 동작을 화면 안에서 실행할 수 있다.

- 다섯 주요 route, 모바일 메모 상세 route, 모바일 일괄 복사 확인 route와 메모 화면의 일괄 복사 패널에서 같은 역할의 버튼, 입력과 알림이 같은 디자인 토큰 및 `shared/ui` 구성요소를 사용하고, 포커스 표현도 같은 규칙을 따른다. 실제 한국어 콘텐츠를 넣은 대표 구성요소의 기본, hover, `focus-visible`, pressed, disabled, 오류와 진행 상태가 시각 및 접근성 검토를 통과한다.
- 다섯 주요 route, 모바일 메모 상세 route와 모바일 일괄 복사 확인 route의 제목, 본문, 버튼, 입력과 상태 문구의 계산된 `font-family`에서 Pretendard가 기본 글꼴이며 serif display 글꼴이 사용되지 않는다. 글꼴을 불러오지 못한 경우에도 sans-serif 대체 글꼴을 사용한다.
- 넓은 메모 화면에서 중립적인 application bar, 낮은 대비의 따뜻한 중립색 캔버스와 흰색에 가까운 메모가 서로 구분된다. 목재 무늬, 노란 sticky note와 짙은 탐색 영역이 보이지 않고 메모 본문이 배경 및 제어보다 먼저 보인다.
- DOM 검사에서 일반 폼 제어가 네이티브 HTML 요소로 렌더링되고, 각 입력의 이름, 설명, 오류와 키보드 포커스를 보조 기술이 확인할 수 있다. 외부 접근성 부품을 추가했다면 폼 값을 다루지 않는 승인된 구성요소에서만 사용하며 외부 기본 테마가 화면에 보이지 않는다.
- 다섯 주요 route, 모바일 메모 상세 route, 모바일 일괄 복사 확인 route와 메모 화면의 일괄 복사 패널에서 사용자에게 보이는 문구를 역할별로 확인했을 때 제목이나 컨트롤을 되풀이하는 안내, 구현 기술 및 빌드 상태 설명과 동작에 필요하지 않은 소개 문구가 없다. 클립보드 쓰기처럼 결과가 화면에 직접 나타나지 않는 동작의 상태, 입력 조건, 접근 가능한 이름과 오류 뒤 다음 행동은 확인할 수 있다.
- 다섯 주요 route와 보조 route에서 접속 확인, 빈 상태, 단일 오류, 페이지 전체 폼과 한 화면의 유일한 콘텐츠에 장식용 카드가 반복되지 않는다. 메모와 선택 가능한 일괄 복사 항목처럼 항목 자체가 독립적인 조작 대상인 표면은 유지하고, 그 밖의 관련 내용은 제목, 간격, 정렬 또는 구분선으로 묶여 있다.
- 넓은 화면에서 새 메모와 일괄 복사 제어가 캔버스 시작 높이를 줄이지 않고, 두 버튼 이외의 빈 overlay 영역에서 메모를 선택하고 이동할 수 있다. 메모가 제어 위치에 있어도 그 메모를 다른 위치로 옮기거나 편집할 수 있다.
- 모바일에서 수집 또는 확인 중 새로고침하면 현재 작업을 복원하지 않는다. `/`에서는 평상시 메모 목록이 보이고 `/batch-copy`에서는 저장 목록 관리 화면이 보이며, 이어가기 UI가 나타나지 않는다. 같은 실행에서 확인 화면의 화면 내 뒤로가기 또는 브라우저 뒤로가기를 실행하면 저장 목록 관리 UI를 거치지 않고 메모 선택 화면으로 돌아가며 다음 확인 진입 때 현재 순서를 유지한다.
- 모바일 메모 목록의 모든 메모를 일괄 복사 입력에 사용할 수 있다. 대표 메모 자료량에서 IndexedDB 전체 조회 시간, 첫 화면 표시, JavaScript heap, DOM 수와 스크롤 반응을 기록하고, 선택한 최적화 뒤 동일한 관찰 항목으로 비교한다. 성능 비교는 전체 메모 접근과 원문 복사를 유지한 상태에서 이루어진다.
- 사용 빈도, 텍스트 분석, 템플릿과 설정의 넓은 화면 및 320 CSS px 화면에서 바깥 테두리와 내부 행 구분선이 같은 내용 묶음을 중복해서 나누지 않는다. 내용을 구분하는 데 필요한 표 행 구분선, 입력 포커스와 오류 표시는 확인할 수 있다.
- `/batch-copy`의 저장 목록 관리 화면은 기존 디자인 토큰과 글자 크기 및 굵기 위계를 사용하고 한 줄 작업 헤더, 본문 우선순위와 간격 토큰을 유지한다. 목록 바깥을 장식용 카드로 감싸지 않고, 독립 항목을 구분하는 표면과 내용 관계에 필요한 선만 남긴다. 관리 목록에서 재정렬, 복제, 삭제, 복사, 취소, 오류 복구와 `focus-visible`을 사용할 수 있고, 메모 화면의 일괄 복사 패널 표현은 달라지지 않는다.

## 모델 기반 탐색 테스트

요구사항의 상태, 행동과 불변 조건에서 행동 순서를 자동 생성해 예제 기반 테스트가 놓치는 반복 입력, 순서 변경과 누적 상태 오류를 탐색할 수 있어야 한다. 현재 저장소의 상태 변화가 있는 도메인 하나에 먼저 적용하고, 기존 단위 테스트, 통합 테스트와 Playwright E2E를 유지해야 한다.

### 모델과 실행 조건

- 기존 테스트의 준비 자료, 실행한 동작과 검증문을 먼저 파악하고 확인하는 목적을 문서에 기록해야 한다. 실제 브라우저 및 저장소를 사용하는 검사와 대역을 사용하는 검사를 구분하며, 테스트의 예상값을 검토 없이 요구사항으로 채택하지 않아야 한다.
- 첫 적용 대상은 메모 기능이다. 편집, 저장 및 초안 복구, 생성과 배치, 삭제 및 복원과 개별 복사의 행동 순서를 탐색하고 실제 저장소와 화면에서도 확인한다. 기존 테스트의 목적과 요구사항을 비교해 단계별 작업을 정한다.
- 메모 기능을 세분화하고 각 기능마다 행동 생성, 오류 탐지, 실패 순서 축소, 로그 기록과 재현을 모두 입증해야 한다. 한 기능의 일부 성공을 다른 기능이나 메모 기능 전체의 완료로 대신하지 않아야 한다.
- 일괄 복사 목록은 요구사항 확인 전까지 모델 기반 탐색 대상으로 삼지 않는다.
- 요구사항만 있는 단계에도 추상 상태, 행동, 정상 전이, 비정상 시도와 불변 조건을 정의하고 기대 결과가 없는 동작을 식별할 수 있어야 한다. 실행할 구현이 생기면 같은 모델을 연결해야 한다.
- 모델은 실제 구현보다 단순해야 하며, 운영 코드의 알고리즘, React state 또는 IndexedDB 레코드 전체를 복제해 정답으로 사용하지 않아야 한다.
- 행동과 실제 실행 방법을 분리해야 한다. 순수 규칙은 Domain Adapter로 실행하고, 실제 API가 있는 경우 HTTP Adapter를, 브라우저 동작을 검사할 때 Playwright Adapter를 연결해 같은 행동 의미와 적용 가능한 불변 조건을 재사용해야 한다. 각 기능의 결과를 직접 확인할 실행 계층에서 생성부터 재현까지 입증해야 한다.
- 실행 계층에 따라 시도할 수 없는 행동과 실제로 실행한 행동을 구분해야 한다. UI가 막은 행동을 실행 성공이나 도메인 규칙 검증으로 계산하지 않아야 한다.
- 정상 행동과 비정상 시도를 별도로 표현해야 한다. 비정상 시도는 요구사항에 따라 거부, 안전한 무변경 또는 허용된 반복 결과를 검사하며, 정상 행동의 실행 조건으로 모두 걸러내지 않아야 한다.
- 정상 전이, 허용된 오류와 보존할 상태, 기대 결과 미정 상태를 구분해야 한다. 명시된 요구사항 또는 불변 조건 위반, 요구사항 모순, 기대 결과 미정과 실행 환경 실패를 서로 다른 결과로 보고해야 한다.
- 기대 결과가 미정인 행동은 임의의 오류나 성공으로 판정하지 않아야 한다. 해당 행동의 판정은 결정 전까지 보류하고, 이미 정해진 행동의 탐색은 계속할 수 있어야 한다.
- 생성, 실행, 판정, 실패 축소와 재실행은 LLM 없이 TypeScript 코드로 수행해야 한다. 핵심 생성 및 축소 엔진은 fast-check를 사용하고 자체 난수 생성기나 축소기를 만들지 않아야 한다.
- LLM은 상태, 행동, 불변 조건과 미정의 전이 후보를 제안하는 보조 수단으로만 사용할 수 있다. 검토 후 커밋된 모델과 요구사항에 근거한 판정만 CI에서 실행해야 한다.
- 기존 모듈별 TDD 분류를 유지해야 한다. 순수 규칙의 예제 기반 TDD에 생성형 테스트를 추가하되, 실제 Clipboard 권한, IndexedDB 수명과 브라우저 이벤트의 증거를 모델 실행으로 대체하지 않아야 한다.

### 탐색, 축소와 재현

- 반복, 행동 순서 변경, 허용되지 않은 전이, 빈 값과 허용 범위의 바로 안팎 값, Unicode 입력, 실패 후 재시도, 중간 취소, 초기화 및 새로고침, 오래된 식별자, 중복 입력과 긴 행동 순서를 탐색 정책으로 표현해야 한다. 각 정책은 대상 도메인의 실제 행동과 기대 결과가 정해진 경우에 적용해야 한다.
- 실패한 행동 순서와 입력을 축소해 더 짧은 재현 사례를 보고하고, 같은 실행 조건에서 그 실패를 다시 실행할 수 있어야 한다.
- 실패 기록에는 seed, path와 필요한 replayPath, 실제 실행 순서와 축소 결과, 초기 및 실패 시점 모델, 실행 계층, 위반한 불변 조건, 예상 결과와 관찰 결과를 포함해야 한다. 실행 버전과 설정도 식별할 수 있어야 한다.
- 로컬 빠른 실행, PR, main과 야간 탐색의 실행 횟수와 행동 수 상한을 별도 설정으로 관리해야 한다. 수치는 PoC 실행 시간과 탐색 결과로 정하고 CI에서도 재현 가능한 실행을 제공해야 한다.
- 중요한 규칙 위반, 실제 장애 또는 재발 가능성이 큰 실패는 재현 가능한 회귀 사례로 보존할 수 있어야 한다. 모든 축소 결과를 별도 예제 테스트로 복제할 필요는 없다.

### 첫 도메인 PoC의 완료 증거

아래 최소 조건은 메모 도메인의 PoC에 적용한다. 세부 기능별 입증은 별도로 진행하며 저장 기능 하나의 완료를 다른 메모 기능의 시작 조건으로 삼지 않는다.

- UI 없이 Domain Adapter에서 상태 모델 한 개, 정상 행동 3개 이상, 비정상 시도 2개 이상과 불변 조건 2개 이상을 실행한다. 생성 후보 수와 실제 실행 수를 구분해 비정상 시도가 실제로 실행됐음을 확인한다.
- 알려진 불변 조건 위반을 둔 통제된 사례에서 실패를 탐지하고, 불필요한 행동이나 입력을 줄인 뒤 같은 위반을 재현한다. 정상 구현에서는 같은 사례가 통과하며 실제 애플리케이션에 결함을 남기지 않는다.
- 같은 seed 및 재실행 정보와 실행 조건으로 로컬과 CI에서 같은 실패를 확인한다. 로그에서 축소된 행동 순서, 불변 조건 이름과 예상 및 관찰 결과를 읽을 수 있다.
- 기존 예제 테스트와 생성형 테스트가 함께 실행된다. 모델이 구현 알고리즘을 복제하지 않는지, 행동 추가에 필요한 코드량, 로컬 빠른 실행 시간과 동일 조건의 결과 일치 여부를 확인한다.
- 탐색의 가치는 테스트 개수 증가가 아니라 기존 테스트가 놓친 오류, 예상하지 못한 재현 순서, 요구사항의 빠진 규칙 또는 반복 및 순서 조합 오류를 찾은 증거로 평가한다. 실제 오류 발견 여부는 통제된 결함 탐지 결과와 구분해 기록한다.

### 후속 확장 조건

첫 PoC에는 범용 UI 자동 탐색기, 실행 중 UI에서 행동을 추론하는 기능, 동시성 탐색, XState와 독립 배포 패키지를 포함하지 않는다. HTTP Adapter를 위해 현재 로컬 애플리케이션에 서버 API를 새로 만들지 않는다.

세부 메모 기능의 입증에 필요한 실행 계층은 해당 기능 작업에서 연결한다. 공통 탐색 정책은 실제 반복되는 책임을 확인한 뒤 분리한다. 브라우저 탐색에서는 연속 클릭, 포커스 이동, 뒤로가기 및 앞으로가기, 새로고침, 여러 탭, 화면 크기 변경, 키보드와 이동 중 늦게 도착한 응답을 실제 도메인 행동과 연결한다. 동시성 탐색은 비동기 완료 순서와 실제 저장소의 실행 조건을 제어할 방법을 정한 뒤 진행한다.

공통 TypeScript 패키지는 두 번째 도메인 또는 저장소에서 재사용을 확인한 뒤 추출 여부를 판단한다. 여러 도메인 사용, 여러 저장소의 수요, 실제 오류 발견을 거친 API 안정화, 공통 코드 분리, 실행 설정 및 보고서 재사용, 실행 엔진과 도메인 API의 분리 가운데 세 조건 이상을 확인해야 한다. Codex Skill은 모델 API가 안정된 뒤 초안 생성과 검토를 보조하도록 추가할 수 있다.

상태 및 전이 도달률, 행동 쌍과 불변 조건 실행 횟수, 회귀 사례의 선행 실행, 실행 중 UI와 모델의 행동 비교, LLM의 모델 검토와 변경 내용에 따른 탐색 비중 조절은 후속 확장 항목이다. 모든 상태의 완전 탐색이나 형식 검증, 기존 E2E의 전면 교체는 목표로 삼지 않는다. 초기 범위에서 제외된 확장은 아래 계정 및 동기화 백로그의 우선순위를 바꾸지 않는다.

## 구현에 적용할 결정 원칙과 기본값

좁은 화면에서 다른 주요 화면으로 이동하는 탐색은 메모 목록과 보조 화면의 Drawer가 맡는다. 메모 상세와 일괄 복사 확인 및 저장 목록 관리에는 Drawer를 두지 않고 해당 과업의 한 줄 헤더와 되돌아가기 동작을 유지한다. 모든 화면에 하나의 공통 프레임을 적용하지 않으며 화면별 헤더, 스크롤과 하단 동작은 과업에 맞춘다. 파생 중립색, 표면별 모서리 반경, pointer용 제어 크기와 motion 수치는 대표 화면에서 명암 대비와 밀도를 확인해 정하며 사용자 동작을 바꾸지 않는다.

현재 구현 결과를 바꾸는 선택에 필요한 값이 정해지지 않은 경우에는 구현을 시작하기 전에 최신 공식 자료, 현재 저장 자료와 실제 화면 근거를 교차검증한다. 그 결과 가운데 사용자 자료 손실과 조작 충돌을 가장 적게 만들고 접근 가능한 방법을 채택하며, 검토한 선택지, 채택 이유, 영향과 다시 검토할 조건을 결정 기록과 계획에 남긴다. 계정 동기화나 라이브러리 연결처럼 현재 범위에서 제외한 작업의 선택은 해당 백로그를 시작할 때 같은 절차로 정한다.
- 문서, 계획, 코드와 커밋 문구에는 요구사항에서 행동 주체를 직접 밝힌 경우에만 인칭 표현을 사용해야 한다. 출처가 없는 가상 역할을 요청, 결정 또는 승인 근거처럼 만들지 않아야 한다.

현재 로컬 애플리케이션에는 다음 기본값을 적용한다.

- 넓은 화면의 메모 원문은 마지막 입력 800ms 뒤 자동 저장을 시작한다. `blur`, 애플리케이션 내부 화면 이동, 문서가 숨겨질 때와 `pagehide`에서는 대기 중인 내용을 즉시 저장한다. 화면의 입력값은 저장 완료와 분리해 유지하고, 최신 복구 초안을 IndexedDB에 먼저 기록한 뒤 메모 저장이 완료되면 초안을 지운다. 메모 저장은 완료됐지만 초안 제거에 실패하면 저장된 메모와 입력을 유지하고 다음 저장 기회에 초안 제거를 다시 시도한다. 저장 실패는 본문을 가리지 않는 위치에 원인과 재시도를 표시하며 입력과 복구 초안을 유지한다.
- 작은 화면의 상세 편집은 명시적 저장을 사용한다. 저장되지 않은 입력을 둔 애플리케이션 내부 이동에는 계속 편집하거나 변경사항을 버릴 선택을 제공한다. 저장을 반복 실행하지 않고 실패하면 원문과 복구 초안을 유지한다.
- 모바일 일괄 복사는 저장된 일괄 복사 목록과 분리된 빈 작업으로 시작하고 현재 앱 실행의 메모리에만 둔다. 애플리케이션 내부 이동에서는 현재 단계, 항목, 순서와 클릭 횟수를 유지하되 새로고침하거나 브라우저를 다시 열면 초기화한다. 수집 화면의 헤더 뒤로가기와 확인 페이지의 `취소`를 실행하면 같은 실행의 작업을 버린다.
- 모바일 일괄 복사 수집 상태에서는 짧은 누르기만 항목을 추가한다. 길게 누르기는 개별 복사나 항목 추가를 실행하지 않는다. 확인 페이지의 복제 항목은 대상 바로 뒤에 새 ID로 넣으며 재정렬, 복제와 삭제는 원본 메모와 저장 목록을 바꾸지 않는다.
- 넓은 화면에서 포커스가 있는 메모 선택 지점에서 `Command+Option+Enter`를 누르면 그 메모를 일괄 복사 목록에 추가한다. `Command` keydown으로 selection 표시가 사라져도 현재 포커스 대상 ID로 key sequence를 완료한다. 설정에서 끌 수 있는 보조 키 동작은 pointer의 `Command+Option+클릭`이며 키보드 추가 동작은 유지한다.
- 모바일 일괄 복사 확인 및 저장 목록 관리 페이지에서 drag를 사용하지 못하는 사용자는 설정을 켠 뒤 액션 시트의 `위로 이동` 또는 `아래로 이동` 아이콘 버튼을 실행해 같은 인접 순서를 만들 수 있다. 이 대안과 키보드 조작은 drag와 같은 재정렬 명령을 사용한다.
- 모바일 일괄 복사 drag는 항목 왼쪽의 이동 핸들에서만 시작한다. 본문 누르기와 세로 스크롤, `pointercancel` 또는 완료 전 `lostpointercapture`는 순서를 바꾸지 않아야 한다.
- 메모 이동 핸들과 빈 캔버스 시점 이동은 시작점부터 mouse 및 pen `5 CSS px`, touch `10 CSS px`를 넘은 뒤 drag로 판정한다. 모바일 목록의 개별 복사는 500ms 동안 `10 CSS px` 안에 머물고 같은 메모 안에서 손을 뗀 경우 완료한다.
- 넓은 화면과 모바일 일괄 복사 화면의 항목에는 이동 핸들과 더보기를 둔다. 더보기에는 `복제`와 `삭제`를 제공하고, 설정을 켠 경우에만 현재 실행할 수 있는 `위로 이동`과 `아래로 이동`을 추가한다. 직접 이동과 키보드 조작은 drag와 같은 재정렬 명령을 사용해야 한다.
- 넓은 화면의 항목 동작 선택창은 `popover="auto"`, 이름 있는 `role="group"`과 일반 네이티브 버튼을 사용한다. 열기 및 닫기 포커스를 관리하며 현재 범위에는 ARIA menu 역할과 외부 접근성 부품을 추가하지 않는다. 좁은 화면의 확인 및 관리 페이지에서는 화면 아래에서 열리는 액션 시트를 사용하고 이동 동작만 보이는 텍스트 없는 방향 아이콘으로 표시한다. 시트 상단의 닫기 버튼, 바깥 누르기, 기기 뒤로가기와 `Escape`로 닫으며 동작 실행 뒤 자동으로 닫는다.
- 공유 알림 영역은 애플리케이션 실행 동안 한 곳에서 결과 한 건만 관리하고 화면 위쪽 중앙에 표시하며 포커스를 가져가지 않는다. 내부 페이지 이동에서 같은 알림과 원래 남은 시간을 유지하고, 닫히거나 만료된 알림은 돌아왔을 때 다시 표시하지 않는다. 모든 토스트의 오른쪽에 해당 토스트를 닫는 아이콘 버튼을 두며 단순 성공은 짧게 표시한다. 실행 취소 또는 다시 시도 동작이 있는 알림은 5초를 기본값으로 삼고 hover와 `focus-within`에서 남은 시간을 멈춘다. 지속해서 확인해야 하는 실패는 해당 작업 가까이의 상태로 남긴다.
- 상단 탐색과 메모 화면의 주 작업 제어는 `1..999`, 메모 선택 지점은 저장된 `1000..32767`의 양의 `tabindex`를 사용한다. 새 메모는 현재 메모 최댓값 다음 값을 받고, 누락, 중복, 정수가 아닌 값과 범위 밖 값은 기존 값, 생성 시각과 ID 순으로 안정 정렬한 뒤 `1000`부터 빈틈없이 다시 배정한다. 본문, 이동 핸들, 복사, 더보기와 패널 제어는 이 양수 구간 뒤에 네이티브 DOM 순서로 탐색한다.
- 선택 지점의 `Enter` 또는 더보기의 속성 동작으로 속성 패널을 열면 첫 속성 입력으로 포커스를 옮긴다. 빈 캔버스 클릭은 캔버스 viewport로 포커스를 옮기고, 상위 임시 조작이 없을 때 `Escape`는 메모 및 일괄 복사 항목 선택을 함께 해제하되 현재 포커스를 옮기지 않는다. `Command`로 숨겨질 보조 제어에 포커스가 있으면 같은 메모의 선택 지점으로 먼저 옮긴다.
- 최근 활성 오른쪽 패널을 닫으면 이전 패널을 다시 표시하지 않는다. 속성 패널의 유효한 초안은 닫기 전에 한 번 적용하고, 유효하지 않은 초안은 유지한 채 첫 오류 입력으로 포커스를 옮긴다. 별도의 `저장값으로 되돌리기`를 실행해야 잘못된 초안을 버리고 닫을 수 있다. `Escape`는 선택만 해제하며 패널 대상과 초안을 바꾸지 않는다.
- 선택된 메모는 accent 기반 selection 상태, 속성 패널 대상은 별도 중립 표시와 패널 머리의 원문 첫 줄로 구분한다. 두 메모가 같을 때에도 selection, focus와 properties target을 색 하나에 의존하지 않고 각각 확인할 수 있어야 한다.
- 메모 X와 Y의 고정 최솟값과 최댓값을 제거한다. 원점과 기존 4096 바깥을 지나도 메모를 배치할 수 있어야 한다. 메모 크기는 위치와 독립적으로 너비 `240..4095`, 높이 `180..4095`를 유지한다. 기존에 저장된 위치를 양수나 이전 캔버스 안으로 다시 옮기지 않아야 한다.
- 일괄 복사 패널은 메모 작업 영역이 `72rem` 이상일 때 너비 `22rem`의 나란한 패널로, `48rem` 이상 `72rem` 미만일 때 모달로 표시한다. 작은 화면 메모 미리보기는 내용에 따라 짧아지고 `12rem`을 넘지 않는다. 두 값은 현재 화면 너비 예산과 기본 글자 크기를 바탕으로 정한 초기 제품값이다.
- 삭제 취소는 삭제 전 `zIndex`를 그대로 보존한다. 삭제 이후 다른 메모의 순서가 바뀌었다면 같은 `zIndex`가 생길 수 있으며, 복원 시 중복을 없애려고 다른 메모를 다시 번호 매기지 않는다. 일반 재조회와 새로고침에서도 복원해 저장한 값을 유지해야 한다.
- 맨 앞 또는 맨 뒤로 보내기가 성공하면 활성 메모의 `zIndex`를 `1..N`의 고유하고 빈틈없는 값으로 배정한다. 나머지 메모의 상대 순서를 유지한 전체 결과를 하나의 IndexedDB transaction에서 저장하며 `tabindex`를 바꾸지 않는다. 이 고유성 및 연속성 조건을 삭제 또는 복원 직후에 적용하지 않는다.
- 메모 삭제 취소 알림은 5초 뒤 사라지고 포커스를 가져가지 않는다. hover와 `focus-within`에서는 남은 시간이 멈춘다. 연속 삭제는 현재 실행의 LIFO 이력에 쌓으며 알림이 보이는 동안 최신 삭제 한 건을 `실행 취소`할 수 있다. 라우트 이동에서는 이력을 유지하고 새로고침 뒤에는 복원하지 않는다. 삭제한 메모에 포커스가 있었다면 다음 `tabindex` 메모, 이전 메모와 새 메모 제어 순으로 옮기며, 실행 취소로 복원하면 복원된 메모로 옮긴다.

구현값의 근거, 대안과 재검토 조건은 [구현 필수 결정 교차검증](references/required-implementation-decisions-research.md), [데스크톱 입력과 피드백 복원력 조사](references/desktop-input-and-feedback-resilience-research.md)와 각 결정 기록에서 관리한다.

## 초기 범위에서 제외한 백로그

### 최우선: 계정 및 동기화

계정 생성, 로그인, 동기화, 백엔드와 데이터베이스는 모든 백로그 가운데 우선순위가 가장 높다. 현재 로컬 애플리케이션을 완성한 뒤 다른 백로그보다 먼저 진행한다.

이 백로그에는 다음 결과가 포함된다.

- 사용자는 계정을 만들고 로그인할 수 있다.
- 사용자는 계정에 연결된 메모, 일괄 복사 항목과 템플릿을 여러 브라우저에서 동기화할 수 있다.
- 백엔드와 데이터베이스가 인증, 접근 권한, 동기화 상태와 데이터 보관을 처리한다.
- 로컬과 계정 실행 형태에서 공통으로 제공하는 과업은 같은 화면 구조와 조작 방식을 사용한다.
- 계정 동기화처럼 로컬에서 제공하지 않는 과업과 조작 UI는 로컬 애플리케이션에 표시하지 않는다.

백로그 작업을 시작하기 전에 다음 사항을 정해야 한다.

- 계정 생성과 로그인 방식
- 로컬과 계정 실행 형태를 빌드 시점 설정으로 나눌지, 배포 시점 설정으로 나눌지와 기능 가용성을 어떤 단위로 표현할지
- 동기화 충돌 해결 규칙, 삭제 전파와 계정 데이터 삭제 범위
- 서버 API, 데이터베이스 구조와 여러 기기 사이의 일관성 기준
- 계정 기능을 추가한 뒤 로컬과 계정 실행 형태의 공통 화면이 같은 정보 구조와 조작을 유지하는지 확인할 방법

### 그 밖의 후속 항목

- LLM을 사용하지 않고 의미가 비슷한 텍스트를 자동으로 판별하는 동작은 초기 개발 범위에 포함하지 않고 후속 개발 항목으로 남긴다.
- 의미가 비슷하다고 판별한 텍스트를 바탕으로 한 템플릿 제안도 후속 개발 항목으로 남긴다.
- 메모 안 URL의 자동 링크 변환, 클릭 이동, 미리보기와 링크 정보 불러오기는 초기 개발 범위에 포함하지 않는다.
- 로컬 자료의 내보내기와 가져오기, 브라우저가 지운 자료의 복구는 초기 개발 범위에 포함하지 않는다.

### 라이브러리 및 포트폴리오 연결

개인 메모 애플리케이션을 라이브러리 패키지로 빌드하고 포트폴리오 웹 애플리케이션이 선택한 라우트에서 불러오는 작업은 백로그로 남긴다. 현재 구현 범위와 완료 증거에는 라이브러리 빌드 및 포트폴리오 라우트 연결을 포함하지 않는다.

백로그 작업을 시작하기 전에 다음 사항을 정해야 한다.

- 라이브러리 패키지를 같은 저장소의 workspace에서만 사용할지, 별도로 배포해 다른 저장소에서도 설치할 수 있게 할지
- 라이브러리가 지원할 호스트를 Next.js App Router로 제한할지, 다른 React 기반 호스트에서도 사용할 수 있게 할지
- 포트폴리오 웹 애플리케이션이 개인 메모의 단일 라우트만 연결할지, 일괄 복사, 사용 빈도, 텍스트 분석, 템플릿과 설정의 하위 라우트까지 연결할지
- 독립 실행 형태와 포트폴리오 라우트 연결 형태에서 바깥쪽 탐색, 페이지 제목, 테마와 알림 영역 가운데 무엇을 개인 메모 모듈이 그리고 무엇을 호스트가 그릴지
- 포트폴리오 라우트 연결 형태에서 로컬 모드만 제공할지, 계정 모드와 서버 쪽 연결도 함께 제공할지
- 라이브러리 빌드의 공개 진입점, 스타일과 Web Worker 파일 제공 방식 및 호스트 버전 호환 범위
