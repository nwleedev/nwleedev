# 개인 메모 앱의 Independent Work 선정 요구사항

`apps/notes`를 개발자 소개 사이트 `apps/entry`의 Independent Work에 추가할 가치가 있는지 판단한다. 실제 사용 목적, 성과와 기여를 근거로 이력서나 포트폴리오에 쓸 내용을 평가 문서와 플랜에 정리한다.

## 필요한 결과

- `apps/entry`의 역할, 개발 의도와 기존 Independent Work의 선정 기준을 확인한다.
- `apps/notes`에서 이력서나 포트폴리오에 작성할 가치가 있는 성과와 기여를 찾아 추가 권고 또는 보류의 이유를 제시한다. 추가를 전제하지 않는다.
- `apps/notes`의 변경 커밋을 하나씩 평가해 어떤 문제 해결 역량을 보여주는지 판단한다. 기록만으로 알 수 없는 목적, 성과와 기여는 추가 정보로 확인한다.
- 프로젝트 경험을 이력서나 포트폴리오에 작성하는 방법을 조사하고 검토 문서와 플랜에 반영한다.
- 구현 방법의 상세 설명을 피하고 목적, 성과와 문제 해결을 판단할 수 있는 내용을 작성한다.
- 짧은 프로젝트 소개에서는 겪은 불편, 해결 방향을 선택한 이유와 직접 사용하며 개선한 점을 먼저 전달한다. 기능 목록이나 사용 절차가 소개의 중심이 되지 않도록 한다.
- 사용 방법과 개선된 점은 무엇을 하려 했고 무엇이 달라졌는지 알 수 있는 자연스러운 한국어로 설명한다.
- 평가에 이은 사이트 반영 절차를 진행한다. 선정 이유와 소개 문구를 확정하고, 사이트 선정 문서와 한국어 및 영어 Independent Work에 반영한다.

## 완료를 확인할 자료

평가 문서와 플랜에서 사이트의 역할, 메모 앱의 소개 가치, 성과 후보의 근거, 소개 문구 제안과 후속 절차를 확인할 수 있어야 한다. 소개 문구만 읽어도 시작한 이유, 직접 내린 판단과 개선한 점을 알 수 있어야 한다. 문서는 작업용 워크트리 브랜치에 작성한다.

사이트에서는 두 언어로 같은 목적과 기여를 전달하고, 확인한 소스를 열 수 있어야 한다. 기존 한 페이지 구성과 다른 항목을 유지한다. 각 절차의 완료 근거는 플랜에 기록한다.
