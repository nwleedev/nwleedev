# 개인 메모 앱의 소개 가치 평가 플랜

저장 결함의 수정과 초안 복구 동작을 근거로 Independent Work 추가를 권고한다. 이번 평가는 문서와 소개 문구를 제안하며, 항목 등록과 애플리케이션 변경은 포함하지 않는다.

기준은 [요구사항의 필요한 결과와 완료 자료](requirements.md)다. 이후 화면을 변경하게 되면 [개발 지침](../../dev/README.md)과 [Astro 구현 지침](../../dev/frontend/astro-fsd-tailwind.md)을 적용한다.

## 평가 절차

1. 사이트의 역할과 선정 기준을 확인한다. `apps/entry`의 현재 소개와 설계 기록, `apps/notes`의 요구사항, 코드와 Git 기록을 대조해 `references/assessment.md`에 근거를 정리한다. 기능의 존재, 실행 결과와 이용자 성과를 구분할 수 있으면 완료다.
2. 경력 채용과 경험 서술 기준을 조사한다. 국내 기업의 프론트엔드 채용공고와 이력서 작성 자료를 비교해 `references/hiring-and-writing.md`에 적용할 기준을 정리한다. 각 기준에 직접 연결되는 출처와 자료의 적용 범위를 확인한다.
3. 성과 후보를 평가하고 문구를 제안한다. 목적, 해결한 문제, 확인된 결과와 기존 소개에 보태는 역량을 기준으로 `references/assessment.md`를 완성한다. 근거 없는 수치와 역할을 제외한 문구, 추가 권고 또는 보류 이유와 후속 조건이 있으면 완료다.

위 절차는 문서 작성 단위이며 테스트 코드나 TDD를 적용하지 않는다. 기존 문서와 코드는 평가 자료로만 사용한다. 생성할 파일은 이 패키지의 요구사항, 플랜과 두 참고 문서이며 기존 파일을 수정하거나 삭제하지 않는다.

## 평가 결과와 완료 근거

- 사이트의 역할과 선정 기준: [소개 가치 평가의 entry 역할](references/assessment.md#appsentry의-역할과-개발-의도)에 현재 화면과 기존 선정 기록의 근거가 있다.
- 채용과 경험 서술 기준: [경력 프론트엔드 채용 조사](references/hiring-and-writing.md)에 여섯 기업의 요구와 자료의 확인일 및 모집 상태, 프로젝트 서술에 적용할 기준이 있다.
- 성과와 소개 문구: [소개 가치 평가](references/assessment.md)에 실제 저장 결함과 수정의 근거, 성과 후보의 우선순위, 한국어 및 영어 소개안과 추가 권고 이유가 있다.
- 실행 결과: 운영 빌드 후 저장, 복구와 분석의 기존 시나리오 다섯 개가 Chromium, Firefox와 WebKit에서 모두 통과했다. [실행 확인 범위](references/assessment.md#현재-실행으로-확인한-결과)는 15개 실행과 과거 기록을 구분한다.

## 항목 추가를 선택할 때의 후속 적용안

이 절차는 항목 추가와 소개 문구를 선택한 뒤 적용할 제안이다. 현재 평가만으로 기존 소개 내용이나 선정 결정을 변경하지 않는다.

1. 소개할 목적과 결과를 확정한다. [성과 후보와 소개안](references/assessment.md#independent-work에-실을-문구-제안)의 주장에 각각 근거가 있는지 확인한다. 실행 주소 없이 소스 링크만 사용할 경우에도 링크가 무엇을 보여주는지 명확해야 한다. 확인되지 않은 수치와 기여 역할이 없어야 다음 단계로 진행한다.
2. 사이트 선정 기록을 반영한다. `docs/designs/developer-portfolio-f4b7/requirements.md`의 Independent Work에 필요한 변경을 제안하고, 문구가 확정되면 `decisions/project-availability.md`에 새 선정 이유를 반영한다. 메모 앱의 필수 제외 기록과 새 소개가 모순되지 않으면 완료다.
3. 소개 내용을 반영한다. `apps/entry/src/shared/terms/ko.json`과 `en.json`의 Independent Work 항목에 같은 목적, 결과, 기간과 소스 링크를 담는다. 기존 한 페이지 구성과 다른 항목의 기능을 유지한다. 저장 및 복구 성과보다 기능 목록이나 기술 정보가 앞서지 않는지, 두 언어가 같은 내용을 전달하는지 확인한다.
4. 소개 화면을 확인한다. [개발 지침](../../dev/README.md)과 [Astro 구현 지침](../../dev/frontend/astro-fsd-tailwind.md)의 검사 및 빌드 기준을 적용하고, 한국어와 영어 화면에서 항목과 링크를 확인한다. 새 테스트 코드 작성이나 별도 상세 화면 제작은 이 제안에 포함하지 않는다.

## 평가를 멈추는 조건

성과 설명에 필요한 수치, 개인 기여 또는 이용 결과를 확인할 수 없으면 해당 주장을 보류한다. 확인 가능한 기능과 판단의 평가는 계속한다. 실제 항목 등록은 평가 이후의 별도 선택이다.
