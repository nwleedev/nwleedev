# 메모 앱 커밋별 소개 가치 평가

`apps/notes`는 Independent Work에 추가할 가치가 있다. 반복 지침 입력과 매개변수별 명령어 메모 관리의 불편을 일괄 복사와 템플릿으로 바꾼 목적 및 직접 내린 판단이 확인됐다. 개별 커밋의 입력 및 저장 문제 해결은 그 도구의 프론트엔드 역량을 설명할 근거다. 현재 평가는 **목적과 직접 정한 기여를 앞에 둔 추가 권고**이며 실제 항목 반영은 별도 선택이다.

이 문서는 [선정 요구사항](../requirements.md)의 개별 커밋 평가다. 2026년 10월 2일, `a06bfc94c64232581742792a9834b82f5963f225`까지의 저장소 이력을 기준으로 한다. `apps/notes` 파일이 변경된 커밋 18개 가운데 초기 5개는 합친 기록이다. 그 본문에서 중복을 제외한 메모 앱 관련 변경 175개를 찾았다. 111개는 앱 파일, 64개는 관련 설계 또는 개발 지침을 바꾼 기록이다. 나머지 13개와 함께 개별 변경 188개를 평가하며, 이 숫자를 성과의 크기로 사용하지 않는다.

아래는 현재 이력의 18개 커밋 평가다. 합치기 전 175개 변경의 개별 판단은 [합친 이력의 개별 변경 평가](squashed-history.md)에 있다. 커밋 제목보다 실제 전후 차이, 저장 자료와 사용자 동작, 이후 변경에서 유지되는지를 기준으로 판단한다. 커밋 작성자 정보는 개인의 판단이나 기여율을 입증하는 자료로 사용하지 않는다.

## 경쟁력을 설명할 수 있는 내용

### 텍스트를 보관한 뒤 조합하고 다시 사용하는 과업

앱의 차이는 메모 작성 자체보다 여러 원문에서 필요한 텍스트를 고르고 순서를 바꿔 복사하는 과업에 있다. 반복 부분을 템플릿으로 만들고 달라지는 부분만 입력하는 기능도 같은 목적에 연결된다. `8ab8917`, `0c4d4ab`, `849b34e`, `8cc7957`의 결정 및 구현이 [초기 통합 커밋](https://github.com/nwleedev/nwleedev/commit/b9ae452)에 포함된다.

재사용할 대상은 AI 작업 지침과 스킬 호출 문구, 입력 및 출력 파일만 바뀌는 Python 명령어다. 여러 지침을 고르는 일괄 복사와 고정된 명령어에서 달라지는 부분을 입력하는 템플릿은 직접 선택한 기능이다. [사용 목적과 입력 문제](workflow-and-input.md)에 확인한 목적, 기여와 구현 근거가 있다. 이 목적과 기능 선택을 프로덕트 엔지니어 소개의 첫 근거로 삼되 작성 시간 절감이나 다른 사람의 사용 만족도를 주장하지 않는다.

### 편집 내용과 저장 원문의 불일치 해결

`266ec02`는 앞선 자동 저장이 끝나기 전에 추가 입력이 생겼을 때 최신 원문이 저장되지 않는 문제를 다룬다. `7291f47`은 모바일 연속 저장 누락과 숨은 데스크톱 편집기가 저장 버튼 전에 복구 초안을 원문으로 확정하는 문제를 수정한다. 최초 수정의 통합 이력은 각각 [b9ae452](https://github.com/nwleedev/nwleedev/commit/b9ae452)와 [bb14d8d](https://github.com/nwleedev/nwleedev/commit/bb14d8d)다. `41c3dd0`은 그 뒤 복구와 저장 자료 검사를 보강한 기록이다.

사용자에게 보이는 값과 실제 저장 결과를 구분하고, 연속 입력 및 화면 이동에서 생기는 오류를 재현한 사례다. 단일 저장 버튼을 연결한 사실보다 설득력이 있다. 다만 직접 만든 앱의 결함을 수정한 결과이므로 회사 서비스의 운영 장애 해결이나 이용자 피해 감소와 같은 성과로 바꾸지 않는다.

### 실패한 단계와 이미 성공한 단계를 구분

`f811f3b`는 원문 저장 성공과 초안 제거 실패를 구분한다. `c784077`은 저장 형식 변경에서 기존 텍스트와 순서를 옮기며, `cd1f749`는 저장 도중 일부 쓰기만 남거나 늦은 연결 결과가 최신 상태를 바꾸는 조건을 다룬다. 근거는 [초기 통합 이력](https://github.com/nwleedev/nwleedev/commit/b9ae452), [저장 처리](../../../../apps/notes/src/_pages/notes/model/save-note-content.ts)와 [실제 저장소 검사](../../../../apps/notes/src/_app/composition/indexed-db/personal-notes-database.indexeddb.test.ts)다.

저장 단계와 이전 조건을 구분한 사례는 로컬 자료의 일관성과 복구를 판단하는 역량의 근거다. 자료 이전과 실패 처리가 있는 코드는 확인되지만 실제 이용자의 자료를 운영 중 이전한 경험까지 확인되는 것은 아니다. 같은 원문의 다음 저장에서는 불필요하게 본문 버전을 늘리지 않고 남은 초안만 정리하는 결과를 설명할 수 있다.

### 여러 입력 방식이 같은 작업 결과를 내도록 조정

`e2e6f87`은 포인터, 키보드와 메뉴의 재정렬을 같은 삽입 규칙으로 맞추고 원문, 항목 ID와 포커스를 보존한다. `20bc777`은 포인터를 놓은 뒤에도 캔버스가 따라 움직이던 문제를 수정한다. `16f088b`는 멀리 떨어진 좌표를 화면에 표시할 때 메모가 겹치던 문제를 다룬다. 근거는 [초기 통합 이력](https://github.com/nwleedev/nwleedev/commit/b9ae452)와 [후속 조작 수정](https://github.com/nwleedev/nwleedev/commit/41c3dd0)이다.

드래그 이력에는 이미 이동한 시점을 되돌리던 처리의 수정, WebKit 정상 입력을 취소하던 추정의 폐기와 문서에 도착한 종료 입력의 보완이 있다. [원인과 해결 결과](workflow-and-input.md#드래그-문제의-원인과-해결한-결과)는 각 변경과 현재 동작을 연결한다. 드래그 외의 실행 방법은 [W3C의 Dragging Movements 설명](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)과도 연결된다. 대안 조작 일부를 확인한 것으로 앱 전체의 WCAG 준수를 주장하지 않는다.

### 검사가 실제 결함을 찾는지 확인

저장, 입력과 이탈 행동을 조합하고 실패 순서를 줄여 재현한 기록은 대표 문제 해결을 뒷받침한다. 특히 `7291f47`은 실제 앱에서 발견한 결함과 수정이 이어진다. `91b4be7`, `bfd6833` 등의 의도적인 저장 누락은 검사의 탐지 능력을 확인한 조건이며 발견한 앱 결함 수에 더하지 않는다.

검사 개수나 fast-check 사용 자체보다, 화면과 저장소의 차이를 찾고 테스트용 화면이 운영 화면을 대신하던 검사를 바로잡은 판단이 의미 있다. 다만 회사 경력의 E2E 경험과 겹치므로 별도 검사 프로젝트처럼 소개하지 않고 저장 문제 해결의 근거로 붙인다. 세부 이력은 [개별 변경 평가](squashed-history.md)에 있다.

**조작 복원과 유지보수의 보조 근거.** [커밋 원문](https://github.com/nwleedev/nwleedev/commit/5d82889)은 첫 메모가 생성 버튼과 겹치지 않게 하고 메모 작성, 이동, 초안과 이탈의 처리를 구분한다. 주어진 화면에서 실제 조작이 가능한지를 확인한 사례다. [당시 비교 기록](../../notes-architecture-refactor-4d8c/plan.md#u20-후속-변경의-사용자-동작과-의존-방향을-확인한다)에 성능 개선을 뒷받침할 결과는 없다. 표시 시간 중앙값은 오히려 늘었고 표본은 세 번이므로 성능 최적화 성과로 쓰지 않는다.

### 6396efd: 기능별 외부 동작 연결

**기술 선택을 설명하는 보조 근거.** [커밋 원문](https://github.com/nwleedev/nwleedev/commit/6396efd)은 무관한 기능까지 한 객체로 연결하던 구성을 분리하며 공통 저장소 연결과 Worker 종료를 유지한다. 왜 전체 앱의 의존성을 한곳에 모으지 않았는지 설명할 자료다. 실제 변경 비용의 전후 비교가 없어 생산성 향상을 주장하지 않는다.

### 5bed85c: 늦은 알림 종료와 검사 오류

**동시성 문제의 보조 근거.** [커밋 원문](https://github.com/nwleedev/nwleedev/commit/5bed85c)은 이전 알림의 타이머가 새 알림을 닫는 조건을 구분한다. 저장 완료 전에 판단하던 검사와 웹폰트 중복 레코드도 다룬다. 알림의 잘못된 종료를 해결한 부분과 검사 환경을 정비한 부분은 서로 다른 결과이며, 폰트 변경을 용량 최적화 성과로 제시하지 않는다.

### 10c7d91: 선택 작업과 알림의 유지 기간 결정

**설계 판단의 보조 근거.** [커밋 원문](https://github.com/nwleedev/nwleedev/commit/10c7d91)은 모바일 선택을 현재 실행으로 제한하고, 내부 이동에서는 같은 알림과 남은 시간을 유지하도록 정한다. 문서 변경 자체는 동작 완료의 근거가 아니며 `7048eaf`와 함께 설명한다. 저장할 자료와 일시적인 선택을 구분한 이유는 직접 확인할 필요가 있다.

### 7048eaf: 선택 초기화와 이동 중 알림 유지

**현재 동작을 설명할 후보.** [커밋 원문](https://github.com/nwleedev/nwleedev/commit/7048eaf)은 모바일 선택을 내부 이동에서 유지하고 새로고침과 취소에서는 초기화한다. 저장된 메모와 일괄 복사 목록은 유지하면서 이전 모바일 선택 저장소를 제거한다. 알림은 화면 이동에도 남은 시간을 유지하며 닫힌 알림이 되살아나지 않게 한다. 현재 작업, 저장 자료와 알림의 유지 기간을 과업에 맞게 판단한 사례다. 이 변경이 실제 사용 중 어떤 혼란을 줄였는지 확인하면 소개 가치가 높아진다.

## 선정 판단과 확인할 사실

프론트엔드 기술 역량의 근거로는 충분하다. 저장 실패, 비동기 완료, 브라우저 입력과 데이터 이전을 사용자 결과와 연결할 수 있다. [당근 공고](https://careers.daangn.com/jobs/role/7689088003/)가 요청하는 문제 판단과 개선 결과, [LINE Pay 공고](https://careers.linecorp.com/ko/jobs/3005/)가 요청하는 웹 기본기 및 서비스 개발 경험과 연결되는 자료다. 다만 이 공고의 협업, 운영과 서비스 성장 경험까지 개인 앱 하나로 충족하는 것은 아니다.

대표 성과로 소개할 목적과 선택은 확인됐다. 지침을 반복 입력하는 불편과 매개변수별로 늘어나는 명령어 메모를 정의하고, 일괄 선택 및 템플릿, 모바일 대안과 아이콘 제어, 구조 변경을 고려한 IndexedDB를 직접 선택했다. 구현된 도구와 드래그 및 저장 문제 해결을 연결하면 기능 목록을 넘어 그 과업을 선택한 판단을 설명할 수 있다.

- 현재 가장 자주 사용하는 기능과 실제 이용 빈도.
- 실제 모바일 문제의 기기, 발생 동작과 수정 기록의 연결.
- 오류 원인 분석 및 코드 수정에서 직접 맡은 부분. 문제 정의와 기능 및 기술 선택은 이미 확인된 기여다.
- 실제 이용 결과가 있다면 확인 가능한 기록과 비교 조건. 숫자가 없으면 구체적인 전후 행동으로 설명한다.

추가 정보가 없어도 확인된 문제 정의와 직접 정한 기능은 소개할 수 있다. 개별 수정의 주도 역할, 시간 절감과 다른 이용자의 성과는 확인될 때만 더한다. 짧은 소개와 이력서에 남길 후보는 [종합 평가](assessment.md)에 정리한다.
