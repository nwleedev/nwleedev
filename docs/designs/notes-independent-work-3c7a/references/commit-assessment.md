# 메모 앱 커밋별 소개 가치 평가

`apps/notes`는 Independent Work에 추가할 가치가 있다. 반복 지침 입력과 매개변수별 명령어 메모의 불편을 일괄 복사 및 템플릿으로 풀어낸 목적과 직접 정한 선택이 근거다. 커밋별 입력 및 저장 결함의 수정은 프론트엔드 문제 해결을 설명할 사례다. 평가는 **목적과 직접 정한 기여를 앞에 둔 추가 권고**다.

평가 대상은 [선정 요구사항](../requirements.md)의 개별 커밋이다. 이력 확인일은 2026년 10월 2일이며 기준 앱은 `a06bfc94c64232581742792a9834b82f5963f225`다. 앱 파일을 바꾼 커밋 18개 중 초기 5개는 통합 기록이다. 그 안의 중복을 제외한 175개는 앱 변경 111개와 설계 및 개발 지침 변경 64개로 구성된다. 나머지 13개와 합쳐 개별 변경 188개가 평가 대상이다.

아래는 현재 이력 18개의 판단이며 통합 전 175개의 판단은 [개별 변경 평가](squashed-history.md)에 있다. 기준은 사용자 동작과 저장 원문의 전후 차이, 이후에도 그 동작이 유지되는지다.

## 경쟁력을 설명할 수 있는 내용

### 텍스트를 보관한 뒤 조합하고 다시 사용하는 과업

여러 원문에서 필요한 텍스트를 고르고 순서를 바꿔 복사하는 과업이 앱의 차이다. 반복 문장을 템플릿으로 만들고 달라지는 부분만 입력하는 조작도 같은 목적에 연결된다. 근거인 `8ab8917`, `0c4d4ab`, `849b34e`와 `8cc7957`은 [초기 통합 커밋](https://github.com/nwleedev/nwleedev/commit/b9ae452)에 포함된다.

재사용할 대상은 AI 지침과 스킬 호출 문구, 입력 및 출력 파일만 바뀌는 Python 명령어다. 일괄 선택과 템플릿을 직접 정한 이유는 [사용 목적과 입력 문제](workflow-and-input.md)에 있다. 이 목적과 조작의 선택을 프로덕트 엔지니어 소개의 첫 근거로 삼는다.

### 편집 내용과 저장 원문의 불일치 해결

`266ec02`는 앞선 자동 저장이 끝나기 전에 추가 입력이 생겼을 때 최신 원문이 저장되지 않는 문제를 수정한다. `7291f47`은 모바일 연속 저장 누락과 숨은 데스크톱 편집기가 저장 버튼 전에 복구 초안을 원문으로 확정하는 문제를 수정한다. 최초 수정의 통합 이력은 각각 [b9ae452](https://github.com/nwleedev/nwleedev/commit/b9ae452)와 [bb14d8d](https://github.com/nwleedev/nwleedev/commit/bb14d8d)다. `41c3dd0`은 그 뒤 복구와 저장 자료 검사를 보강한 기록이다.

화면 원문과 실제 저장 원문을 비교해 연속 입력 및 화면 이동에서 생긴 결함을 재현하고 수정한 사례다. 소개할 내용은 두 동작이 겹칠 때 저장 의도를 보존한 판단이다.

### 실패한 단계와 이미 성공한 단계를 구분

`f811f3b`는 원문 저장 성공과 초안 제거 실패를 구분한다. `c784077`은 저장 형식 변경에서 기존 텍스트와 순서를 옮긴다. `cd1f749`는 일부 쓰기만 남거나 이전 연결의 늦은 완료가 최신 상태를 바꾸는 조건을 처리한다. 근거는 [초기 통합 이력](https://github.com/nwleedev/nwleedev/commit/b9ae452), [저장 처리](../../../../apps/notes/src/_pages/notes/model/save-note-content.ts)와 [실제 저장소 검사](../../../../apps/notes/src/_app/composition/indexed-db/personal-notes-database.indexeddb.test.ts)다.

같은 원문을 다시 저장할 때는 본문 버전을 유지하고 남은 초안만 정리한다. 이미 성공한 저장과 실패한 정리를 구분하고, 자료 이전에서 기존 원문을 보존한 판단이 소개할 내용이다.

### 여러 입력 방식이 같은 작업 결과를 내도록 조정

`e2e6f87`은 포인터, 키보드와 메뉴의 항목 순서 변경을 같은 삽입 규칙으로 맞추고 원문, ID와 포커스를 보존한다. `20bc777`은 포인터를 놓은 뒤에도 캔버스가 따라 움직이던 문제를, `16f088b`는 먼 좌표를 표시할 때 메모가 겹치던 문제를 수정한다. 근거는 [초기 통합 이력](https://github.com/nwleedev/nwleedev/commit/b9ae452)와 [후속 조작 수정](https://github.com/nwleedev/nwleedev/commit/41c3dd0)이다.

드래그 이력에는 시점 되돌림의 수정, WebKit 정상 입력을 취소하던 추정의 폐기와 브라우저 문서로 전달된 종료 처리의 보완이 있다. [원인과 수정 뒤 동작](workflow-and-input.md#드래그-문제의-원인과-해결한-결과)은 각 사례를 현재 앱에 연결한다. 메뉴와 직접 이동이라는 대안은 [W3C의 Dragging Movements 설명](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)과 대조할 수 있다.

### 검사가 실제 결함을 찾는지 확인

저장, 입력과 이탈 행동을 조합하고 실패 순서를 줄여 재현한 기록은 대표 문제 해결을 뒷받침한다. 특히 `7291f47`은 실제 앱에서 발견한 결함과 수정이 이어진다. `91b4be7`, `bfd6833` 등의 의도적인 저장 누락은 검사의 탐지 능력을 확인한 조건이며 발견한 앱 결함 수에 더하지 않는다.

화면과 저장소의 차이를 찾고, 테스트용 화면을 검사하던 코드를 실제 앱 검사로 바꾼 판단이 의미 있다. 회사 경력의 E2E 경험을 보충하는 저장 문제 해결의 근거로 설명한다. 세부 이력은 [개별 변경 평가](squashed-history.md)에 있다.

**보조 근거.** [커밋 원문](https://github.com/nwleedev/nwleedev/commit/10dfbb4)은 전달만 하던 구성요소를 줄이고 로딩, 실패와 빈 목록에서도 관리 화면의 폭을 일관되게 유지한다. 화면별 중복을 정리한 사례이나 유지보수 시간이나 변경 비용 감소를 확인한 성과는 아니다.

[당시 비교 기록](../../notes-architecture-refactor-4d8c/plan.md#u20-후속-변경의-사용자-동작과-의존-방향을-확인한다)에 성능 개선을 뒷받침할 결과는 없다. 표시 시간 중앙값은 오히려 늘었고 표본은 세 번이므로 성능 최적화 성과로 쓰지 않는다.

**기술 선택을 설명하는 보조 근거.** [커밋 원문](https://github.com/nwleedev/nwleedev/commit/6396efd)은 서로 무관한 작업을 한 객체로 연결한 구성을 나누며 공통 저장소 연결과 Worker 종료를 유지한다. 앱 전체의 의존성을 한곳에 모으지 않은 이유를 설명할 자료다. 변경 비용의 비교값은 없다.

### 5bed85c: 늦은 알림 종료와 검사 오류

**동시성 문제의 보조 근거.** [커밋 원문](https://github.com/nwleedev/nwleedev/commit/5bed85c)은 이전 알림의 타이머가 새 알림을 닫는 조건을 구분한다. 저장 완료 전에 판단하던 검사를 고치고 웹폰트 중복 레코드도 정리한다. 알림의 잘못된 종료를 해결한 부분과 검사 환경을 정비한 부분은 서로 다른 결과이며, 폰트 변경을 용량 최적화 성과로 제시하지 않는다.

### 10c7d91: 선택 작업과 알림의 유지 기간 결정

**설계 판단의 보조 근거.** [커밋 원문](https://github.com/nwleedev/nwleedev/commit/10c7d91)은 모바일 선택을 현재 실행으로 제한하고, 내부 이동에서는 같은 알림과 남은 시간을 유지하도록 정한다. 문서 변경 자체는 동작 완료의 근거가 아니며 `7048eaf`와 함께 설명한다. 저장할 자료와 일시적인 선택을 구분한 이유는 직접 확인할 필요가 있다.

### 7048eaf: 선택 초기화와 이동 중 알림 유지

**현재 동작을 설명할 후보.** [커밋 원문](https://github.com/nwleedev/nwleedev/commit/7048eaf)은 모바일 선택을 내부 이동에서 유지하고 새로고침과 취소에서는 초기화한다. 저장된 메모와 일괄 복사 목록은 유지하면서 이전 모바일 선택 저장소를 제거한다. 알림은 화면 이동에도 남은 시간을 유지하며 닫힌 알림이 되살아나지 않게 한다. 현재 작업, 저장 자료와 알림의 유지 기간을 과업에 맞게 판단한 사례다. 이 변경이 실제 사용 중 어떤 혼란을 줄였는지 확인하면 소개 가치가 높아진다.

## 선정 판단과 확인할 사실

저장 실패, 비동기 완료, 브라우저 입력과 자료 이전은 프론트엔드 문제 해결을 설명할 근거다. [당근 공고](https://careers.daangn.com/jobs/role/7689088003/)의 문제 판단 및 개선 경험과 [LINE Pay 공고](https://careers.linecorp.com/ko/jobs/3005/)의 웹 기본기 및 서비스 개발 요구에 연결할 수 있다.

소개할 목적과 직접 정한 선택은 확인됐다. 지침의 반복 입력과 매개변수별 명령어 메모 증가를 해결하려고 일괄 선택, 템플릿, 모바일 대안과 아이콘 제어 및 IndexedDB를 선택했다. 현재 앱의 조작과 드래그 및 저장 결함의 수정이 이 판단을 뒷받침한다.

- 가장 자주 하는 작업과 실제 이용 빈도.
- 모바일 문제를 겪은 기기와 동작, 이를 수정한 커밋.
- 개별 오류 분석과 코드 수정에서 직접 맡은 부분.
- 실제 사용 뒤 달라진 행동이나 측정값, 이를 확인할 기록과 비교 조건.

추가 정보가 없어도 확인된 문제 정의와 선택은 소개할 수 있다. 위 사실을 더 확인하면 개인 역할과 이용 성과를 구체화할 수 있다. 짧은 소개와 이력서 문구는 [종합 평가](assessment.md)에 있다. 이 평가의 기술 사례는 로컬 앱의 전후 동작에 한정되며 회사 운영, 조직 도입이나 앱 전체의 WCAG 준수를 입증하는 자료는 아니다.
