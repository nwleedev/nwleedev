# 개인 메모 앱의 Independent Work 소개 가치

`apps/notes`를 Independent Work에 추가할 것을 권고한다. 반복 입력과 늘어나는 명령어 메모의 원인을 직접 정리하고, 기존 내용을 재사용하는 해결 방향을 정한 경험이 근거다. 직접 사용하며 발견한 불편을 개선한 점까지 연결하면 사용자 문제를 발견하고 해결 방향을 구체화하는 역량을 보여줄 수 있다.

평가 기준은 [선정 요구사항](../requirements.md)이며 항목 추가와 소개 문구는 제안이다. 앱 근거는 `a06bfc94c64232581742792a9834b82f5963f225`와 그 이전 Git 기록이다. [커밋별 평가](commit-assessment.md)는 현재 이력 18개를, [통합 전 이력](squashed-history.md)은 중복을 제외한 앱 및 문서 변경 175개를 평가한다. [사용 목적과 입력 문제](workflow-and-input.md)는 2026년 10월 3일 확인한 제작 목적과 직접 정한 선택을 담는다. 실행 근거의 날짜와 대상은 [10월 2일 실행 기록](#2026년-10월-2일-확인한-실행-결과)에 있다.

## apps/entry의 역할과 개발 의도

`apps/entry`는 회사 경력을 중심으로 개발자의 판단과 성과를 전달하는 한국어 및 영어 한 페이지 소개 사이트다. 저장소 전체가 여러 미니 애플리케이션으로 프론트엔드 역량을 보여주려는 목적을 갖지만, entry의 첫 화면은 모든 앱을 나열하거나 실행하는 역할을 맡지 않는다. [사이트 요구사항의 역할과 정보 순서](../../developer-portfolio-f4b7/requirements.md)와 [현재 홈페이지](../../../../apps/entry/src/_pages/home/ui/HomePage.astro)에서 이 구분을 확인할 수 있다.

현재 소개는 서비스 문제의 원인을 찾고 사용자가 정보와 작업 상태를 정확히 확인하도록 개선한 경험을 전달한다. 회사 경력 다음에 Open Source와 Independent Work를 배치해 회사 밖의 경험을 보충한다. Independent Work는 제목, 기간, 설명과 선택적인 링크 및 기술 정보를 표시한다. 근거는 [한국어 소개 내용](../../../../apps/entry/src/shared/terms/ko.json)과 [Independent Work 구성](../../../../apps/entry/src/_pages/home/ui/IndependentWorkSection.astro)이다.

현재 두 항목은 AI Agent Workflow와 Offline Translation Web App이다. 전자는 저장소 규칙과 문구 검사, 후자는 네트워크 연결 없이 번역하는 브라우저 앱 경험을 설명한다. [첫 버전의 독립 작업 선정](../../developer-portfolio-f4b7/decisions/project-availability.md)은 새로운 항목이 기존 두 작업과 다른 판단 또는 확인 가능한 결과를 보태야 한다고 정한다.

당시 메모 앱은 개발 중인 목적과 기능만 확인돼 경력 중심 소개에서 우선순위가 낮았다. 지금은 실제 제작 목적과 직접 정한 선택, 사용하며 개선한 점을 연결할 수 있어 선정 근거가 구체화됐다.

## 소개할 가치가 있는 기여

### 반복 입력과 메모 증가의 원인을 정리한 판단

매번 새 문구나 메모를 만드는 부담을 줄이려고 기존 내용을 재사용하는 방향을 직접 정했다. AI 에이전트에 지침과 스킬 호출 문구를 반복해서 입력하는 일이 번거로웠고, 같은 Python 스크립트도 입력 및 출력 파일의 조합마다 명령어 메모를 따로 만들면 관리하기 어려웠기 때문이다.

반복해서 쓸 내용과 매번 달라지는 값을 구분한 판단이 이 프로젝트의 출발점이다. 일괄 복사와 템플릿은 그 판단을 실제로 쓸 수 있게 한 수단이다. 짧은 소개에서는 불편을 발견한 이유와 해결 방향을 정한 기여를 먼저 전달한다. 근거는 [직접 사용하면서 정의한 문제와 선택](workflow-and-input.md#직접-사용하면서-정의한-문제와-선택)과 [메모 재사용의 커밋 근거](commit-assessment.md#필요한-내용을-다시-쓸-수-있게-한-판단)다.

### 직접 사용하며 찾은 불편을 개선한 경험

실제 모바일 사용에서 발견한 화면 문제를 개선한 경험도 개인 기여로 소개할 수 있다. 익숙한 스티커 메모처럼 메모를 자유롭게 배치하되, 모바일에서는 화면 크기와 터치 입력에 맞는 사용 방법을 직접 정했다. AI가 만든 화면에서 아이콘을 선택하고 불필요한 텍스트 버튼을 줄인 판단도 이 경험에 포함된다.

이 사례는 사용할 기능을 정하는 데서 끝나지 않고 직접 쓰면서 개선할 점을 찾은 경험을 보여준다. [사용 목적과 화면 선택](workflow-and-input.md#직접-쓰면서-화면과-사용-방법을-개선한-기여)이 근거다. 기기별로 겪은 현상과 개별 수정 커밋의 연결은 추가 확인할 사실이다.

## 소개를 뒷받침하는 문제 해결 근거

저장 의도와 실제 원문이 어긋난 두 결함의 수정이 구체적인 기술 사례다. 모바일에서 다른 원문을 연속 저장하면 두 번째 입력이 저장되지 않던 문제와, 상세 화면을 여는 것만으로 저장 전 원문이 바뀌던 문제를 수정했다. 최초 수정 `7291f47`은 [bb14d8d](https://github.com/nwleedev/nwleedev/commit/bb14d8d)에 합쳐졌으며, [41c3dd0](https://github.com/nwleedev/nwleedev/commit/41c3dd0)은 복구와 저장 자료 확인을 보강했다. 상세 근거는 [저장 불일치 평가](commit-assessment.md#편집-내용과-저장-원문의-불일치-해결)에 있다.

마우스를 놓아도 화면이 계속 움직이거나 입력이 중단되면 시작 위치로 돌아가던 문제도 해결한 기록이 있다. 정상 WebKit 입력까지 취소한 조건은 폐기했다. [드래그 문제의 원인과 해결 결과](workflow-and-input.md#드래그-문제의-원인과-해결한-결과)는 브라우저에서 관찰한 현상을 근거로 해결책을 수정한 사례다.

이미 저장한 원문을 유지하고 실패한 초안 정리만 다시 시도한 판단, 저장 형식이 바뀌어도 이전 자료를 읽을 수 있게 한 판단은 [실패 단계와 성공 단계의 구분](commit-assessment.md#실패한-단계와-이미-성공한-단계를-구분)에서 확인할 수 있다. 이 기술 사례들은 소개한 판단을 뒷받침하며, 이력서나 면접에서 개인이 맡은 부분에 맞춰 보충할 내용이다.

Worker와 IndexedDB라는 기술 이름은 기존 번역 앱과 회사 경력에도 있다. 저장과 드래그 오류가 어떻게 달라졌는지가 이 앱이 보태는 근거다. [구조 변경 비교](../../notes-architecture-refactor-4d8c/plan.md)의 세 번 측정은 성능 개선을 입증하지 않으며, 렌더 횟수와 변경 비용의 감소도 확인되지 않았다.

## 2026년 10월 2일 확인한 실행 결과

운영 빌드 후 기존 사용자 시나리오 다섯 개를 Chromium, Firefox와 WebKit에서 실행해 15개 실행이 모두 통과했다.

- 모바일 상세 화면에서 계속 입력하고 저장한 뒤 화면을 떠날지 선택했을 때의 원문 보존.
- 복구 초안이 있는 목록에서 상세 화면을 열어도 저장 전 원문을 유지하는지 확인.
- 복구 초안을 저장한 뒤 초안 제거가 실패해도 다음 저장에서 정리되는지 확인.
- 분석을 요청한 뒤 실제 Worker가 실행돼 비교 후보를 표시하는지 확인.
- 분석 요청 직후 메모 화면으로 이동했을 때의 처리 확인.

근거 파일은 [메모 화면 E2E](../../../../apps/notes/e2e/notes.spec.ts), [분석 화면 E2E](../../../../apps/notes/e2e/analysis.spec.ts)와 [브라우저 실행 설정](../../../../apps/notes/playwright.config.ts)이다. 저장과 복구는 화면 입력을 실제 IndexedDB 원문과 비교했다. 초안 제거 실패는 검사에서 주입한 조건이다.

15개 통과는 로컬 운영 빌드의 위 다섯 시나리오에 한정된다. 과거 플랜의 전체 검사 건수와 실패 주입 기록은 각 당시의 확인 자료다. 실제 모바일 기기나 운영 성과의 측정으로 합산하지 않는다.

## Independent Work에 실을 문구 제안

소개 문구는 시작한 이유, 재사용을 선택한 판단과 직접 사용하며 개선한 점을 전달한다. [채용과 경험 서술 기준](hiring-and-writing.md#이-프로젝트에-적용할-서술-기준)에 따른 제안이다.

- 제목: `Personal Notes Workspace`
- 기간: `2026`
- 기술 정보: `TypeScript`, `React`, `Next.js`, `IndexedDB`
- 소스 링크: [평가한 버전의 메모 앱](https://github.com/nwleedev/nwleedev/tree/a06bfc94c64232581742792a9834b82f5963f225/apps/notes).

한국어 설명 제안:

> AI 에이전트에 지침을 매번 다시 입력하고, Python 실행 조건마다 명령어 메모를 따로 만드는 불편을 해결하려고 시작했습니다. 반복해서 쓸 내용과 매번 바뀌는 값을 구분해, 메모를 늘리는 대신 필요한 내용을 재사용하도록 기획했습니다. 모바일에서 직접 쓰며 발견한 불편을 바탕으로 화면 구성과 사용 방법을 개선했습니다.

영어 설명 제안:

> Started this personal project to address repeatedly entering instructions for AI agents and keeping a separate Python command note for each execution scenario. Chose to reuse existing notes rather than keep adding copies, distinguishing reusable text from values that change. Improved the layout and ease of use based on issues encountered while using it on mobile.

이력서에서는 직접 내린 판단을 먼저 적고, 지원할 직무에 맞는 문제 해결 사례를 보충한다. 개별 오류 분석과 코드 수정의 개인 역할은 확인된 만큼 덧붙인다.

- AI 지침을 반복해서 입력하고 실행 조건마다 명령어 메모가 늘어나는 불편을 정의하고, 기존 내용을 재사용하는 해결 방향을 선택한 경험.
- 익숙한 메모 사용 경험과 모바일에서 직접 겪은 불편을 바탕으로 화면 구성과 사용 방법을 개선한 기여.
- 저장 의도와 다른 원문이 남거나 마우스를 놓아도 화면이 계속 움직이던 문제를 해결한 프로젝트 사례. 상황과 달라진 점은 [커밋별 평가](commit-assessment.md)에 있다.

## 추가 여부를 결정하는 기준

기존 두 항목과 다른 판단을 보태므로 추가를 권고한다. AI Agent Workflow는 작업 규칙과 문구 검사를 설명한다. 메모 앱은 개인의 반복 입력과 메모 관리 문제에서 출발해 해결 방향을 정하고 직접 쓰며 개선한 경험을 보여준다. Offline Translation Web App과 겹치는 기술 이름보다 실제 불편을 찾고 개선한 사례가 선정 근거다.

이용자 증가, 시간 절감과 처리 성능의 측정값은 확인되지 않았다. 개인의 오류 분석 및 코드 수정 역할, 운영 중 이용자 자료를 이전한 경험과 앱 전체의 접근성 준수도 현재 근거로 확정할 수 없다. 이 평가는 확인된 문제 정의와 선택, 실제로 개선된 화면과 저장 결과에 근거한다.

메모의 로컬 저장과 LLM 없이 실행하는 텍스트 분석이 평가 대상이며, 계정 동기화나 웹앱 전체의 오프라인 실행은 포함하지 않는다. [메모 앱의 실행 조건](../../personal-notes-app-8fd/requirements.md#반드시-지킬-조건)이 그 기준이다.

소개를 더 구체화할 사실은 [커밋 평가의 추가 확인 사항](commit-assessment.md#선정-판단과-확인할-사실), 사이트 반영 절차는 [후속 적용 플랜](../plan.md#항목-추가를-선택할-때의-후속-적용안)에 있다.
