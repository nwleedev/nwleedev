# 개인 메모 앱의 Independent Work 소개 가치

`apps/notes`를 Independent Work에 추가할 것을 권고한다. 반복 입력하던 AI 작업 지침을 골라 복사하고, 매개변수마다 늘어나던 Python 명령어 메모를 템플릿으로 재사용하려고 만든 도구다. 직접 겪은 불편을 일괄 복사, 템플릿과 화면별 조작으로 풀어낸 판단이 소개의 중심이다. 브라우저 입력과 저장 결함을 수정한 사례가 프론트엔드 역량의 근거를 보탠다.

평가 기준은 [선정 요구사항](../requirements.md)이며 항목 추가와 소개 문구는 제안이다. 앱 근거는 `a06bfc94c64232581742792a9834b82f5963f225`와 그 이전 Git 기록이다. [커밋별 평가](commit-assessment.md)는 현재 이력 18개를, [통합 전 이력](squashed-history.md)은 중복을 제외한 앱 및 문서 변경 175개를 평가한다. [사용 목적과 입력 문제](workflow-and-input.md)는 2026년 10월 3일 확인한 제작 목적과 직접 정한 선택을 담는다. 실행 근거의 날짜와 대상은 [10월 2일 실행 기록](#2026년-10월-2일-확인한-실행-결과)에 있다.

## apps/entry의 역할과 개발 의도

`apps/entry`는 회사 경력을 중심으로 개발자의 판단과 성과를 전달하는 한국어 및 영어 한 페이지 소개 사이트다. 저장소 전체가 여러 미니 애플리케이션으로 프론트엔드 역량을 보여주려는 목적을 갖지만, entry의 첫 화면은 모든 앱을 나열하거나 실행하는 역할을 맡지 않는다. [사이트 요구사항의 역할과 정보 순서](../../developer-portfolio-f4b7/requirements.md)와 [현재 홈페이지](../../../../apps/entry/src/_pages/home/ui/HomePage.astro)에서 이 구분을 확인할 수 있다.

현재 소개는 서비스 문제의 원인을 찾고 사용자가 정보와 작업 상태를 정확히 확인하도록 개선한 경험을 전달한다. 회사 경력 다음에 Open Source와 Independent Work를 배치해 회사 밖의 경험을 보충한다. Independent Work는 제목, 기간, 설명과 선택적인 링크 및 기술 정보를 표시한다. 근거는 [한국어 소개 내용](../../../../apps/entry/src/shared/terms/ko.json)과 [Independent Work 구성](../../../../apps/entry/src/_pages/home/ui/IndependentWorkSection.astro)이다.

현재 두 항목은 AI Agent Workflow와 Offline Translation Web App이다. 전자는 저장소 규칙과 문구 검사, 후자는 네트워크 연결 없이 번역하는 브라우저 앱 경험을 설명한다. [첫 버전의 독립 작업 선정](../../developer-portfolio-f4b7/decisions/project-availability.md)은 새로운 항목이 기존 두 작업과 다른 판단 또는 확인 가능한 결과를 보태야 한다고 정한다.

당시 메모 앱은 개발 중인 목적과 기능만 확인돼 경력 중심 소개에서 우선순위가 낮았다. 지금은 실제 제작 목적, 직접 정한 선택과 저장 결함의 전후 동작을 연결할 수 있어 선정 근거가 구체화됐다.

## 반복 지침과 명령어를 다시 사용하는 목적

필요한 지침을 골라 함께 복사하고, 명령어의 바뀌는 부분만 입력하는 템플릿을 직접 선택했다. AI 작업의 제한과 스킬 호출 문구를 반복해서 입력하는 일이 번거로웠고, Python 스크립트의 입력 및 출력 파일 조합마다 명령어 메모가 늘어났기 때문이다. 근거는 [사용 경험과 회고](workflow-and-input.md#직접-사용하면서-정의한-문제와-선택)에 있다.

스티커 메모의 익숙한 자유 배치와 크기 변경, 캔버스 시점 이동을 제공하고 모바일에는 별도의 선택 및 확인 조작을 정했다. [메모 앱의 의도한 결과](../../personal-notes-app-8fd/requirements.md#의도한-결과)와 현재 앱에서 이 선택을 확인할 수 있다.

`apps/notes`는 이 저장소 안에서 독립 실행하는 앱이다. [실행 조건](../../personal-notes-app-8fd/requirements.md#반드시-지킬-조건)은 브라우저의 로컬 처리와 웹앱을 제공하는 서버를 구분한다. 메모의 로컬 저장과 LLM 없이 실행하는 텍스트 분석이 현재 평가 대상이며, 계정 동기화나 웹앱 전체의 오프라인 실행은 포함하지 않는다.

## 앞에 둘 성과와 기여

### 텍스트 재사용 과업을 화면과 저장 규칙으로 연결

반복 지침과 명령어 관리의 불편을 일괄 복사와 템플릿으로 해결하려 한 판단을 먼저 소개한다. 넓은 화면에서는 원문 메모와 작업 사본을 나란히 확인하고, 모바일에서는 선택, 순서 편집과 복사를 이어간다. 작업 사본을 편집해도 원본 메모는 유지한다. 명령어는 고정된 부분과 입력값을 나눈 템플릿으로 재사용한다.

직접 정한 기여는 문제 정의, 일괄 선택과 템플릿, 화면별 조작 및 IndexedDB 선택이다. AI가 만든 화면에서 불필요한 텍스트 버튼을 줄인 판단도 포함된다. [사용 경험](workflow-and-input.md)은 이 선택의 근거이며, [커밋별 텍스트 재사용 평가](commit-assessment.md#텍스트를-보관한-뒤-조합하고-다시-사용하는-과업)는 구현된 동작을 연결한다.

### 모바일 저장 누락과 저장 전 원문 변경 해결

사용자의 저장 의도와 실제 원문을 맞춘 두 결함 수정이 가장 구체적인 기술 사례다. 첫 저장 뒤 다른 원문을 입력해 다시 저장하면 화면과 저장소의 내용이 달라지던 문제를 수정했다. 복구 초안이 있는 모바일 목록에서 상세 화면으로 이동하는 것만으로 저장 전 원문이 바뀌던 문제도 수정됐다.

결함의 발생 동작과 수정 뒤 상태는 [모바일 명시적 저장과 이탈 기록](../../personal-notes-app-8fd/plan.md#모바일-명시적-저장과-이탈)에 있다. 최초 수정 `7291f47`은 [bb14d8d](https://github.com/nwleedev/nwleedev/commit/bb14d8d)에 합쳐졌으며, [41c3dd0](https://github.com/nwleedev/nwleedev/commit/41c3dd0)은 복구와 저장 자료 확인을 보강했다.

현재 [상세 편집 처리](../../../../apps/notes/src/_pages/notes/model/use-note-detail-editing.ts), [화면 선택](../../../../apps/notes/src/_pages/notes/ui/notes-collection.tsx)과 [화면 및 저장소 비교 검사](../../../../apps/notes/e2e/notes.spec.ts)에서 수정된 동작을 확인할 수 있다.

회사의 인증 및 주요 절차 E2E 경험과 검사 도구 사용은 겹친다. 메모 앱이 보태는 내용은 브라우저에 저장한 원문, 복구 초안과 화면 전환이 함께 동작할 때 생긴 실제 결함을 해결한 사례다. 입력한 원문이 의도대로 저장되는지 확인한 사례로 설명하면 기존 소개를 보충한다.

### 복구 초안과 정리 실패 후 재시도

실패한 단계만 다시 시도하고 이미 저장한 원문은 유지하는 판단을 소개할 수 있다. 메모 저장에 실패하면 복구 초안을 남긴다. 메모 저장은 성공했지만 초안 제거만 실패하면 원문을 유지하고 다음 저장에서 정리를 다시 시도한다.

근거는 [초안 제거 재시도 결정](../../personal-notes-app-8fd/decisions/note-draft-cleanup-retry.md), [초안 복구와 제거 재시도의 검사 기록](../../personal-notes-app-8fd/plan.md#초안-복구와-제거-재시도)과 [현재 저장 처리](../../../../apps/notes/src/_pages/notes/model/save-note-content.ts)다. 저장 실패 뒤 화면을 다시 열어 복구한 동작은 실패를 주입한 Browser Mode 검사에서 확인했다.

### 화면과 입력 방식에 맞는 메모 작업

캔버스 이동 중 입력이 중단되면 화면이 시작 위치로 돌아가거나, 마우스를 놓아도 화면이 계속 움직이는 문제를 해결한 기록이 있다. 종료를 추정한 조건이 WebKit의 정상 드래그까지 끊는 것을 확인하고 그 조건을 폐기한 판단도 있다. 근거는 [드래그 문제의 원인과 해결 결과](workflow-and-input.md#드래그-문제의-원인과-해결한-결과)다. 이 사례는 브라우저의 실제 입력을 근거로 해결책을 수정하는 역량을 보여준다.

포인터, 키보드와 메뉴로 순서를 바꿔도 원문, 항목 ID와 포커스를 유지한다. 직접 이동 버튼은 설정으로 선택할 수 있으며 모바일은 항목 동작을 별도 시트로 제공한다. 실제 모바일 사용 경험은 확인됐고, 기기별로 겪은 현상과 수정 커밋의 연결은 추가 확인할 사실이다.

### 분석과 구조 개선의 위치

분석에서는 외부 LLM 없이 줄의 일치, 포함 관계와 문자열 조각의 겹침을 비교한다. [분석 처리](../../../../apps/notes/src/_pages/analysis/model/analyze-text.ts)와 [Worker 연결](../../../../apps/notes/src/_pages/analysis/api/worker-text-analyzer.ts)은 잘못된 원문이나 오래된 요청의 비교값을 표시하지 않는 조건을 설명할 근거다.

Worker와 IndexedDB는 번역 앱과 회사 경력에도 등장하므로 이 앱에서는 실패와 입력 중단을 판단한 사례를 우선한다. 작업별 외부 동작을 분리한 구조 정리는 유지보수 판단을 설명할 면접 자료다. [구조 변경 비교](../../notes-architecture-refactor-4d8c/plan.md)의 세 번 측정은 성능 개선을 입증하지 않으며, 렌더 횟수와 변경 비용의 감소도 확인되지 않았다.

## 2026년 10월 2일 확인한 실행 결과

운영 빌드 후 기존 사용자 시나리오 다섯 개를 Chromium, Firefox와 WebKit에서 실행해 15개 실행이 모두 통과했다.

- 모바일 상세 화면에서 연속 입력 및 저장과 이탈 선택을 조합하는 동작.
- 복구 초안이 있는 목록에서 상세 화면을 열어도 저장 전 원문을 유지하는 동작.
- 복구 초안을 저장하고 초안 제거 실패를 다음 저장에서 정리하는 동작.
- 명시적으로 분석을 요청한 뒤 실제 Worker 자산을 실행해 분석 후보를 표시하는 동작.
- 분석 요청 직후 메모 화면으로 이동하는 동작.

근거 파일은 [메모 화면 E2E](../../../../apps/notes/e2e/notes.spec.ts), [분석 화면 E2E](../../../../apps/notes/e2e/analysis.spec.ts)와 [브라우저 실행 설정](../../../../apps/notes/playwright.config.ts)이다. 저장과 복구는 화면 입력을 실제 IndexedDB 원문과 비교했다. 초안 제거 실패는 검사에서 주입한 조건이다.

15개 통과는 로컬 운영 빌드의 위 다섯 시나리오에 한정된다. 과거 플랜의 전체 검사 건수와 실패 주입 기록은 각 당시의 확인 자료다. 실제 모바일 기기나 운영 성과의 측정으로 합산하지 않는다.

## Independent Work에 실을 문구 제안

소개 문구는 반복 지침과 명령어 메모의 불편을 일괄 복사와 템플릿으로 해결하려 한 판단을 담는다. [채용과 경험 서술 기준](hiring-and-writing.md#이-프로젝트에-적용할-서술-기준)에 따른 제안이다.

- 제목: `Personal Notes Workspace`
- 기간: `2026`
- 기술 정보: `TypeScript`, `React`, `Next.js`, `IndexedDB`
- 소스 링크: [평가한 버전의 메모 앱](https://github.com/nwleedev/nwleedev/tree/a06bfc94c64232581742792a9834b82f5963f225/apps/notes).

한국어 설명 제안:

> AI 작업 지침을 매번 입력하고 매개변수마다 명령어 메모가 늘어나는 불편을 해결하려고 텍스트 재사용 도구를 설계했습니다. 필요한 지침을 골라 함께 복사하고, 명령어에서 바뀌는 부분만 입력하는 템플릿을 제공합니다. 데스크톱과 모바일에 맞는 조작을 정하고 실제 사용에서 발견한 화면 문제를 조정했습니다.

영어 설명 제안:

> Designed a text reuse tool to avoid repeatedly typing AI task instructions and maintaining separate command notes for each parameter combination. It combines selected instructions for copying and generates command text from reusable templates with variable inputs. Defined separate desktop and mobile interactions and refined the interface through personal use.

이력서에서는 지원할 직무에 맞는 사례를 고른다. 첫 두 후보는 직접 정의한 목적과 기능 선택이며, 나머지는 프로젝트의 기술 사례다. 개별 오류 분석과 코드 수정의 개인 역할은 확인된 만큼 덧붙인다.

- 반복 입력하던 AI 작업 지침과 스킬 호출 문구를 필요한 조합으로 선택하고 한 번에 복사하는 도구 설계. 스티커 메모에 익숙한 자유 배치와 모바일 선택 및 확인 조작을 과업에 맞게 정의.
- 입력 및 출력 파일 조합마다 늘어나는 Python 명령어 메모를 고정 문장과 입력값으로 나눈 템플릿 정의.
- 캔버스 시점이 중단 뒤 되돌아가거나 종료 뒤 계속 움직이는 문제 수정. WebKit에서 정상 입력까지 취소하던 종료 조건을 폐기하고 마지막 시점을 유지하도록 조정한 프로젝트 사례.
- 모바일에서 서로 다른 원문을 연속 저장할 때 두 번째 입력이 저장되지 않던 문제와, 상세 화면 이동만으로 복구 초안이 원문에 반영되던 문제를 수정. 실제 화면과 저장소의 원문을 비교하는 시나리오를 브라우저 3종에서 확인.
- 메모 저장 성공 후 초안 제거만 실패하는 상황에서 원문을 유지하고 다음 저장으로 정리를 재시도하는 동작 제공. 저장 실패 후 복구는 실패를 주입한 브라우저 검사에서 확인.
- 저장 형식 변경에서 기존 텍스트 순서, 사용 기록과 설정을 이전하고 저장소를 다시 열어 보존 여부를 확인하는 검사 제공.

## 추가 여부를 결정하는 기준

기존 두 항목과 다른 판단을 보태므로 추가를 권고한다. AI Agent Workflow는 작업 규칙과 문구 검사를 설명한다. 메모 앱은 필요한 지침을 골라 조합하고 명령어의 입력값을 바꾸는 도구를 만든 판단을 보여준다. Offline Translation Web App과 겹치는 기술 이름보다 드래그와 저장 결함의 전후 동작을 근거로 붙인다.

이용자 증가, 시간 절감과 처리 성능의 측정값은 확인되지 않았다. 개인의 오류 분석 및 코드 수정 역할, 운영 중 이용자 자료를 이전한 경험과 앱 전체의 접근성 준수도 현재 근거로 확정할 수 없다. 이 평가는 확인된 문제 정의와 기능 선택, 앱의 수정된 동작에 근거한다.

소개를 더 구체화할 사실은 [커밋 평가의 추가 확인 사항](commit-assessment.md#선정-판단과-확인할-사실), 사이트 반영 절차는 [후속 적용 플랜](../plan.md#항목-추가를-선택할-때의-후속-적용안)에 있다.
