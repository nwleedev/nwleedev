# 반복 텍스트 재사용의 목적과 입력 문제 해결

`apps/notes`는 반복되는 AI 작업 지침과 명령어를 다시 입력하고 관리하던 불편을 해결하려고 만든 개인 도구다. 필요한 문구를 선택해 조합하는 일괄 복사와, 명령어의 바뀌는 부분만 입력하는 템플릿이 같은 목적에 연결된다. 이 목적과 직접 선택한 조작 방식은 Independent Work에 추가할 근거가 된다. 드래그의 정상 완료와 중단을 구분한 사례는 이를 뒷받침하는 프론트엔드 문제 해결이다.

이 자료는 [선정 요구사항](../requirements.md)의 목적, 기여와 문제 해결 평가를 뒷받침한다. 제작 목적과 선택은 개발자의 사용 경험 및 회고로 확인했으며 이 자료의 확인일은 2026년 10월 3일이다. 구현 근거는 `a06bfc94c64232581742792a9834b82f5963f225`의 앱과 그 이전 변경이다. 직접 정한 요구와 구현된 동작을 구분하며, 개별 코드 작성이나 오류 분석의 담당까지 회고에서 확인한 것은 아니다.

## 직접 사용하면서 정의한 문제와 선택

### 반복 지침과 스킬 호출 문구의 선택 및 조합

AI 에이전트로 작업할 때 작업 단계에 맞는 제한과 스킬 호출 문구를 반복해서 입력해야 했다. 지침 파일에 적은 내용만으로 의도한 작업을 이어가기 어려운 경우가 있어, 필요한 문구를 매번 다시 입력하는 일이 번거로웠다. 해결할 과업은 여러 지침을 보관하고 이번 작업에 필요한 것만 골라 한 번에 복사하는 것이다.

사용하던 macOS 스티커 메모에서는 여러 문구를 편리하게 골라 함께 복사하는 작업이 불편했다. 익숙한 메모 배치와 크기 변경은 유지하고, 보조 키를 누른 채 메모를 선택해 일괄 복사에 모으는 방식을 직접 정했다. [Apple의 스티커 메모 안내](https://support.apple.com/guide/stickies/welcome/mac)는 메모 배치와 크기 변경을 설명한다. 기존 조작의 익숙함과 직접 겪은 복사 과업의 불편을 함께 고려한 선택이다.

`0c4d4ab`의 메모 선택과 복사, `849b34e`의 작업 사본 편집이 [초기 통합 이력](https://github.com/nwleedev/nwleedev/commit/b9ae452)에 포함된다. 현재 [일괄 복사 화면](../../../../apps/notes/src/features/edit-batch-copy/ui/batch-copy-list.tsx)은 모은 원문의 순서를 편집하고 함께 복사하는 과업을 제공한다. 필요한 지침을 선택하고 조합하는 동작이 확인된 결과다.

### 매개변수 때문에 늘어나던 명령어 메모

업무에서 같은 Python 스크립트를 입력 파일과 출력 파일 등의 매개변수만 바꿔 실행했다. 조합마다 명령어 메모가 늘어나 관리가 어려웠으므로, 고정된 명령어와 바뀌는 부분을 나누고 필요한 값만 입력하는 템플릿을 직접 선택했다.

`8cc7957`의 구현은 [초기 통합 이력](https://github.com/nwleedev/nwleedev/commit/b9ae452)에 포함된다. 현재 [템플릿 편집](../../../../apps/notes/src/entities/template/model/edit-segments.ts)과 [문장 생성](../../../../apps/notes/src/entities/template/model/render-template.ts)은 원문의 특정 부분을 입력 항목으로 바꾸고 새 값으로 문장을 만든다. 반복해서 보관하던 명령어를 템플릿과 입력값으로 나눈 판단이 소개의 근거다. 확인된 기능은 명령어 문장의 생성이다.

### 화면과 조작을 실제 과업에 맞게 정한 기여

직접 정한 내용은 자유로운 메모 위치와 크기, 캔버스 시점 이동, 모바일의 대체 조작, 아이콘 사용과 불필요한 상시 텍스트 버튼의 정비다. AI가 만든 화면에서도 텍스트를 선택하고 읽는 과업에 맞는 제어를 판단한 경험으로 설명할 수 있다.

현재 일괄 복사 항목은 이동 핸들과 더보기를 사용한다. 직접 위아래 이동은 설정을 켰을 때 실행 가능한 방향만 제공하며, 모바일은 항목 동작을 아래에서 열리는 시트로 제공한다. 근거는 [작업 화면 결정](../../personal-notes-app-8fd/decisions/focused-text-utility-workspace.md)과 [모바일 시트 결정](../../personal-notes-app-8fd/decisions/mobile-batch-copy-action-sheet-dismissal.md)다.

상시 텍스트 제어를 줄이면서 드래그 외의 조작을 남겼다. [W3C의 Dragging Movements 설명](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)은 드래그 없이 같은 일을 할 수 있는 단일 포인터 대안을 요구하며 키보드 조작과 구분한다. 모바일에서도 터치 드래그를 제공한다. 선택, 확인과 항목 동작을 화면 및 입력 방식에 맞게 나눈 결과로 설명한다.

실제 모바일 기기에서 사용하며 UI 문제를 조정한 경험도 확인됐다. 이력에는 화면 높이가 줄 때 목록과 제어가 가려지는 문제, 바깥 스크롤과 좁은 팝오버를 다룬 변경이 있다. [모바일 통합 이력](https://github.com/nwleedev/nwleedev/commit/bb14d8d)과 [스크롤 후속 이력](https://github.com/nwleedev/nwleedev/commit/41c3dd0)은 그 변경의 근거다. 어떤 기기에서 관찰한 문제가 어떤 변경으로 해결됐는지는 추가로 확인할 수 있으며, 모든 브라우저 검사를 실제 기기 확인으로 바꾸지 않는다.

## 드래그 문제의 원인과 해결한 결과

### 이미 이동한 화면이 시작 위치로 돌아감

이동을 끝내거나 중단한 뒤에도 마지막으로 본 캔버스 시점을 유지하도록 수정했다. 이전에는 입력 중단을 메모 이동의 취소와 같은 방식으로 취급해 화면까지 시작 시점으로 되돌렸다. 캔버스를 보는 위치와 메모 자체의 저장 위치는 다른 의미이므로 취소 결과도 구분해야 했다.

`ff4faa7`에서 시작 시점으로 되돌리는 처리를 제거했다. `366136b`는 창과 문서의 비활성화 및 다음 입력에서 남은 이동을 정리해 이전 시작점이 다시 쓰이지 않게 했다. 둘은 [초기 통합 이력](https://github.com/nwleedev/nwleedev/commit/b9ae452)에 포함된다. 현재 [캔버스 시점 처리](../../../../apps/notes/src/_pages/notes/model/use-notes-board-view.ts)는 중단된 입력을 끝내면서 표시된 시점은 유지한다.

### 종료를 추정하는 조건이 정상 드래그까지 중단

WebKit에서 정상 드래그를 끊던 종료 추정을 폐기하고, 실제 입력의 종료와 비활성화를 구분하도록 판단을 수정했다. 당시 비교에서는 버튼 및 압력 값을 이용한 조건과 창 포커스만 이용한 조건이 정상적인 첫 마우스 입력까지 취소했다.

`9f47ba8`과 `e226224`는 그 선택을 바로잡은 문서 변경이며 자체가 구현 완료의 근거는 아니다. [당시 입력 결정](../../personal-notes-app-8fd/decisions/note-selection-and-properties.md)과 현재 [캔버스 시점 처리](../../../../apps/notes/src/_pages/notes/model/use-notes-board-view.ts)를 함께 근거로 삼는다. 특정 속성이 항상 종료를 뜻한다고 가정하지 않고 실제 브라우저 동작을 근거로 선택을 바꾼 사례다.

[W3C Pointer Events Level 3](https://www.w3.org/TR/pointerevents3/)는 입력 종료, 취소와 캡처 상실을 구분하며 정상 종료 뒤 캡처가 자동 해제되는 순서도 설명한다. 이 표준은 종료와 캡처 해제를 같은 실패로 취급하지 않을 근거다. WebKit의 정상 입력 중단은 저장소에 기록된 당시의 관찰이다. 확인한 표준 문서는 2026년 6월 30일 Recommendation이다.

### 마우스를 놓아도 캔버스가 계속 움직임

캡처 대상이 바뀐 뒤 종료 입력이 문서에 도착하면 캔버스에 이동 상태가 남아, 다음 마우스 이동에서도 화면이 따라 움직이는 문제를 수정했다. 정상적으로 놓은 입력이 다음 조작으로 이어지지 않게 종료를 확인할 대상을 보완했다.

최초 수정 `20bc777`은 [후속 조작 통합 이력](https://github.com/nwleedev/nwleedev/commit/41c3dd0)에 포함된다. 현재 [시점 처리](../../../../apps/notes/src/_pages/notes/model/use-notes-board-view.ts)와 [캔버스 검사](../../../../apps/notes/e2e/notes.spec.ts)는 문서에 전달된 종료 입력을 처리하는 동작의 근거다. 화면 이동, 정상 종료와 입력 중단을 구분해 다음 조작을 보존한 사례로 소개할 수 있다.

## 저장 구조 변경을 고려한 기술 선택

개발 중 메모와 관련 자료의 구조가 바뀔 것을 고려해 IndexedDB를 직접 선택했다. 소개할 내용은 저장 API의 이름보다, 구조가 바뀌어도 기존 텍스트와 기록을 이어서 읽는 조건을 다룬 판단이다.

[MDN의 IndexedDB 사용 안내](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Using_IndexedDB)는 버전 변경에서 저장 구조를 바꾸고 이전 자료를 보존할 필요를 설명한다. 현재 [저장소 버전 처리](../../../../apps/notes/src/_app/composition/indexed-db/open-personal-notes-database.ts)와 [자료 이전](../../../../apps/notes/src/_app/composition/indexed-db/migrate-personal-notes-database.ts)은 기존 메모, 사용 기록과 설정을 이전하는 근거다. `c784077`은 [초기 통합 이력](https://github.com/nwleedev/nwleedev/commit/b9ae452)에 포함된다. 소개에서는 기술 선택을 이 자료 보존의 동작에 연결한다.

## 소개에 남길 판단

직접 정의한 불편과 기능 및 입력 방식의 선택은 개인 기여로 확인됐다. 앱에서 확인되는 텍스트 선택과 조합, 매개변수만 바꾸는 문장 생성은 그 선택의 결과다. 브라우저 입력과 저장 결함의 수정은 기술적 근거로 연결한다. 이용 빈도, 시간 절감과 개별 수정의 직접 담당은 확인되지 않았으므로 수치나 역할을 추가하지 않는다.

기존 AI Agent Workflow 항목은 작업 규칙과 문구 검사를 설명한다. 메모 앱에는 그 규칙을 작성한 이야기를 반복하기보다, 필요한 지침을 골라 조합하고 명령어의 입력값을 바꾸는 도구를 만든 목적을 남긴다. [종합 평가와 소개안](assessment.md)은 이 차이를 기준으로 추가를 권고한다.
