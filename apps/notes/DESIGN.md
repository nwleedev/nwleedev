# 개인 메모 디자인 체계

개인 메모는 자주 쓰는 텍스트를 빠르게 기록하고, 찾아서 복사하며, 순서대로 모아 재사용하는 작업 화면이다. 본문이 장식과 관리 제어보다 먼저 보여야 하며 복사는 숨은 제스처나 더보기 안에만 두지 않는다.

이 문서는 구현에 적용할 UI 규칙을 관리한다. 사용자 동작과 자료 규칙은 [요구사항](../../docs/designs/personal-notes-app-8fd/requirements.md), 시각 방향은 [텍스트 재사용 작업 화면 결정](../../docs/designs/personal-notes-app-8fd/decisions/focused-text-utility-workspace.md), 조작 수명은 [조작 피드백과 실패 복구 결정](../../docs/designs/personal-notes-app-8fd/decisions/interaction-feedback-and-recovery.md)을 따른다.

[디자인 근거](../../docs/designs/personal-notes-app-8fd/references/focused-text-utility-design-system-research.md)와 [상용 수준의 조작 경험 조사](../../docs/designs/personal-notes-app-8fd/references/commercial-service-ux-research.md)는 공식 자료와 현재 구현에서 확인한 차이를 기록한다.

## 시각 원칙

- 본문을 가장 높은 시각 우선순위에 둔다. 배경, 선, toolbar와 그림자가 본문보다 먼저 보이지 않아야 한다.
- 복사 동작은 넓은 화면의 메모에서 바로 찾을 수 있어야 한다. 좁은 목록에서는 메모 전체를 누르는 기본 동작으로 복사하고, `Command+클릭`과 길게 누르기는 해당 화면의 빠른 조작으로 유지한다.
- 속성, 앞뒤 겹침 순서, 삭제, 복제와 재정렬 대안은 더보기 또는 현재 작업에 필요한 위치에서 제공한다.
- 이동 가능한 대상은 명시적인 핸들을 사용한다. 편집 가능한 본문과 항목 전체를 drag 시작 영역으로 사용하지 않는다.
- 동작 결과는 짧게 알린다. 화면 구조와 실행 과정을 설명하는 안내 문장을 계속 표시하지 않는다.
- hover, `focus-visible`, selection, dragging과 error가 생긴 때에 필요한 제어와 상태를 드러낸다. hover가 없는 환경에서는 실행에 필요한 제어를 항상 제공한다.
- pointer 화면은 조밀하게, touch 화면은 편안한 조작 영역으로 만든다. 아이콘 크기와 조작 영역 크기를 같은 값으로 취급하지 않는다.

## 색과 표면

- 브랜드 accent는 `#EE5165`다. 주요 동작, 현재 탐색 위치, 선택, 포커스, 삽입선과 짧은 상태 확인에 제한해 사용한다.
- `#EE5165` 위 흰색 일반 문구는 사용하지 않는다. foreground는 실제 계산 색으로 일반 문구 대비 `4.5:1` 이상을 확인한 조합만 사용한다.
- 토큰은 canvas, surface, text, icon, border, accent, focus, selection, danger, success와 warning 역할로 이름을 정한다. `note`, `note-header`, `wood`, `rail` 같은 물체 이름을 색 체계의 중심으로 사용하지 않는다.
- 배경은 따뜻한 중립색, 캔버스는 낮은 대비의 중립색, 메모와 입력은 흰색에 가까운 표면을 사용한다. 목재, 종이, 노란 sticky note, 장식용 grid와 넓은 gradient를 사용하지 않는다.
- 기본 화면, 캔버스, 메모, 목록, 입력과 고정 panel은 flat이다. drag 중인 대상만 raised, popover, toast와 dialog는 overlay 깊이를 사용한다.

## 글자와 간격

- Pretendard Variable 한 계열을 사용한다. 기본 본문은 400, UI 강조는 500, 제목과 강한 label은 600을 우선한다.
- 메모 본문은 일반 UI label보다 크게 보이거나 더 넉넉한 줄 높이를 사용해 텍스트가 대상의 중심임을 드러낸다.
- 간격은 4px 리듬을 기본으로 한다. 2, 6, 10px은 반복되는 아이콘 및 글자 정렬 보정에만 사용한다.
- pointer 아이콘 제어는 `24 × 24 CSS px` 이상의 조작 영역 또는 WCAG 간격 예외를 충족한다. touch 아이콘 제어는 약 `44px` 조작 영역을 기본 후보로 검증한다.
- 선은 app shell, panel, input, 독립된 대상과 overlay를 구분해야 할 때만 사용한다. 간격과 정렬로 충분한 section에 선을 추가하지 않는다.
- 모서리는 control, note object, floating surface와 pill 역할로 구분한다. pill은 count나 상태처럼 형태 자체가 뜻을 전달할 때만 사용한다.

## 상태와 motion

- focus는 현재 키보드 조작 위치, selection은 현재 선택한 대상, properties target은 속성 panel이 참조하는 대상이다. 세 상태를 같은 선이나 색 하나로 표현하지 않는다.
- `focus-visible`은 2 CSS px 둘레에 해당하는 면적과 충분한 대비를 갖는 일관된 표시를 사용한다. `forced-colors`에서도 포커스와 선택을 구분한다.
- motion은 hover, pressed, 선택 변화, popover, toast, drag lift와 재정렬 관계를 설명할 때만 사용한다.
- 페이지 전환, section 등장, 배경, 저장 성공과 반복 장식에는 motion을 사용하지 않는다. `prefers-reduced-motion`에서 비필수 transition을 제거한다.
- 비동기 동작은 시작, 진행, 완료와 복구 상태를 구분한다. 화면을 먼저 갱신하는 동작은 저장 실패에서 입력 전 자료, 선택과 포커스를 되돌릴 수 있을 때만 사용한다.

## 애플리케이션과 메모 화면

- 넓은 화면에서는 application bar 아래의 나머지 영역을 메모 캔버스로 사용한다. 별도 페이지 제목, 메모 수와 안내 banner를 표시하지 않는다.
- 좁은 화면에서는 메모 목록과 상세 화면에 한 줄의 주 헤더만 둔다. 메모 목록과 보조 화면에서 다른 주요 화면으로 이동할 때는 Drawer를 사용하고, 상세 및 일괄 복사 화면에는 Drawer를 표시하지 않는다.
- 모든 route에 적용하는 공통 프레임을 사용하지 않는다. 넓은 메모 보드, 좁은 목록, 상세 편집, 일괄 복사 작업과 보조 화면은 각자 필요한 헤더, 탐색, 스크롤과 하단 동작을 갖는다. 같은 역할의 구성만 재사용한다.
- 넓은 화면 메모의 왼쪽 위에는 이동 핸들, 오른쪽 위에는 복사와 더보기를 둔다. 본문은 별도 편집 및 완료 상태 없이 계속 편집하고 자동 저장한다.
- 더보기는 속성, 맨 앞으로, 맨 뒤로와 삭제를 제공한다. 기본 상태에서 네 동작을 모두 나열하지 않는다.
- 기본 메모에는 강한 그림자를 사용하지 않는다. hover는 조작 가능성을 조금 높이고, selection과 `focus-visible`은 서로 구분한다. dragging에서만 메모를 raised 상태로 바꾼다.
- 좁은 화면 메모 미리보기는 본문만 제한된 줄로 자른다. 제목, emoji, icon, 별도 헤더와 `내용 더 있음` badge를 추가하지 않는다.
- 좁은 화면에서 메모를 누르면 즉시 복사하고 수정 아이콘 버튼을 누르면 상세 화면으로 이동한다. 길게 누르기도 복사하며 뒤따르는 click은 중복 복사하거나 상세 이동을 실행하지 않는다. 일괄 복사 수집 상태에서는 각 메모의 개별 복사 아이콘을 표시하지 않고, 메모를 누르면 클립보드에 쓰지 않은 채 현재 작업에 추가한다.
- 평상시 좁은 메모 목록에서만 새 메모 아이콘 버튼을 화면 우측 하단에 둔다. 저장된 일괄 복사 항목 수 링크는 메모 목록 Drawer의 주요 화면 링크 아래에 구분해 표시하고, 일괄 복사 수집 상태의 하단 동작과 충돌하지 않게 한다. 저장된 항목이 없으면 Drawer 링크를 표시하지 않는다.
- 상세 화면은 전체 본문 편집을 중심에 두고 editor를 다시 카드나 panel로 감싸지 않는다. 명시적 저장과 저장하지 않은 변경 이탈 확인을 유지한다.

## 일괄 복사

- 일괄 복사는 정렬 가능한 텍스트 모음이다. 평상시 drop zone, 삽입선과 drag 안내 문구를 표시하지 않는다.
- 각 항목 왼쪽에는 이동 핸들, 오른쪽에는 더보기를 둔다. 더보기는 복제와 삭제를 제공하고, 설정에서 직접 이동을 켠 경우에만 가능한 위쪽 또는 아래쪽 한 자리 이동을 추가한다.
- drag가 시작되면 미리보기와 raised 깊이를 제공하고 원래 위치를 이해할 수 있게 한다. 실제 결과가 생기는 앞뒤 위치에만 삽입선을 표시한다.
- 목록 가장자리에서는 현재 목록을 자동으로 scroll한다. 유효하지 않은 놓기, scroll 취소, `pointercancel`과 완료 전 `lostpointercapture`에서는 순서를 바꾸지 않는다.
- 놓은 뒤 선택한 항목을 삽입 위치로 이동하고 사이 항목을 한 자리씩 밀어낸 결과를 즉시 화면에 반영한다. 저장 실패 시 이전 순서, 선택과 포커스를 복원하고 다시 시도할 동작을 제공한다.
- drag를 사용하지 않는 위치 이동과 keyboard 조작도 같은 재정렬 명령을 사용한다. 이동 뒤 같은 항목에 포커스를 유지하고 항목 이름과 새 위치를 live region으로 알린다. 원본 메모, 원문 스냅샷, 항목 ID와 사용 횟수는 바꾸지 않는다.
- 넓은 화면의 여러 관리 동작은 실행 버튼 가까이의 backdrop 없는 동작 선택창으로 제공한다. 좁은 화면은 touch 조작 영역을 확보한 action sheet 방향을 사용하되 세부 배치는 승인 뒤 확정한다.

## 피드백과 문구

- 복사 성공은 `복사됨`으로 알리고 포커스를 가져가지 않는다.
- 복사 실패는 `복사하지 못했습니다.`와 다시 시도하거나 설정을 확인할 수 있는 동작을 제공한다.
- 자동 저장 성공에는 toast를 사용하지 않는다. 명시적 저장 성공은 저장 제어의 짧은 상태 변화로 알린다.
- 자동 저장과 화면 자료 불러오기 실패는 현재 입력과 복구 초안을 유지하고, 실패한 작업 가까이에 자동으로 사라지지 않는 상태와 다시 시도 동작을 둔다.
- 삭제는 복원할 수 있을 때 `메모를 삭제했습니다.`와 `실행 취소`를 제공한다. 되돌릴 수 없는 삭제에만 확인 dialog를 사용한다.
- 일시 결과는 하나의 공유 알림 영역에 현재 한 건만 표시한다. 새 결과가 이전 결과를 바꾸면 표시 시간을 다시 센다.
- 모든 토스트의 오른쪽에 접근 가능한 이름의 닫기 아이콘 버튼을 둔다. 닫기는 알림 표시만 끝내며 실행 취소나 다시 시도를 실행하지 않는다. 실행 취소나 다시 시도 동작이 있는 알림은 5초를 기본값으로 삼고 hover와 `focus-within`에서 시간을 멈춘다.
- validation, 자동 저장 실패, 저장하지 않은 변경과 사용자가 반드시 처리해야 하는 오류를 toast에만 표시하지 않는다.
- 문구는 내용 식별, 이동할 곳, 동작 이름, 입력 label, 필요한 조건, 중요한 결과와 오류 복구에만 사용한다.

## 만들지 않는 공통 구성요소

현재 요구가 없는 generic Card, Carousel, Tabs, Badge 모음, Progress bar, Skeleton, Date Picker와 Tooltip 체계를 미리 만들지 않는다. 메모 목록과 보조 화면에 필요한 Drawer는 탐색 책임에 한정하며 범용 화면 프레임으로 확장하지 않는다. 실제 화면 두 곳 이상에서 같은 책임과 상태가 확인되거나 한 화면의 접근성 및 상태 일관성을 맡아야 할 때만 `shared/ui`로 옮긴다.

## 확인 기준

- 넓은 pointer 화면, 320 CSS px, 200% 글자 확대, `forced-colors`와 `prefers-reduced-motion`에서 주요 과업을 완료할 수 있어야 한다.
- 모든 icon-only button은 실행 결과를 설명하는 접근 가능한 이름을 갖는다.
- drag와 같은 결과를 만드는 단일 pointer 대안과 keyboard 조작을 제공한다.
- 복사, 저장, 선택, 포커스, 속성 대상, dragging과 error를 색 하나, hover 하나 또는 motion 하나로만 전달하지 않는다.
- 같은 pointer 입력이 복사와 상세 이동, drag와 항목 실행, 메모 이동과 캔버스 이동을 함께 실행하지 않는다.
- 실행 동작이 있는 알림은 hover와 `focus-within`에서 자동 종료 시간이 멈추고, 지속 오류는 해결되기 전에 사라지지 않는다.
- 화면별 임의 색, 간격, 모서리와 그림자가 새 디자인 규칙을 만들지 않아야 한다.
